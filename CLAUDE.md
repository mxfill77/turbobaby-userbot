# CLAUDE.md — turbobaby-userbot (ПК-контур)

Репозиторий ПК-контура TurboBaby: userbot (`userbot_listen.py`), модерация
(`moderation_bot.py`/`moderation_core.py`), клиентский suggest (`suggest.py`),
ПК-оркестратор (`pc_orchestrator.py`) и агент управления (`pc_agent.py`).
Brain/Bridge живут на VPS — здесь только исполнение на ПК.

## Модель и мышление (дефолт репозитория)

Дефолт всех сессий этого репо задан в `.claude/settings.json`: модель
`claude-opus-5`, `effortLevel: xhigh`, `alwaysThinkingEnabled: true`,
`env.MAX_THINKING_TOKENS = 31999`. **Каждая задача — ultrathink**: думай на полный
бюджет, а не «по-быстрому».

**Решение владельца 30.07.2026: `claude-opus-5` — единственная голова обеих полос.**
Основная — `claude-opus-5`, запасная — `claude-opus-4-8` (полными идентификаторами:
короткий алиас даёт HTTP 404, класс #194). Так на ПК (`THINKER_MODEL`,
`EXECUTOR_MODEL`) и на VPS (`ORCH_MODEL`, `ORCH_MODEL_FALLBACK`, `EXECUTOR_MODEL`).
Прежняя голова снята с работы: её имена нормализатор моделей уводит на
`claude-opus-5`, чтобы застрявшее в чьём-то окружении старое значение не вернуло её
мимо `.env`. Клиентский `suggest` живёт на своей паре (`SUGGEST_MODEL=sonnet`) — это
отдельный контур, его не трогаем.

**Какая ручка что переключает (проверено по коду 31.07.2026).** Список выше читается как
«четыре env-ручки»; на ПК это не так, и правка «не той» ручки не переключает ничего:

| ручка | ПК | VPS |
|---|---|---|
| `THINKER_MODEL`, `THINKER_FALLBACK` | **настоящие env-ручки** думателя (`pc_orchestrator.py` → `THINKER_MODEL`/`THINKER_FALLBACK`, оба через нормализатор в полный id) | своя пара |
| `EXECUTOR_MODEL` | **НЕ ручка — константа в коде** (`pc_orchestrator.py` → `EXECUTOR_MODEL = "claude-opus-5"`). Env не читается сознательно: комментарий рядом — «застрявший `.env` не смеет молча переключить модель, класс #194». Смена модели исполнителя = правка строки + коммит, self-update перезапустит демон | env-ручка |
| `ORCH_MODEL`, `ORCH_MODEL_FALLBACK`, `EXECUTOR_EFFORT` | **имена VPS-полосы, ПК-код их не читает вовсе** | настоящие ручки |

Отсюда два ложных диагноза, которых надо избегать:
- «поправил `EXECUTOR_MODEL` в конфиге» — на ПК не переключит ничего, а греп по конфигу даст
  ложное подтверждение «настроено». Ключа там и нет (сверка-2 §1 V3).
- «отказ основной головы подхватит запасная» — **у ПК-исполнителя ветки фолбэка нет**:
  `--fallback-model` есть только у думателя (`pc_orchestrator.py` → `_thinker_exec`), в argv
  исполнителя его нет. Для headless-исполнителя отказ головы = провал задачи, а не фолбэк.

Ручка **модели** на ПК — это НЕ `.claude/settings.json`: оттуда headless-полоса берёт только
`effortLevel` и `MAX_THINKING_TOKENS` (`pc_orchestrator.py` → `repo_thinking_settings`).
Поле `model` в settings.json правит интерактивные сессии, а не демона.

## Ритуал журнала (ОБЯЗАТЕЛЬНО)

Каждая сессия Dispatch/Cowork **и каждая сессия Claude Code Remote Control**
(канал с телефона, задача Планировщика `TurboBabyRC`) **ЗАВЕРШАЕТ** любую
правку или действие **ДВУМЯ КАНАЛАМИ** — ровно как Dispatch:

1. **FACT-отчёт владельцу** в самой сессии: что сделано, чем ПРОВЕРЕНО ПО ФАКТУ
   (PID, хеш коммита, статус гейта, вывод команды), что осталось. Сессия без
   итогового FACT-отчёта — **дефект**, а не «молча всё хорошо».
2. **Строка в журнал** `cowork_log`:

```
python cowork_log_append.py "DONE Dispatch <время>: <что сделано>"
```

Без такой записи работа считается **несделанной**. Пиши строку в самом конце —
после коммита/пуша, с локальным временем и (если был коммит) коротким хешем.

Развилка-остановка (нужен выбор человека) фиксируется тем же журналом, но с
префиксом `ASK` вместо `DONE`.

**Что ЛОЖИТСЯ в мозг на самом деле (проверено по `cowork_log_append.py` → `stamp_line`, 31.07).**
Писатель сам штампует дату **сразу после типа**, поэтому строка в мозге выглядит НЕ так, как
образец выше. Это важно не для красоты, а для поиска:

| что пишешь | что ложится в мозг |
|---|---|
| `DONE Dispatch 14:20: …` | `DONE <дата время> UTC: Dispatch 14:20: …` |
| `DONE RC 2026-07-31 14:20: …` | `DONE <дата время> UTC: RC 2026-07-31 14:20: …` |
| `ARTIFACT тема → docs/artifacts/…` | `DONE <дата время> UTC: ARTIFACT тема → …` |

Следствия, каждое — готовый ложный диагноз:
- **Искать RC-итоги по `^DONE RC` бесполезно** — совпадений ноль всегда, и это НЕ значит,
  что RC-сессии не пишут журнал. Ищи `RC` в теле строки.
- **`ARTIFACT` типом записи не является.** Опознаваемые типы — ровно
  `DONE|NOTE|ASK|PLAN|BLOCKED|WAITING|SKIPPED` (`cowork_log_append.py` → `LOG_TYPES`);
  всё прочее получает тип `DONE`. Поэтому ритуал «ARTIFACT, потом DONE» выглядит в мозге как
  **два DONE**, а статистика по типам это не различает.
- Приведение формата к коду (или кода к формату) — правка кода, здесь не сделана;
  записано в остатки сверки.

**ЖУРНАЛ — ИНДЕКС, А НЕ ХРАНИЛИЩЕ ТЕЛ (правило владельца, заведено 31.07.2026).** В журнал идёт
итог 3–5 строк плюс ссылка на артефакт; всё длинное живёт файлом. Это не пожелание, а поведение
кода: строка длиннее **600 символов** (`cowork_log_append.py` → `LINE_MAX`) автоматически
раскладывается писателем на две части — тело уходит в
`docs/artifacts/journal/ГГГГ-ММ-ДД-ЧЧММСС-<тип>.md`, а в мозг ложится голова, обрезанная по
границе фразы, плюс путь и полная длина:

```
DONE <штамп>: <итог> … → docs/artifacts/journal/2026-07-31-091200-done.md (полный текст 2785 симв.)
```

Порог не назначен, а **измерен**: 81 живая строка правильного вида «итог + путь» даёт максимум
588 символов, 600 — ближайшее круглое выше него, поэтому вынос не трогает ни одной уже
правильной записи. Замер и эффект (за неделю 23–30.07 порог превысили бы 140 записей из 400,
журнал −68.6%) — в [`docs/artifacts/2026-07-31-journal-index-threshold.md`](docs/artifacts/2026-07-31-journal-index-threshold.md).
Следствия для сессии: **пиши итог сам** — авто-вынос это страховка, а не замена смысла (машина
режет по границе фразы, но не знает, что в отчёте главное); файл-тело **не попадает в git сам**
(untracked) — нужное коммить руками; если вынос сорвался (нет доступа к диску), писатель
СОЗНАТЕЛЬНО отдаёт строку в мозг целиком: потерянная запись хуже длинной.

**Про таймаут вызова.** Внутренний бюджет писателя больше 30с: два запроса (чтение+запись),
на каждом свой сокет-таймаут, плюс повтор на транспортных ошибках
(`cowork_log_append.py` → `RETRY_TRIES`, `with_retry`). **Внешний `timeout 30` на ручном вызове
опасен**: он убивает процесс ДО ветки `except`, и строка не уходит ни в мозг, ни в спул —
тихая потеря записи при честном рапорте «журнал повис». Если ограничиваешь время — бери
запас (≥150с) либо не ограничивай. К автоматике это не относится: `SessionEnd`-хук
(`dispatch_notify.py` → `_cowork`) запускает запись **отдельным процессом**, внешний таймаут
к ней неприменим.

Если `cowork_log` действительно повис — так и скажи («cowork_log повис, DONE запишем позже»),
не блокируйся на нём. И **не повторяй запись вслепую**: known-класс — ложный отказ при уже
легшей строке, слепой повтор даёт дубль в журнале.

Автоматика этот ритуал **страхует, но не заменяет**: хук `SessionEnd` шлёт карточку
«✅ Code-сессия завершена: <сводка>» в **тему постановки задач 328** (инбокс 1160 и личка —
фолбэки) и сам дописывает строку в `cowork_log` (`dispatch_notify.py --hook session_end`).
Автокарточка — это хвост-страховка на случай обрыва; развёрнутый FACT-отчёт по пунктам
всё равно за сессией.

**Адрес карточки выбирает ОДИН признак — ждёт ли сообщение ОТВЕТА владельца**
(`dispatch_notify.deliver` → `awaits_reply`, правило владельца 10.08.2026). Ждёт → инбокс
1160; не ждёт (итог сессии, сводка, «задача выполнена») → тема постановки 328. Вид сообщения
адресом не распоряжается: перечень видов протухает на первом новом виде — именно так итог
сессии 175 раз из 184 занимал инбокс собой. Замок: карточка **с кнопкой** и **высшая карточка
§7** попадают в 1160 ВСЕГДА, мимо признака и переживая его поломку. `--topic <id>` — это
адрес, названный вызывающим, а не маршрут. Разбор и числа:
[`docs/artifacts/2026-08-10-inbox-awaits-reply-route.md`](docs/artifacts/2026-08-10-inbox-awaits-reply-route.md).

**RC-сессии — отдельное правило (памятка `docs/RC_BRAIN_BRIDGE.md`):** КАЖДАЯ RC-сессия (канал
с телефона, задача Планировщика `TurboBabyRC`) **финальным шагом пишет итог в мозг** через
`cowork_log_append.py`. Формат строки, который ты НАБИРАЕШЬ:

```
DONE RC <дата> <время>: <что сделано, с фактами и хешами>
```

(в мозг он ляжет со штампом писателя между `DONE` и `RC` — см. таблицу «что ложится в мозг»
выше; искать RC-итоги по `^DONE RC` бесполезно.)

(`ASK` вместо `DONE` для развилки; когда RC-работа шла на VPS — ещё и `cclog … --pulse` там,
двойная фиксация ПК+VPS). **Без этой записи сессия считается НЕЗАВЕРШЁННОЙ** — даже если код
закоммичен и проверен. Готовые шаблоны и детали — в
[`docs/RC_BRAIN_BRIDGE.md`](docs/RC_BRAIN_BRIDGE.md).

## Мины в рабочем дереве: почему `grep -rn` по репо врёт (заведено 31.07.2026)

В дереве лежат файлы, которых **нет в git**, но которые греп находит наравне с боевыми.
Каждый из них уже стоил ложного диагноза — проверяй принадлежность, а не только совпадение.

| что лежит | чем опасно |
|---|---|
| **`manager-bot/`** — снимок VPS-кода от 01–02.06.2026 (`bot.py`, `splinter.py`, `bridge_client.py`, свой `.git`, свой `venv`), под `.gitignore`, `git ls-files manager-bot` → **0** | 1) `grep -rn` молча смешивает две реальности: имя `BridgeClient` живёт ТОЛЬКО там (в ПК-дирижёре класс называется `Bridge`) — грепающий чинит чужой июньский код, думая, что смотрит ПК-дирижёра; 2) **боевой `suggest.py` ходит туда за тремя фолбэками** — `LOCAL_FAQ`, `PARK_LIST_FILE`, `PLAYBOOK_FILE`: при падении Bridge клиент получит июньский срез FAQ и парка как живой, и это не будет видно нигде |
| ↳ **`manager-bot/docs/playbook.md` — не снимок, а ЖИВОЕ состояние вне git** (поправка 31.07, замер mtime) | FAQ и парк действительно лежат от **02.06**, а playbook — от **23.07**: в него **пишет боевой `suggest.py`** (`append_playbook_rule`, раздел «## Выученные правила», открытие на `"w"` в трёх местах). Отсюда два ложных диагноза: (а) «в `manager-bot/` всё июньское» — playbook свежий и меняется сам; (б) «каталог — мусор, снести» — снос уничтожит **накопленные выученные правила**, которых нет ни в git, ни в мозге. Каталог сносить НЕЛЬЗЯ |
| **`docs/artifacts/2026-07-23-guard-v3-files/pretool_guard.py`** — копия гарда на 23.07, **872 строки** против живого, выросшего почти втрое (мерить `wc -l pretool_guard.py`, число растёт каждую неделю) | греп по гарду выдаёт две версии; вывод «правила X в гарде нет» получается из архивной копии. Материальная причина класса «чинишь не тот гард» |

`task-2026-07-20-questions-filter.md`, второй — в том же коммите, что внёс отрицаемые строки).

## Правило артефактов (решения владельца)

Если в ходе задачи создан артефакт для решения владельца (таблица, список
кандидатов, дифф, варианты развилки) — **СРАЗУ**, в момент создания:

1. Сохрани его файлом в `docs/artifacts/ГГГГ-ММ-ДД-<тема>.md`.
2. Зафиксируй одной строкой в `cowork_log`:

```
python cowork_log_append.py "ARTIFACT <тема> → docs/artifacts/<файл>: <суть в 10 слов>"
```

(`ARTIFACT` — слово ритуала, а НЕ тип записи: в мозг строка ляжет как
`DONE <штамп>: ARTIFACT …`, см. таблицу типов выше. Правило «финальный DONE ссылается на
артефакт путём» проверяющего в коде не имеет — нарушение молчаливо, держи его сам.)

Финальный DONE обязан **ссылаться на артефакт** (путь к файлу), а не
пересказывать «список собран». Артефакт, оставшийся только в тексте сессии, —
потерянный артефакт: сессия закроется, а владельцу решать не по чему.

## Запись в мозг (Brain-доки) с ПК — ТОЛЬКО через brain_writer

Единственный легальный канал записи в Brain-доки с ПК — доверенный писатель
`brain_writer.py` (образец — VPS-cclog): секреты Bridge берёт САМ процесс писателя,
агентские скрипты их **не читают и в коде не видят**. Интерфейс:

```
venv/Scripts/python.exe brain_writer.py (--id <file id> | --name <док>) "строка"   # CLI
brain_writer.append(text, doc_id=…|name=…, [anchor=…, place=…, require_above=…])   # функция
brain_writer.apply(mutate, …)   # движок для одноразовых скриптов со СВОЕЙ якорной логикой
```

Встроено и неотключаемо: бэкап старого текста в `tmp/brain_backup_*.txt` ДО записи,
якорная вставка (якорь обязан найтись ровно 1 раз), идемпотентность, ОБРАТНОЕ ЧТЕНИЕ
с дословной сверкой. Гард ПК держит канал зелёным ПО ИМЕНИ модуля (`_RE_SAFE_SCRIPTS`),
содержимое не сканируется.

**ЗАПРЕЩЕНО** (класс 328, «утренний ASK про пульс»): одноразовые скрипты в `tmp/` (и где
угодно), которые САМИ читают конфиг с секретами (load_env/BRIDGE_TOKEN) ради записи в мозг, —
это красный канал по гарду и потерянное время владельца. Нужна запись — импортируй
`brain_writer` или зови его CLI; в скрипте живёт только строковая логика (якоря, склейки,
текст блока). Журнальная строка DONE/ASK — по-прежнему через `cowork_log_append.py`.

## Правило-класс: мок внешнего ответа обязан КОПИРОВАТЬ живой формат

Фикстура/мок любого внешнего источника (ответ Bridge, тело страницы Google Maps,
HTTP-редирект, строка листа) обязана дословно повторять **живой формат прода**, а не
идеализированную схему «как удобно тесту». Инцидент трассы #51 — два разрыва «мок ≠
реальность» сразу:
- зоны доставки: тесты гоняли dict `{"name":…,"lat":…}`, а живой `delivery_zones_get`
  отдаёт **позиционный список** `["Раваи", 7.771, 98.327, 590, 4]` = `[name,lat,lon,
  price,radius]` — резолвер (dict-only) молча ронял ВСЕ 16 зон → ложный `[уточнить]`;
- разворот короткой ссылки: мок звался через `_expand`, минуя сеть, и прятал, что живой
  goo.gl отдаёт `302 Found`+`Location`, а `_NoRedirectHandler` поднимает `HTTPError` на
  `opener.open` (а не возвращает 3xx) — продовый `_default_expand` падал на первом 302.

Правило: снимай живой ответ прода **фикстурой** (см. `fixtures/delivery_zones_get.live.json`,
снят read-only пробой) и клади голдены на неё; редирект-цепочку мокай через `HTTPError`
с реальным `Location`, а не в обход. То же, что моки колонок листа: формат мока = формат
источника. И помни: подгонять синтетическую зону ровно под пин ради «красивого» числа —
тот же анти-паттерн (голден врёт). Честный итог живого пина важнее ожидаемого.

## Правило-класс: golden-тесты детекта = РЕАЛЬНЫЕ фразы клиента

Тесты любого детекта намерения (прайс-интент, модель, даты и т.п.) обязаны
включать **дословное сообщение клиента** из живого провала, а не
идеализированную формулировку. Юнит на «прайс»/«все модели» был зелёным, но
живая фраза «Какие марки и модели… какие цены на аренду…» давала False —
классический разрыв «тест ≠ реальность». Добавляя фикс детекта, клади реальную
фразу + 4–5 парафраз RU/EN в позитивы и контрпримеры (одна модель / приветствие /
только депозит) в негативы.

## Правило-класс: зеркало правила с чужой полосы обязано сверить его ПОСЫЛКУ (заведено 04.08.2026)

Порт правила с полосы сервера — это перенос **посылки**, а не строк. Прежде чем зеркалить,
назови, **на каком факте своей полосы** правило стоит, и проверь этот факт **замером здесь**.
Совпадение формы ничего не доказывает: полосы расходятся, и правило, верное там, может быть
здесь уже отменённым — тогда «зеркало» **воскрешает закрытый класс слоем позже**.

Живой случай, из которого правило заведено (дежурный по карточкам, `card_duty.py`). Условие
«объект пуст → карточку снять» на VPS стои́т на посылке «нет объекта ⇔ признак поймал
ПОДСТРОКУ». На ПК эта посылка **измерена мёртвой 02.08.2026**, за два дня до зеркала
(`pretool_guard.card_gate`, класс Д-3): замок `_verb_acts` (31.07) перенёс отсев подстроки на
слой раньше и забрал у ветки весь вход — 22 срабатывания за 10673 решения до него и **ноль**
за 2813 после. С тех пор пустой объект означает «ДЕЙСТВИЕ РАЗОБРАНО, цель не извлеклась»,
и среди фикстур замера был `taskkill /F /T /FI "IMAGENAME eq python.exe"` — снос всех python
на машине. Слепая копия глушила бы такие карточки.

Три вопроса перед любым зеркалом (все — с числом в ответе, а не с «вроде так же»):
1. **На каком факте стои́т правило там** — и жив ли этот факт здесь? Меряй по логу/коду своей
   полосы, а не по докстрингу чужой.
2. **Не закрыт ли этот класс здесь раньше и другим устройством?** Тогда вклад зеркала — ноль,
   и честный итог «ноль» дороже красивого «снято N». На ПК так вышло со всеми четырьмя
   условиями дежурного: замок происхождения (31.07), изоляция проб, объектный гейт (02.08).
3. **Что здесь есть такого, чего там нет?** У ПК это `unknown`/`unknown_tool` — имена, которыми
   гард называет СОБСТВЕННОЕ незнание; у сервера в `_ACTIONS` таких нет вовсе, и правило,
   верное для 14 настоящих операций, на 20 ПК-видов переносится уже с поправкой.

Разбор целиком: [`docs/artifacts/2026-08-04-card-duty-pc-mirror.md`](docs/artifacts/2026-08-04-card-duty-pc-mirror.md).

## Слой ожиданий полосы ПК — О1 и О2 (заведён 11.08.2026, зеркало сервера)

Система спрашивает, что ДОЛЖНО было произойти и не произошло. До 11.08 слоя на ПК не было вовсе
(перепись 467: 287 цепочек, 42 оборвал контур, ожидание заметило бы 0 — потому что механизма нет).
Решение — `expectations_pc.py` (чистая функция «факты → вердикт»), руки — `expectations_pc_run.py`,
регресс и инвариант `EXPECT_PC_PURE` — `test_expectations_pc.py` (49 проверок, в гейте).

| ожидание | предмет | порог | чем обоснован (замер СВОЕЙ полосы 22.07–11.08) |
|---|---|---|---|
| **О1**·`new`/`approved` | строку не берут при СВОБОДНОМ исполнителе | **45 мин** ЧИСТОГО ожидания | 139 пар «создана → взята»: медиана 1.8 · p90 7.2 · max законного 19.7 мин. Контрфакт без условия занятости: 30 мин → 16 флагов, 15 мин → 35 |
| **О1**·`in_progress` | строка замерла в работе | **100 мин** | окно `CLAIM→COMPLETE`: 112 окон, max законного 2712с; потолок законного = 2 попытки × 2700 + хвост = 5412с; реапер демона 5400с |
| **О2** | демон даёт ОБОРОТ `poll_once`, а не просто существует | **20 мин** тишины **в часах бодрствования** | 992 паузы витка: медиана 172с · p95 305с · max законной 605с. Порог 1200с → 0 эпизодов за 20 суток |

Четыре вещи, которые здесь легко перепутать, и каждая уже стоила бы ложного диагноза:

1. **Порог О2 нельзя брать по возрасту heartbeat.** ПК спит, и стенной возраст после сна равен сну.
   Тишина мерится `QueryUnbiasedInterruptTime` (сон в неё не идёт), накоплением от наблюдения к
   наблюдению. Часов нет → исход **«неизвестно»**, а не «жив».
2. **Идущий заход — работа, а не остановка.** Демон исполняет `claude -p` СИНХРОННО внутри
   `poll_once`, а heartbeat пишет ПОСЛЕДНЕЙ строкой (`pc_orchestrator.py:3500`), поэтому любой
   заход выглядит остановкой. Замок: штамп `pc_orchestrator.task_started.json` оправдывает тишину,
   но не дольше `TASK_TIMEOUT` + хвост (55 мин). Контрфакт БЕЗ замка на том же корпусе — **25
   ложных заметок за 20 суток** (на сервере тот же класс дал 10 ложных из 10).
3. **Третий исход обязателен.** «Проверить невозможно» → «неизвестно», и оно НЕ закрывает открытый
   эпизод: молчание источника выздоровлением не является. Ни одна ветка не превращает «не смог
   проверить» в «проверено и хорошо».
4. **Наблюдатель не живёт на том, за чем следит.** Все сторожа очереди ПК (реапер одиночек, реапер
   сирот, TTL подтверждения, сторож цепей) живут ВНУТРИ `poll_once` — вставший демон не судит себя
   ни одной из них.

**НАБЛЮДАТЕЛЬ В ПРОДЕ НЕ УСТАНОВЛЕН — это состояние названо, а не спрятано.** Код готов и проверен
живым прогоном, но задача Планировщика — красная операция (`schtasks`), её ставит ВЛАДЕЛЕЦ одной
командой из-под администратора:

```
schtasks /Create /TN TurboBabyExpectPC /SC MINUTE /MO 10 /RL HIGHEST /F /TR "D:\turbobaby-bot\venv\Scripts\python.exe D:\turbobaby-bot\expectations_pc_run.py"
```

(одной строкой намеренно: перенос через `^` живёт только в cmd.exe и в PowerShell ломает вызов.)

До установки ожидания живут только ручным прогоном (`--status` / `--dry`), и у него есть названная
ловушка: сухой прогон состояние НЕ ПИШЕТ, а тишина О2 копится от наблюдения к наблюдению — значит
на ручных вызовах О2 при отставшем heartbeat всегда честно отвечает «неизвестно». **Откат:** порог
ветки в ноль (`EXPECT_PC_NEW_MIN` / `EXPECT_PC_RUN_MIN` / `EXPECT_PC_TURN_MIN`) — ветка мертва
целиком; полностью — снять задачу Планировщика.

**Что слой НЕ покрывает (честно):** смерть самой машины (наблюдатель живёт на ПК — выключенный ПК
не наблюдает никто; это предмет серверного О4), молчание моста (снимка нет → О1 честно молчит;
предмет серверного О5), `needs_approval` (ждёт живого владельца — не судим), клиентский контур.
Задач слой НЕ СТАВИТ и процессов НЕ ПЕРЕЗАПУСКАЕТ ни одной веткой — в отличие от серверного
оригинала, где сильная ветка есть.

Числа реплея живым кодом (что заметили бы задним числом по корпусу переписи 467): **О1 — 3 из 42**
(id 61, 291, 353; раньше живого терминала на 3 мин, 28 мин и 8.3 ч), ложных 0; **О2 — 0 из 42**,
ложных 0. Разбор:
[`docs/artifacts/2026-08-11-expectations-pc-o1-o2.md`](docs/artifacts/2026-08-11-expectations-pc-o1-o2.md).

## Правила рабочей среды — свод (заведён 25.07.2026)

Полный разбор с фактами: [`docs/ENV_PLAYBOOK.md`](docs/ENV_PLAYBOOK.md). Файл одинаков в ОБОИХ
репозиториях. Здесь — только сами правила; за каждым стоит живой инцидент 23–25.07.

1. **Каналы.** Артефакт файлом в `docs/artifacts/` → строка `ARTIFACT` в журнал → FACT-отчёт в
   сессии → строка `DONE`/`ASK`. Финальный `DONE` **ссылается на артефакт путём**, а не
   пересказывает его. Запись в Brain-доки с ПК — только через `brain_writer`.
2. **Мощность — три РАЗНЫЕ ручки:** модель, усилие (`--effort`), бюджет мышления. **Замер 24.07:
   ключевое слово в тексте задания уровень усилий НЕ меняет** — это конфигурационная ручка
   (`ultrathink` стоял в 10 заданиях из 11, признаком тяжести быть не может). Имя модели обязано
   быть ПОЛНЫМ: короткий алиас даёт `404`. Клиент (RC/Desktop) перекрывает `effortLevel` репо.
3. **Одна задача — один вызов.** Серверный заход не дробить: бэкап → правка → тесты → гейт →
   коммит → откат при любом красном, всё внутри одного ssh. 25.07 это спасло дерево: вызов упёрся
   в 4 красных теста и **сам откатился**. Вывод гейта **никогда** не захватывать в `$( )`.
4. **Очередь внутри сессии последовательна.** Связанные задачи — по очереди здесь же, они
   переиспользуют собранную фактуру. Новая сессия — только под несвязанную тему.
5. **Судить по ДЕЙСТВИЮ, а не по подстроке.** Нет числа или имени (PID, путь, таблица, хост) —
   карточки быть не должно. Слова `гейт`/`тесты`/`коммит` в признаках не держим. Разбор сегментов
   обязан уважать кавычки. Явный запрет владельца бьёт всё остальное.
   **Перечни классов — [`docs/guard-classes.md`](docs/guard-classes.md)** (три списка разной
   длины; «да» на класс снимает карточку ТОЛЬКО этому классу: одобренный `env` не открывает
   `Read` секретов — у него класс `read_secret`).
6. **Финальный шаг сессии — итог в журнал** (`DONE`/`ASK`). Без записи сессия незавершена. Боевые
   токены в тексте записи **называть словами**, а не цитировать: поверх нашего гарда работает
   второй, внешний слой защиты, которого в репозитории нет.
7. **Сводка — гипотеза, числа — факт.** Сверять с сырым выводом; при расхождении верить числам и
   говорить об этом. За три дня сводка ошибалась четыре раза, числа — ни разу.
8. **Проверка повторяет живой формат запуска.** Фикстура снимается с прода; мок, переставший
   задевать ветку, хуже отсутствующего; способ запуска (`-m unittest` против прямого файла) — тоже
   часть формата; голдены детекта — на дословных фразах.
9. **Класс-фикс — сразу на ОБЕ полосы.** Иначе зеркальные дыры: 25.07 признак «это тест-прогон» на
   VPS смотрел имя файла, а на ПК окружение — один класс, две течи. Не закрыть вторую сейчас —
   записать её в остатки **с точками касания**.
