# CLAUDE.md — turbobaby-userbot (ПК-контур)

Репозиторий ПК-контура TurboBaby: userbot (`userbot_listen.py`), модерация
(`moderation_bot.py`/`moderation_core.py`), клиентский suggest (`suggest.py`),
ПК-оркестратор (`pc_orchestrator.py`) и агент управления (`pc_agent.py`).
Brain/Bridge живут на VPS — здесь только исполнение на ПК.

## Модель и мышление (дефолт репозитория)

Дефолт всех сессий этого репо задан в `.claude/settings.json`: модель
`claude-opus-5`, `effortLevel: xhigh`, `alwaysThinkingEnabled: true`,
`env.MAX_THINKING_TOKENS = 31999`. **Каждая задача — ultrathink**: думай на полный
бюджет, а не «по-быстрому».

**Решение владельца 30.07.2026: `claude-opus-5` — единственная голова обеих полос.**
Основная — `claude-opus-5`, запасная — `claude-opus-4-8` (полными идентификаторами:
короткий алиас даёт HTTP 404, класс #194). Так на ПК (`THINKER_MODEL`,
`EXECUTOR_MODEL`) и на VPS (`ORCH_MODEL`, `ORCH_MODEL_FALLBACK`, `EXECUTOR_MODEL`).
Прежняя голова снята с работы: её имена нормализатор моделей уводит на
`claude-opus-5`, чтобы застрявшее в чьём-то окружении старое значение не вернуло её
мимо `.env`. Клиентский `suggest` живёт на своей паре (`SUGGEST_MODEL=sonnet`) — это
отдельный контур, его не трогаем.

## Ритуал журнала (ОБЯЗАТЕЛЬНО)

Каждая сессия Dispatch/Cowork **и каждая сессия Claude Code Remote Control**
(канал с телефона, задача Планировщика `TurboBabyRC`) **ЗАВЕРШАЕТ** любую
правку или действие **ДВУМЯ КАНАЛАМИ** — ровно как Dispatch:

1. **FACT-отчёт владельцу** в самой сессии: что сделано, чем ПРОВЕРЕНО ПО ФАКТУ
   (PID, хеш коммита, статус гейта, вывод команды), что осталось. Сессия без
   итогового FACT-отчёта — **дефект**, а не «молча всё хорошо».
2. **Строка в журнал** `cowork_log`:

```
python cowork_log_append.py "DONE Dispatch <время>: <что сделано>"
```

Без такой записи работа считается **несделанной**. Пиши строку в самом конце —
после коммита/пуша, с локальным временем и (если был коммит) коротким хешем.
Вызов делай с таймаутом (~30с); если `cowork_log` повис — так и скажи
(«cowork_log повис, DONE запишем позже»), не блокируйся на нём.

Развилка-остановка (нужен выбор человека) фиксируется тем же журналом, но с
префиксом `ASK` вместо `DONE`.

Автоматика этот ритуал **страхует, но не заменяет**: хук `SessionEnd` шлёт карточку
«✅ Code-сессия завершена: <сводка>» в тему 1160 (личка — фолбэк) и сам дописывает
строку в `cowork_log` (`dispatch_notify.py --hook session_end`). Автокарточка — это
хвост-страховка на случай обрыва; развёрнутый FACT-отчёт по пунктам всё равно за
сессией.

**RC-сессии — отдельное правило (памятка `docs/RC_BRAIN_BRIDGE.md`):** КАЖДАЯ RC-сессия (канал
с телефона, задача Планировщика `TurboBabyRC`) **финальным шагом пишет итог в мозг** через
`cowork_log_append.py`. Формат строки — точный:

```
DONE RC <дата> <время>: <что сделано, с фактами и хешами>
```

(`ASK` вместо `DONE` для развилки; когда RC-работа шла на VPS — ещё и `cclog … --pulse` там,
двойная фиксация ПК+VPS). **Без этой записи сессия считается НЕЗАВЕРШЁННОЙ** — даже если код
закоммичен и проверен. Готовые шаблоны и детали — в
[`docs/RC_BRAIN_BRIDGE.md`](docs/RC_BRAIN_BRIDGE.md).

## Правило артефактов (решения владельца)

Если в ходе задачи создан артефакт для решения владельца (таблица, список
кандидатов, дифф, варианты развилки) — **СРАЗУ**, в момент создания:

1. Сохрани его файлом в `docs/artifacts/ГГГГ-ММ-ДД-<тема>.md`.
2. Зафиксируй одной строкой в `cowork_log`:

```
python cowork_log_append.py "ARTIFACT <тема> → docs/artifacts/<файл>: <суть в 10 слов>"
```

Финальный DONE обязан **ссылаться на артефакт** (путь к файлу), а не
пересказывать «список собран». Артефакт, оставшийся только в тексте сессии, —
потерянный артефакт: сессия закроется, а владельцу решать не по чему.

## Запись в мозг (Brain-доки) с ПК — ТОЛЬКО через brain_writer

Единственный легальный канал записи в Brain-доки с ПК — доверенный писатель
`brain_writer.py` (образец — VPS-cclog): секреты Bridge берёт САМ процесс писателя,
агентские скрипты их **не читают и в коде не видят**. Интерфейс:

```
venv/Scripts/python.exe brain_writer.py (--id <file id> | --name <док>) "строка"   # CLI
brain_writer.append(text, doc_id=…|name=…, [anchor=…, place=…, require_above=…])   # функция
brain_writer.apply(mutate, …)   # движок для одноразовых скриптов со СВОЕЙ якорной логикой
```

Встроено и неотключаемо: бэкап старого текста в `tmp/brain_backup_*.txt` ДО записи,
якорная вставка (якорь обязан найтись ровно 1 раз), идемпотентность, ОБРАТНОЕ ЧТЕНИЕ
с дословной сверкой. Гард ПК держит канал зелёным ПО ИМЕНИ модуля (`_RE_SAFE_SCRIPTS`),
содержимое не сканируется.

**ЗАПРЕЩЕНО** (класс 328, «утренний ASK про пульс»): одноразовые скрипты в `tmp/` (и где
угодно), которые САМИ читают конфиг с секретами (load_env/BRIDGE_TOKEN) ради записи в мозг, —
это красный канал по гарду и потерянное время владельца. Нужна запись — импортируй
`brain_writer` или зови его CLI; в скрипте живёт только строковая логика (якоря, склейки,
текст блока). Журнальная строка DONE/ASK — по-прежнему через `cowork_log_append.py`.

## Правило-класс: мок внешнего ответа обязан КОПИРОВАТЬ живой формат

Фикстура/мок любого внешнего источника (ответ Bridge, тело страницы Google Maps,
HTTP-редирект, строка листа) обязана дословно повторять **живой формат прода**, а не
идеализированную схему «как удобно тесту». Инцидент трассы #51 — два разрыва «мок ≠
реальность» сразу:
- зоны доставки: тесты гоняли dict `{"name":…,"lat":…}`, а живой `delivery_zones_get`
  отдаёт **позиционный список** `["Раваи", 7.771, 98.327, 590, 4]` = `[name,lat,lon,
  price,radius]` — резолвер (dict-only) молча ронял ВСЕ 16 зон → ложный `[уточнить]`;
- разворот короткой ссылки: мок звался через `_expand`, минуя сеть, и прятал, что живой
  goo.gl отдаёт `302 Found`+`Location`, а `_NoRedirectHandler` поднимает `HTTPError` на
  `opener.open` (а не возвращает 3xx) — продовый `_default_expand` падал на первом 302.

Правило: снимай живой ответ прода **фикстурой** (см. `fixtures/delivery_zones_get.live.json`,
снят read-only пробой) и клади голдены на неё; редирект-цепочку мокай через `HTTPError`
с реальным `Location`, а не в обход. То же, что моки колонок листа: формат мока = формат
источника. И помни: подгонять синтетическую зону ровно под пин ради «красивого» числа —
тот же анти-паттерн (голден врёт). Честный итог живого пина важнее ожидаемого.

## Правило-класс: golden-тесты детекта = РЕАЛЬНЫЕ фразы клиента

Тесты любого детекта намерения (прайс-интент, модель, даты и т.п.) обязаны
включать **дословное сообщение клиента** из живого провала, а не
идеализированную формулировку. Юнит на «прайс»/«все модели» был зелёным, но
живая фраза «Какие марки и модели… какие цены на аренду…» давала False —
классический разрыв «тест ≠ реальность». Добавляя фикс детекта, клади реальную
фразу + 4–5 парафраз RU/EN в позитивы и контрпримеры (одна модель / приветствие /
только депозит) в негативы.

## Правила рабочей среды — свод (заведён 25.07.2026)

Полный разбор с фактами: [`docs/ENV_PLAYBOOK.md`](docs/ENV_PLAYBOOK.md). Файл одинаков в ОБОИХ
репозиториях. Здесь — только сами правила; за каждым стоит живой инцидент 23–25.07.

1. **Каналы.** Артефакт файлом в `docs/artifacts/` → строка `ARTIFACT` в журнал → FACT-отчёт в
   сессии → строка `DONE`/`ASK`. Финальный `DONE` **ссылается на артефакт путём**, а не
   пересказывает его. Запись в Brain-доки с ПК — только через `brain_writer`.
2. **Мощность — три РАЗНЫЕ ручки:** модель, усилие (`--effort`), бюджет мышления. **Замер 24.07:
   ключевое слово в тексте задания уровень усилий НЕ меняет** — это конфигурационная ручка
   (`ultrathink` стоял в 10 заданиях из 11, признаком тяжести быть не может). Имя модели обязано
   быть ПОЛНЫМ: короткий алиас даёт `404`. Клиент (RC/Desktop) перекрывает `effortLevel` репо.
3. **Одна задача — один вызов.** Серверный заход не дробить: бэкап → правка → тесты → гейт →
   коммит → откат при любом красном, всё внутри одного ssh. 25.07 это спасло дерево: вызов упёрся
   в 4 красных теста и **сам откатился**. Вывод гейта **никогда** не захватывать в `$( )`.
4. **Очередь внутри сессии последовательна.** Связанные задачи — по очереди здесь же, они
   переиспользуют собранную фактуру. Новая сессия — только под несвязанную тему.
5. **Судить по ДЕЙСТВИЮ, а не по подстроке.** Нет числа или имени (PID, путь, таблица, хост) —
   карточки быть не должно. Слова `гейт`/`тесты`/`коммит` в признаках не держим. Разбор сегментов
   обязан уважать кавычки. Явный запрет владельца бьёт всё остальное.
6. **Финальный шаг сессии — итог в журнал** (`DONE`/`ASK`). Без записи сессия незавершена. Боевые
   токены в тексте записи **называть словами**, а не цитировать: поверх нашего гарда работает
   второй, внешний слой защиты, которого в репозитории нет.
7. **Сводка — гипотеза, числа — факт.** Сверять с сырым выводом; при расхождении верить числам и
   говорить об этом. За три дня сводка ошибалась четыре раза, числа — ни разу.
8. **Проверка повторяет живой формат запуска.** Фикстура снимается с прода; мок, переставший
   задевать ветку, хуже отсутствующего; способ запуска (`-m unittest` против прямого файла) — тоже
   часть формата; голдены детекта — на дословных фразах.
9. **Класс-фикс — сразу на ОБЕ полосы.** Иначе зеркальные дыры: 25.07 признак «это тест-прогон» на
   VPS смотрел имя файла, а на ПК окружение — один класс, две течи. Не закрыть вторую сейчас —
   записать её в остатки **с точками касания**.
