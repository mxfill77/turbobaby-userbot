## 3. Что произойдёт при approve — РАБОТА НЕ РОДИТСЯ

Ветка и строка: **`pc_orchestrator.py:2060-2065`**, внутри `process_approved()`:

```python
if _is_revizor_owner_card(task.get("task_text")):
    # info-карточка ревизора: approve = «принято», без headless-прогона фиктивного текста
    bc.complete_task(tid, "done", "🔍 owner-находки ревизора приняты Филиппом")
    _cowork(f"ревизор: owner-карточка #{tid} принята (approve)")
    log.info("APPROVED id=%s ревизор-owner-карточка → принято", tid)
    continue
```

`_is_revizor_owner_card` (`:5676-5679`) = `task_text.startswith("[ревизор-находки]")` — у
карточки 6 `task_text` начинается ровно так, значит ветка сработает гарантированно.

Границы:
- `continue` **до** `run_task` — headless-исполнитель не запускается ВООБЩЕ;
- ни одной задачи в очередь не ставится, ни одного коммита, ни одной правки файла;
- задача переходит `approved → done` с фиксированной строкой «owner-находки ревизора приняты
  Филиппом»;
- в `cowork_log` ложится одна строка «ревизор: owner-карточка #6 принята (approve)».

**Ответ прямо:** карточка **закрывается как «принял к сведению»**, как 95 и 100 — работы она
не рождает. Двенадцать находок при approve **исчезают вместе с карточкой**: следующий прогон
ревизора уже не найдёт `needs_approval`-карточку по маркеру (`_revizor_find_owner_card`,
`:5853-5858` ищет строго `status == "needs_approval"`), `prior_lines` окажется пустым, и
неразобранные находки не перенесутся. Работу по ним надо ставить ОТДЕЛЬНО, до approve.

Симметрично: reject/отклонение тоже не рождает работы — карточку закроет Splinter.
