### Почему self-update молчал до 21:13, хотя файл был готов в 20:54

Не сбой, а ровно то «отложенно», которого требовал п.2 задания. Две причины, обе по коду:

1. `maybe_self_update` сравнивает **блоб в HEAD**, а не файл на диске (`_head_blob` →
   `git rev-parse HEAD:pc_orchestrator.py`). До коммита `9e518b7` в 21:07:14 в HEAD лежал старый
   блоб — обновляться было не на что.
2. Вызов стоит **в конце тика опроса, после `poll_once()`** (`pc_orchestrator.py:6382-6389`), а
   `poll_once()` выполняет задачу синхронно. Демон с 20:45:15 по 21:13:11 был занят задачей 128,
   и тик не доходил до проверки. Самообновление сработало на первом же тике после её закрытия.

То есть демон **сам** отложил рестарт до конца чужой работы и **сам** его выполнил — механизм
исправен, вмешательства не требовалось.

## ШАГ 5. Откуда берётся КЛАСС операции после «да»

**Из строки, которую пишет САМ ГАРД, а не `_card` и тем более не модель.** Цепочка целиком:

| # | место | что происходит |
|---|---|---|
| 1 | `pretool_guard._write_marker` (`:2728-2729`) | к тексту карточки **дописывается последней строкой** `Класс операции: <вид>` — из класса, который вычислил САМ гард. Строка живёт только в headless-канале |
| 2 | `pc_orchestrator._detect_needs_approval` | читает файл-маркер, сверяет `run_token` запуска → текст карточки |
| 3 | `bc.set_needs_approval(tid, card)` | карточка сохраняется рядом очереди (поле `what`) |
| 4 | `pc_orchestrator._approved_kinds` (`:1134-1151`) | после «да» берёт `item["what"]` (или `result`) — **сохранённую карточку гарда**, а не вывод исполнителя |
| 5 | `pretool_guard.kinds_from_card` (`:2236-2254`) | слой 1 — regex `_RE_KIND_LINE` по строке из п.1; слой 2 — фраза карточки (`_human`), страховка для карточек, выписанных до появления слоя 1 |
| 6 | `PRETOOL_APPROVED_KINDS` | класс уезжает ребёнку |

**Слоя `op=` больше нет.** Проверено обоими способами:

- **в памяти живого демона** (он импортирует гард, значит слой жил бы прямо там):
  `_RE_OP_MARK` — найдено **0**; `Класс операции: ` — найдено **2**;
- **поведением** `kinds_from_card`:

| текст | класс |
|---|---|
| подделка модели `op=delete op=env op=sqlite op=git_force` | **(ПУСТО — одобрять нечего)** |
| настоящая карточка гарда | `env` |
| настоящая + подмешанная подделка | `env` (подделка класса не добавила) |

### Честный остаточный край (слой 2)

`tmp/probe_layer2_edge.py`: если модель **дословно** повторит человеческую фразу карточки
(`'Хочу обратиться к .env / секретам'`, 33 символа при пороге 12), слой 2 класс выдаст:

```
op=-форма (снятый слой)                    → (ПУСТО)
модель дословно повторила ФРАЗУ карточки   → env
модель повторила фразу И строку класса     → delete
```

**Через ПК-демон этот край недостижим**, и вот почему по коду: `_approved_kinds` читает
`item["what"]` — то есть СОХРАНЁННУЮ карточку, а положить туда что-либо может только
`bc.set_needs_approval`, который вызывается исключительно из ветки файл-маркера гарда. Текст
модели в поле `what` не попадает вовсе, значит `kinds_from_card` его никогда не увидит. Замок по
происхождению закрывает край не сам по себе, а тем, что **отрезает единственную дорогу к нему**.

Отсюда практический вывод: **на полосе, где замка по происхождению НЕТ, этот край достижим** —
см. раздел ниже.
