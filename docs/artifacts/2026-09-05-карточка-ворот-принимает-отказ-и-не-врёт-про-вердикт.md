касается. Работа велась с нуля.

## 1. Премиса — проверена своими командами, не на слово

Проба: `_scratch_card_truth_0905/probe_premise.py` (только чтение; ни один реестр не тронут).

### 1.1 У карточки одна дверь — подтверждено

Живой `card_text` печатает ровно два пропуска и ни одного слова для отказа:

```
Пропуск — одно из двух:
 • твоё «да»: ответь «выкати» — применю этим же коммитом в ближайшую минуту;
 • зелёный прогон через тренажёр — …
```

Разбор ответов знал отказ ещё меньше — **ноль форм из шести**:

| ответ владельца | `_match_command` до правки |
|---|---|
| `выкати` | `release_client` |
| `не выкатывай` | **None** |
| `нет` | **None** |
| `отбой` | **None** |
| `отказ` | **None** |
| `не надо` | **None** |
| `отклоняю` | **None** |

`None` означает не «отказ принят», а «это не команда» — ответ уезжал в headless-путь как
дев-задача. Владелец, ответивший «нет», не получал ни расписки, ни следа.

### 1.2 Вердикт на 74be777 — ЛОЖЬ, дословная причина из кода

```
trainer_verdict('74be777') -> False
дословная причина: корпус кейсов не тот, на котором снят вердикт
```

Строка кода, которая это говорит, — `client_contour.py`, ветка сверки корпуса:

```python
    sha = corpus_sha(cases_path)
    if not sha or str(rec.get("corpus_sha") or "") != sha:
        return False, "корпус кейсов не тот, на котором снят вердикт"
```

Числа замера:

| что | значение |
|---|---|
| ключей в ящике `green` | ровно один — `74be777` |
| запись 74be777 | `result=green`, кейсов 12/12, чеков 224/224, прогонов 2, `clean=True` |
| `corpus_sha` записи | `98ad5e3e2c256542` |
| `corpus_sha` корпуса на диске | `6d5d78f0d83acdca` |
| кейсов в `trainer_cases.json` на диске | **16** |
| вердикт записи на ЕЁ СОБСТВЕННОМ коммите | `(False, 'корпус кейсов не тот, на котором снят вердикт')` |

Последняя строка — суть дефекта (б): запись не открывает даже тот коммит, на котором снята.

### 1.3 Что владелец читал в карточке

```
trainer_status(HEAD=4aadeb0) → «вердикта на этот коммит нет (последний зелёный — на 74be777)»
```

Слово «последний зелёный» здесь — утверждение о зелени, которой нет ни на одном коммите. Строка
читается как обнадёживающая («зелень есть, просто не тут»), а правда — «зелени нет нигде».

**Все три пункта премисы подтверждены.**

## 2. Что сделано

Единица одна, как и заказано: одно место разбора, две строки карточки, одно место записи, свои тесты.

### 2.1 Слово отказа — выбор и обоснование

Список **закрытый и якорный** (совпадает, только когда ВЕСЬ текст задачи и есть ответ), регистр не
учитывается:

```
не выкатывай · не выкатывать · не выкатываем · не выкати · не раскатывай · не применяй ·
не надо · нет · отбой · отказ · отклоняю · отклонить      (плюс форма «нет, не выкатывай»)
```

Головное слово — **«не выкатывай»**: это зеркало самого рычага «выкати», та же основа, спутать
нельзя, и в карточке две двери встают рядом одной парой. **«нет»** внесено потому, что это
дословно то слово, которым владелец ответил живой карточке 05.09, — не принять его значило бы не
закрыть тот самый случай, ради которого задача заведена. Остальные — обиходные формы того же
решения.

Почему список, а не шаблон «всё, что начинается с „не“»: широкий шаблон перехватывал бы дев-задачи.
Проверено голденом — `тз: почини детект, не надо трогать прайс` → `None` (headless-путь, как было).

### 2.2 Третий исход: переспросить, а не догадываться

Ответ, похожий на отказ, но в список не входящий, отказом **не считается**:

| ответ | исход | что делает |
|---|---|---|
| `не выкатывай`, `нет`, `отбой`, … | `deny_client` | пишет отказ, закрывает повод |
| `не сейчас`, `пока нет`, `погоди`, `стоп`, `позже`, `не уверен`, `подумаю`, … | `deny_unclear` | **ничего не пишет**, переспрашивает |
| `выкати`, `раскати`, `примени` | `release_client` | как было |

Догадка здесь дорога в обе стороны: принять «не сейчас» за отказ значит замолчать повод, который
владелец хотел отложить на час. Ответ переспроса называет точные слова обеих дверей и прямо
говорит: «повод остался открытым, ворота держат».

Честный остаток: закрытый список отговорок покрывает перечисленные формы, а не любую мыслимую
фразу. Всё непокрытое уезжает по старой дороге в headless — то есть тоже не одобряет ничего
(fail-closed в обе стороны).

### 2.3 Где живёт след отказа — и почему там

**Строка в журнал** (лента) — `_exec_deny_client` зовёт `_cowork`:
`ворота клиентского контура: владелец сказал «нет» на <коммит> (форма «<форма>») — ничего не
применяю, повод закрыт`.

**Запись рядом с поводом** — ключ `denied` в реестре решений владельца
`pc_orchestrator.client_release.json`, **рядом с ключом `approved`**. Выбор места: это ОДНА
развилка и одно решение владельца об ОДНОМ коммите; разносить два исхода по разным файлам значило
бы дать им разную судьбу при ротации и разное время жизни. Ротация та же (`_KEEP=50`).

Файл вердикта тренажёра (`pc_orchestrator.client_trainer_green.json`) в этой работе **не тронут
ни на запись, ни на удаление** — читался только штатным API `trainer_verdict`. Живая проба
подтверждает: после отказа `release_reason` → `None`, файла оснований не появилось.

Третья запись — **повод, о котором спросили** (`remember_asked`, ключ `asked` в том же реестре).
Она нужна потому, что ответ «нет» приезжает ОТДЕЛЬНОЙ задачей, формы в себе не несёт, а HEAD к
тому времени успевает уехать: без неё отказ закрыл бы не тот повод. Повод запоминается ровно там,
где вопрос задан, — при отправке карточки; ушедший в ленту отказ повода не открывает и не
запоминается.

### 2.4 Карточка называет ОБА ответа

```
Пропуск — одно из двух:
 • твоё «да»: ответь «выкати» — применю этим же коммитом в ближайшую минуту;
 • зелёный прогон через тренажёр — <причина>
Не надо — ответь «не выкатывай» (или «нет», «отбой»): запишу твой отказ и по этому поводу
   спрашивать перестану. Отказ ничего не применяет и ничего не откатывает; на другом
   коммите с другим составом файлов спрошу снова.
```

Слова «Отказ ничего не применяет и ничего не откатывает» стоят в карточке не для красоты: без них
вторая дверь читалась бы как вторая дорога к выкатке.

### 2.5 Повод закрыт — но отказ не вечен

Тишина двухслойная, и второй слой заведён прямо против предсмертного взгляда задания:

| случай | адрес | почему |
|---|---|---|
| тот же повод (тот же коммит + та же форма) | **лента**, всегда | это дословно тот вопрос, на который ответ уже дан |
| та же форма на ДРУГОМ коммите | **лента**, но лишь `DENY_MUTE_SEC = 24 ч` | по существу тот же вопрос — но не навсегда |
| другой состав клиентских файлов / другие дети | **карточка**, сразу | «новый коммит с новой формой спросить вправе» |
| нечитаемый реестр решений | **карточка** | fail-loud: молчание по недосмотру хуже лишней карточки |

Почему 24 часа. Класс 21.08 дал **14 карточек одной формы за сутки** — вот это залп. Темп полосы —
4.3 закрытых задачи в сутки, то есть «нет», сказанное вчера, относится ко вчерашнему состоянию
дерева. Одна карточка на форму в сутки залпом не является, а молчание длиннее суток было бы уже
забвением: заглушить пару «дети + файлы» навсегда значит съесть СЛЕДУЮЩИЙ, уже нужный, вопрос о
выкатке. Именно поэтому в адрес отказа подаётся коммит — без него судить можно было бы только по
паре «дети + файлы», и тишина стала бы вечной.

Отказ не отнимает и права передумать: «выкати» после «нет» открывает ворота как обычно, а запись
об отказе остаётся историей (голден `test_peredumal_da_posle_neta_rabotaet`).

### 2.6 Строка про вердикт говорит правду

Правила сверки записи вынесены в `_verdict_holds` **без единого послабления** (те же семь условий:
result=green, тот же коммит целиком, все чеки, ≥12 кейсов, ≥2 прогона, чистое дерево, тот же
корпус) — и теперь их можно задать записи про ЕЁ СОБСТВЕННЫЙ коммит. Отсюда три различимых
состояния:

| состояние | что говорит карточка |
|---|---|
| вердикта нет вовсе | `прогона не было` |
| вердикт есть и держится, но на другом коммите | `вердикта на этот коммит нет; ДЕЙСТВУЮЩИЙ зелёный — на <X>` |
| запись есть, но не открывает и свой коммит | `зелёного вердикта нет НИ НА ОДНОМ коммите: запись на <X> есть, но она не открывает и его (<причина>)` |
| вердикт есть и на этом коммите | `зелёный: кейсов …, чеков …, прогонов …, коммит совпал` |

Живая карточка на HEAD `4aadeb0` после правки:

```
 • зелёный прогон через тренажёр — зелёного вердикта нет НИ НА ОДНОМ коммите: запись на
   74be777 есть, но она не открывает и его (корпус кейсов не тот, на котором снят вердикт)
```

Слово «последний зелёный» из карточки исчезло. Правило сравнения корпуса не ослаблено — голден
`test_pravila_sravneniya_korpusa_ne_oslableny` гоняет шесть порч записи и требует, чтобы ни одна
не открыла ворота и ни одна не была названа зелёной.

## 5. Изоляция, заведённая одновременно с веткой

Реестр решений владельца лежит в корне репо ровно как реестр форм заморозки — значит прогон тестов
писал бы в БОЕВОЙ реестр «о чём спросили», а живой отказ владельца закрыл бы повод из теста. Этот
класс полоса уже проходила дважды (замер 22.08: боевой `gate_seen.json` держал n=160 по форме,
нарощенные прогонами тестов). Поэтому `RELEASE_FILE` добавлен в изоляцию `Base` и в замок
`test_puti_ruchki_vedut_vne_repozitoriya` **в том же коммите, что и сама ветка**, а не после первого
живого промаха.

## 6. Что НЕ сделано и что осталось честным остатком

- Поведение ворот не менялось ни одной веткой: fail-closed на месте, отказ ничего не разрешает.
- Новой дороги к одобрению не создано: `deny_client` и `deny_unclear` не зовут `approve` ни разу
  (голден проверяет мок `approve` — вызовов ноль).
- Файл вердикта не правился и не удалялся.
- Отговорки вне закрытого списка (§2.2) переспроса не получают — уезжают в headless как раньше.
- Слова отказа приходят задачей в очередь; голосового/кнопочного канала у этой двери нет, как не
  было и у «выкати».
