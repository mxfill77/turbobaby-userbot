Ключ в реестре появляется только от ЯВНОЙ регистрации (`create_brain_plain` с ключом,
`register_brain_doc`), и никак иначе.

документа `shtab_box_probe*` в папке нет вовсе**, поэтому «ключа нет» само по себе ничего бы не
доказало. Доказательство даёт не отсутствие пробы, а **14 живых документов, которые в папке лежат

## 4. Почему на этом останавливаться было НЕЛЬЗЯ (контроль, которого задание не заказывало)

Задание строит вывод так: ключа нет → значит реестр не видит документов, созданных в папке. Это
**born-false**, если пробного документа в папке нет: тогда мерили отсутствие стимула, а не
слепоту реестра. Поэтому — один read-only контроль тем же каналом, GET-экшеном
`list_brain_folder` (заведён в проде 02.09, @84):

```
ok=True  count=48  folders_count=1  truncated=False  scanned=48
folder_id=1uWqHsxk7aEWoSNqaUBMmqkYOh2UKYLkY
```

- **Детей-файлов в папке мозга: 48**, список НЕ обрезан (`truncated=False`, `scanned=48`).
- **`prefix=shtab_box_probe` → `count=0`.** Документа с таким именем в папке **НЕТ**.
- Подстрока `probe` в именах всех 48 детей — **0 совпадений**. Подстрока `shtab` — 2
  (`KB_shtab_frame`, `shtab_box`), `box` — 1 (`shtab_box`).
- Подпапка ровно одна — `_archive` (`1r3NCEoPZUPshQNht_F6cvg80cF2Jpqcj`), это каталог архиватора.

**Вывод контроля:** пробный документ Штабом в папку мозга не положен (или положен не сюда).
Прямого стимула, который задание считало существующим, на живом мосту нет.

## 6. Механизм, а не догадка

`brain_writer.list_brain` (боевой код этой полосы, docstring): «реестр живёт в Script Properties
проекта Apps Script (`BRAIN_MANIFEST`) и наружу отдаётся ЕДИНСТВЕННЫМ экшеном моста».

Сторона моста, снимок `tmp/bridge_head/ReadDocs.js` (**снимок 30.07.2026** — берётся как
объяснение, не как доказательство; доказательство — замер §5):

```javascript
var BRAIN_PROP_KEY = 'BRAIN_MANIFEST';

function getBrainManifest_() {
  var raw = PropertiesService.getScriptProperties().getProperty(BRAIN_PROP_KEY);
  if (!raw) return {};
  try { return JSON.parse(raw); } catch (e) { return {}; }
}
```

Реестр — это **строка JSON в Script Properties**, которую мост читает как есть. Папку он при
этом не обходит ни одной строкой. Меняют её только явные экшены: `create_brain_plain` (с ключом),
`register_brain_doc`, `unregister_brain_doc`, замена id при `replace`. Создание файла в папке
средствами Drive ни один из них не зовёт — потому ключ и не появляется.

## 7. Что это значит для цели: может ли Штаб класть задания в ящик сам

**Через реестр — не может.** Документ, созданный Штабом прямо в папке, ключа не получит, а
разрешение имени (`brain_writer.resolve_name`) сопоставляет имя именно с ключами ЖИВОГО реестра —
такой документ для чтения по имени не существует.

**Прод-ящик папку тоже не читает** (замер по коду: `list_brain_folder` и слово `folder` в
`shtab_box.py`, `shtab_box_run.py`, `shtab_box_signals.py` — **0 совпадений**). Живой путь —
`read_node` → чтение узла `shtab_box` доверенным писателем. То есть сегодня задание попадает в
ящик **дозаписью в узел `shtab_box`**, и никак иначе.

**Но дорога есть, и она не в реестре.** Мост с 02.09 умеет перечислять папку — GET
`list_brain_folder` с отбором по `prefix` (проверено этим же заходом: 48 детей, `prefix=shtab_box`
→ 1). Значит «Штаб кладёт файл в папку → ПК его подбирает» технически возможно, но требует
**правки кода ящика** (научить `shtab_box_run` читать папку по префиксу) — это отдельная работа,
заходом не делалась: задание запрещало править код.

## 8. Границы честности

- Сказано «пробного документа в папке нет» — про **корень** папки мозга. Содержимое подпапки
  `_archive` этот экшен не перечисляет; если Штаб положил пробу туда, заход её не увидел бы.
- Три чтения реестра доказывают его состояние **в интервале 06:38:33–06:41:24 UTC 03.09**, и
  ничего не говорят о более позднем: свежесть даёт только новое чтение.
- Снимок кода моста в `tmp/bridge_head/` — от **30.07**, прод сегодня @84. Он объясняет механизм,
  но приговор §1–§5 держится на живых замерах, а не на нём.
- Контрольный прогон списка папки оборвался `TimeoutError` транспорта на четвёртом (уже
  необязательном) префиксе; все нужные числа сняты ДО обрыва и повторены отдельным вызовом
  (06:42:40 → 06:42:43, `count=48` — то же самое).
