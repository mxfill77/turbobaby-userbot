## 2–3. Но контур БЕЗ ревизора не остался — там работает другой

Это главное, чего не видно из самого модуля. В `pc_orchestrator.py` живёт полноценный
**думатель-ревизор**, и он в работе:

| что | где | как |
|---|---|---|
| точка вызова | `pc_orchestrator.py:4825` `maybe_revizor()` | главный цикл демона ПК |
| период | `:3933` `REVIZOR_HOURS` (дефолт **6 ч**) | метка прошлого тика на диске `pc_orchestrator.revizor_state.json` — restart-proof |
| источник | `:3935` `REVIZOR_DB = moderation_ipc.db` | **та же самая БД**, read-only |
| отбор | `:4187` `if r.get("status") in ("ready", "sent", "test_held")` | **тот же набор статусов**, что и у `run_reviewer` |
| судья | `:4258` `_revizor_consult` → `_thinker_exec` | LLM, `THINKER_MODEL`, `--max-turns 1`, таймаут `REVIZOR_TIMEOUT=300`с |
| правила | `docs/revizor_checklist.md` | читается на КАЖДОМ тике; фолбэк `REVIZOR_CHECKLIST_DEFAULT` |
| что делает с результатом | `:4613` `_revizor_route` | три действия: `task` → задача-находка в очередь (бюджет `REVIZOR_DAILY_BUDGET`=2/сутки, дедуп по классу), `owner` → сводная карточка `[ревизор-находки]` в инбокс, `noise` → отбросить |

### И там уже есть детерминированные чеки

```
pc_orchestrator.py:4513  _REVIZOR_PR_CLASS = "#92"   # пост-релизные находки чек-листа QUOTE/DELIVERY
pc_orchestrator.py:4515  _REVIZOR_PR_NEEDS_J = "строка J дословно"
pc_orchestrator.py:4516  _REVIZOR_PR_NEEDS_DELIVERY = "доставка = цена зоны"
```

⚠️ **`jcheck` из спасённого модуля — это тот же чек, что уже работает.** «J-цена из
`pricing_note` использована дословно» и «строка J дословно» класса #92 — одно и то же.

А два других чека **непокрыты**. Чек-лист думателя судит по семи классам:

```
[класс а] числа не из quote          [класс д] ложная ✅ трекера
[класс б] чужая модель               [класс е] повтор приветствия/канцелярит
[класс в] переспрос данного          [класс ж] анкета на первом сообщении
[класс г] утечка служебного
```

Ни «депозит требует ОБА (деньги И паспорт)», ни «год поколения против денежного контекста»
среди них нет. `depcheck` и `yearcheck` — **реально новое покрытие**, причём
детерминированное, без вызова модели.

### Куда встраивать

В `maybe_revizor`, рядом с `_revizor_postrelease_findings` — там уже готовый слот для
детерминированных находок и уже собран пакет окна. Ничего нового строить не нужно: источник,
период, бюджет, дедуп и канал доставки находок уже есть.

## 4. Объём подключения

| файл | что | строк |
|---|---|---|
| `pc_orchestrator.py` | ленивый импорт `reviewer` (как `moderation_ipc`), вызов рядом с `_revizor_postrelease_findings`, **адаптер формата**, строка в лог | ~20–30 |
| `test_pc_orchestrator.py` | адаптер даёт валидные находки; дубль `jcheck` не плодит вторую находку рядом с #92; fail-safe `(0, [])` не ломает тик | ~40–60 |

**Адаптер обязателен — форматы разные:**

```
reviewer.py отдаёт:      {client_id, check, detail, draft_snippet}
_revizor_route ждёт:     {class, client_id, action, evidence, task_text}   (action ∈ task|owner|noise)
```

Итого **~60–90 строк в двух файлах**. Отдельным решением владельца — что делать с дублем
`jcheck`: выключить его в `reviewer.py` или снять #92-чек, но не держать оба.

## 5. Прямой ответ

**Чеки лежат мёртвым грузом.** Модуль в дереве, отгружен, под 39 зелёными юнитами — и ни один
боевой путь его не зовёт: `run_reviewer` не вызывается ниоткуда.

Но формулировка «контур без ревизора» была бы неверной: ревизор там работает каждые 6 часов,
судит LLM по семи классам чек-листа и уже несёт один детерминированный чек. Из трёх спасённых
чеков **один дублирует работающий** (`jcheck` ↔ #92 «строка J дословно»), а два
(`depcheck`, `yearcheck`) закрывают то, чего сейчас не проверяет никто.
