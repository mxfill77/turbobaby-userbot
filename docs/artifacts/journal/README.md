# Тела записей журнала (автоматический вынос)

Сюда `cowork_log_append.py` кладёт **тело** записи, если строка журнала переросла порог
`LINE_MAX` (600 символов). В `cowork_log` вместо простыни уходит итог и путь к файлу:

```
DONE 2026-07-31 09:12 UTC: <итог 3–5 строк> … → docs/artifacts/journal/2026-07-31-091200-done.md (полный текст 2785 симв.)
```

Правило владельца: **журнал — индекс, а не хранилище тел.**

## Чем это НЕ является

Это **не** `docs/artifacts/*.md`. Там лежат артефакты **решений владельца** (таблица,
кандидаты, дифф, развилка) — их пишет человек и на них ссылается финальный `DONE`.
Здесь — машинный вынос текста, который иначе уехал бы в мозг целиком. Смешивать нельзя:
артефактов-решений 94 штуки, а вынос по замеру даёт ~140 файлов в неделю — решения
утонули бы в теле переписки.

## Откуда порог 600

Замер по живому журналу 31.07.2026 (`cowork_log` + `cowork_log_archive`, 2058 записей за
19.06–30.07), разбор — [`../2026-07-31-journal-index-threshold.md`](../2026-07-31-journal-index-threshold.md):

* 78.2% записей ≤ 600 символов, и держат они всего 25.5% объёма журнала;
* остальные 21.8% держат 74.5% — это отчёты, уехавшие в мозг целиком;
* строки **уже правильного вида** «итог + путь» (81 живая `ARTIFACT`-запись): p50 = 177,
  p90 = 218, **максимум 588**.

Порог 600 — ближайшее круглое число выше 588. По построению он не трогает ни одной записи,
которая формат уже соблюдает. Менять его — только пересняв замер.

## Git

Файлы **не** в `.gitignore` намеренно: заигноренное тело живёт только на этом ПК, а журнал
читают и с телефона, и с VPS — ссылка стала бы мёртвой молча. Untracked-файлы авто-фетчу
демона не мешают (`pc_orchestrator.py:4132` считает грязью только tracked-правки).
Тело, которое стоит сохранить, коммитится руками той же сессией.
