## 4. Отрицательная проверка: расхождение видно

Проба сделана ровно так, как просило задание: в `CLAUDE.md` подставлена редакция назад
(**01.09.2026 #1**, все 3 вхождения), затем всё возвращено.

Сверка — не на память, а против ЖИВОГО чтения канона (20:54:14 UTC, отдельный процесс):

```
до подстановки:
  КАНОН (живое чтение): 02.09.2026 #1
  CLAUDE.md заявляет:   02.09.2026 #1
  ВЕРДИКТ: СОВПАЛО — проекция собрана с живой редакции

после подстановки редакции назад:
  КАНОН (живое чтение 20:54:14 UTC): 02.09.2026 #1
  CLAUDE.md заявляет:                01.09.2026 #1
  ВЕРДИКТ: РАСХОЖДЕНИЕ — проекция отстала на редакцию, прав канон
  строка 17 файла: | версия канона, с которой собрана проекция | **01.09.2026 #1** |
```

Видно расхождение **двумя разными способами**, и это важно: сверка машиной работает, только
если кто-то её запустит.

1. **Человеку, открывшему файл** — 17-я строка, в первой же таблице документа, до любого
   правила; рядом пункт 1 инструкции «сверь её номер с первой строкой живого `KB_shtab_frame`».
2. **Машине** — одной командой без нового кода: номер из строки таблицы против номера из шапки
   живого узла.

Дополнительный, незапланированный признак: при подстановке 01.09 в файле остаётся ссылка на
`docs/tasks/frame-edition-20260902.txt` — внутреннее противоречие проекции самой себе, тоже
видимое читающему.

**Возврат доказан хешем, а не словом:** `sha256(CLAUDE.md)` до пробы и после возврата —
`8497f4485df522015bc3021390e30dfb3a341c23178f29866cc66f53b84f5222`, `sha256sum -c` → `OK`.

**Чего эта проба НЕ доказывает (честная граница):** подставлялась только строка версии, а не
числа старой редакции (25094 симв., sha256 `d4315466…`). Проба показывает, что расхождение
ВИДНО; она не показывает, что кто-то обязан посмотреть — принудительного сличения при старте
headless-сессии в коде нет и этим заходом не заводилось (кода не меняли).
