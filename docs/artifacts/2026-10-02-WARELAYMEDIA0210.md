## 1. `wa_send.send_media` — тем же путём, что текст

- **Ворота общие.** `_door` разрезан на `_gate` (ручка → ключ → окно 24 ч) и `_send_loop` (отправка под
  общим дедлайном, повтор 429/5xx/молчания транспорта — как было). Поведение текста и реакции не менялось:
  `test_wa_send` (копия на клон) 90/90.
- **Порядок у медиа:** ручка WA_SEND → `media_check` (вид, формат по `MEDIA_MIMES`, подпись ≤ 1024 у
  фото/видео/документа, размер по описанию Telegram ≤ предела) → ключ → окно 24 ч → файл `fetch(предел)`
  (байты в памяти; если их больше предела — отказ) → загрузка `POST /media` → `POST /messages`.
- **Загрузку клиент не видит**, поэтому любой её провал — `not_sent` («файл в 360dialog не загружен: …»).
  Молчание транспорта и 429/5xx повторяются под тем же дедлайном (до 3 раз). Это безвредно: лишний файл
  остаётся в 360dialog, второго сообщения не будет. Отказ сервера (4xx) не повторяется.
- **Исход отправки** — те же три: `sent` (с wamid), `not_sent`, `unknown`. Сверх полей текста: `uploads` и
  `dropped_caption`. Отказ до сети, который человек исправит сам, несёт `topic_words` — слова для темы.
- **Сообщение:** `{"type": <вид>, <вид>: {"id": <id медиа>, "caption"?, "filename"? (документ)}}`. У места —
  `{"type": "location", "location": {latitude, longitude, name?, address?}}`, файла и загрузки у него нет.
- **Выход в сеть один** — `_open`. Шов текста и реакции — `_post` (`transport`), шов загрузки —
  `_post_media` (`upload`). Тесты подменяют оба.

## 2. Вид Telegram → вид WhatsApp (`wa_agent_tg.media_of`)

| из темы | уходит | замечание |
|---|---|---|
| фото | `image`, `image/jpeg` | берётся самый крупный размер, который влезает в предел |
| видео, гиф (`animation`), видео-кружок | `video` | mime из Telegram, если его нет — `video/mp4` |
| голосовое | `audio` | mime из Telegram, если нет — `audio/ogg`; подписи у аудио в WhatsApp нет |
| аудио | `audio` | только форматы WhatsApp: AAC, AMR, MP3, MP4, OGG |
| документ | `document`; если это картинка, видео или аудио формата WhatsApp — своим видом | имя файла уходит; формат вне списков — ответ «формат … WhatsApp как документ не принимает» |
| стикер статичный | `sticker`, `image/webp` | анимированный и видео-стикер — вид без пары |
| геоточка, место (`venue`) | `location` | у места — название и адрес; **живая геоточка — вид без пары**, её движение (правка) — молча |
| контакт, опрос, кубик, игра, история, платное медиа, счёт, розыгрыш, список задач | — | ответ «не отправлено: <вид> в WhatsApp из темы не отправляется — наружу ничего» |

Голосовое, аудио или стикер с подписью уходят без подписи (в WhatsApp у этих видов её нет). Тогда кроме 👌
бот отвечает: «ушло без подписи: у голосового в WhatsApp подписи нет — напишите её отдельным сообщением».

## 3. Больше предела

- Размер по описанию Telegram (`file_size`) проверяется **до сети** — нет ни `getFile`, ни загрузки, ни
  отправки. Ответ: «не отправлено: файл 17 МБ больше предела 16 МБ (видео в WhatsApp) — наружу ничего».
  Для документа: «… файл 25 МБ больше предела 20 МБ (Telegram отдаёт боту файл до 20 МБ) …».
- Если в сообщении размера нет, а `getFile` назвал больше предела — файл не скачивается. Ответ: «не
  отправлено: файл из Telegram не получен (файл 21 МБ больше предела 20 МБ) — наружу ничего».
- Если размера не назвал никто, файл скачивается, и его байты сверяются с пределом. Больше — ответ
  «файл 6 МБ больше предела 5 МБ (фото в WhatsApp)», загрузки нет.
- МБ = 1024². Спор на самом краю предела решит отказ сервера (4xx → `not_sent` словами API), второго
  сообщения он не даёт.

## 4. Альбом

Альбом Telegram — это отдельные сообщения с общим `media_group_id`. Каждое идёт своим ключом (id сообщения
Telegram), поэтому **каждый файл уходит отдельным сообщением WhatsApp** в порядке прихода, и 👌 ставится на
каждый. Подпись альбома Telegram держит на первом сообщении, поэтому она уходит с первым файлом, остальные
— без подписи. Тест: три фото, подпись у первого → 3 загрузки, 3 отправки, подписи `[подпись, —, —]`.
Мутант «альбом одним ключом» убит. Если человек подписал не первый файл, подпись уйдёт с тем файлом, у
которого она стоит: переносить её код не будет.

## 5. Исход в теме и история клиента

- Тема видит то же, что при тексте (WARELAYTEXT0210 §2): 👌 / ответ с причиной / «не знаю, дошло ли». К ним
  добавлены слова отказов до сети (`W_TOPIC`: «не отправлено: <причина> — наружу ничего») и строка «ушло
  без подписи». Ошибка загрузки идёт прежними словами «ошибка двери — файл в 360dialog не загружен: …».
- Одно сообщение темы — не больше одной отправки (таблица `relay`, тот же ключ). Человек прислал медиа —
  агент с этим клиентом на паузе, как при тексте (в том числе если файл больше предела).
- **`outbox` получил колонку `kind`** (миграция `ALTER TABLE` на старте ядра; NULL — текст). В записи —
  вид (`image`, `voice`, `location`, …) и подпись (у места — название и адрес либо координаты).
  `wa_history.read_sent` читает `kind`, если колонка есть, а `with_sent` даёт элемент со словом вида. Модель
  видит «мы: [фото] подпись», «мы: [голосовое]», «мы: [геоточка] 7.77, 98.32».
- Журнал службы: «тема: сообщение 700 (image) → sent». Подписи, номера и ключа бота в журнале нет
  (тест). Ключ бота живёт только в адресе скачивания.
