## 2. Развод `clasp`: слой прав + слой гарда

Одного `settings.json` мало. Хук `PreToolUse` возвращает `ask` **поверх** `allow` — значит
карточка исчезает, только когда **оба** слоя зелёные. Поэтому правка парная.

| подкоманда | решение | почему |
|---|---|---|
| `status` `pull` `versions` `deployments` `logs` `list` `--version` | **allow** | чтение проекта, прод не трогают |
| `push` | **allow, если прод ЗАКРЕПЛЁН на номере версии**; иначе ask | `push` заливает HEAD; деплой на `@76` отдаёт свою версию и не меняется |
| `deploy` `undeploy` `redeploy` | **ask** | выкатка и снятие живого деплоя |
| `run` | **ask** | исполнение функции в живом контуре |
| `login` `clone` `create` и прочее | **ask** | в список чтения не входит |

**Пин доверенный, а не заявленный.** Реестр `clasp_prod_pins.json` (в корне репо). Гард верит
ему только если файл **под git и без незакоммиченных правок** — иначе сессия расширила бы себе
права, дописав пин сама (та же дыра, что закрыта для конфига `.claude`). Проверено фактом
после коммита: `_clasp_prod_pinned` → `True`, `clasp push` из `tmp/bridge_gs` → `defer`,
тот же `clasp push` из каталога без `.clasp.json` → **ask** (цель не опознана — не пин).

Живой пин на сегодня: проект `12iXPDU_…Ybv9HhOJ`, прод-деплой `AKfycb…hXNOqw`, **версия 76**
(источник — `docs/artifacts/2026-07-29-cowork-log-rotation.md`: «прод … переведён с @75 на @76»).

**Судим по действию.** `echo "выкатка clasp deploy не делалась"`, `which clasp`,
`ls ~/.clasprc.json` командой `clasp` больше не считаются.

## 6. Правило «нет объекта и числа → карточки нет, строка в журнал»

**Было:** на ПК-полосе правила **не было**. Свод `CLAUDE.md` п.5 его требует («Нет числа или
имени — карточки быть не должно»), но код звал `_card()` безусловно. Живой пример суток:

```
ls -la *.log* 2>/dev/null | head -40; echo "---SCHTASKS XML---"; ls *.xml *.vbs 2>/dev/null
```

→ карточка «Хочу выполнить операцию Планировщика задач». Планировщика в команде нет ни в одной
командной позиции — слово стояло внутри `echo`.

**Стало:** `card_or_journal()` считает объект и число. Пусто и там, и там → карточки нет, в
журнал пишется решение `journal` (след остаётся, действие идёт). Проверено сквозь stdin:
stdout пуст, в журнале строка `| journal | schtasks |`.

**Hard-блок — исключение, он остаётся:** `unknown` (сбой разбора самого гарда) и `.env`/секреты
спрашивают всегда, даже если имя файла осталось внутри тела скрипта. Настоящий
`schtasks /Change /TN TurboBabyRC /DISABLE` карточку по-прежнему даёт — с объектом `TurboBabyRC`.

**Попутно найдено (не карточка, а недоставка).** Вход хука читался системной кодовой страницей
(cp1251), и кириллица в команде приезжала мохибейком **в саму карточку**: замер до правки —
`echo ПРОБА-кириллица` попадал в журнал как `РџР РћР‘Рђ`. В тот же класс попала недоставка
29.07 10:47:31: Telegram отверг и DM, и фолбэк в тему 205 с `400 Bad Request: strings must be
encoded in UTF-8` — карточка до владельца **не дошла**. Оба места (`pretool_guard`,
`dispatch_notify`) теперь читают stdin как UTF-8 с `errors="replace"`. Что именно из двух
породило тот конкретный 400 — не воспроизводил и не утверждаю.
