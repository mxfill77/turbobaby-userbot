## 4. Чего находка НЕ учитывает

1. **`operational_change` — это ТОПЛИВО ступени A, а не приговор о дисциплине.** `chain_trigger`
   (`review_auto.py:403`) пропускает расписки без него, `case_for_chain` (`:499`) на них падает
   `not_operational`. Сузить признак до «тронут прод-код» = отнять **12 поводов из 23 (52 %)**.
2. **«Тронуто только `docs/`» ≠ «операционного не было».** Расписка `pc-2026-09-01-102`
   (единственный коммит `e6f340d`, единственный файл — `docs/artifacts/2026-09-02-shtab-frame-raised-0902.md`)
   принадлежит цепочке, поднявшей **живой узел мозга** до редакции 02.09 #1. Это операционное
   изменение, которого git не видит вовсе. Признак по git-путям объявил бы её «ничего не сделала».
3. **Находка отменила бы собственное рождение.** Пакеты, из которых собрана эта самая заявка, —
   `…-98`, `…-100`, `…-102`, `…-109`; все четыре расписки имеют `operational_change: true`, а
   `pc-2026-09-01-102` — из тех самых «только docs/». При сужении признака пакет 102 не собрался
   бы, и **один из пяти источников заявки #107 не существовал бы**.
4. **Вторая половина находки — «не писать в мозг» — закрыта регламентом, а не спором.** Три
   источника из пяти сами пометили это словом «неизвестно» (`100-codex`, `102-manus`,
   `109-manus`). Ответ есть: `grep -n "журнал" docs/tasks/frame-edition-20260902.txt` → строка
   **149: «Каждая сессия финальным шагом пишет итог в журнал.»** (канон рамки, редакция
   02.09.2026 #1, всего 8 упоминаний журнала). Журнал обязателен; «неизвестно» каналов снимается
   фактом. Исполнять этот пункт нельзя ни одной строкой.
5. **Адрес находки — печать, а не механизм** (§2): даже верную правку по названному адресу сделать
   невозможно.

## 6. Правка, названная СЛОВАМИ (решение владельца; ничего не применено)

1. **Свой коммит — это коммит, сделанный ПОСЛЕ старта задачи.** У демона уже есть штамп
   `pc_orchestrator.task_started.json` с полем `at`; сверять с ним время коммита в
   `review_auto_run` перед тем, как класть его в `verified_commits`. Цена по замеру: из списков
   уйдут **7 коммитов из 31**, исход сменит **1 расписка из 23** (#99). Дёшево.
2. **Нужен ЧЕТВЁРТЫЙ слаг причины.** Сегодня их три (`review_auto.py:210`, зафиксированы тестом
   `test_review_auto.py:151-158`). «Коммит существует, но сделан до старта» — это не
   `commit_unverified` («объявила, а его нет»): нужен отдельный `commit_foreign`, иначе честная
   цитата будет выглядеть расхождением отчёта с деревом.
3. **Развести имя и смысл, НЕ трогая гейт.** Оставить `operational_change` как топливо ступени A
   (иначе §4.1), а рядом положить отдельное поле «тронут ли код вне `docs/`» — для печати и
   отчётов. Тогда фраза «боевого кода не правил» и расписка перестают противоречить друг другу,
   а поводов не убывает ни одного.
4. **НЕ делать:** снимать пометку у разведок целиком; убирать запись в журнал; править
   `pc_orchestrator.py:8902`.

Правки требуют изменения `test_review_auto.py` (три исхода зафиксированы литералами) — это цена,
названная заранее.
