# ПК засыпает: корень, числа, что осталось владельцу (30.07.2026)

Разбор по задаче «ПК больше не засыпает». Всё ниже — запросом к системе, не по памяти.

## Итог одной строкой

**ПК не засыпает сам.** Таймауты простоя уже отключены (`0` и от сети, и от батарей). Обе
засыпания за 7 суток — **явный вызов усыпления из меню Пуск**. Бот терял **12 ч 10 м в неделю**.

## 1. Схема питания (дословно, `powercfg /q SCHEME_CURRENT SUB_SLEEP`)

Активная схема: `8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c (Высокая производительность)`.

| настройка | псевдоним | от сети (AC) | от батарей (DC) |
|---|---|---|---|
| Сон после | `STANDBYIDLE` | `0x00000000` | `0x00000000` |
| Гибернация после | `HIBERNATEIDLE` | `0x00000000` | `0x00000000` |
| Разрешить гибридный спящий режим | `HYBRIDSLEEP` | `0x00000001` | `0x00000001` |
| Разрешить таймеры пробуждения | `RTCWAKE` | `0x00000001` | `0x00000000` |

`powercfg /a` — доступны **Ждущий режим (S3)**, **Гибернация**, **Быстрый запуск**. Гибридный сон
**недоступен** («низкоуровневая оболочка не поддерживает»), то есть `HYBRIDSLEEP=1` висит впустую.

`powercfg /waketimers` прочитать не удалось — требует прав администратора (оболочка сессии их не
имеет, `IsInRole(Administrator) = False`).

## 2. Сны за 7 суток — их ДВА, не «каждую ночь»

Источник: журнал Windows System, `Microsoft-Windows-Power-Troubleshooter` id=1 (даёт пары
засыпание→пробуждение точно). Журнал хранит записи с **21.06.2025** — окно покрыто целиком,
это не обрезка ротацией.

| засыпание | пробуждение | длительность |
|---|---|---|
| 26.07 10:02:51 | 26.07 13:14:42 | 3 ч 11 м 51 с |
| 30.07 03:43:15 | 30.07 12:41:21 | **8 ч 58 м 06 с** |
| | **ИТОГО** | **12 ч 09 м 57 с** |

## 3. Корень: усыпление кликом, а не таймаутом

`Kernel-Power` id=187, **оба раза один и тот же вызывающий**:

```
ApiCallerName=\Device\HarddiskVolume4\Windows\SystemApps\
  Microsoft.Windows.StartMenuExperienceHost_cw5n1h2txyewy\StartMenuExperienceHost.exe
SystemAction=2  LightestSystemState=2
```

`Kernel-Power` id=42: `TargetState=4 EffectiveState=4 Reason=4 Flags=0` → S3, **Reason=4 =
Application API** (не «System Idle»).

Почему клик вообще усыпляет — `powercfg /q SCHEME_CURRENT SUB_BUTTONS`:

```
GUID настройки питания: a7066653-8d6c-40a8-910e-a1f54b84c7e5  (Кнопка питания меню "Пуск")
  Псевдоним GUID: UIBUTTON_ACTION
  Текущий индекс настройки питания от сети:   0x00000000   ← 0 = «Сон»
  Текущий индекс настройки питания от батарей: 0x00000000   ← 0 = «Сон»
```

Обратное действие подтверждает ручной характер: `powercfg /lastwake` → «Тип: фиксированная
функция / **Кнопка питания**» — будили тоже руками.

**Групповых политик питания нет** (`HKLM\SOFTWARE\Policies\Microsoft\Power` отсутствует), значит
powercfg никем не перекрывается и держать настройку будет.

## 4. Число для владельца: сколько бот был недоступен

**12 ч 10 м за 7 суток ≈ 7,2 % недели**, из них **8 ч 58 м — одна ночь 30.07**.

Считано по окнам сна, а НЕ по разрывам в `userbot.log`: тот событийный (147 строк за неделю),
сумма его пауз (167,9 ч) означает «клиенты молчали», а не «бот лежал». Что демон реально
проспал — подтверждено его собственным логом: `детект пробуждения ПК: скачок wall-clock 32381с`
в 12:42:20 (30.07) и `11611с` в 13:15:02 (26.07).

Перезагрузки добавляют мелочь: 30.07 01:14–01:17 (три старта подряд, бот вернулся в 01:17:44) и
24.07 — 34 с. Автостарт бота после загрузки работает.

## 5. Порог сигнала — из живого лога, не из головы

За 22–30.07 детект пробуждения срабатывал **369 раз**. Демон исполняет задачу **синхронно** в
главном цикле, поэтому честный виток растягивается до `TASK_TIMEOUT+POLL_SEC`:

| порог | срабатываний | из них настоящих снов |
|---|---|---|
| > 600 с | 26 | 2 (**24 ложных**, максимум ложного 1776 с) |
| > 1800 с | 2 | 2 |
| > 2760 с (принят) | 2 | 2 (**ложных ноль по построению**) |

Принят дефолт `SLEEP_ALARM_SEC = TASK_TIMEOUT + POLL_SEC = 2760 с`. Оба настоящих сна (11611 с и
32381 с) проходят с 4–12-кратным запасом. Переопределяется `PC_SLEEP_ALARM_SEC`.

## 6. Что осталось владельцу (нужен администратор)

Единственная дыра — пункт «Сон» во флайауте Пуска. Выполнить в **администраторском** окне:

```
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\FlyoutMenuSettings" /v ShowSleepOption /t REG_DWORD /d 0 /f
```

Текущее состояние ключа (проверено чтением): `ShowSleepOption=1`, `ShowHibernateOption=1`,
`ShowLockOption=1`. После правки нужен перезапуск `explorer.exe` или перевход; ботов это не
касается. «Завершение работы» и «Перезагрузка» остаются.

Правку таймаутов делать **не нужно** — `standby-timeout-ac` и `hibernate-timeout-ac` уже `0`.
