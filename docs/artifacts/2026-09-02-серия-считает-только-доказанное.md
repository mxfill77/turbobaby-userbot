## 1. Премиса — проверена первым действием, подтвердилась целиком

Задание назвало премису и потребовало проверить её по журналу и коду. Проверено, все три части
верны. Ни одна не была принята на слово.

### 1.1 «Вердикт „неизвестно, адрес не назван“ не меняет статус в режиме `addr`»

Код, `done_judge_pc.enforces` (последние строки модуля):

```python
def enforces(verdict, mode):
    if not verdict or verdict.get("verdict") == DONE or mode == MODE_OFF:
        return False
    return mode == MODE_ALL or bool(verdict.get("address"))
```

Безадресный вердикт рождается с `address=None` (`judge()`, ветка «адрес результата не назван
задачей — доказывать нечем»). В режиме `addr` `bool(None)` даёт `False` → статус не меняется.
**Подтверждено.** Это не дефект: дефолт `addr` выбран сознательно (полное правило владельца —
режим `all`, и его включение остаётся решением владельца; в этом заходе режим НЕ трогали).

### 1.2 «Не оставляет следа в отчёте»

Код, `pc_orchestrator._judge_done`, ветка до правки:

```python
    if not done_judge_pc.enforces(verdict, mode):
        if not verdict.get("address"):
            # …приписка «адреса нет» в КАЖДОМ отчёте была бы шумом, а не сведением.
            return status, result          # ← отчёт байт-в-байт прежний
```

**Подтверждено.** И это тоже осознанное решение прежнего захода, а не оплошность.

### 1.3 «Сводка контура при этом считает такую цепочку чистой»

Код, `contour_digest.is_clean` до правки: `return outcome == "done"` — и всё.

Почему след не доезжал до счёта, даже если бы отчёт его нёс: счёт серии читает **слепок
очереди**, а у СДАННОЙ строки слепок причины не несёт вовсе. `queue_snapshot_pc.apply_failed`
заполняет `why` только для упавших; сданность выводится из отсутствия строки среди `failed`:

```python
    for tid, item in out.items():
        if item.get("outcome") is None and tid not in seen and at is not None and at <= read_at:
            item["outcome"] = "done"       # причины у этой ветки нет и быть не может
```

**Подтверждено.** Класс замкнут: след суда жил РОВНО в логе демона (`V0-DONE`), а счёт серии
в лог не смотрит ни одной строкой.

## 3. Что сделано — устройство

### 3.1 След суда переживает заход: реестр вердиктов

`done_judge_pc` получил реестр `tmp/done_judge_pc/judged.json` — в ТОЙ ЖЕ единственной папке,
куда модуль уже пишет пакеты V0; второго адреса записи ему не заводилось.

Запись на КАЖДОЕ заявленное `done`, независимо от режима:

```python
done_judge_pc.note(tid, verdict)     # стои́т ДО развилки режима
if not done_judge_pc.enforces(verdict, mode):
    ...
```

Порядок здесь — замок, а не вкус: **режим распоряжается СТАТУСОМ, а не памятью о суде.** Поставь
запись после развилки — и в дефолтном `addr` след безадресного закрытия снова стал бы невидимым,
то есть заход не сделал бы ничего. Порядок сторожит тест (`test_the_ledger_is_written_before_the_mode_fork`),
а не дисциплина правки.

Три свойства, каждое названо и проверено:

* **Часов у реестра нет** — их нет у всего модуля (инвариант `test_freshness_is_measured_not_clocked`
  запрещает `time`/`datetime`/`calendar` и подстроки `st_mtime`, `utcnow`, `monotonic`). Порядок и
  обрезку хвоста держит счётчик `seq`, растущий на единицу от максимума уже лежащего.
  Хвост — `LEDGER_MAX = 300`: окно счёта серии 30 цепочек при темпе полосы 4.3 закрытых в сутки,
  то есть ≈70 суток и десятикратный запас над окном.
* **Отсутствие записи — это «судья не судил», а не «всё хорошо».** Пустой и битый реестр читаются
  ОДИНАКОВО — `{}`, и это не молчание, а отсутствие доказательств.
* **Запись не смеет уронить заход.** Любой отказ диска — `None` и тишина: судья, падающий на своём
  реестре, закрыл бы задачу хуже, чем судья без реестра.

Изоляция от боевого файла сделана крюком, а не договорённостью: `ledger_path(root=None)` уводит
путь через `log_setup.state_path`, и под тест-прогоном реестр уезжает в temp. Без этого регресс
врезки (`test_pc_orchestrator.TestStageCJudgeWiring`) писал бы в БОЕВОЙ реестр полосы — тот самый
класс «гейт съел спул» от 05.08.2026.

### 3.2 Два исхода разведены в счёте

`contour_digest` больше не считает `done` синонимом чистоты. Функция сданности и функция чистоты
разъехались намеренно — на их склеивании класс и стоял:

```python
def is_closed_done(outcome):        # СДАНА (исход очереди)
    return outcome == "done"

def is_clean(row, judged=None):     # ЧИСТАЯ = сдана И доказана судьёй
    return (is_closed_done(one.get("outcome"))
            and judged_of(one.get("id"), judged) == JUDGE_PROVED)
```

У закрытия теперь **четыре** ответа, а не два, и все четыре — с именами:

| исход | что значит | чистая? |
|---|---|---|
| `доказана` | судья прочитал продукт по названному адресу | **да, и только она** |
| `без адреса` | адрес результата задачей не назван — судить было НЕЧЕМ | нет |
| `не доказана` | адрес назван, доказать не вышло (ветка режима `off`; в `addr` такая строка уходит в `failed` и сюда не доезжает) | нет |
| `не судил` | записи о суде нет вовсе (строка старше ступени C) | нет |

Три последних серию не двигают по правилу **«не доказан сильнее неизвестно»** — тому же, которым
живут слой ожиданий полосы (О1–О4, пункт 3) и `series_pc`. Прямое следствие, названное вслух:
**пустой реестр ОБНУЛЯЕТ серию, а не сохраняет её.** Обратное поведение было бы дырой ровно того
размера, которую заход закрывает.

Замок полноты: сумма четырёх чисел равна числу сданных строк окна — дыры в разборе быть не может
(`test_the_four_answers_sum_to_the_closed_rows_of_the_window`).

## 4. Отрицательный тест — обязателен, и он есть парой с положительным

Прибор, который не двигает серию НИКОГДА, проходит любой отрицательный тест и бесполезен. Поэтому
отрицательный ходит парой с положительным контролем — оба на ОДНИХ И ТЕХ ЖЕ рядах.

**В чистом слое** (`test_contour_digest.TestSeriesCountsOnlyTheProven`):

```python
ROWS = [{"id": 7, "outcome": "done", ...}, {"id": 8, "outcome": "done", ...}]

# ОТРИЦАТЕЛЬНЫЙ: поддельный ряд done без адреса
cd.series(ROWS, judged=_blind(7, 8))   → streak 0 · blind 2 · proved 0
# ПОЛОЖИТЕЛЬНЫЙ: тот же ряд с доказанным адресом
cd.series(ROWS, judged=_proved(7, 8))  → streak 2 · proved 2 · blind 0
```

Плюс: одно безадресное закрытие в хвосте обрывает серию доказанных (как «упало»); молчание судьи
(`None`, `{}`, чужой ключ) чистой цепочкой не является; четвёртый исход «судья смотрел и не
доказал» отличается от «не смотрел»; строка несёт оба числа задания.

**Сквозной, через весь ход** (`TestSeriesEndToEnd`): чистая функция может быть права, а сводка всё
равно врать — между ними лежит чтение реестра, и молча отвалиться может именно оно. Поэтому
поддельные ряды кладутся ФАЙЛАМИ на своём корне, и проверяется готовая строка сообщения:

* ряд `done` без адреса → `streak 0`, и в тексте сводки стои́т `закрыто без адреса 2`;
* тот же ряд доказанным → `streak 2`, в тексте `судья доказал 2`;
* реестра на диске нет вовсе → `streak 0`, в тексте `судья не судил 2`.

**Боевой очереди и боевого реестра тесты не касаются ни одной веткой** — только поддельные ряды на
временном корне.

**Врезка** (`test_pc_orchestrator`): след суда ложится во ВСЕХ ТРЁХ режимах (`addr`, `all`, `off`),
и запись стои́т выше развилки режима.

**Реестр** (`test_done_judge_pc.TestLedger`, 12 проверок): безадресный вердикт отличим от «не
доказал»; порядок держит счётчик, а не время; хвост режется по счётчику; переотправленная задача
обновляет запись, а не заводит вторую; битый реестр читается как молчание, а не падение; отказ
записи молчалив; ручка `DONE_JUDGE_PC_LEDGER` уводит файл в сторону, не тронув боевого пути.

## 6. Что заход НЕ делал (границы названы)

* **Режим судьи `DONE_JUDGE_PC` не переключался.** Задача чинила СЧЁТ, а не строгость судьи;
  включение режима `all` остаётся решением владельца. Дефолт как был `addr`, так и остался.
* **Гард, карточки и ворота не тронуты.** Клиентского контура заход не касается.
* **Боевая очередь тестами не тронута** — только поддельные ряды на временном корне.
* **Процессы не перезапускались, `.env` и конфиги не читались, ничего не удалялось.**
* Реконструкция реестра из лога считалась в памяти и на диск не ложилась.
* Временное — в `_scratch_series_addr_0902/` (три пробы: `probe_before.py`, `probe_after.py`,
  `probe_unwired.py`).

Честная граница самого счёта: серия по-прежнему судит ОДНОШАГОВЫЕ цепочки (допущение полосы,
измеренное `series_pc`) и по-прежнему берёт числа из слепка очереди, а не из счётчика
`series_pc.state.json` — тот в демона не врезан.
