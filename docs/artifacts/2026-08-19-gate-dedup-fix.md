# Ключ дедупа карточки ворот: обе стороны приводятся к одной длине

Правка 19.08.2026, коммит **`70635de`**. Основание — разведка задачи 20,
[`docs/artifacts/2026-08-19-gate-double-card.md`](2026-08-19-gate-double-card.md).

Цель была ровно одна и выполнена ровно она: **обе стороны ключа дедупа приводятся к одной
длине перед сравнением**. Логику ворот, тексты карточки, число входов, состав `held`, файл счёта
серии, процессы и рабочие таблицы не трогали; карточек не открывали и не закрывали.

---

## 1. Что именно изменено — одна строка

`pc_orchestrator.py` → `_client_block`:

```python
-    key = (str(commit), tuple(held))
+    key = (client_contour.short(commit) or str(commit), tuple(held))
```

плюс комментарий над ней. Больше в воротах не изменено **ничего**: `git diff --stat` по правке
кода — `pc_orchestrator.py | 14 +++-` (13 строк комментария + 1 строка ключа).

Нормализатор не заводился, он **уже лежал** — `client_contour.py:319`, и его докстринг написан
ровно про этот класс: «Разные места дают 7/9/40 символов — сверять их „как есть“ значило бы терять
одобрение владельца на ровном месте». Асимметрия и была дефектом: сторона «пропустить»
(`release_reason` → `owner_approved`/`trainer_verdict` → `short`) нормализована с самого начала,
сторона «промолчать» — нет. Поэтому одно «да» открывало обе дороги, а один отказ рождал две карточки.

**Фолбэк `or str(commit)` — не украшение.** `short()` на не-хеше отдаёт **пустую строку**; без
фолбэка две РАЗНЫЕ нехешевые метки (`'old'`, `'staraya-metka'`) схлопнулись бы в один пустой ключ,
то есть правка дедупа сама породила бы молчание. Это отдельный голден (§4).

## 2. Забор Честертона: зачем один вход подаёт девять символов

**Затем, что это НЕ ключ, а подпись для человека, и она старше самих ворот.**
`short = head[:9]` (`pc_orchestrator.py:6224`) внесён коммитом **`6d8a3b1` от 11.07.2026**
(«авто-применение кода детей на ЛЮБОЙ новый коммит») — за **19 суток** до заведения ворот
(30.07). В том коммите строка обслуживала только показ: `log.info("… рестартнут до %s")`,
`_cowork("авто-применил {short}: …")`, `_notify("… реконсиляция {short}")` и строку-итог. Девять,
а не семь, потому что тик реконсиляции берёт **полный 40-символьный** `git rev-parse HEAD`
(`_full_head`) и режет его сам — а путь self-update просит короткий хеш у самого git
(`git rev-parse --short` → 7). Ворота 30.07 просто взяли готовую переменную соседней строкой.

**Не сломает ли нормализация что-то, что на девять символов опирается — нет, и вот почему.**
Единственное сравнение коммитов во всём `pc_orchestrator.py` — `old_commit == new_commit` внутри
`_diff_names`, где обе стороны приходят из одного источника (`_head_commit`) и наша правка их не
касается:

```
$ grep -n "commit ==\|== commit\|commit !=\|!= commit\|short ==\|== short\|short !=" pc_orchestrator.py
5920:    if not old_commit or not new_commit or old_commit == new_commit:
```

Всё остальное, куда течёт `commit` из `_client_block`, либо **уже нормализует само**
(`release_reason`, `trainer_status` → оба зовут `short()`), либо просто печатает: `log.error`,
строка в `cowork_log`, `card_text` — включая `Откатить: git revert --no-edit <commit>` (git
принимает любую однозначную длину). Ключ — единственное место, где длина решала исход, и правится
только он: карточка владельцу приходит **байт в байт прежняя**, с девятью символами (голден §4
это проверяет отдельно, `assertIn(head[:9], cards[0])`).

Что нормализация действительно меняет по существу: два коммита с общим 7-символьным префиксом
стали бы одним ключом. Это тот самый риск, который сторона «да» несёт с 30.07 (`owner_approved`
хранит семёрку), и git сам считает семь символов достаточными для `--short`. Цена промаха
несимметрична и посчитана: слипание — лишнее молчание об одном отказе, разлипание — лишняя
карточка; первое ловится голденом (б), второе жило в бою 20.2 суток.

## 6. Что правка НЕ делает (честно)

* **Вторую карточку не «удаляет», а гасит по ключу.** Ветка ворот в
  `_selfupdate_restart_children` цела и продолжает **держать ботов**; замолчал только повтор
  текста. Это ровно то, что разведка назвала правильным: лишняя там карточка, а не гейт.
* **Дедуп по-прежнему не переживает рестарт демона** (`_CLIENT_HELD_WARNED` — dict в процессе).
* **Число входов в ворота осталось три**, диапазоны и `where` не тронуты; карточка по-прежнему
  называет владельцу **голову диапазона**, а не клиентский коммит внутри него (побочный замер §4
  разведки, отдельный класс).
* Ни `userbot`, ни `moderation_bot` не перезапускались; клиентских файлов правка не касается,
  поэтому собственные ворота на неё не сработают.

То есть цена нормализации сегодня — **ноль склеек на всей истории**, и сам git по-прежнему
считает семь символов однозначными. Это не вечная гарантия: git удлиняет `--short` при появлении
неоднозначности, а `short()` режет до 7 жёстко. Сторожа у этого нет, и заводить его не просили —
записано как остаток, а не как закрытая дыра.

**Три входа в ворота перемерены по коду** (подтверждают посылку разведки):

```

6026  _selfupdate_restart_children → new_commit      = `rev-parse --short`  → 7 симв.
6293  reconcile_children_tick      → short = head[:9] от _full_head() (40)  → 9 симв.
```

Девятка — одна и ровно у реконсиляции, то есть у входа, который стоит в тике **вплотную** к
self-update. Единственное сравнение коммитов во всём файле — `old_commit == new_commit`
(`pc_orchestrator.py:5980`, внутри `_diff_names`), обе стороны из одного источника, правкой не
задето.

**Итог повторной проверки: правка годится.** Оба обязательных отрицательных теста устояли,
включая важнейший (б) — разные коммиты дают две карточки, склейки нет.
