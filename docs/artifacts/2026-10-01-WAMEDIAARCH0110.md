## П.2 — скорость и бюджет

Замер: два файла по `scp`, каждый в своём соединении, прямо на место в `media/`.

| файл | байт | время |
|---|---|---|
| 1 | 19 848 723 | 4,571 с |
| 2 | 2 994 107 | 1,732 с |

Установка ssh — 0,72 с. Чистая скорость по разнице двух замеров: 16 854 616 байт за 2,839 с = **5,94 МБ/с**.

Арифметика: 1 345 733 760 байт / 5,94 МБ/с ≈ **227 с**. Остаток до границы 1 890 с на момент замера — 1 576 с
(с начала прошло 314 с). Весь объём влезает с запасом ×6,9, поэтому переносилось всё, без хвоста. Порядок в
tar всё равно «свежие первыми»: при обрыве уцелели бы свежие.

Факт: поток tar 1 347 737 600 байт прошёл за **206,9 с**, считая ssh, — это **6,51 МБ/с**. Сборка tar заняла
203,4 с.

## П.3 — перенос

- **Один поток tar** в формате PAX, файлом на диск не писался. `tmp/wa_media_0110/send_tar.py` передаёт его
  через `ssh`, на сервере `tee >(sha256sum) | tar -xf - --skip-old-files --no-same-owner` в
  `/root/wa_archive/media` при `umask 077`. Копии tar на сервере не осталось: лежит только его хеш
  `/root/wa_archive/media_0110.tar.sha256` (68 байт).
- **Имя в архиве** — `sha256(содержимое).расширение`. Для 2 597 файлов копии получилось 2 595 разных имён.
- **Хеши обеих сторон:**
  - tar на ПК = tar на сервере = `16f24cf2…ca808b00`;
  - на сервере `sha256sum` по каждому файлу сверен с планом ПК: ok 2 595, несовпадений 0, не хватает 0,
    лишних 0;
  - имя файла совпадает с хешем содержимого у 2 595 из 2 595.
- **Два файла замера** уже лежали на месте, и tar их пропустил (`--skip-old-files`). Их хеши входят в 2 595
  сверенных.
- **Права.** `scp` оставил этим двум файлам 644, им поставлен 600. После захода файлов не 600 — 0, каталогов
  не 700 — 0. Владелец root.
