## 1. `wa_send.send_reaction`

- `send_reaction(to, wamid, emoji, …)` (`wa_send.py:343`). Тело — `{"type": "reaction", "reaction":
  {"message_id": wamid, "emoji": emoji}}` (`build_reaction`, `:327`). Пустой эмодзи означает снятие.
- Путь общий с текстом (`_door`, `:376`): ручка `WA_SEND` → ключ → окно 24 ч (до сети, три исхода) →
  POST под общим дедлайном. Исходы и слова — как у текста: `sent` / `not_sent` / `unknown`, поле
  `verify`. До двери отказ двумя словами: «номер не назван» или «не назван wamid».
- Ключ — `api_key` (`:139`): `WA_360_API_KEY`, иначе `WA_D360_API_KEY`. Берётся первое **годное**
  имя: пустое и заполнитель пропускаются. Если не годно ни одно — отказ до сети. В причине только
  имена и слова «пуст» или «заполнитель», значение не попадает никуда.
- Показ берёт ключ медиа тем же `api_key` (`wa_tg_mirror.py:151`): правило одно для обеих служб.
- `send_text` по поведению не менялся (`test_wa_send` 90/90). Единственное отличие — ключ теперь
  тоже по `api_key`.

## 2. Читатель

- `allowed_updates` = `["callback_query","message"]`, если включены карточки, плюс
  `"message_reaction"`, если включены реакции (`wa_agent_tg.py:300`). Читатель остаётся один:
  второй получил бы 409.
- Реакции работают и без карточек: при `WA_AGENT_CARDS=0`, `WA_AGENT_REACT=1` опрос просит только
  `message_reaction`, нажатия и реплаи не разбираются (`test_react_only_no_card_actions`).
- `on_reaction` (`:460`) принимает обновление только при трёх условиях: чат — группа показа
  (`show_chat`), выключатель включён, поставил человек (`user` без `is_bot`; анонимный админ
  приходит как `actor_chat` = сама группа).
- Сообщение темы сводится к wamid (`_react_target`, `:413`), обе базы открываются только mode=ro:
  1. в базе показа `shown`: `msg_id = ?`, `state='shown'`, `solo=1`, ключ `msg:`/`file:` с wamid,
     не `row:`; wamid должен получиться ровно один;
  2. в очереди `wa_inbox` по wamid: вид строки по `wa_kind` — входящее клиента или наше эхо.
     Реакции, квитанции и предысторию реакцией не трогаем.
- Если wamid нет, наружу ничего не уходит, остаётся строка «реакция: сообщение темы N — wamid нет
  (почему), наружу ничего». Причины названы словами: не из показа или показано до 40b158b, пачка,
  больше одного wamid, цель не сообщение, база не прочитана.

## 3. Выключатель, одна отправка, журнал

- `WA_AGENT_REACT` (`REACT_FLAG`, `:58`; `Tg(react=False)`) по умолчанию **выключен**, без ключа бота
  выключен тоже. Выключенный выключатель значит: вида нет в `allowed_updates`, а пришедшее обновление
  даёт строку «выключен, наружу ничего». Если выключены и карточки, и реакции, HTTP-вызовов 0.
- У бизнеса в WhatsApp одна реакция на сообщение. Поэтому реакции людей группы хранятся в
  `tg_reacts(msg_id, who, emoji, seq=update_id)`, и клиенту уходит последняя по времени. Когда
  последний человек снимает свою реакцию, возвращается реакция предыдущего; когда снимают все,
  уходит снятие.
- Дедуп двухслойный:
  - offset: обновление ниже offset не разбирается;
  - `tg_react_out(msg_id → emoji, outcome)`: что уже уходило на это сообщение **любым исходом**
    (`sent`, `not_sent`, `unknown`), второй раз не шлётся.

  Строка `sending` пишется до двери, поэтому обрыв посреди вызова повтора не даёт. Окно закрыто →
  `not_sent`, и это тоже «уходило»: ни повтор обновления, ни такт не шлют снова. Новое изменение
  человека — новая отправка.
- Журнал: «реакция: сообщение темы N · реакция|снятие → исход · причина двери». В журнале id
  сообщения и исход; эмодзи, номера, текста и ключа нет (`test_log_has_ids_no_emoji_no_number`,
  мутант «журнал несёт эмодзи» убит).

## 4. Эмодзи, которых нет на другой стороне

**Telegram → WhatsApp (это задание).** Набор реакций Telegram (73 эмодзи, `ReactionTypeEmoji`) —
обычные эмодзи Unicode, а WhatsApp принимает любое эмодзи. Поэтому неподходящих среди обычных нет,
каждое уходит как есть. Семь из них Telegram пишет без U+FE0F, в текстовом начертании: ❤, ❤‍🔥, 🕊,
✍, ☃, 🤷‍♂, 🤷‍♀. Клиенту уходит полная форма с U+FE0F (`WA_FULL_FORM`, `:67`), иначе у него будет
значок шрифта вместо картинки.

Вне набора у Telegram есть только `custom_emoji` (премиум) и `paid` (звёзды). В WhatsApp их нет —
**не шлём**, пишем строку журнала «вид custom_emoji в WhatsApp не существует». Для итога сообщения
такая реакция человека считается отсутствием реакции: если она заменила обычную, клиенту уходит
снятие или реакция предыдущего человека. У премиума до трёх реакций — берётся последняя обычная.

**WhatsApp → Telegram (40b158b, не менялось).** U+FE0F и оттенок кожи снимаются; эмодзи вне набора
Telegram даёт одну строку в теме вместо реакции.

Круг замыкается: ❤ из темы уходит клиенту как ❤️, а ❤️ клиента ложится в тему как ❤.
