**Арифметика до работы (как предписано).** Первые два случая — 32.7 с и 36.2 с → **34.5 с на

## §7. Развилки на решение владельца (сессия НИЧЕГО не чинила)

1. **Сетка парка на старом источнике.** Подключать ли к ней записанное правило. Мешает названное
   препятствие: у сетки нет дат клиента (якорь — завтра), а сезон правило приписывает по дате
   НАЧАЛА аренды. Пока не подключено, самый дорогой запрос («сколько стоит на пик») отвечается
   ценой дна.
2. **Поколения XMAX в цене.** Правило знает одну базу `XMAX 300` (623 ฿), лист различал 557 и
   662 ฿. Заводить ли отдельную базу New Gen — решение владельца; сегодня клиенту по обоим
   поколениям посчиталось бы одно число.
3. **Октябрьский подъём.** В правиле записан ровно 1.000. «Появился спрос — чуть поднимаем» —
   ручная правка файла; кто и по какому признаку её делает, не назначено.
4. **Ветка «зову человека»** (полгода / смешанный период / просьба о скидке) — по-прежнему
   отсутствует как исход. Три случая из двенадцати.
5. **Окно отката даты назад — 182 суток** (`_PAST_ROLL_MAX_DAYS`, случай 10). Цена забора не
   изменилась: вопрос про май, июнь, июль, заданный в августе, клиент получить не может.
6. **Запас бюджета сторожа.** Живые проходы сегодня 36–69 с при бюджете 90 с и один
   необъяснённый отказ на ~10 наблюдений. Двукратного запаса, которым бюджет обосновывался,
   по факту нет.
