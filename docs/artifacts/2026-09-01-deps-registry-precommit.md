# Класс надзора за зависимостями закрыт: расхождение реестра видно НА КОММИТЕ, а не через отказ эстафеты

**Дата:** 01.09.2026 · **полоса:** ПК · **задача:** 86 · **вершина на момент работы:** `9041f29`

## 0. Что здесь закрыто одной фразой

У демона два РУЧНЫХ реестра зависимостей, которые обязаны совпадать с фактом импортов на диске.
Их и раньше стерегли три теста, но узнавал о красном **не автор правки, а демон** — на
self-update, часы спустя, отказом эстафеты. Теперь ту же сверку делает **pre-commit**:
`deps_registry_check.py` + `deploy/hooks/pre-commit`. **Класс надзора за зависимостями закрыт**
не тем, что реестр стал считаться сам (это сломало бы тесты-сторожа, см. §4), а тем, что
**момент обнаружения переехал с self-update на коммит**.

## 3. Механизм (пункт 3 задания — способ назван)

**`deps_registry_check.py`** — сторож, который гоняет **ТЕ ЖЕ САМЫЕ три теста**, что и гейт
демона, а не свою копию их логики:

- `TestSelfUpdateDepClosure.test_dirty_gate_watches_exactly_what_start_loads_unconditionally`
- `TestSelfUpdateDepClosure.test_lazy_dependencies_are_a_named_remainder_not_a_silent_gap`
- `TestApprovalReachesExecutor.test_orch_runtime_covers_every_top_import_of_daemon`

Копия алгоритма разъехалась бы с оригиналом молча, и сторож начал бы стеречь позапрошлое
правило — поэтому логика не дублируется ни строкой. Цена: **~2 с** (замер: 3 теста за 1.5–2.0 с),
и то лишь на коммитах, где в индексе есть `.py`; коммит доков/журнала сторож пропускает сразу.

**`deploy/hooks/pre-commit`** — версионируемый хук (зеркало приёма VPS `core.hooksPath`).
Включён местной настройкой:

```
git config core.hooksPath deploy/hooks     # включить
git config --unset core.hooksPath          # снять (полный откат механизма)
git commit --no-verify                     # разовый обход
```

До правки `core.hooksPath` не был задан вовсе, а в `.git/hooks` лежат только `*.sample` —
**ни один существующий хук не вытеснен** (проверено `ls .git/hooks`).

**Три исхода, а не два** (правило полосы «не смог проверить» ≠ «проверено и хорошо»):

| код | смысл | что делает хук |
|---|---|---|
| 0 | сверено, расхождения нет (или в индексе нет `.py`) | пропускает молча |
| 1 | расхождение названо поимённо | **держит коммит** + печатает, в какой из двух реестров вносить |
| 2 | сверить не смог: нет интерпретатора, тесты-сторожа не загрузились, таймаут | пропускает, но **громко** |

Полярность выбрана сознательно: хук — **ранний слой**, жёсткая сеть под ним (unittest-гейт
демона) осталась на месте. Сломанный сторож не имеет права заблокировать полосе коммиты; но и
выглядеть зелёным, ничего не проверив, он не имеет права тем более — на это заведены
7 проверок в `test_deps_registry_check.py` (в том числе «тест-сторож переименовали» и
«прогнано меньше, чем просили» → оба «неизвестно», а не «хорошо»).

## 4. Развилка, решённая ОТКАЗОМ: почему реестр не стал считаться сам

Задание допускало и такой путь («новый верхний импорт попадает под надзор автоматически»).
Отвергнут по факту, а не по вкусу: **оба теста-сторожа сравнивают ФАКТ с РУЧНЫМ кортежем**
(`unconditional == set(o._ORCH_RUNTIME)`; `set(_dep_files()) - set(_ORCH_RUNTIME) ==
set(_ORCH_LAZY_UNCOVERED)`). Начни кортеж считаться тем же обходом — сравнение станет
тавтологией, и тесты **перестанут уметь падать вовсе**: надзор не автоматизировался бы, а
исчез. Для `_ORCH_LAZY_UNCOVERED` цена ещё выше: это не «список файлов», а **записанный
остаток** — признание, что дыра есть и почему её оставили («WIP в suggest.py глушил бы ВСЮ
доставку демону»). Автосчёт превратил бы признание в молчание. Правку тестов задание
запрещало прямо, но здесь запрет и не понадобился: автоматизировать надо было **надзор**, а не
реестр.

## 5. Отрицательная проба (пункт 5 задания) — живая, с реальным коммитом

Фиктивный верхний импорт `import price_gate` внесён в шапку `pc_orchestrator.py`.

1. Сторож руками → **exit=1**, поимённо: `'price_gate.py'`, `'price_freshness.py'`,
   `'price_freshness_run.py'` (транзитивный тест увидел весь куст, прямой — корень).
2. **Настоящий** `git add pc_orchestrator.py && git commit -m "…"` → хук отклонил:
   `commit_exit=1`, `FAILED (failures=2)`, **HEAD остался `9041f29`** — коммит не родился.
3. Проба убрана; `git diff --quiet HEAD -- pc_orchestrator.py` → **совпало байт-в-байт**;
   сторож снова зелёный.

Побочно проба показала и третий исход вживую: промежуточная правка сломала отступ в шапке
демона, тесты не загрузились — сторож ответил **«НЕИЗВЕСТНО»** и коммит держать не стал,
ровно как задумано.

Файлов проба не создавала и не удаляла: фиктивным импортом взят **уже существующий** модуль
репозитория — чтобы «убрать за собой» означало правку, а не удаление.

## 7. Что механизм НЕ закрывает (честный остаток)

1. **`core.hooksPath` — местная настройка, в git её нет.** Свежий клон репозитория приедет без
   надзора, пока не выполнят строку из §3. Хук версионируется, включение — нет.
2. **`--no-verify` обходит сторожа** сознательно (иначе он стал бы тем самым «нельзя
   закоммитить»). Обход не тихий: после него красное поймает гейт демона — то есть ровно
   прежнее поведение, не хуже.
3. **Сторож смотрит РАБОЧЕЕ ДЕРЕВО, а гейт демона — HEAD.** Частично собранный коммит (правка
   на диске есть, в индексе нет) может разойтись в вердиктах. Для раннего слоя это принято
   осознанно: дешевле ложная тревога, чем пропуск.
4. **Полоса VPS не тронута.** Там свой `core.hooksPath=deploy/hooks` и свои реестры; зеркалить
   без проверки посылки на той полосе (правило 04.08) эта задача не имела права. Точка
   касания названа: `orchestrator_daemon` и его список зависимостей.
