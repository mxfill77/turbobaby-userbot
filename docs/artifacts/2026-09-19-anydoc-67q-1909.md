## Что заход выяснил об инструменте, не ставя его

Разведка шла по **исходнику**, вытянутому открытым каналом git: `git clone --depth 1 --branch
v0.2.4 https://github.com/firecrawl/anydoc tmp/konverter_proba/istochnik`.

**Мина имени, и она дорогая.** Наивная команда `pip install anydoc` поставит **не тот пакет**.
Дословно из `python/pyproject.toml:5-8` источника:

> The distribution installs as `firecrawl-anydoc` (the bare `anydoc` name on PyPI is held by an
> unrelated package) and imports as `anydoc`.

То есть имя дистрибутива — `firecrawl-anydoc`, имя импорта — `anydoc`, и на PyPI голым именем
владеет ПОСТОРОННИЙ пакет. Промах здесь выглядел бы как успех: менеджер ответит «установлено»,
`import anydoc` может даже пройти, а конвертировать будет чужой код.

**Версия и колесо под эту машину.** `Cargo.toml:8` и `python/Cargo.toml:5` → **0.2.4** (старший
тег репозитория). Сборка — maturin, `pyo3 = { version = "0.29", features = ["abi3-py310",
"extension-module"] }` (`python/Cargo.toml:17-19`). `abi3-py310` означает: одно колесо на платформу
покрывает Python 3.10 и выше, то есть **наш 3.12.5 покрыт**. Цель `x86_64-pc-windows-msvc` в
матрице колёс есть (`.github/workflows/release.yml`, задачи `build-wheels` и `test-wheels`) —
значит готовое колесо под Windows x64 на PyPI лежит и **Rust-цепочка на машине не понадобится**
(что важно: `cargo` здесь не установлен, и сборка из исходника упала бы).

**п.2 — что пакет утянет за собой.** В `python/pyproject.toml` раздела `dependencies` **нет
вовсе**: у дистрибутива **ноль объявленных рантайм-зависимостей**, вся тяжесть — в скомпилированном
Rust-модуле `anydoc._anydoc` внутри самого колеса. Значит **чужих версий пакет молча не двигает**:
менять ему нечего. Это разведка по исходнику, а не по ответу менеджера — окончательное число даёт
`pip install` своим отчётом, и его надо сверить с нулём при живой установке.

**Отдельная новость, которой в задании нет, а для этой полосы она важнее версии.** У конвертера
есть ветка с выходом наружу: параметр `ocr` (`python/anydoc/__init__.py`). Умолчание —
`ocr="reject"`, и тогда, дословно, «Documents anydoc converts itself never leave the machine».
Значение `ocr="hosted"` отправляет **весь документ** в Firecrawl Parse. На полосе, где запрет
«наружу из проверки не уходит НИЧЕГО», это готовый канал утечки, открывающийся одним
именованным аргументом. Проба захода зовёт конвертер **только с умолчанием**; правило для
будущего — `ocr="hosted"` на этой полосе не звать ни разу.

## п.3 и п.4 — прогон подготовлен целиком, не хватает только пакета

Готов и **проверен на своей половине** `tmp/konverter_proba/proba_konvertera.py`. Он создаёт
документы **своим же кодом** (бизнес-данных не касается ни байтом, п.0г соблюдён), гоняет их
через конвертер и читает результат обратно. Прогон 19.09 показал:

```
docx  proba.docx | на диске 1852 байт | тело-исходник 1395 символов
xlsx  proba.xlsx | на диске 1642 байт | тело-исходник  503 символа
csv   proba.csv  | на диске   38 байт | тело-исходник   27 символов
битый bityi.docx | на диске  760 байт (не zip вовсе)
замок docx: частей в контейнере 5, целостность OK
замок xlsx: частей в контейнере 5, целостность OK
!!! КОНВЕРТЕР НЕ УСТАНОВЛЕН: No module named 'anydoc'
```

То есть **входы существуют и настоящие**: docx и xlsx — не «похожие файлы», а живые OOXML-контейнеры
по 5 частей, `zipfile.testzip()` на обоих вернул `None`. В docx лежат заголовок первого уровня
(`Heading1` + `outlineLvl 0`) и таблица 3×2; в xlsx — та же таблица на `inlineStr`; csv — она же
голой строкой. Три формата вместо требуемых двух.

Отрицательный тест (п.4) заряжен тем же скриптом: `bityi.docx` — верное расширение и 760 байт
мусора, который не zip вовсе. Ожидание по исходнику: конвертер поднимает `anydoc.ConvertError`
с текстом `unrecognized file content` (`python/tests/`, строка 77 — `assertRaisesRegex`), а на
испорченном-но-опознанном файле — `MalformedError`. Скрипт печатает тип и текст исключения и
отдельно сверяет наследование от `ConvertError`; если исключения не будет и вернётся строка —
он **сам назовёт это ДЕФЕКТОМ** и вернёт ненулевой код. Но **это пока ожидание из чужого
исходника, а не наш замер**: п.4 считается сделанным только после живого отказа на этой машине.
