## Безопаснее: **cherry-pick в чистую ветку**, а не rebase-с-выбросом

```
git checkout -b rebuild-main origin/main      # чистая база: уже с _strip_script_cli_args
# cherry-pick ТОЛЬКО полезные, oldest→newest, 88db1ae НЕ трогаем:
git cherry-pick f291c77 4a17cf3               # чисто
git cherry-pick a5c148e                        # ⚠ конфликт pretool_guard.py -> резолв -> continue
git cherry-pick a72bb6d
git cherry-pick f185099                        # ⚠ второй заход по guard (если затронут) -> резолв
git cherry-pick 0bbca3d 56fbd69 1f6741b 651db0a 1bc3051
# ea1933e — только если submodule 3b0368c доступен на remote
# верификация ПЕРЕД тем как двигать main:
pytest -q tests/test_pretool_guard.py         # + entity-тесты
git ls-files | grep -E '(^|/)_[^_/].*\.py$|\.bak|_bridge_bak' && echo "МУСОР ЕСТЬ" || echo "мусора нет"
git status --porcelain                         # пусто
# только после зелёных тестов и «мусора нет»: перевести main на rebuild-main и push
```

**Почему cherry-pick безопаснее rebase-drop:**
1. Гарантированно чистая база (`origin/main` уже без 574 файлов и уже с origin-guard) — мусор
   физически не может попасть, берём только выбранное.
2. `88db1ae` отсекается ОПУЩЕНИЕМ (не выбираем), а не «удалением строки» в `rebase -i` с надеждой,
   что от него ничего не зависит.
3. Единственный конфликт `pretool_guard.py` резолвится один раз, под контролем, на пике `a5c148e`.
4. `main` остаётся нетронутым бэкапом, пока `rebuild-main` не проверен (тесты + «мусора нет»).
   Только потом двигаем `main` и пушим. Rebase переиграл бы тот же конфликт И всё равно требует
   выброса `88db1ae` — больше шансов ошибиться.
