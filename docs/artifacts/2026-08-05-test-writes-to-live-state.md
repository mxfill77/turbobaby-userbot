### Поправка к артефакту: состав 12 находок восстановим ПОЛНОСТЬЮ

Артефакт инцидента считает «4 + 7 = 11 против 12 в спуле: одна находка, по-видимому, лежала там
раньше». Пересчёт по сырому логу даёт **ровно 12**, и лишней не остаётся:

* `20:28:26` — 4 находки owner-карточек: пост-релиз окно 244119252 (2), окно 1226243168 (1),
  чеки черновиков окно 1226243168 (1, класс #93);
* `20:29:32`–`20:32:08` — 8 находок клиентского контура; итоговая строка демона говорит это
  прямым числом: «**8 находок** по КЛИЕНТСКОМУ контуру переведены из задач в owner-карточки».

4 + 8 = 12. Сходится со спулом дословно. Заодно видно, что **второй замок 6d41c37 отработал**:
у прогонов 14:27 и 20:28 одинаковое `since=2026-08-04T01:25:10.114920+00:00` — метка НЕ сдвинулась,
поэтому окно 831088817 отревизовано повторно, а дедуп схлопнул его 4 находки с находками 14:30.

**Владельцу для решения:** классы и окна известны (перечислены в §3 артефакта инцидента),
дословная нагрузка — нет. Поднять их заново можно только перепрогоном ревизора по этим окнам.

### Изоляция боевой ОЧЕРЕДИ держится на алфавите — замер

`moderation_ipc` имеет правильный замок: под `TESTING=1` `DB_PATH` уводится в temp, а `_conn()`
роняет любую попытку открыть боевой `moderation_ipc.db`. Но флаг взводит **импорт
`test_isolation`**, а его импортируют 14 тест-файлов из 42. Замер двумя способами запуска:

```
полный discover                         → TESTING = True   DB_PATH = …\Temp\turbobaby_TESTING_ipc.db
гейт демона (_gate_unittests):
  unittest test_pc_orchestrator …       → TESTING = False  DB_PATH = D:\turbobaby-bot\moderation_ipc.db
                                          REVIZOR_DB       = D:\turbobaby-bot\moderation_ipc.db
```

В полном гейте спасает случайность: `test_booking_draft.py` идёт первым по алфавиту и импортирует
`test_isolation` раньше, чем кто-либо импортирует `moderation_ipc`. **А собственный гейт демона
самообновления гоняет ровно два модуля, ни один из которых `test_isolation` не импортирует, — и
там боевая очередь открыта, а тривайр мёртв.** Переименуй `test_booking_draft.py` — и полный гейт
переедет в ту же ветку молча.

## 3. ОДНО ПРАВИЛО НА КЛАСС — И ПОЧЕМУ ИМЕННО ЭТО

**Правило не изобретено, а взято своё же, уже боевое.** В репо давно живёт `log_setup.log_path()`:
он решает, куда РЕАЛЬНО писать лог, по **способу запуска процесса** (`log_setup
._started_as_test_runner`: `__main__.__spec__` = `unittest`/`pytest`, либо argv `test_*.py`), а не
по доброй воле теста. Замер обоих концов:

```
argv[0] = …\unittest\__main__.py   → _started_as_test_runner = True   → …\Temp\turbobaby_TESTING_pc_orchestrator.log
argv[0] = pc_orchestrator.py       → _started_as_test_runner = False  → D:\turbobaby-bot\pc_orchestrator.log
```

На этом дискриминаторе уже держится боевой лог демона — он проверен продом, и расширение его с
логов на состояние **нового режима отказа не вносит**.

**Форма: `log_setup.state_path(filename)`** — близнец `log_path`, но уводит не в общий temp, а в
ОДНОРАЗОВЫЙ каталог на процесс (состояние двух прогонов не должно встречаться в одном файле).
Правило стоит **в самой константе**, а не в `setUp`:

```python
REVIZOR_SPOOL_FILE = _state(os.path.join(REPO, "pc_orchestrator.revizor_spool.json"))
```

Почему именно так, а не «изолируй в тесте» — ровно по устройству дефекта. Оба найденных случая
выглядят одинаково: **у живой функции ЕСТЬ параметр пути для изоляции, и тест его не передал.**
`_persist_client_watch(state, now, path=None)` → `path = CLIENT_WATCH_FILE if path is None`.
`_revizor_route` → спул по умолчанию. Договорённость забывается молча и грепом не проверяется;
константа, указывающая не туда, — не забывается.

### Применено в этом заходе

`log_setup.state_path()` + перевод на неё 11 констант: `CLIENT_WATCH_FILE`, `CHAIN_CARD_STATE`,
`TASK_START_FILE`, `COWORK_LEDGER`, `LESSON_RETRY_FILE`, `LESSON_WAIT_STATE`, `APPROVAL_LEDGER`,
`AUTOFETCH_STATE_FILE`, `REVIZOR_STATE_FILE`, `REVIZOR_SPOOL_FILE`, `WD_STATE_FILE`
(`pc_orchestrator.py`) и `LEDGER_PATH` (`cowork_log_append.py`).

Голдены — `test_log_setup.TestStatePathIsolation`, написаны от инцидента: главный из них
(`test_live_state_constants_do_not_point_into_the_repo`) сам идёт тест-прогоном и требует, чтобы
боевые константы состояния в этот момент **не указывали в репозиторий**. Он упал бы на коде до
правки — то есть поймал бы и съеденный спул, и переписанный снимок надзора.

## 4. ОСТАТКИ, НАЗВАННЫЕ ЧЕСТНО

1. **`trainer_rules.json` и `pc_ask_*.marker` не переведены.** Первый — тренажёр (клиентский
   контур заморожен границами задачи), второй — изоляция проб, границами трогать запрещено.
   Точки касания названы, заряженность доказана перехватом.
2. **Гейт демона самообновления (`_gate_unittests`) остаётся без `test_isolation`** — боевая
   очередь `moderation_ipc.db` там открыта, тривайр мёртв. Правка на одну строку (импорт или
   `env["TESTING"]="1"` в `subprocess.run`), но это правка ветки самообновления демона — отдельным
   заходом, не третьей темой в этот коммит.
3. **Полоса сервера не поправлена.** Зеркального класса «спул» там нет, но `memory.DB_PATH` без
   изоляции — тот же класс с другим файлом. Точка касания: `memory.py:18`, тесты обходят её
   параметром `Memory(db_path=…)`, а не подменой пути.
4. **Утраченные 13 строк реестра `cowork_log.ledger` не восстанавливались.** Реестр —
   вспомогательное кольцо следов, авторитетен мозг (`cowork_log`); восстановление означало бы
   боевую запись, которой в этой задаче нет. Бэкап до гейта лежит в
   `tmp_state_iso_20260805_r1/backup_state/` — если владелец решит вернуть, есть откуда.
5. **`pc_orchestrator.client_watch.json` оставлен как есть** (фикстура `ts=1301.0`, `children={}`).
   Демон перезапишет его своим тиком надзора; на момент записи артефакта — ещё нет.
