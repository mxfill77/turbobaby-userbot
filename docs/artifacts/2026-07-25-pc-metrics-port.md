## 1. Различия модуля метрик между репозиториями

До порта ПК-копия была **байт-в-байт равна серверной ДО правки**: 133 строки,
`sha256 5297cce341f88423cbc9a7cc2c48d05b65deaa79d926bdd704e8c8208fa292a7`, содержимое совпадает
построчно. Никакой «специфики ПК» в самом модуле нет и не было — он лане-агностичен по замыслу.

Значит различие между репозиториями = ровно тот патч, что уехал на сервер:

| что | было на ПК | стало (как на VPS) |
|---|---|---|
| формат строки | `task lane model effort start end dur_s outcome attempts selfheals tokens_in tokens_out` | + `type=`, `mode=`, `src=` после `lane=` |
| `dur_s` | `int(round(float(dur_s)))` → короче 1,5 с схлопывалось в `0` | `float(dur_s):.2f` |
| признак теста | функции не было | `under_test(argv0, env, modules)` — чистая, проверяется юнитом |
| тип задачи | не было | `task_type` / `task_type_explain` + 4 группы признаков |
| CLI | не было | `python task_metrics.py [--type "<текст>"]` |
| строк в файле | 133 | 240 |

Полный дословный diff — в теле коммита `4c81efd` (`git show 4c81efd -- task_metrics.py`).

## 2. Порт байт-в-байт: чем это доказано

Патч применён **теми же якорями и тем же текстом замены**, что и на сервере, и **все три якоря
совпали ровно по одному разу**. Совпадение якорей в каждой правленой области + идентичность
исходного файла ⇒ результат равен серверному по построению.

```
sha256 task_metrics.py ПОСЛЕ порта: 515f3a45b78c2f7f248c27b77d5dc356cabdf15e8e878d577f1a4fe8df05da05
окончания строк: LF=240, из них CRLF=0 (чистый LF, как на сервере; core.autocrlf=true,
                 но рабочий файл записан с LF, и git кладёт в объект тот же LF)
```

⚠ **Честная оговорка:** равенство сверено *по построению*, а не сличением с файлом сервера — этот
заход был локальным, без ssh. Прямая проверка — одна команда на VPS:
`sha256sum task_metrics.py` должен дать ровно `515f3a45b78c2f7f24…`.

## 3. Специфика ПК — сохранена, а не переписана

На ПК разведение тестовых и боевых логов **своё, и оно другое по замыслу**: `log_setup` не глушит
лог теста, а уводит его в `%TEMP%\turbobaby_TESTING_<имя>.log`. И там прямо записано, почему
признак берётся не так, как на сервере:

> «Намеренно НЕ проверяем "есть ли unittest в sys.modules": демон импортирует `gate_selective`,
> который гоняет тесты, — по такому признаку БОЕВОЙ `pc_orchestrator.log` молча уехал бы в temp,
> и живая диагностика исчезла бы ровно тогда, когда она нужнее всего.»

Это оставлено как есть. Общий `under_test` добавлен **вторым** признаком и только ради поля
`mode=`:

```python
_UNDER_TEST = task_metrics.under_test((sys.argv[0] if sys.argv else ""), os.environ, sys.modules)
try:
    _UNDER_TEST = _UNDER_TEST or log_setup.is_test_context()
except Exception:
    pass
```

### Дыра на ПК оказалась ЗЕРКАЛЬНОЙ серверной

| | что проверял | чего не проверял | как течёт |
|---|---|---|---|
| **VPS** | имя входного файла `test_*` | окружение (`ORCH_TEST_MODE`) | копия теста под чужим именем → пишет в боевой журнал |
| **ПК** | окружение и способ запуска (`-m unittest`) | имя входного файла | `python test_pc_orchestrator.py` напрямую → пишет в боевой журнал |

Закрыто с обеих сторон: на VPS добавлен `ORCH_TEST_MODE`, на ПК — признак «входной файл
`test_*.py`». Ложного срабатывания у демона нет: его входной файл называется `pc_orchestrator.py`,
и на это стоит регресс в `test_log_setup.py`.

## 5. Живая строка метрик ПК

Снята с **настоящего** call-site `pc_orchestrator.run_task` (исполнитель замокан, ни claude, ни
сети; лог демонстрации уведён в temp, поэтому строка честно помечена `mode=test`):

```
METRICS task=4242 lane=pc type=code mode=test src=metrics_demo.py model=claude-opus-4-8
effort=xhigh start=2026-07-25T14:07:03+00:00 end=2026-07-25T14:07:04+00:00 dur_s=0.36
outcome=done attempts=1 selfheals=0 tokens_in=na tokens_out=na
```

Та же строка, как её напишет боевой демон:

```
METRICS task=4242 lane=pc type=code mode=prod src=pc_orchestrator.py model=claude-opus-4-8 …
```

Разбор: `type=code` — признак «фикс» в тексте задания; `dur_s=0.36` — **раньше эта же задача дала
бы `dur_s=0`**; `mode`/`src` называют, кто написал строку.

Признаки типа на живых формулировках владельца:

```
type=read   признак=read-only              ultrathink ТОЛЬКО read-only. Ничего не менять.
type=code   признак=фикс                   ultrathink Приземлить проверенный фикс через merge.
type=build  признак=выкатить               ultrathink Выкатить одометр в прод.
type=other  признак=(нет → честное other)  ultrathink Перезапустить демон, чтобы вступили новые
                                           пороги гейтов (коммит 0bbca3d).
```
