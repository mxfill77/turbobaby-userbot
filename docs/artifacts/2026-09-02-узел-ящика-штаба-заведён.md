**Дата:** 02.09.2026, вечер (замеры — местное время ПК, штампы моста — UTC).
**Полоса:** ПК. **В git не коммичено** — узел живёт в мозге, здесь только запись о нём.
**Временное место названо:** `_scratch_shtabbox_reg_0902/` в корне репозитория (`header.txt`,
77 байт — текст шапки для stdin).

## Премиса: проверена чтением, а не памятью

`brain_writer.py --list-brain` (только чтение, отдельный процесс) ДО правки:

```
КЛЮЧЕЙ ВСЕГО: 36 (включая folder_id — это папка, не док)
```

`shtab_box` среди них НЕТ; рядом стоит `shtab_frame` — тот самый сосед, которого мост называл в
подсказке. Премиса задания подтверждена.

**Сверка с числом из лога демона, чтобы не родить ложный диагноз «реестр поменялся».** Демон в
18:04:47 и 18:36:34 писал «в живом реестре такого ключа нет (**ключей 35**)», а `--list-brain`
показал **36**. Расхождения нет: CLI считает и `folder_id` (и сам говорит об этом строкой),
резолвер имён — только доки. 36 − 1 = 35.

## Что сделано: ровно одна запись, штатным писателем

Форма взята из раздела «Узел-ящик: имя и формат» артефакта
`docs/artifacts/2026-09-02-ящик-заданий-штаба.md`: имя и ключ — **short-форма без приставки
`KB_`**, в теле — шапка-заголовок.

```
cat _scratch_shtabbox_reg_0902/header.txt | venv/Scripts/python.exe brain_writer.py --create shtab_box --name shtab_box -
```

Текст подан **через stdin, а не argv**: argv на этом ПК коверкает кириллицу, а `_stdin_text()`
декодирует вход явным UTF-8. Файл проверен побайтно ДО отправки: 77 байт, начинается с `e2 95 90`
(значит BOM нет), последовательности `ef bf bd` (U+FFFD) — 0 совпадений.

Расписка моста:


Слепого повтора не было и не потребовалось: расписка дошла с первого раза. (Ветка потери расписки

## Обратное чтение НЕЗАВИСИМЫМ процессом, по имени из живого реестра

```
venv/Scripts/python.exe brain_writer.py --probe --name shtab_box
PROBE ok: 39 символов, строк 2, U+FFFD 0; голова:
═══ ЯЩИК ЗАДАНИЙ ШТАБА — полоса ПК ═══
```

Это не то же обратное чтение, что внутри `create_plain`: там свой же процесс сверял свой же текст
по `id`, здесь — **другой процесс, адресация по ИМЕНИ**, то есть через реестр.

Реестр после записи (тот же read-only CLI):

```
"shtab_box": "1I4A2OdajN4-fUyonz13ky3Pd_mmR7Zvs",
"shtab_frame": "1DiXr3jxoZYxkWaS7k4X4SR0u2xQKUTCi",
КЛЮЧЕЙ ВСЕГО: 37 (включая folder_id — это папка, не док)
```

`--resolve shtab_box` → `name:shtab_box  [ключ реестра]`: имя разрешается ПРЯМЫМ ключом, без
добора по границе токена.

**Числа узла:** ключ `shtab_box`, имя `shtab_box`, file id `1I4A2OdajN4-fUyonz13ky3Pd_mmR7Zvs`,
тело **39 символов** (38 видимых + хвостовой перевод строки), U+FFFD — 0. Ключей в реестре стало
37 против 36 (доков 36 против 35). Других узлов не касались ни одной веткой.

## Демон: читает — да; своей строкой это в журнале ещё не сказал

Читающий путь проверен **тем же кодом, который зовёт демон** (`shtab_box_run.tick`, у демона —
`maybe_shtab_box` → `runner or shtab_box_run.tick`), отдельным процессом, сухим ходом:

```
venv/Scripts/python.exe shtab_box_run.py --status
день: 2026-09-02 (замер 2026-09-02T11:57:22.421254Z)
узел: shtab_box — прочитан
блоков в ящике: 0, не разобрано: 0
очередь: прочитана, рядов 7, работа владельца: #119
```

Было (журнал демона, `pc_orchestrator.log`, две последние строки ящика ДО правки):

```
18:04:47 INFO ящик Штаба: узел-ящик не прочитан (узел shtab_box не прочитан: ИМЯ НЕ РАЗРЕШЕНО …
         В живом реестре такого ключа нет (ключей 35) …) — что в нём лежит, НЕИЗВЕСТНО
18:36:34 INFO ящик Штаба: узел-ящик не прочитан (… то же …)
```

**Своей строки демон за эту сессию не дал, и это не случайность, а устройство.** `maybe_shtab_box()`
стои́т в главном цикле ПОСЛЕ `poll_once()`, а `poll_once()` → `process_new()` исполняет `claude -p`
**синхронно**. Эта сессия и есть та задача: `CLAIM id=119 in_progress` в 18:56:08, `RUN id=119
(timeout=2700s)` в 18:56:09. Замер, подтверждающий, что виток стои́т: heartbeat замер на **18:51**
(при `POLL_SEC=60`), после 18:56:09 в журнале ни строки. Значит витка ящика не будет, пока эта
задача не закончится, — **ждать его изнутри сессии значит ждать событие, которое сама сессия и
блокирует**. Ни одного оборота ящика за сессию не прошло; двух не прошло тем более.

**Что скажет демон первым же витком после закрытия задачи** (по `shtab_box_run._why`, порядок
проверок там же): `node_ok` теперь ИСТИНА, поэтому ветка «не прочитан» недостижима. Останется одно
из двух — «в очереди задача владельца (#N) — заданий Штаба не берём ни одного», если в очереди
будет работа владельца, либо «ящик пуст: блоков в узле shtab_box нет». Троттлинг: метка оборота
`pc_orchestrator.shtab_box_tick.json` = `{"ts": 1788348906.34}` (18:36:34), пол паузы
`SHTAB_BOX_MIN_SEC=1800` → ближайший законный виток не раньше **19:06:34**. Стоп-файла
`pc_orchestrator.shtab_box.off` в корне нет — ветка включена.

Это ЧЕСТНОЕ «не дождались», а не «увидели»: строка про пустой ящик в журнале демона на момент
отчёта ОТСУТСТВУЕТ, и выдавать сухой прогон за неё нельзя. Дописано только то, что проверяемо:
читающий путь — тот же самый, и на нём узел читается.
