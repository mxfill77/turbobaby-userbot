## 2. Чем мерить сон

**`kernel32.QueryUnbiasedInterruptTime`** — несмещённые часы прерываний: в S3/гибернации не
тикают. `time.monotonic()` на Windows = `GetTickCount64`, смещённые, проспанное в них есть.
Разница двух часов и есть сон ЧИСЛОМ. Живой замер этого захода (03.08 05:07):

```
GetTickCount64             = 359 482,0 c
QueryUnbiasedInterruptTime = 327 197,4 c
разница                    =  32 284,6 c   против журнала Windows 32 286 c → расхождение 1,4 c
```

Спутать с залипанием сети **невозможно по конструкции**: висящий сокет жжёт несмещённые часы
ровно так же, как настенные, — разница остаётся 0. Это не порог, а свойство источника.

**Он уже в файле и уже вычислен — но ПОСЛЕ решения.** `awake_monotonic()` — `pc_orchestrator.py:1067`;
`slept` считается на строке **6785**, а решение принимает `_woke_from_sleep` (**5513**, зовётся с
**6779**) по `(now-prev) > POLL_SEC + WAKE_JUMP_MARGIN`. Правильный инструмент лежит на две строки
ниже неправильного решения и уходит только в текст WARNING'а и в `report_long_sleep`.

**Запас порога обязателен:** `slept > 0` не годится — суточная поправка службы времени (2,8 с)
даёт фантом. Запас **≥ 60 с** безопасен: наибольший ложный `slept` = 2 с, наименьший настоящий
сон = 32 286 с, между ними четыре порядка. Критерий `slept > 60` на данных окна: **672 → 1**.

Внешний журнал (`Get-WinEvent … Power-Troubleshooter id=1`) — только для разбора постфактум:
запрос стоит сотни мс, в горячий цикл не годится.

## 3. Что сломается, если выключить

Потребителей детекта в репозитории ровно **два** (`pc_agent.py` grace не видит — читает дисковый
снимок надзора).

**Плечо 1 — grace вотчдога** (`_client_grace_until = now + 120`, строка 6783; потребитель 5364).
Класс #171 держат ТРИ слоя: (а) finder различает три исхода (5389), (б) «мёртв» = три условия
(5397–5404), (в) grace. Снятие (в) класс не открывает — плюс cooldown 900 с и halt после 3 смертей.
**А стоит (в) дороже, чем спасает:** за окно подавлено **135** тиков, и подавленный тик списывается
как полноценный (`_client_watch_last_run = now` на 5465 стоит ДО тела, тело выходит на 5367) ⇒
120 с grace покупают 300 с (`CLIENT_WATCH_SEC`) слепоты: **135 × 300 = 40 500 с ≈ 11 ч 15 м (6,7 %
окна)**. Ради чего заведён — за 7 суток не случилось ни разу: «не смог проверить» — **0**,
«циклов подряд СЛЕП» — **0**, вето «лог свеж» — **0**. Зато вотчдог сделал 4 настоящих подъёма, и
31.07 userbot пролежал **1229 с** при проектных 300 с — между 15:13 и 15:33 ложный детект сработал
4 раза, в 15:18:27 в логе стоит `grace … — вердикты отложены`.

**Плечо 2 — `report_long_sleep` (5566): ЕДИНСТВЕННЫЙ производитель карточки `🛌 ПК СПАЛ`** (строка
в журнал + сигнал в тему 328 с числом накопившихся задач lane=pc). Выключить детект целиком —
значит, что настоящий восьмичасовой простой контура не увидит никто. Ровно это и было 30.07.

**Что НЕ сломается (важно):** бюджет бодрствования `_wait_awake`/`awake_monotonic` (1101/1067)
зовёт часы напрямую и от детекта не зависит — таймаут задачи не сгорит на сне в любом случае.

**Тесты, которые придётся провести через правку:** `test_pc_orchestrator.py:2523-2525` (3 assert'а
на `_woke_from_sleep`), `test_pc_sleep_alarm.py` (19 кейсов), `test_pc_awake_clock.py` (15 кейсов).

## Итог

Выключать нельзя — плечо 2 единственное. Правка по существу одна: **звать сном только измеренный
