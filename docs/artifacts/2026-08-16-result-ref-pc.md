## 2. Почему маркером, а не десятой колонкой

Не из удобства, а по границе полосы. Лист очереди у полос **ОДИН** (`docs/dec_port_spec.md:115`,
разбор 15.08 §7): десятую колонку даёт только правка Apps Script моста — операция чужой полосы
и красная отсюда. Полоса уже носит структурное состояние маркерами в `task_text`, и это
записанное решение, а не самодеятельность: «Родство цепи — ТОЛЬКО по паттернам в `task_text`
(схема очереди не менялась, решение плана C)». Так же едут `[шаг i/N родитель pid]`,
`[сводка родитель pid]`, `[коррекция плана родитель pid]` и restart-proof остаток плана.

Замок на завтра встроен в читателя: `result_ref.read_item` **сначала смотрит настоящую колонку
`result_ref`** ряда и только потом маркер. В день, когда мост колонку заведёт, мирить полосы
будет нечем — колонка перекроет маркер сама, ни один читающий не правится.

## 3. Где записывается и где читается (две точки, больше нет ни одной)

| роль | место | как |
|---|---|---|
| **запись при создании шага** | `pc_orchestrator.py:4877` `_loc_release(pid, j, total, text, k=0, ref=result_ref.EMPTY)` | `result_ref.prefix(ref)` вклеивается между маркером шага и текстом ТЗ; дефолт `""` → пустая вставка |
| **чтение при чтении ряда** | `pc_orchestrator.py:4905` `_loc_step_ref(it)` → `result_ref.read_item(it)` | ряд очереди → `"<вид>:<указатель>"` \| `""` |

Непонятый адрес шаг **не роняет** (исход шага полю не подчиняется ни одной веткой), но и не
глотается молча: уходит `log.warning` с самим значением и списком видов. Собирает адрес
`make()`, и он **отказывает громко** (`ValueError`) — тихая потеря адреса и есть тот класс,
ради которого поле заводится.

## 4. Замок захода — три проверки, все обязательные

### A. Старый путь жив

* **20 сборок в гейте** (4 набора «номер/всего/текст/коррекция» × 5 способов сказать «адрес не
  назван»: `EMPTY`, `""`, `None`, `"   "`, вызов вообще без `ref`) — строка шага совпала с
  композицией ДО правки. **Расхождение 0 байт** (16 сборок той же формы в пробе).
* **Цепь целиком без адресов** прошла создание → взятие → закрытие → сводку: `[(1,3,done),
  (2,3,done), (3,3,done)]`, сводка «3/3 шагов done», карточек 0, маркера `[result_ref` нет
  ни в одном тексте.
* Полный гейт: **3388 → 3420 тестов, красных как было — две, те же самые**.

### B. Новое поле живёт (читаем НАЗАД, а не верим возврату)

Для каждого из 5 видов: `_loc_release(..., ref=make(вид, указатель))` → ряд **перечитан из
очереди** через `get_pending("new")` → `_loc_step_ref(row)` совпал с записанным **дословно**,
`parse` вернул исходную пару. Заодно проверено, что вставка не сломала ни одного живого
читателя строки: `_STEP_RE` даёт те же `(i, n, pid)`, `gate_selective.parse_step` → `(True,i,n)`,
`_loc_group_chains` по-прежнему собирает цепь, хвост ТЗ на месте.

Живые образцы (они же — фикстуры теста): `commit:a545ad2` ·
`file:docs/artifacts/2026-08-16-result-ref-pc.md` · `row:moderation_ipc.db:drafts:1278` ·
`brain:queue_state_pc §полоса ПК` · `service:pc_orchestrator PID 12345 старше HEAD a545ad2`.

### C. Отрицательный тест — поле ИНЕРТНО

Пять заведомо ложных адресов (нулевой коммит, несуществующий файл, чужая база, выдуманный узел
мозга, несуществующий сервис) повешены на КАЖДЫЙ шаг цепи 1→3. Отпечаток исхода — статусы и
номера шагов, текст сводки, карточки — **совпал с прогоном без адресов**. При этом маркер
доехал до исполнителя на **3 шагах из 3** (иначе тест доказывал бы лишь, что поле не
записалось), а единственная разница строк сводится к самому маркеру, байт в байт.

Инертность держится **устройством, а не обещанием**, и это проверяется двумя замками:
* `RESULT_REF_PURE` (`test_result_ref.py`) — ast-разбор: у модуля поля **нет рук**. Единственный
  импорт `re`; ни `os`, ни `subprocess`, ни моста, ни базы. Проверить адрес он НЕ УМЕЕТ.
  Инвариант проверен на 5 подлогах — каждый обязан его уронить.
* `test_C_the_field_is_inert_by_construction_not_by_promise` — ast по живому
  `pc_orchestrator.py`: `_loc_step_ref` **не вызван ни одной веткой демона**, а сам модуль зовут
  ровно двумя вызовами: `prefix` (запись) и `read_item` (чтение). Красный этот тест = поле
  подключили к решению; это отдельное решение владельца, а не побочный эффект правки.

## 5. Чего заход НЕ делал (граница держалась)

Вердикт шага не тронут; третий исход не введён; правила «нет адреса — нет зелёного» нет;
ни одно из 87 мест переписи не правлено; планировщик адресов по-прежнему не называет (в бою
`ref` не передаёт **ни один** вызов — поле сегодня пустое всегда и по всему пути). Боевая
очередь не пересоздавалась и не чистилась, `moderation_ipc.db` не открывалась, процессы и
сервисы не трогались, мост по сети не звался ни разу.

## 7. Найдено попутно (честно, без правки боевого кода)

* **Гейт полосы стреляет в боевой мост.** `process_new` на КАЖДЫЙ claim спавнит настоящий
  `queue_snapshot_pc.py --tick` (`_queue_snapshot`), и в тестах он уходил в живой мост —
  замечено по `ResourceWarning: subprocess … is still running`. Это тот же класс, что уже
  назван в этом файле для `_notify_chain_card` («спам-луп 14:25 14.07»), вторым местом.
  Закрыто **только в тестовой сцене** (`LocBase.setUp` мокает слепок); боевое поведение не
  менялось. Остаток: тот же спавн живёт в сценах `test_pc_orchestrator`.
* **Храповик неразбора красен на `main` до любой правки** — 2 падения, 947 против линии 845
  по пяти чужим файлам. Линию заход НЕ поднимал: свой вклад измерен отдельно и равен нулю.
* **Ворота грязного дерева поймали автора третий раз подряд.** Новый верхний импорт демона
  обязан стоять в `_ORCH_RUNTIME`; пропуск дал 3 красных теста (+1 наведённый в
  `test_pretool_guard.TestMarkerIsolation`, который гоняет те же модули подпроцессом). Добавлено
  `"result_ref.py"` — все четыре зелёные.
* **Замок метода про `julianday()` в этом заходе неприменим и не применялся:** разностей времени
  заход не считал ни одной. Поля `created`/`updated` очереди — текстовые ISO **моста**, а
  `julianday()` — функция SQLite; сравнение здесь дословное, строка со строкой.

## 8. Что должно совпасть с полосой VPS

Имя `result_ref`; тип «строка `<вид>:<указатель>`»; пустое = «не назван»; пять литералов видов
`commit|file|row|brain|service`; разделитель — первое двоеточие. Разойдётся имя или словарь
видов — два несовместимых формата в ОДНОМ листе очереди, и цена этого выше, чем польза поля.
