## 3. Что находка НЕ УЧИТЫВАЕТ — три вещи, каждая числом

### 3а. «Плюс git» — это ДРУГОЙ читатель, а не часть той же сборки

```
$ grep -n "read_only_marks\|changes_state\|git_moves" contour_digest.py contour_digest_run.py
contour_digest.py:467:def read_only_marks():
contour_digest.py:476:def changes_state(root_text):
contour_digest.py:483:    return not any(text.startswith(m) for m in read_only_marks())
contour_digest.py:558:        if changes_state(row.get("goal")):
contour_digest_run.py:226:def git_moves(root, since_ts, paths, runner=None):
contour_digest_run.py:406:        rows, why = git_moves(root, since, paths, runner=runner)
```

Метки живут в **чистой логике** и питают ровно одно число серии (`moved`). git живёт в **руках**
и питает раздел «оси». Между ними нет ни одного вызова: `series(rows, target, judged)` про git не
знает вовсе. Формулировка «сборка состояния через метки плюс git» склеивает два независимых
источника в один упрёк, и снятие меток раздел «оси» не упростит ни на строку.

### 3б. «Требует поддерживать отдельные маркеры ради одного агрегата» — опровергнуто

Метки существуют не ради сводки, и сводка — их читатель, а не заказчик.

```
$ grep -cE '(^|[^_A-Z])(CLAIM_MARK|TASK_MARK|ASK_MARK)([^_A-Z]|$)' \
      review_intake.py recon_auto.py contour_digest.py

recon_auto.py:4
contour_digest.py:2

$ grep -cE 'REVIEW_CLAIM_MARK|RECON_ASK_MARK' pc_orchestrator.py

```

Владельцы меток — `recon_auto.py` (4) и `review_intake.py` (3); их же по литералу читает
`pc_orchestrator.py` (3 литерала, 4 обращения) — по ним гарды опознают ряд-заявку и автозадачу.
Сводка держит **2 упоминания** и является ЕДИНСТВЕННЫМ их читателем-агрегатором. Убери сводку
целиком — все три метки останутся на месте, и ни один модуль не станет проще. Поддерживать их
ради одного агрегата полоса не начинала: агрегат пришёл к готовым меткам последним.

Мина замера, названная вслух: наивный `grep -c "ASK_MARK"` даёт `pretool_guard.py: 7` и
`pc_orchestrator.py: 9` — и все эти совпадения на самом деле `PRETOOL_ASK_MARKER`, к разведочным
меткам отношения не имеющий. Первый счёт этой разведки был именно таким и был неверен; числа выше
сняты уже с границей слова. Это ровно класс «grep по репо врёт» из проекции полосы.

### 3в. «Дешевле читать расписки цепочек» — на этой полосе НЕ выполнимо

Канал сам назвал свою неуверенность: «Достаточность расписок для всех требуемых статусов
