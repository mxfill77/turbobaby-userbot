## 1. Порядок блоков

Кэш включён — запрос такой:

```
system = [
  {text: SYSTEM_PROMPT (или SYSTEM_PROMPT_BOOK — по WA_AGENT_BOOK_READ)},
  {text: «ЗНАНИЯ КОМПАНИИ — снимки узлов мозга …»
         + «УЗЕЛ business_rules (123134 симв.):\n<текст>» + «УЗЕЛ faq (7788 симв.):\n<текст>»,
   cache_control: {type: "ephemeral", ttl: "1h"}}        ← префикс кэша: всё до этой отметки включительно
]
messages[0].content =  СЕГОДНЯ · ВОЗРАСТ ЗНАНИЙ (business_rules — снят N мин назад; faq — …)
                       · УРОКИ ЛЮДЕЙ · ЦЕНА · НАЛИЧИЕ / АРЕНДА КЛИЕНТА · НУЖЕН ЧЕЛОВЕК
                       · ИСТОРИЯ ПЕРЕПИСКИ · КЛИЕНТ СЕЙЧАС
```

- **Префикс меняется только со сменой узла.** Возраст («снят N мин назад») ушёл из префикса в блок «ВОЗРАСТ
  ЗНАНИЙ» сообщения. Причина непрочтения («мост ответил отказом (…)») тоже ушла туда: в префиксе у непрочитанного
  узла только «НЕИЗВЕСТНО — не прочитан (причина — в блоке «ВОЗРАСТ ЗНАНИЙ»)». `Knowledge` перечитывает узлы раз в
  10 мин. Тот же текст даёт тот же префикс, и кэш читается (тест `second_draft_in_ttl_reads_cache`: чтений узлов 2+2,
  префикс равен байт-в-байт).
- Правило 5 инструкции («только из узлов знаний ниже») осталось верным: знания стоят сразу за инструкцией.
- **Уроки — после префикса.** Они меняются при «Сделать правилом»/«Откатить» и весят до 8 000 симв., а
  `business_rules` — 123 тыс.
- **Напоминание** (`build_followup`) — то же правило со своей инструкцией `FOLLOW_SYSTEM_PROMPT`. Поэтому у него свой
  префикс и своя запись в кэш: инструкция стоит впереди знаний (§6 п.4).
- Выключен — `system` строкой, узлы с возрастом в сообщении, порядок прежний (тест `cache_off_request_as_before`:
  запрос равен запросу адаптера без параметра `cache`).

## 2. Срок кэша — 1 час

Выбор — **«1h»** (по умолчанию для `WA_AGENT_CACHE=1`); «5m» можно задать явно. Обоснование — в долях цены входа
префикса `c`. Без кэша черновик стоит `1c`, попадание — `0.1c`, промах — `1.25c` при 5 мин и `2c` при 1 ч.

- Кэш 5 мин выгоднее, чем без кэша, только если промахов меньше **78 %** (`1.25p + 0.1(1−p) < 1`). Кэш 1 ч — если
  промахов меньше **47 %** (`2p + 0.1(1−p) < 1`).
- Поток: 15–20 черновиков в сутки (WAAGENTLIVE0110: 15 серий входящих за сутки, 6 номеров, медиана ответа с
  телефона 27,5 мин). В 13 активных часах средняя пауза — 39–52 мин. По Пуассону паузу больше 5 мин имеют
  **88–91 %** вызовов, больше 60 мин — **21–32 %**. Добавим первый вызов дня: промахов при 5 мин ≈ 89–92 %, при 1 ч
  ≈ 25–36 %.
- Значит, 5 мин здесь хуже, чем без кэша (+11–15 % в сутки), а 1 ч лучше (§5). Живые серии кучнее Пуассона:
  клиент отвечает в ту же беседу. Поэтому для 1 ч это оценка снизу.
- Чего не знаем: живого распределения пауз между черновиками. Архив WhatsApp этот заход не читал (запрет).
  Узнаем после включения — по строкам «цена:» в журнале (доля `чтение из кэша > 0`).

## 3. Цена черновика по usage — журнал, сводка, учёт трат

- `paid_call` читает из usage `input_tokens` (вход после кэша), `cache_creation_input_tokens` с разбивкой
  `ephemeral_5m/1h`, `cache_read_input_tokens` и `output_tokens` (`usage_of`). `cost_of` считает цену по
  `spend_ledger.cost_usd`: вход × P + запись 5 мин × 1.25P + запись 1 ч × 2P + чтение × 0.1P + выход × Pout. Цены
  моделей берутся из общей с Splinter таблицы. Запись без разбивки по сроку считается по дорогому (2×), чтобы учёт
  не занижал.
- **Журнал** — после каждого вызова, до разбора ответа (деньги потрачены и при не-JSON):
  `черновик: цена: вход N · запись в кэш W (5 мин a, 1 ч b) · чтение из кэша R · выход O → $X (без кэша $Y)`,
  у напоминания — `напоминание: цена: …`. Только числа (тест: ни текста клиента, ни номера).
- **Сводка службы** (раз в 5 мин) дописывает итог с рестарта: `модель: вызовов K · вход … · запись в кэш … · чтение из
  кэша … · выход … · $X (без кэша $Y)`. Без адаптера (черновики выключены) сводка прежняя.
- **Учёт трат Splinter** (`spend_ledger.meter`) раньше брал только `input_tokens` и `output_tokens`. С кэшем это
  занизило бы траты: запись и чтение в `input_tokens` не входят. Теперь в учёт уходит вход в токенах по цене входа
  (`in + 1.25·w5 + 2·w1h + 0.1·r`), и доллары совпадают. Без кэша это прежний `input_tokens` (тест).
- Строка старта службы: `кэш промпта (WA_AGENT_CACHE): вкл, срок 1h — …` или `выкл — запрос модели как раньше`.
