## П.2 — запись в реестр (commit `ffd0abd1`)

* Реестр тот же, `pc_orchestrator.cards_ledger.jsonl`. В нём новое событие `пуш`, одна строка на
  **доставленное** сообщение: `{ts, event, rod, class, op, src, channel, mid}`. Текста сообщения в
  строке нет. Строка пишется только после того, как Telegram вернул номер.
* **Признак идёт из места события по структуре, а не по словам.** Гард зовёт отправителя ключом
  `--guard-push <red|top> <класс>` (`guard_push_argv`). `dispatch_notify` по этому ключу и ветке
  `--hook notification` решает, откуда пришло сообщение. `push_row` выводит `op` только из источника:
  «гард-пуш» даёт True, «хук-notification» даёт None, любой другой источник тоже None. Параметров
  `op` и `text` у функции нет.
* **Слова признак не поднимают, это закреплено тестами.** Текст карточки гарда вместе с
  «Класс операции: env», «NEEDS_APPROVAL» и «ВЫСШАЯ ЦЕНА», отправленный без ключа, строки не
  создаёт вовсе. Те же слова в `🔔` оставляют `op=null`.
* Боевой вызов и проверка различаются в коде: без явного пути строка идёт в боевой реестр только
  при боевой точке входа (замок 1, `live_send_verdict`), а проверка пишет в путь, который назвала
  сама. Откат прежний: `CARD_LEDGER_OFF=1`.
* Честный предел: ключ `--guard-push` может набрать руками любой процесс с шеллом. Это граница
  против шума, как у маркера гарда, а не против подделки.
