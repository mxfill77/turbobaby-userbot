## 3. Какие правила это порождали — поимённо

1. **`_RED_CMD`, строка с `(ssh|scp|sftp|nc|ncat|telnet)` → `network`.** Признак **подстрочный**:
   слово где угодно в строке красит команду. Под него попадали:
   - рабочий канал `ssh -i ~/.ssh/turbobaby_vps root@5.223.94.179 …` — **148 карточек**, при том
     что в `settings.json` он разрешён отдельным правилом;
   - `Get-Command ssh -ErrorAction SilentlyContinue` — просто поиск бинарника;
   - `$K = Join-Path $HOME ".ssh\turbobaby_vps"` — путь к ключу;
   - слово «SSH» **внутри текста записи в журнал**.
2. **`_is_pure_config_read`.** Требовала, чтобы команда **начиналась** со смотрелки, поэтому
   `python -c "import json; json.load(open('…/.claude/settings.json'))"` считался правкой конфига.
3. **`ask`-правила `Bash(ssh *)`, `Bash(scp *)`, `Bash(sftp *)`** в проектном слое — тот же шум,
   но уровнем выше: шаблон не умеет отличить свой хост от чужого.
4. `delete`/`env` — уже вылечены сегодняшним `ec6d8ee` («боевые слова в данных»): из 21 карточки
   `delete` осталась одна.

## 4. Что сужено

Тот же принцип, что и весь сегодняшний день: **судим по действию, а не по подстроке.**

1. **`_net_cmd_kind(cmd)`** — сетевой инструмент должен стоять в **командной позиции сегмента**
   (структурно, через `_cmd_index`/`_base`). Дальше:
   `ssh`/`scp`/`sftp` к **своей** машине (явный список + `Host` из `~/.ssh/config`) → вопроса нет;
   `ssh` к **чужому** хосту и `curl`/`wget`/`iwr`/`irm`/`nc`/`telnet` → красное, как было.
2. **`_is_pure_config_read`** — красное это **намерение записи** (`>`/`>>`, `Set-Content`,
   `Add-Content`, `Out-File`, `New-Item`, `Copy-Item`, `Move-Item`, `cp`, `mv`, `sed -i`,
   `open(...,'w')`, `.write(`, `json.dump`). Зелёное требует **обоих** условий: есть признак
   чтения **и** нет признака записи — поэтому `echo '{}' > .claude/settings.json` остаётся красным.
3. **`.claude/settings.json`** — из `ask` убраны три правила: `Bash(ssh *)`, `Bash(scp *)`,
   `Bash(sftp *)`. Решение отдано структурному гарду. Всё остальное в `allow`/`ask`/`deny` не
   тронуто, `bypassPermissions` не включался.

### Дыра, которую поймал существующий тест

Первая редакция структурного разбора не видела команду **после ключевого слова шелла**:
`until curl -s https://x; do sleep 5; done` переставал краснеть, потому что в командной позиции
стояло `until`. `test_until_wait_does_not_whitelist_red` упал немедленно:

```
AssertionError: Tuples differ: ('defer', 'unknown') != ('ask', 'network')
```

Починен **код, а не ожидание**: `until/while/if/then/do/done/else/elif/exec/command` добавлены к
обёрткам, за которыми ищется настоящая команда.
