## 3. Шаг 3: правка — тот же ПРИЗНАК, что у исполнителя, а не ещё одно окончание имени

Задание прямо запрещает «дописать ещё одно окончание имени в список». Не дописано ни одного:
из функции признак имени **убран целиком**, а на его место встал ровно тот, что уже стоит у
исполнителя, — регулярка по тексту работы, взятая **посимвольно** из живого
`orchestrator_daemon.py` (правка 07.09):

```python
_RE_FAST_TASK = re.compile(r"^\s*задача\b", re.I)   # работа, ОБЪЯВИВШАЯ СЕБЯ быстрой


def _stall_threshold_sec(it):
    """…"""
    if _is_pc_item(it):
        cap = _env_sec("PC_STEP_TIMEOUT", 3600)
    elif _RE_FAST_TASK.match(str((it or {}).get("task_text") or "")):
        cap = _env_sec("TASK_TIMEOUT", 600)
    else:
        cap = _env_sec("TASK_TIMEOUT_DEV", 2700)
```

Ветка полосы pc оставлена нетронутой сознательно: её исполнителем `_task_timeout` не судит вовсе
(шаги ПК идут через `process_pc_chains` с `PC_STEP_TIMEOUT`), и зеркалить там нечего.

**Слово `endswith` в функции осталось ровно одно — в ДОКСТРОКЕ**, где сказано, чем порог судил
до 08.09 и почему имени больше нет. В исполняемой части его ноль (проверено срезом функции после
докстроки, §6). Это названо здесь потому, что `grep -c endswith` по функции даёт `1` и читается
как «не долечено».

**Механизм доставки: точечный патч по двум якорям + коммит с ЯВНЫМ перечнем файлов.** Прибор —
`tmp/task200_mirror/patch_stall.py` (ПК), уходит на сервер потоком в stdin, на сервере после себя
не оставляет ничего. Встроено: якоря обязаны найтись **ровно по одному разу** (голова
`def _stall_threshold_sec(it):`, хвост `    return cap + STALL_GRACE_SEC`) — иначе `СТОП` и ноль
записей; сухой прогон первым (прогнан, печатает «было/станет», файлов не пишет);
идемпотентность (`_RE_FAST_TASK` в файле → «правка уже стои́т», выход); бэкап ДО записи в
`/root/tmp/task200-devbot-backup/` (существующий файл не перезаписывается); обратное чтение
каждого файла со сверкой с записанным.

Замер прибора: `devbot.py` **2984 → 3001** строк, sha256 `9a2d9c273ed0df17…` →
`f63fefc53b13c572d1df2d164a3bc91675cde8f7dfa8cdb1f29eae6b2355b5d3`.

  реапера по `_DEV_SUFFIXES`. Не тронут по прямому запрету задания: файл входит в шесть файлов
  незавершённой работы 172. Закрыть его сможет только тот заход, которому разрешат этот файл.
- **Ложные карточки прошлого посчитать нечем, и я их не считал.** Текст тревоги уходит в телеграм,
  а в `splinter.log` не пишется (`grep "Задача.*зависла"` → 0 совпадений за весь лог). Поэтому
  «тревога больше не ложная» доказано **кодом и пробой** (§4: расхождений было 3, стало 0), а не
  подсчётом карточек. Утверждать «столько-то ложных карточек снято» этот заход права не имеет.
- **Первый живой ряд под новым порогом не наблюдался** — заход задач не создавал и очередь не
  трогал. Первое реальное задание длиннее 12 минут и станет замером.
- **Быстрая ветка «задача:» недостижима для рядов девбота** — постановщик срезает командный
  префикс перед очередью (`_try_enqueue`), и маркер до порога не доезжает. Это ровно так же у
  исполнителя, поэтому зеркало верно; но сама ветка мертва у обоих, и чинится она правкой
  постановщика — отдельное решение.
- **Коммит не запушен**, полный предпушевой гейт не гнан: гнался один тест темы (§5). Отгрузка —
  отдельный круг.
- **Ничего, кроме девбота, не поднято и не погашено** ни одной командой.
