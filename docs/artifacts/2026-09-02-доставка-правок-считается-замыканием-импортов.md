### Новое: О6 в слое ожиданий

`expectations_pc.code_state` / `code_states` / `_o6` (чистое решение, импортов у модуля
по-прежнему ровно два) + `expectations_pc_run.code_facts` (руки: считают замыкание тем же
`client_contour.closure(..., cut=())`, снимают mtime файлов замыкания и момент запуска процесса
пробой `OpenProcess(QUERY_LIMITED_INFORMATION)` по номеру из лока).

Предмет — разность двух чисел: `newest` (самая свежая mtime среди файлов замыкания) минус
`started` (момент запуска процесса). Порог **30 мин** = 64× измеренной задержки доставки у демона
(28 с: 02.09 22:35:30 «гоняю гейт» → 22:35:58 новый процесс) и ровно три периода наблюдателя.
Откат — `EXPECT_PC_CODE_MIN=0`, ветка умирает целиком до чтения фактов.

**Почему mtime, а не время коммита.** Python грузит модули С ДИСКА, а не из истории git; предмет
называется «на диске новее, чем в памяти» буквально. Незакоммиченная правка рабочего дерева этим
признаком видна — тот же урок 28.07.2026 («рестарт применяет состояние диска целиком»). Ни одной
ветки с git в О6 нет.

**Ключ эпизода — момент ЗАПУСКА процесса, а не свежесть файла.** Ключ по mtime давал бы новую
заметку на каждый коммит в любой из 63 файлов замыкания бота (шум), ключ по возрасту — новую
заметку каждые десять минут. Момент запуска неподвижен ровно столько, сколько длится одно и то же
молчание. Закреплено `test_the_verdict_is_recomputed_every_run_and_never_goes_silent`: десять
подряд прогонов дают десять вердиктов и ОДИН ключ.
