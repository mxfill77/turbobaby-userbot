# Зеркало класса VPS на ПК: удаление вне временных каталогов проходило молча

**Дата:** 2026-08-03 · **Полоса:** ПК (`pretool_guard.py`) · **Основание:** серверный коммит
`53ce1a9`, артефакт `docs/artifacts/2026-08-03-delete-outside-tmp` (полоса VPS). В основании
названо зеркало: снимок ПК-гарда `/root/_twotails_20260726`, строки 816–818 — «ранний green,
не-python команда уходит в defer и решает allow-слой». Координаты не давались; место найдено
разбором живого гарда и подтверждено прогоном.

---

## 1. Где была дыра (замер, а не чтение кода)

Прогон `decide_for_role` по фикстурам на HEAD **до** правки. Полная матрица —
`tmp/delhole-20260803-k1/matrix.txt`, здесь итог: **12 форм сноса файла репозитория проходили
молча** (`defer` = гард выходит `sys.exit(0)`, а `.claude/settings.json` разрешает `Bash(*)` —
значит команда исполняется без вопроса).

| форма | вид до правки | почему молчала |
|---|---|---|
| `rm suggest.py` | `defer/delete` | `_is_mass_delete` = False: одна цель |
| `rm docs/artifacts/2026-01-01-x.md` | `defer/delete` | то же |
| `del pc_agent.py` | `defer/delete` | то же |
| `Remove-Item -Force D:/turbobaby-bot/suggest.py` | `defer/delete` | то же |
| `ri docs/ENV_PLAYBOOK.md` | `defer/delete`, **объект пуст** | то же + `_extract_delete_target` не знает алиас `ri` |
| `unlink suggest.py` | `defer/unknown` | имени нет в `_DEL_CMDS` → вид не назначен, а `unknown` доктринально не красный |
| `shred -u suggest.py` | `defer/unknown` | то же |
| `find docs -name "*.md" -delete` | `defer/unknown` | действие — ПРЕДИКАТ, не имя команды |
| `find . -name "*.pyc" -exec rm {} \;` | `defer/unknown` | то же |
| `git rm suggest.py` | `defer/word_delete` | глагол не в командной позиции → `_verb_acts` False, следом **ранний зелёный шорткат** `_RE_READONLY_SHELL` (в нём стоит имя `git`) |
| `git rm -r --cached docs` | `defer/word_delete` | то же |
| `git rm suggest.py && git commit -m x` | `defer/word_delete` | то же |

Три разные причины, один результат. Третья — ровно тот «ранний green» из основания.

**Находка серверной полосы подтверждена здесь дословно.** Общий скан-текст режет позиционные
аргументы скриптов и вместе с ними съедает САМО ДЕЙСТВИЕ:

```
CMD : venv/Scripts/python.exe tools/clean.py --root docs -delete "*.md"
SCAN: venv/Scripts/python.exe tools/clean.py
```

Предикат `-delete` и маска исчезают целиком. Поэтому у класса **свой разбор сегментов по СЫРОЙ
команде** (`_delete_walk`), а не общий `_scan_text`.

- **косвенность невидима**: `python some_script.py` логируется одной строкой, `os.remove` внутри

## 3. Что сделано

Форма — серверная, не своя: **гард судит ЦЕЛЬ, а не глагол.**

- `_delete_walk` — ЕДИНСТВЕННЫЙ разбор класса, по СЫРОЙ команде, посегментно и структурно.
  Знает `rm/del/erase/rmdir/rd/remove-item/ri/unlink/shred`, `git rm`, `find … -delete`,
  `find … -exec rm`. Возвращает `_DelWalk(acts, targets, recurse, mask, provider)`.
  `_delete_scan` остался фасадом на него — второго списка форм в модуле нет.
- `_delete_stays_red` — вся доктрина одной функцией. **Зелёное ровно одно:** КОНКРЕТНЫЕ пути во
  временных зонах (`tmp/`, `%TEMP%\claude\**`). Красное, fail-closed: маска, цель вне зон,
  корень репо, неназванная цель.
- Ветка в `_decide_bash_body` — **ниже всех красных ветвей и ВЫШЕ зелёных шорткатов**: именно
  она снимает «ранний green» для `git rm`/`unlink`/`shred`/`find`.
- `DEL_TARGET_UNKNOWN` в `_UNNAMED_OBJ`: удаление — высший вид, поэтому «действие разобрано,
  цель не названа» (`find … | xargs rm`, `Get-ChildItem … | Remove-Item`) кончается **отказом**,
  а не подтверждаемой карточкой «удалить неизвестно что».
- `_is_mass_delete` **снят вместе с посылкой**, а не переименован: концепт «массовое удаление»
  решения больше не принимает. Тест сторожит, что имя не вернулось.

Объект карточки = путь, число = сколько целей (`_card_fields`, уже читало `_delete_scan`).

### Две находки, всплывшие по дороге

1. **`Remove-Item Env:\X` — не файл.** Живых строк в журнале 5 за неделю (headless-прогоны
   тестов: `$env:STEP_SELFHEAL='1'; … ; Remove-Item Env:\STEP_SELFHEAL`). Правка «цель вне зон →
   красное» покрасила бы их все. Развилка сделана ПО ЦЕЛИ, как и весь класс: элемент провайдера
   PowerShell файлом не является (`_RE_PS_PROVIDER`). Файл в той же строке краснеет.
2. **POSIX-`shlex` съедал обратный слэш.** `Remove-Item D:\turbobaby-bot\tmp\x` приезжал целью
   `D:turbobaby-bottmpx` — путь, не совпадающий ни с одной зоной. На этой машине основной шелл
   PowerShell, то есть так набирается БОЛЬШИНСТВО путей: уборка в `tmp/` из него считалась
   удалением вне временных каталогов. Разбор переведён на `posix=False`.

**Два кейса переехали из `FALSE_CASES` в `TRUE_RED`** — `Remove-Item …\cowork_log.spool -Force`
и `rm -f tmp_guard_cards.json`. Это не смягчение теста, а смена доктрины: обе команды сносят
файл в КОРНЕ РЕПО (`tmp_guard_cards.json` начинается на `tmp_`, но в каталоге `tmp/` не лежит),
а прежняя посылка «один файл ⇒ карточки нет» и была дырой класса. Сама находка случая 6
(`-Force` — не рекурсия) осталась под сторожем: проверяется прямо, тестом
`test_force_is_still_not_recursion`.

**Одно поведение ослаблено, и это названо честно:** рекурсивная уборка в `tmp/` с обратными
слэшами (`Remove-Item D:\turbobaby-bot\tmp\bridge -Recurse -Force`) была красной и стала
зелёной. Она была красной ИЗ-ЗА порчи пути в `shlex`, а не по доктрине; доктрина «уборка в
`tmp/` зелёная» не менялась — разбор наконец ей соответствует. Обход через `..` доверия
по-прежнему не получает.

## 5. Границы и остатки

- Клиентский контур, реестр каналов, замок происхождения, изоляция проб, объектный гейт и
  дедуп — **не тронуты**.
- **`python script.py --root docs -delete "*.md"` красным НЕ стал** и не должен: аргумент чужого
  скрипта — данные, гард не знает, что скрипт делает. Находка VPS про съеденный предикат учтена
  тем, что СВОЙ класс читает сырую команду; расширять её на argv любого скрипта — путь к ложным
  карточкам на каждом запуске.
- **Ложное срабатывание, найденное по дороге и НЕ чинившееся:** `pretool_guard.log:3383` —
  `deny|delete` на read-only конвейере `Get-Content … | ForEach-Object …`, чей ТЕКСТ содержал
  имена глаголов удаления. Причина — `_verb_acts` fail-safe при неразобранных кавычках
  PowerShell. Чинить в этом заходе не стали: любая правка там ослабляет красное, а класс —
  отдельный («текст вместо действия» в PowerShell-конвейерах). Точка касания: `_verb_acts`,
  ветка `except` вокруг `shlex.split`.
- Полоса **VPS в этот заход не тронута** (на сервер не ходили) — там класс уже закрыт `53ce1a9`.
