## 4. Забор Честертона (пункт 4): срок НУЖЕН, и охраняет он ЦЕПЬ

```
pc_orchestrator.py:4524  _LOC_OPEN = ("new","in_progress","needs_approval","approved")  # НЕЗАКРЫТЫЙ статус шага

pc_orchestrator.py:5115  open_steps = [...] ; if open_steps: return   # вотчдог цепей: «цепь движется» — не наш случай
```

Три сторожа промахиваются мимо неё ПО ПОСТРОЕНИЮ: `process_stuck_singles` судит только
`in_progress` (`:3433-3439`), `_loc_watchdog_tick` просыпается только когда открытых шагов НЕТ

вечно висящую цепь, у которой нет наблюдателя ни одного.** Второе, что он охраняет, — свежесть
разрешения: «да», пришедшее через сутки, запустило бы красную операцию по дереву, которое за
эти сутки уехало (на полосе 25 прогонов из 184 длиннее самого срока, self-update перезапускает
демона на новом коммите — 03:44:47 в окне 78 это видно дословно).

**Но охраняемого им имущества в этих семи случаях НЕ БЫЛО.** Все 36 карточек корпуса, чьё
происхождение прослеживается по снимку очереди, — `from=Filipp-328-dev`, то есть **одиночки, а не
шаги цепи** (остальные 15 из 51 — вне снимка: старая нумерация до 28.07 либо после переписи). Для
одиночки «висящая карточка» не блокирует ничего: `process_new` (`:2856`) читает только полосу
`new` и клеймит следующую задачу независимо от того, сколько рядов ждут «да».

Забор поставлен верно и стои́т не там, где ходят. Снимать его нельзя — но и оправдывать им смерть
одиночки нечем.
