## 2. Хранилище и поля

**Хранилище:** каталог `topic_feed/` рядом с модулем (`/root/turbobaby-manager-bot/topic_feed/` после
применения; в `.gitignore`). На каждую тему свой файл `<chat>_<topic>.jsonl`, одна строка JSON на
событие. Файл **только дописывается**: удаления и перезаписи нет ни в одной ветке кода. Подмена
каталога — `TOPIC_FEED_DIR`. Под метками тестов (`ORCH_TEST_MODE`, `PRETOOL_NOPUSH`, `PRETOOL_TEST_RUN`,
`PYTEST_CURRENT_TEST`) каталог свой на процесс, `/tmp/topic_feed_test_<pid>`, как у файла вопроса о
пробеге из 0088. Поэтому живой гейт боевую ленту не засоряет. Запись — один `open(…, "a")` без
блокировок; sqlite и `memory.db` не трогаются.

| поле | что |
|---|---|
| `chat`, `topic` | чат и тема (тема None → 0) |
| `mid` | id сообщения Telegram (у вопроса бота — id отправленного; у разбора фото — id первого фото) |
| `ts` | время: у входящего — время сообщения в Telegram, у прочих — время записи |
| `role` | `staff` · `pym` · `owner` · `bot` (по `PYM_USERNAMES` / `OWNER_USERNAMES` / `is_bot`) |
| `kind` | `text` · `photo` · `button` · `bot_ask` (вопрос бота) · `bot_msg` (прочее сообщение бота) · `record` (запись в учёт) · `vision` (разбор фото) |
| `reply_to` | на какое сообщение реплай; служебное «тема создана» реплаем не считается |
| `text` | краткий текст, не длиннее 300 символов |
| по виду | `hint` (вид подсказки L/I/A1…), `bike`, `source`; учёт: `what`, `km`, `questioned_km`, `done`, `failed`; фото: `mileage`, `conf`, `photo_kind`, `n`, `damage`; `album` |

## 4. topic_context: состав и объём

Порядок блока: шапка «ЛЕНТА ЭТОЙ ТЕМЫ», затем байк темы. Дальше **открытые вопросы**: файл вопроса
о пробеге из 0088 (`_MILEAGE_Q`, с id сообщения-вопроса и возрастом) и словари процесса
`_PENDING_MILEAGE`, `_SOFT_ODO_PENDING`, `_ODO_LOWER_PENDING`, `_BATCH_ODO_PENDING`,
`_PENDING_CORRECTION`, `_PENDING_WORKS`, `_AWAITING_REPLY`, `_ACT_GATE_PENDING`. Затем ТО-заявка
(`_sp_open` → `service_pending_get`), последний подтверждённый пробег (событие `record`, иначе
`_LAST_RECORDED_KM`), строка «ЭТО СООБЩЕНИЕ — РЕПЛАЙ на #id: …» и события: Пхукет, роль, вид, `#id`,
`↩#id`, суть. В конце — одна строка-указание: не переспрашивать отвеченное, ответ на открытый вопрос
считать ответом.

**Объём — числом символов:** предел `TOPIC_CONTEXT_MAX` = 6000. Сверх него отрезаются самые старые
события. Замеры теста:

| случай | событий | символов |
|---|---|---|
| NMAX 155 BLACK 8952 (9 фото + разбор + вопрос + реплай) | 12 | **1656** |
| 45 сообщений по 280 символов | 17 из 30 (предел символов) | **5951** |
| пустая тема (1 событие) | 1 | 497 |

Сбой чтения ленты даёт шапку «НЕ ПРОЧИТАНА (сбой хранилища) — событий не знаю, не «их нет»», а не
«событий 0». Сбой сборки целиком даёт `None`: мозг получает прежний контекст.

## 5. Выключатели и отказоустойчивость

- `TOPIC_FEED_CONTEXT=0` → `topic_context` возвращает `None`, `context_note` мозга прежний **байт в
  байт**. Проверено двумя способами. (1) Против той же сборки с подменённым пустым контекстом.
  (2) Против **кода без ленты**: отдельный процесс на снимке 56bf482 → 1683 символа, равны.
- `TOPIC_FEED=0` → лента не пишется. По умолчанию оба флага включены. Флаги читаются из окружения
  процесса, поэтому смена значения = строка в серверном `.env` + перезапуск.
- Сбой ленты не роняет и не задерживает обработку: каждая точка в `try`, промах = одна строка журнала
  `🧵 лента темы: … не удалось` (не чаще раза в минуту). Тест D: каталог ленты лежит «под файлом», и
  сообщение всё равно обработано за **0.003 с**, перехват вызван, мозг вызван, строка журнала одна.
- Промах читателя — `None`, а не пустое (§6, «пойманное»).

## 7. Как применить вместе с 0088 одним перезапуском (серверная полоса, словом владельца)

Ветка стоит прямо на живом `main` 8dc61b4 и содержит обе правки: 0088 как `56bf482` и ленту как
`9e86d27`. Ветку 0088 `a7f81c3` отдельно применять **не нужно и нельзя**: это та же правка с другим
хешем.
```
cd /root/turbobaby-manager-bot
git rev-parse --short HEAD                      # обязано быть 8dc61b4, иначе остановиться и пересобрать ветку
git fetch origin splinter-topic-feed-0110
git merge --ff-only FETCH_HEAD                  # HEAD → 9e86d27
venv/bin/python3 gate.py                        # живой гейт со своим .env
systemctl restart splinter.service              # ОДИН рестарт: self-update у сервера нет
```
**Оговорка про гейт.** В зеркале красный `test_blind_readers` пришёл с самим 8dc61b4. Если живой гейт
на 8dc61b4 тоже красный, то красный он не из-за этой ветки. Живого гейта я не гонял (он запускается из
живого дерева со своим `.env`) — НЕИЗВЕСТНО.

**Проверка после перезапуска.** Первое сообщение темы обслуживания даёт строку
`🧵 лента темы: каталог /root/turbobaby-manager-bot/topic_feed`. Каждое обращение к мозгу в теме
даёт `🧵 контекст темы → мозг: событий N, открытых M, символов K`. Строки 0088 описаны в
SPLODOREPLY0110 §5.

**Цена перезапуска.** Стираются буферы памяти (фото, ожидания, кнопки отмены, `_TOPIC_FEED` ворот).
Лента начнётся с первого сообщения после перезапуска: истории до него в ней не будет.
