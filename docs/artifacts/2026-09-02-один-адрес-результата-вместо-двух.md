# Один адрес результата вместо двух: ворота ящика Штаба читают ту же форму, что судья закрытия

2026-09-02-один-адрес-результата-вместо-двух

**Коммит: `1ff8c02`** (`shtab_box.py`, `test_shtab_box.py`, `pc_orchestrator.py`,
`docs/artifacts/2026-09-02-ящик-заданий-штаба.md`). Ось: этап 3, слой ожиданий. Замер и правка —
02.09.2026.

## Премиса подтверждена первым действием: форм было ДВЕ, и пересечение их ПУСТО

Задание требовало проверить чтением кода. Проверено — и подтвердилось дословно.

| кто | что он считает адресом | где |
|---|---|---|
| **ворота приёма ящика** | канон Штаба `[result_ref: <вид> <указатель>]` | `shtab_box.check` → `result_ref.is_named(result_ref.read(body))` |
| **судья закрытия** | русская проза `АДРЕС РЕЗУЛЬТАТА: файл в <папка> за <дд.мм> со словами <слова>` (и вариант с прямым путём) | `done_judge_pc.read_address` → `_RE_ADDR_PROSE` / `_RE_ADDR_PATH` |

Замер (`_scratch_addr_canon_0902/probe.py`, живые модули репозитория):

```
образец из документации ящика    ворота: берут       | судья: АДРЕСА НЕ ВИДИТ
тот же блок в форме судьи        ворота: НЕТ (no_address) | судья: адрес прочитан
```

**Пересечение двух форм пусто.** Следствие не «неудобно», а по построению: задание, прошедшее
ворота ящика, приходило к ступени C с вердиктом «адрес результата не назван задачей —
доказывать нечем», то есть закрывалось НЕДОКАЗАННЫМ при любом исполнении и попадало в реестр
вердиктов безадресным — ровно тем классом, ради которого реестр 02.09 и заводили (замер того
захода: серия 18 подряд, доказано судьёй 5, закрыто без адреса 13).

Третья половина премисы — про кириллицу — тоже верна: у формы с прямым путём набор символов
пути латинский (`[0-9A-Za-z_][0-9A-Za-z_./-]*\.[0-9A-Za-z]+`), и на имени
`2026-09-01-findings-видны-в-теме-Аудит.md` судья слеп.

## Какая форма остаётся единственной и почему — три свойства, ни одного «на вкус»

**Остаётся ФОРМА СУДЬИ, вид «папка + дата + слова»:**

```
АДРЕС РЕЗУЛЬТАТА: файл в <папка> за <дд.мм> со словами <слова этого шага>
```

| довод | число или свойство |
|---|---|
| **канон `result_ref` не несёт ДОКАЗЫВАЮЩИХ СЛОВ** | `result_ref.parse("[result_ref: file docs/artifacts/2026-09-02-x.md]")` → `('file', 'docs/artifacts/2026-09-02-x.md')`: полей ровно два, поля «слова» нет вовсе. Научи мы судью читать этот маркер — он ответил бы дословно `адрес без слов: доказывать таким адресом нечего` (проверено вызовом `done_judge_pc.judge`). Расхождение переехало бы с ворот ВНУТРЬ суда и стало бы незаметнее |
| **кириллица в именах наших артефактов — норма, а не исключение** | 37 из 52 сентябрьских файлов `docs/artifacts` (**71%**); по всему каталогу — 37 из 467. На таких именах форма с прямым путём читается как «адреса нет», а форма «папка+дата» имени файла НЕ РАЗБИРАЕТ вовсе: снимок за 02.09 видит **21 файл, из них 20 кириллических** |
| **живая форма полосы — эта же** | корпус живых постановок (33 пакета `docs/review_outbox` + `docs/review_inbox`): проза `АДРЕС РЕЗУЛЬТАТА` — **15 файлов**, прямых путей — **0**, `[result_ref:` — **1**, и тот единственный случай — цитата документации САМОГО ЯЩИКА, а не адрес чьего-то шага |

Обратный вариант (научить судью читать `result_ref`) отвергнут первым же доводом: он даёт форму,
которую судья прочитает и всё равно не сможет ею доказать.

## Что стало: ворота спрашивают САМОГО судью, а не свою копию его правила

```python
addr = done_judge_pc.read_address(body)          # ЧУЖАЯ функция, не наша регулярка той же формы
if not addr:      return False, "no_address", "…Форма одна: %s" % ADDRESS_FORM
if not addr.get("words"):
                  return False, "no_address", "адрес назван без слов: доказывать таким адресом нечего…"
```

Обе ветки — дословные отказы судьи, перенесённые ко входу. Разойтись формам теперь нечем: второго
экземпляра правила не существует. Тот же урок, по которому ящик берёт счёт суток у ступени E, а не
пишет свой.

| | было | стало |
|---|---|---|
| ворота приёма | `result_ref.is_named(result_ref.read(body))` | `done_judge_pc.read_address(body)` + его же требование слов |
| импорт чистого модуля | `import result_ref` | `import done_judge_pc` (у него берётся РОВНО `read_address` — список разрешённого держит тест) |
| образец в документации ящика | `[result_ref: file docs/artifacts/2026-09-02-имя.md]` — форма, на которой судья слеп | `АДРЕС РЕЗУЛЬТАТА: файл в docs/artifacts за 02.09 со словами <слова…>` — константа `shtab_box.ADDRESS`, проходящая наши же ворота (тест) |
| отказ ворот | называл канон `result_ref` и пять его видов | называет ЕДИНСТВЕННУЮ форму словами (`ADDRESS_FORM`) |

`result_ref` из репозитория никуда не делся и каноном адреса ШАГА быть не перестал — ящик просто
перестал его звать. Правку списка зависимостей демона это не потребовало: и `result_ref`, и
`done_judge_pc` — верхние импорты демона (`_ORCH_RUNTIME`), то есть накрыты воротами грязного
дерева строже остатка; комментарий реестра приведён к факту тем же коммитом.

## Отрицательные тесты — обе половины, а не одна

Задание требовало проверять и то, что чужая форма НЕ берётся, и то, что верная берётся И судится.
Проверять одну половину мало: расхождение убивало задачу не на воротах (их она проходила), а в суде.

| проверка | что требует |
|---|---|
| `test_NEGATIVE_the_foreign_form_of_the_address_is_not_taken` | блок с адресом в канонe `result_ref` (собранном самим `result_ref.make`, а не литералом) воротами НЕ берётся: `no_address`, и отказ НАЗЫВАЕТ единственную форму. Плюс замок на протухание: если судья когда-нибудь научится читать канон, тест скажет «предпосылка протухла — сведи формы заново» |
| `test_POSITIVE_a_taken_block_is_actually_judged_by_the_closing_judge` | принятый блок проходит ВЕСЬ путь ступени C на поддельном корне: опорный снимок ДО → артефакт по адресу → вердикт `сделано`. Имя артефакта КИРИЛЛИЧЕСКОЕ |
| `test_a_cyrillic_artifact_name_survives_the_chosen_form` | адрес прямым путём с кириллицей судьёй не читается → воротами не берётся (расхождение стои́т отказа на входе, а не недоказуемого закрытия на выходе); «папка+дата» берётся |
| `test_an_address_without_the_proving_words_is_not_taken_either` | адрес без слов отвергается воротами теми же словами, какими его отверг бы судья |
| `test_the_address_gate_asks_the_closing_judge_itself` | пин на ЧУЖУЮ ФУНКЦИЮ (`done_judge_pc.read_address` в исходнике) + прогон трёх читаемых судьёй видов адреса через ворота |
| `test_the_shipped_sample_of_the_address_passes_its_own_gate` | образец `shtab_box.ADDRESS` проходит наши же ворота и читается судьёй |
| `test_the_box_borrows_only_the_address_reader_from_the_judge` | у судьи (умеющего писать на диск) ящик берёт РОВНО `read_address`: инвариант чистоты смотрит на имена модулей и опечатку `note`/`_packets` пропустил бы |

### Доказано, что тесты не пустые

Прогон новых проверок против ящика **из HEAD** (`_scratch_addr_canon_0902/before.py`: старый
`shtab_box.py` перекрывает боевой, источник для пинов подменён на старый файл):

```
ИТОГ НА СТАРОМ ЯЩИКЕ: всего 7, красных 7 (падений 6, ошибок 1)
ВЕСЬ НАБОР НА СТАРОМ ЯЩИКЕ: всего 64, красных 23
```

Красные 7 из 7 — и это ровно те проверки, ради которых заход. Красные 23 из 64 у всего набора —
второе, независимое доказательство премисы: образец набора теперь несёт адрес в форме судьи, и
СТАРЫЕ ворота его не берут (`НЕ ПРИНЯТ (no_address): адрес результата не назван каноном полосы
[result_ref: …]`), роняя даже положительный контроль «здоровый ящик ставит задачу».

## Чего этот заход НЕ делал (честная граница)

* **строгость судьи не тронута:** режим `DONE_JUDGE_PC` не переключался ни разу, дефолт прежний
  (`addr`); задача сводила ФОРМЫ;
* **гард, карточки и ворота контура** не изменены ни строкой; клиентского контура заход не касался;
* **боевая очередь** не тронута: ряды в тестах поддельные, живых оборотов ящика не запускалось;
* **узел `shtab_box` в мозге** по-прежнему заводит Штаб — из ящика по-прежнему ничего не взято, и
  правка доедет до демона self-update'ом;
* **проверка ворот остаётся формальной:** они доказывают, что адрес НАЗВАН читаемой формой, и
  ничего не говорят о том, будет ли по нему что-то лежать. Это судит ступень C после захода.
