устройства/сторож/боты не тронуты.

## 3. Куда цепляются новые сессии — ПРЯМО

**К МЁРТВОЙ среде, не к живой.** Доказательство:
- В логе живого сервера (`rc_server_debug.log`, env_01Abfcn6…) после старта — **только пустые
  поллы** (`work/poll -> 200 (no work, 100 consecutive empty polls)`). Ни одного входящего
  запроса на создание сессии после старта. Если бы телефон целил в живую среду — были бы
  повторные попытки. Их нет → телефон обращается к другой (стухшей) среде → вечный Connecting.
- `rc_remote_control.log` — это лог **жизненного цикла процессов** сторожа (падения/рестарты),
  входящих запросов на сессию он НЕ пишет. Строка 311: `20:06:07 [named-channel] процесс вышел
  (exit=4294967295) — рестарт` — это моё снятие зависшего канала ранее, не запрос сессии.

**Второй, независимый блокер (на ЖИВОЙ среде):** при единственной дошедшей попытке (сразу
после старта, 12:56:17 UTC) сервер вернул `400: GitHub repository access check failed —
re-authorize GitHub in settings`. Т.е. даже если телефон переключить на живую среду, создание
сессии упрётся в протухшую GitHub-авторизацию.

## 4. Где хранится соответствие и можно ли чистить локально

- **Соответствие «телефон → среда» хранится на сервере Anthropic** (`/v1/environments`) и в
  приложении. На ПК локального реестра сред НЕТ: `.claude.json` держит только
  `remoteControlSpawnMode="same-dir"` и `remoteControlSurfacesSeen=["mobile"]`, никаких `env_…`.
- **Локально мёртвые среды убрать нельзя.** `claude rc` просто регистрирует новую при каждом
  старте; старые «отваливаются» серверно/по TTL. Единственный живой сервер уже ровно один
  (PID 15112 = env_01Abfcn6…) — на ПК чинить нечего.

### Что сделать владельцу в приложении/браузере
1. В списке **Devices/Environments** выбрать **текущее** устройство (свежую запись
   `mxfillpc / D:\turbobaby-bot / main`, соответствующую `env_01Abfcn6…`); стухшие записи
   (в т.ч. `env_0135pmoZ…`) — игнорировать/удалить, если UI даёт.
2. **Переавторизовать GitHub** в настройках (Settings → GitHub / re-authorize) — снять `400
   GitHub repository access check failed`, иначе сессии на живой среде не создадутся.
