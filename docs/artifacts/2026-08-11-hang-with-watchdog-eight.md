## 2. Прямой ответ (пункт 2): СЛЕП. И слеп ПО ПРЕДМЕТУ, а не по зоркости

Из трёх вариантов — «не увидел», «счёл здоровым по порогу», «поднял, а оно снова встало» —
верен первый, но с уточнением, которое меняет вывод: **все 75 вердиктов «жив» были ПРАВДОЙ.**
В шести случаях из восьми демон в это время действительно работал — брал другие задачи, писал
METRICS, поднимал userbot. Сторож не ошибся в своём предмете; предмет был не тот.

Строки кода, на которых это стои́т:

```
pc_orchestrator.py:8533   if _heartbeat_fresh(now=now): _mark_alive(); return "alive"
pc_orchestrator.py:8536   pids = find()
pc_orchestrator.py:8537   if pids:
pc_orchestrator.py:8540       log.info("watchdog: heartbeat старше %sс, но процесс демона жив (PID %s) — "
pc_orchestrator.py:8541                "длинная задача/рестарт, не трогаю", HEARTBEAT_STALE, pids)
pc_orchestrator.py:8542       _mark_alive(); return "alive"
```

Критерий — `heartbeat свеж **ИЛИ** процесс жив`. Второе плечо **перекрывает** первое: протухший
продукт (heartbeat) не даёт вердикта, пока в системе есть процесс с нужной командной строкой.
Предмет сторожа — ДЕМОН. Предмет поломки во всех восьми — **строка очереди и её плечо к мосту**
(claim лёг / complete не лёг / задача осиротела при смене экземпляра). У этого предмета
наблюдателя нет ни одного: `«не поднял»` здесь означает не «лечение не сработало», а «лечить
было нечего — больной был не тот».

Против варианта «порог»: ни один вердикт не был пограничным — 75 из 75 попали в ветку 8537,
которая порога не имеет вовсе. Против варианта «лечение не работает»: подъёмов в этих окнах
ноль, а три подъёма за весь корпус (24.07, 30.07, 06.08) лежат ВНЕ всех восьми окон.

## 3. Встречный вопрос (пункт 3): судит PID. Оба сторожа

| сторож | чем судит | строка |
|---|---|---|
| внешний вотчдог демона | **живой PID** (перекрывает продукт) | `pc_orchestrator.py:8536–8543` |
| реапер сирот `PC_ORPHAN_STALE` | **живой PID ребёнка** из отметки старта | `_executor_verdict`, `pc_orchestrator.py:3385–3388` («В отметке есть PID ребёнка → судим ПО НЕМУ») |
| реапер одиночек `PC_SINGLE_STALE` | возраст `updated` = **молчание** | `pc_orchestrator.py:3482–3492` |

То есть да — **это наш известный класс**, тот самый, который на модерботе закрыт О3: там предмет
переписан с «жив процессом» на **продукт тика** (`mtime moderation_ipc.db` при ДОКАЗАННОМ
авторстве). Здесь то же лекарство не применено: у демона продукт (heartbeat) есть, но он стои́т
в `ИЛИ` с PID и потому не решает; у СТРОКИ продукта не спрашивают вовсе.
