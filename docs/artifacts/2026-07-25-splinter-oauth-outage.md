# Боевой сбой Splinter 25.07: LLM недоступен — истекла OAuth-сессия подписки

**Окно:** 03:49–08:00 UTC (10:49–15:00 Бангкок) · **Восстановлено:** 08:00:50 UTC обходным путём
**Причина:** НЕ модель и НЕ ночные правки репозитория

---

## Что именно сломалось (дословно)

```
2026-07-25 03:49:34,462 [ERROR] claude_client: Claude quick() upstream down (graceful ''):
    SplinterLLMError: claude -p rc=1: Failed to authenticate: OAuth session expired and could not be refreshed
```

Последний отказ — `07:52:49`. Всего за сутки **15 отказов LLM**.

**Потерянные записи трат (все три):**
```
03:56:09 UTC (10:56 Бангкок)  → LLM upstream down на ДЕНЬГАХ: wallet=Самоорганизация kind=money lost='-60'
05:18:45 UTC (12:18 Бангкок)  → то же, lost='-60'
07:39:27 UTC (14:39 Бангкок)  → то же, lost='-60'
```
Первый отказ **на деньгах** — `10:56 Бангкок`, ровно то время, что назвал владелец. Похоже, одна
и та же трата, отправленная трижды; **её надо ввести заново**.

## Почему трата теряется, а не деградирует

`claude_client.py:673 _cli_generate` ходит по подписке Max через `claude -p`, и строки 679–680
**намеренно вычищают** `ANTHROPIC_API_KEY`/`OPENAI_API_KEY` из окружения («не платный API»).
Значит при отказе подписки автоматического отката на платный API **нет**. Кассовый путь зовёт
`quick(raise_on_upstream=True)` → типизированный `SplinterLLMError` → запись не сохраняется.
Для остальных путей (`translate`/`intake`/`servicing`) деградация тихая, в пустую строку.

## Версия «виноваты ночные правки» — снята фактами

| проверка | факт |
|---|---|
| боевой код | `git diff --name-only 6a6d7fc HEAD -- '*.py' ':(exclude)tests/' ':(exclude)_*'` → **пусто** |
| конфиг | вне git; mtime `24.07 18:28:59` — за 4.5 ч ДО первой ночной мутации (23:03) |
| имена моделей | `claude-sonnet-4-5` → HTTP 200, `claude-opus-5` → HTTP 200 |
| CLI | версия `2.1.215`, бинарь от **20 июля** — ночного автообновления не было |
| `primaryApiKey` в конфиге CLI | отсутствует (известный класс перехвата подписки ни при чём) |

Отдельный факт без установленной причинности: `/root/.claude/.credentials.json` изменён
`24.07 23:32:35`, за 4 ч 17 мин до первого отказа. Связь с чьими-либо действиями не устанавливалась.

## Что сделано для восстановления

Имя модели менять было не на что — отказ даёт **канал**, а не имя. Включён запасной путь,
заложенный в самом коде (`SPLINTER_LLM_VIA_CLI=1 → генерация по подписке; иначе платный API`):

```
бэкап:  .env.bak-oauth-20260725 (5959 байт)
БЫЛО:   31:SPLINTER_LLM_VIA_CLI=1
СТАЛО:  31:SPLINTER_LLM_VIA_CLI=0
        (в diff ровно 2 строки — одна и та же, других отличий нет)
рестарт: PID 1275 → 75185, active (running), старт 2026-07-25 08:00:50 UTC
```

**Живая проверка тем же путём, что кассовый разбор** — `ClaudeClient.quick(..., raise_on_upstream=True)`:
```
SPLINTER_LLM_VIA_CLI = 0
CLAUDE_MODEL         = claude-sonnet-4-5
ОТВЕТ МОДЕЛИ: 'ok'
ИТОГ: LLM-путь РАБОТАЕТ
```
После рестарта новых отказов нет (счётчик держится на 15). Оговорка: за минуту наблюдения
**реальных кассовых сообщений не приходило**, поэтому подтверждение сквозняком на живой трате
ещё впереди — проверяется первой же настоящей записью.

⚠️ **Это временный обход, а не лечение.** Пока он включён, вызовы Splinter идут за деньги API,
а не по подписке. Настоящее лечение — переавторизовать CLI на сервере: действие интерактивное,
с учётными данными, выполняет владелец. После него вернуть `SPLINTER_LLM_VIA_CLI=1`.

**Откат одной командой:**
```
cp -p /root/turbobaby-manager-bot/.env.bak-oauth-20260725 /root/turbobaby-manager-bot/.env && systemctl restart splinter.service
```

## Побочная находка: фолбэк оркестратора мёртв

Проба API по всем именам из конфига:
```
claude-opus-5      -> HTTP 200
claude-sonnet-4-5  -> HTTP 200
fable              -> HTTP 404  {"type":"not_found_error","message":"model: fable"}
```
`ORCH_MODEL_FALLBACK=fable` — **не существующее имя**. Основная модель демона работает, поэтому
фолбэк ни разу не срабатывал (в логе `запрошена=claude-opus-5, фолбэк=fable, взята=основная`),
но в момент, когда он понадобится, он откажет. Тот же класс, что уже записан в памяти: нужны
ПОЛНЫЕ идентификаторы, вероятно `claude-fable-5`. Не трогал — вне объёма инцидента.

Ещё в логе видны исторические отказы того же CLI-пути:
`rc=1: error: unknown option '-100'` и `'-550'` — это боевой баг 06.07 (сообщение с ведущим `-`
парсилось как опция), он уже закрыт передачей промпта через stdin. К сегодняшнему сбою отношения не имеет.

## Хвосты владельцу

1. Переавторизовать CLI на сервере, затем вернуть `SPLINTER_LLM_VIA_CLI=1`.
2. Ввести заново утраченную трату(ы): кошелёк «Самоорганизация», `-60`, попытки в 10:56 / 12:18 / 14:39.
3. Решить судьбу `ORCH_MODEL_FALLBACK=fable` (скорее всего → `claude-fable-5`).
4. Подтвердить восстановление первой живой записью траты.
