## 2. Показ (`wa_tg_mirror.py`, `_edit_one`)

Своя ветка живой ленты (`_advance`) — для `edit` с новым текстом. Без текста — прежний `_show_one`.

1. **Цель показана одна и её id есть** (`_target_where`, тот же, что у удаления: ключ `msg:`/`file:`,
   `state=shown`, `solo=1`, `msg_id`) — правка этого сообщения темы:
   - текст — `editMessageText`, файл — `editMessageCaption`;
   - новый текст собирают **те же функции, что показали цель**, на копии строки цели с новым текстом
     (`wa_history.edited`). Живая лента — `_live_view`, хвост — `item_line`, файл хвоста — «дата кто · подпись».
     Поэтому вид строки («ДД.ММ ЧЧ:ММ мы: …») не расходится с показанным;
   - ниже — «✏️ изменено с телефона ЧЧ:ММ» (время правки, Пхукет).
2. **Иначе — одна строка** «ДД.ММ ЧЧ:ММ кто: ✏️ изменено сообщение от ЧЧ:ММ, теперь: <новый текст>».
   - Когда: цель в пачке, показана до хранения id, не показана, не из этой темы или чат правку не принял (400).
   - Время цели — из очереди или из архива по key_id (`_target_ts`, как у удаления). Цели нет нигде — без «от».
   - Ответом на цель, если она показана хоть в пачке.
3. **Повтор.**
   - Ключ строки — `msg:<wamid>`: такт, рестарт и тот же wamid правку не повторяют.
   - Таблица `edits` (target, row_id, how) в своей базе службы (CREATE TABLE IF NOT EXISTS) — какая правка
     последней легла на цель и как. Тот же текст на ту же цель под другим wamid (досинхрон) — без второй
     правки и без второй строки.
   - Новый текст той же цели — правка законна, с последним текстом.
   - Обрыв ответа на правку — «не уверен», повтора нет. Отказ не 400 — повтор следующим тактом.
4. **Удаление после правки** зачёркивает то, что сообщение показывает сейчас: новый текст с пометкой правки
   (`_shown_now`), а не прежний.

Ключей `msg:`/`file:` с `solo=1` правка новых не пишет, поэтому читатель реакций (`wa_agent_tg`) их не видит.

## 3. История (`wa_history.py`, `apply_edits`)

Одна склейка на три дороги: файл истории и хвост темы (`prehistory` → `merge`) и модель агента (`read_history`
→ `model_view`).

- **Цель есть в истории** (строка очереди по wamid или запись архива по key_id) и новый текст есть:
  - у цели — **последний** текст (по времени правки, затем по id) с пометкой «(изменено)»;
  - сама правка отдельной строкой не идёт — ни строка очереди, ни её архивная пара.
- **Цели нет** — правка остаётся своей строкой:
  - есть новый текст — «<новый текст> (изменено)»;
  - нового текста нет — «[сообщение изменено]», как сейчас;
  - архивная пара правки (живой случай, 98 из 98) — её текст с пометкой.
- Правки с id ≥ trig — «новое»: их делает живая лента, в историю они не идут (прежнее правило склейки).
- `QCOLS` += `edit_to`, `edit_text`. Очередь без колонок читается NULL — служба и агент не падают.

## 4. Подпись медиа и правка без текста

  как сейчас: строкой «ДД.ММ ЧЧ:ММ кто: [сообщение изменено]», правки сообщения нет.
