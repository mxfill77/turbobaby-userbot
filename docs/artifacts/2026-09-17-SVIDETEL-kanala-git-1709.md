## 1. Пересчёт своим критерием

**Критерий назван до поиска: «от решения к резу».** Идём от решающего оператора назад по потоку данных, а не от реза вперёд.
- Решающий оператор: `re.search/match/findall`, `in`, `startswith`/`endswith`, `==`, ключ словаря или множества, ветвление, возврат вердикта, класса или имени причины, аргумент-свидетельство, выбор адреса.
- Операнд мог стать коротким раньше: в той же функции, через параметр, через поле, записанное короче и потом прочитанное.
- Виды реза: `[:N]`/`[-N:]`, хелперы (`_tail`, `one_line`, `_clip`, `shown`, `goal_line`, `_last_line`), `splitlines()[0]`/`[-1]`, `split(sep)[0]`, `partition`, хвост или голова файла в байтах, лимит при записи.

## 3. Право места судить укороченный текст

**Права нет.**
- **Кто ждёт короткую форму.** У `detail` четыре читателя, и все — показ:
  - строка журнала `_autofetch_note("fetch_failed", …)` — дедуп идёт по `cond`, а не по тексту;
  - `log.warning`;
  - `LinkWatch.fails[…]["text"]` (`[:300]`) — читателей этого поля в отслеживаемом коде, кроме записи на `pc_orchestrator.py:631`, нет;
  - `[:200]` в строке «СВЯЗИ НЕТ».
  - Разбирает короткую форму один свидетель.
- **Какой якорь несёт 160 — никакого.** Число родилось в `0f98122` (#221 авто-фетч) как бюджет строки журнала, когда свидетеля ещё не было. Свидетель (`831b69f`, 05.08) взял уже срезанный показ. Прямое доказательство, что это не якорь, — живой лог: `pc_orchestrator.log*` содержат **2** отказа fetch, и первый лежит как «**tal:** unable to access 'https://github.com/…': Failed to connect to github.com port 443 after 21115 ms: Could not connect to server». Полная строка — **162** знака, рез съел «fa» у машинной метки `fatal:`. Знак уцелел случайно: curl ставит его в конец строки.

**Правка по правилу класса.**
- **Полный текст.** `_git_net_sign(r[2])` судит ПОЛНЫЙ stderr.
- **Где машина ставит знак.** Git пишет свой отказ строкой с меткой `fatal:`/`error:`, ssh-клиент — строкой `ssh:`. Только такие строки читаются. Цитаты `'…'` в них (адреса, имена ссылок, пути — чужой текст) вырезаются до поиска. Строки `remote:` пишет сервер: раз он ответил, связь была.
- **Режется только показ.** `detail = _tail_shown(r[2], 160)`: короче 160 — байт-в-байт как прежде, длиннее — `[показан хвост 160 из N симв.] …`.
- **Свидетельство** несёт ровно найденный знак (`git fetch: «…»`), как у канала API в `_fail_is_network`. Заодно не срабатывает рез `[:200]` в строке «СВЯЗИ НЕТ»: `11 + 33 + 160 = 204` знака.

**Цена, названная вслух.** Все случаи ниже дают `None` («не измерил»), а не ложное «связи нет»:
- git с переведёнными метками («фатальная ошибка:»). Живые отказы полосы английские, 2 из 2;
- ssh-строки без метки `ssh:` (`kex_exchange_identification: … Connection reset`) и строка `errno=` протокола `git://`. Транспорт полосы — https, 2 из 2;
- одиночный апостроф, спаривающийся с цитатой, может вырезать фразу. Живых форм нет.
