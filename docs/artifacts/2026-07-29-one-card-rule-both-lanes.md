# Одно правило карточки на обе полосы: ОБЪЕКТ — гейт, ЧИСЛО — поле

**Дата:** 2026-07-29. **Полосы:** ПК `D:\turbobaby-bot`, сервер — клон `D:\foreign\turbobaby-manager-bot`
(на VPS НЕ выкатывалось). **Гейт ПК:** 29 модулей, **2109 тестов OK** (skipped 10).
**Тесты гарда сервера:** 7 PASS / 7 FAIL — все 7 падают ОДИНАКОВО до и после правки (Linux-окружение).

---

## ПРАВИЛО, к которому сведены обе полосы

```
Карточка выписывается, когда:
  • у операции извлечён ОБЪЕКТ                     — либо
  • это исключение: hard-блок, секреты, ДЕНЬГИ     — они спрашивают всегда.

ЧИСЛО карточку НЕ гейтит НИКОГДА. Оно есть там, где операция несёт его ПО СВОЕЙ ПРИРОДЕ
(сумма, пробег, дата, ключ, версия, PID), и честным прочерком «—» там, где не несёт.
```

Одна функция с одним именем в обоих репозиториях — `card_gate(hit|kind, obj, num)`.
`deny` не ослаблен, `bypassPermissions` не включён, признак `.env` не тронут.

## 1. Что именно разошлось (факты)

| | правило | следствие |
|---|---|---|
| сервер `17221f2` | нет объекта **ИЛИ** числа → карточки нет | молча съедены 4 операции без числа по природе |
| ПК `bd0974d` | нет объекта **И** числа → карточки нет | безобъектная команда с ЛЮБОЙ цифрой карточку **рождала** |

Обе ошибки — из одного корня: число считали признаком «операция настоящая». Оно им не является.
Настоящая операция опознаётся **объектом**; число — свойство лишь части операций.

### Найдена ВТОРАЯ линия того же гейта — без неё правка была бы половинчатой

На сервере карточку гасил не один гейт, а два. Второй — `marker_has_object()`, конверт демону:

```python
_MARKER_OBJECT_RE = re.compile(r"\d")      # было: «есть ли в тексте карточки ХОТЬ ОДНА цифра»
```

Замер до правки — все четыре операции: `marker_has_object = False`. То есть даже с почином
`card_min` в headless карточка до демона **не дошла бы**: `pkill ngrok`, `systemctl stop nginx`,
`DELETE FROM sessions` и отмена проводки цифры не несут вовсе. При этом шаблон операций с парком
несёт «Лист1» — цифра там есть ВСЕГДА, то есть проверка врала в обе стороны сразу. Теперь она
смотрит ту же величину, что и `card_gate`: подписанную строку `Объект:` со значением.

## 5. ГЛАВНОЕ ЧИСЛО — замер по журналу решений за сутки

Окно взято **то же**, что в артефакте `2026-07-29-guard-card-noise.md`, иначе число несравнимо:
`28.07 12:49:36 → 29.07 12:49:36`, **1160 решений** гарда. Реплей КАЖДОГО решения через модуль
из HEAD и модуль рабочего дерева.

| | карточек |
|---|---:|
| было (до `bd0974d`, из артефакта) | 58 |
| стало по `bd0974d` (оценка артефакта) | 29 |
| **правило HEAD — прямой реплей** | **27** |
| **правило НОВОЕ — прямой реплей** | **27** |

**Новое число — 27.** Правка на реальном трафике суток не добавила и не убрала НИ ОДНОЙ карточки:
переворотов `+0 / −0` (считано построчно, а не по итогу — нулевая дельта могла быть и «+3 −3»).

Состав (HEAD и НОВОЕ совпадают): `env` 14, `sqlite` 4, `clasp_deploy` 3, `kill` 2, `network` 2,
`clasp_push` 1, `clasp_run` 1.

**Почему 27, а не 29.** Артефакт 29.07 честно писал, что 5 из 58 решений он не воспроизвёл
(`detail` в журнале обрезан на 300 символах) и посчитал их красными «в пользу осторожности».
Прямой реплей их считает как есть — отсюда 27. Числу верим, сводке нет (свод, п.7).

**Ограничение замера названо:** 268 строк из 1160 имеют усечённый `detail` (≥300 символов) —
для них реплей видит только первые 300 символов, и живое решение могло отличаться. Это то же
ограничение, что у предыдущего замера, оно не устранено.

**Что означает нулевая дельта.** Четыре восстановленные операции за эти сутки просто **не
случались** — их и не должно было быть в журнале, раз правило их гасило молча. Замер показывает
не «фикс ничего не дал», а «фикс не добавил шума»: цена возврата четырёх операций — ноль карточек
на реальном трафике.

## 7. Чего НЕ делал и остатки с точками касания

- **На VPS не выкатывал** — правка только в клоне и в GitHub; выкатка отдельной задачей.
- `deny` не ослаблен, `bypassPermissions` не включён, признак `.env` не тронут.
- **`_proc_class` не трогал:** объект сервера читается как `цель systemctl stop nginx` (с глаголом).
  Объект виден, этого правилу достаточно; переписывать разбор ради косметики — лишний риск.
- **Остаток:** на сервере `sqlite3 <файл> "UPDATE …"` **CLI-формой** до хита `sqlite` не доходит
  вовсе — `classify()` уводит любое не-python в `green` до разбора SQL
  (`pretool_guard.py:classify`, ветка `if not _is_python(scan)`). То есть SQL в чужую БД гард
  ловит только в python-форме. На ПК та же команда красная (`_RED_CMD`, вид `sqlite`) — полосы
  здесь по-прежнему разные. Это **другой класс** (классификация, а не карточка), в задание не
  входил и молча не расширялся.
- **Остаток (прежний, не закрыт):** запись в журнал через heredoc краснеет, если в ТЕКСТЕ записи
  упомянут `.env` — `_RE_ENV` проверяется раньше доверенных по имени скриптов
  (`pretool_guard.py:_decide_bash`). Трогает признак `.env` — под запретом владельца.
- **Замечено по ходу:** в репозитории ПК во время работы шла ЧУЖАЯ сессия — `HEAD` уехал
  `a215a5d` → `b790187` («авто-фетч: строки состояния при СМЕНЕ»), число тестов выросло
  2095 → 2101 не от моей правки. Поэтому базовый замер снят повторно на `b790187`, а `git add`
  делался поимённо.
