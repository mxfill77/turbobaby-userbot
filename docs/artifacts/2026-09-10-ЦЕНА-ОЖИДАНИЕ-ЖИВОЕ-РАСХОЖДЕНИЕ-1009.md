## 2. Из чего живой расчёт собирает 1535 (пункт 2) — по слагаемым

**Проба, на которой всё меряется** (`suggest._smoke_default_probe`): NMAX 155, **2026-08-06 →
2026-08-11**, 5 суток, зона Раваи. **Ставка дня, разложенная:**

| сомножитель | значение | откуда | происхождение |
|---|---|---|---|
| **база модели** | `298 ฿/сут` | `price_source.json` → `base.models[NMAX 155].base_thb_per_day`, класс **скутер** | медиана цены суток **завершённых броней низкого сезона**, срез боевого моста 1282 строки / 1243 годных, `measured_on 2026-09-02` |
| **сезон** | `× 1.000` | период **P1 ИЮНЬ-СЕНТЯБРЬ** (`06-01`…`09-30`), дата начала 06.08 внутри него | **СЛОВО ВЛАДЕЛЬЦА**: «ИЮНЬ-СЕНТЯБРЬ — дно, самые низкие цены, не трогаем»; множитель 1.000 **по построению**, потому что база снята отсюда |
| **ступень срока** | `× 1.03` | корзина **4-6** (5 суток), `term.buckets` | СНЯТО ЗАМЕРОМ 15.08: «четыре-шесть суток — на 3 % дороже недельной, самая дорогая корзина» |
| **скидка** | **никакой** | в формуле сомножителя «скидка» нет вовсе | см. §3: у записанного правила скидки как отдельного множителя не существует |

```
298 × 1.000 × 1.03 = 306.94  →  307 ฿/сут   (округление ПОСУТОЧНОЕ, int(round(...)))
307 × 5                      = 1535 ฿ за срок
```

**Тот же счёт живым кодом** (`price_source.term_total`, `tmp/pc_report/calc_probe2.py`):

```
total = 1535
info  = {"base": 298.0, "period": "P1", "period_name": "ИЮНЬ-СЕНТЯБРЬ", "season": 1.0,
         "bucket": "4-6", "term": 1.03, "cls": "скутер", "low_season": true,
         "split": false, "day_prices": [307], "segments": [["P1", 5, 307]]}
```

**Кепка месяца в этом расчёте не участвует:** сумма 1535 ฿ меньше кепки NMAX 155 (5000 ฿/мес), и
`cap_active` живой котировки — `false`. **Множитель сезона взят один**, потому что `segments`
одна: все пять суток лежат в P1, разбивки по дням не происходит (`split: false`).

**Что делает с числами листа врезка** (`price_source.reprice`, единственная точка):
`day_price 480 → 307`, `total 2400 → 1535`, **`text` СНИМАЕТСЯ** (`price_source.py:546`
`out.pop("text", None)`) — дословная строка столбца J с чужими числами удаляется, чтобы рядом с
новой ценой не звучала старая. Депозит `3000` и признак наличия приходят **живой котировкой** и
не подменяются. Снято живьём:

```
вход  : {"day_price": 480, "total": 2400, "deposit": 3000, "days": 5, "text": "2400 ฿ за 5 дней (Скидка за срок 15%, ...)"}
выход : {"day_price": 307, "total": 1535, "deposit": 3000, "days": 5}          ← поля text больше нет
```

**Именно снятие `text` и есть механика всех пяти падений:** тест ждёт у клиента строку, которую
код с 20.08 сознательно удаляет.

## 4. Цена вопроса числом (пункт 5)

Расчёт **не врёт**, поэтому пункт 5 в своей прямой постановке не наступил. Но число расхождения

| | ฿/день | за 5 суток |
|---|---|---|
| ожидание теста (лист) | 480 | **2400** |
| живой расчёт (правило) | 307 | **1535** |
| **разница** | **−173 ฿/сут** | **−865 ฿ (−36.0 % от 2400; +56.4 % к 1535)** |

**В какую сторону ошибётся клиент, если победит не та сторона:**

* если бы источником снова стал лист (объявленный откат `PRICE_SOURCE_SEASON=выкл`) — клиент на

  аренде NMAX 155 в низкий сезон**. Это **та же слепота листа к сезону**, что измерена 17.08, но с
  другого её конца: там лист **занижал** пик на 27.7–31.7 %, здесь **завышает дно** на 56.4 %;
* если бы «починили» ожидание подгонкой расчёта под 2400 — цена та же самая, знак тот же самый.
  **Подгонка прибора под измеряемое заданием запрещена, и не делалась.**

Величина **−36.0 %** совпадает знак в знак с уже записанной 21.08 (`2026-08-21-goldens-deferred.md`,
§4.1, строка «−36.0 % (2400 → 1535) — случаи 5, 6, 11, 12, 13»). Расхождение **не новое и не
выросло за 20 суток**.

**Честная оговорка о том, чего это число НЕ значит:** 2400/480 — числа мока, а не выставленный
клиенту счёт. Ни один живой клиент этих 865 ฿ не переплатил: класс живёт **внутри тестов**, боевой
путь с 20.08 считает по правилу. Цена дефекта — не деньги клиента, а **пять постоянно красных
проверок**, на фоне которых новая настоящая краснота ценового пути будет неразличима.

| **период через границу сезонов** | NMAX 155, 25.09 → 05.10 (P1 → P2) | «срок аренды пересекает границу сезонов <…> **НЕ называй НИКАКОЙ цены**: ни точной, ни за сутки, ни за весь срок, **ни «от … ฿»**, ни диапазоном, **ни СРЕДНИМ по периоду** <…> цену на такой срок считает человек» + пометка менеджеру `[уточнить: период через границу сезонов]` | **НЕТ** 🟢 |
| **аренда длиннее месяца, ЦЕЛИКОМ в одном периоде** | NMAX 155, 01.08 → 01.09 (31 сут, весь P1) | `NMAX 155 — 158 ฿/день; итого 4898 ฿` (`298 × 1.0 × 0.53 = 157.94 → 158`, `158 × 31`) | **ДА — и это законно**: узел велит «ЦЕЛИКОМ В ОДНОМ СЕЗОНЕ — по цене этого сезона», кепка 5000 ฿/мес не задета (4898 < 5000) |

Три наблюдения, каждое достойно быть записанным:

1. **Молчание запрещено наравне с выдумкой.** Обе карточки несут «МОЛЧАТЬ ТОЖЕ НЕЛЬЗЯ, ответ обязан
   прозвучать» — третий исход здесь **зовёт человека вслух**, а не пропадает.
2. **Запрет «от … ฿» на границе сезонов стои́т явно** — то есть форма «от», законная для кепки
   низкого сезона, на смешанном периоде **не разрешена как лазейка**. Это ровно то место, где
   «правило про «от» есть» могло бы стать ложным основанием назвать число.
3. **Порог 180 суток на живом календаре недостижим отдельно от границы сезонов**: самый длинный
   период файла — P1, 122 суток, поэтому любой срок ≥180 суток пересекает границу и гасится раньше.
   Ветка «от 180 суток» существует, но **на сегодняшнем календаре её нельзя достичь не задев
   сторожа границы** — значит она не проверена живым проходом ни здесь, ни, судя по всему, вообще.
   Это **НЕИЗВЕСТНО**, а не «работает»: заходом не чинилось и заданием не поручалось.

## 6. Что этот заход НЕ доказал — честно

* **Верны ли сами данные правила** (база 298 ฿ и множители). Доказано только, что код применяет
  записанное правило точно, и что правило сходится с деньгами лучше листа (цитата §3.1). Отдельный
  вопрос, здесь не решался.
* **Что сегодня отдаёт живой лист по NMAX 155 на 5 суток.** Не проверялось: дверь ведёт в
  запрещённый лист. На вердикт не влияет (§3.2).
* **Стои́т ли в боевом окружении слово отката** `PRICE_SOURCE_SEASON`. `.env` читать запрещено;
  прочитан код, который его читает: дефолт — **включено**, выключает только опознанное слово из
  `_FALSE` (`0/false/no/off/нет/выкл`), всё прочее оставляет правило.
* **Побочная находка, к цене отношения не имеющая:** шестой красный полного прогона —
  `TestSuggestCredentialContainment.test_anthropic_key_is_read_only_from_environment`, и он
  **печатает боевой ключ прямо в вывод теста** (значение здесь не цитирую словами задания —
  ключ Anthropic из окружения). Это отдельный класс и отдельная задача; этим заходом не чинился и
  в счёт пяти ценовых красных не входит.
