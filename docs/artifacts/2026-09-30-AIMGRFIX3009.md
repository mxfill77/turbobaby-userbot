## 2. Что изменено (3 файла, +410/−33; из них `aimgr_tools.py` — 257 строк правки)

1. **Возраст архива** (`_read_stamp`, `_clock_at`, `_age_line`). Штамп `tmp/chatlog_servicing_tick/state.json`
   (или `CHATLOG_SERVICING_TICK_STATE` — то же имя, что у часов) только читается. Миг удачного захода — `ran_at`,
   когда `seq == done_seq` и не `running`; пока идёт новый заход, `ran_at` — уже его заявка, и берётся
   `done_at − duration_s` прежнего. Первая строка: «последний удачный заход часов … — X сут назад; последняя
   строка … — Y сут назад». Штампа нет / не читается / последний завершённый заход не `ok` —
   «возраст архива: НЕИЗВЕСТНО — <причина>», время последней строки всё равно отдельно.
2. **Темы нет** (`_coverage`, исход `QUIET = "тихо"`). Захват часов читает ВЕСЬ форум от новых к старым, поэтому
   окно удачного захода `[oldest_utc, заход]` скачано без разрыва по всем темам. Покрытие известно, если заход
   удачный, `oldest_utc` есть и последняя строка архива не старше `oldest_utc` (иначе читаем не тот архив, что
   описан штампом). Тогда — «в теме тихо с <oldest_utc> UTC: …покрывает A → B без разрыва; позже захода — не
   скачано; тем без номера в имени K — среди них тему байка не опознать». Нет — НЕИЗВЕСТНО с причиной покрытия.
3. **История видит тему** (`bike_history(topic=…)`, `_topic_part`, `_topic_text`). По умолчанию — архив через
   `bike_topic_msgs` (окно 8 сут: 7 суток Пхукета при любом часе); `topic=None` — прежнее поведение. В ответе
   `topic`: исход, тема, последнее сообщение (время, бот/человек, фото, текст человека), слова ремонта за N суток.
   «В ремонте» — слово ремонта в событиях ИЛИ в теме за N суток; запись человека в теме за N суток — свежая
   запись (правило 27.09: тайцы — только когда свежего нет нигде). День сообщения — пхукетский, как у событий.
4. **Ремонт старше окна** (`REPAIR_NOTE_DAYS = 7`). Слово ремонта в событиях или теме за (N, 7] суток — пометка
   «было упоминание ремонта ДД.ММ, уточнить» (последняя дата); вердикт от неё не меняется. N остаётся
   параметром `days` (по умолчанию `FRESH_DAYS = 3`) — правило владельца не тронуто.
5. **Имя темы** (`_name_gap`). Тема найдена по номеру (не по точному имени), а в имени темы есть слова, которых
   нет в имени юнита (сверка без пробелов и дефисов: «X-Max» = «XMAX», «350» ⊂ «350CC»), — `name_gap` и строка
   «тема найдена по номеру N: имя темы «…», имя юнита «…» (нет в имени юнита: …) — та ли это тема, уточнить»;
   в `bike_history` — пометка с обоими именами. В живом архиве сработало у 1 темы из 5 найденных (9315); у 798,
   6908, 9890, 4685 слова темы есть в имени юнита — пометки нет.

## 5. Пределы, названные числом

1. **Покрытие — только окно ПОСЛЕДНЕГО удачного захода.** Штамп хранит один заход, поэтому «тихо» начинается с
   его `oldest_utc` (24.09 03:23), хотя архив сшит без разрыва и раньше (AIMGRACCEPT: с 18.09). Начало — старейшее
   взятое сообщение, а не «заход − 7 сут»: `stopped_by` штамп не хранит, консервативно. После любой ошибки часов
   «тихо» до следующего удачного захода становится НЕИЗВЕСТНО — честно, но так.
2. **«Тихо» не видит тему без номера в имени:** в архиве таких 1 из 20 — число выводится в строке ответа.
3. **Слово ≠ ремонт.** Вердикт стоит на регулярке ветки (`_REPAIR_RE`); слова бота считаются тоже (у 4685 из
   5 старых слов 1 — бот по-тайски). Для этого колонка «верно?».
4. **Запись человека в теме = свежая запись** — выбор по правилу 27.09; в живом прогоне он не сдвинул ни одного
   вердикта (у 4685 и 9315 свежие события и так есть).
5. **События не прочитаны → «не измерено»**, тема в вердикт тогда не идёт (прежнее поведение не менялось).
6. **Пометка имени** ловит слова темы, которых нет у юнита, но не наоборот: «NMAX 155 BLACK 4685» при юните
   «… BLACK GOLD-2 …» пометки не даёт.
