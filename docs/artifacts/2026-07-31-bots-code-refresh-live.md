## 4. НАХОДКА: почему ворота перестали держать (и это не хорошая новость)

После 03:44 в логе демона нет ни одной строки удержания — но вопрос не решался. Причина в коде
реконсиляции (`pc_orchestrator.py` → `reconcile_children_tick`):

```python
if _last_child_commit is None:        # первый прогон: дети стартовали с текущим HEAD → он уже «применён»
    _last_child_commit = head
    return ""
```

Метка живёт в **памяти процесса** и на старте демона принимает HEAD **на веру**. Демон рестартнул
в 13:57:32 → метка стала `6a5a748`. Дифф `6a5a748..HEAD` — только `pc_orchestrator.py`,
`test_pc_orchestrator.py` и доки, файлов детей нет → `_client_block` **не зовётся вовсе**, метка
молча уезжает на HEAD.

**Следствие, которое стоит записать классом:** допущение «дети стартовали с текущим HEAD» для
`userbot` **ложно уже сутки** — он на fd5388f. Реконсиляция его отставания НЕ ВИДИТ и не увидит
никогда: каждый рестарт демона заново объявляет отставшего актуальным. Ворота тут ни при чём —
удержание 02:33–03:44 было честным, его стёр рестарт демона, а не решение. Тихо отставший
клиентский процесс — это дыра ровно того же класса, что закрывали воротами, только с другой
стороны: там «выкатилось без спроса», здесь «не выкатилось и никто не заметил».
Точка касания для починки: метку `_last_child_commit` держать не в памяти, а рядом с фактом —
сверять с коммитом, на котором РЕАЛЬНО живёт каждый ребёнок. В остатки, кодом здесь не тронуто.

на `6478a39` — **КРАСНЫЙ** (чеков 219/222, кейсов 10/12), `release_reason(cf27178) = None`.

Записано «да» владельца на **HEAD** штатным каналом `client_contour.approve()` — тем самым, что

НЕ тронуто: ни строки в `client_contour.py`, порог тренажёра, рубильник и fail-closed на месте.
Основание — прямое поручение владельца в задании сессии («снять остановку ворот основанием
владельца на конкретный коммит»), записано **на один коммит**, не бланком.

**Важно и проверено:** запись основания сама по себе НИЧЕГО не рестартует. `_exec_release_client`

см. §4 (в диффе от метки нет файлов детей). То есть «да» воротам и рестарт — два РАЗНЫХ решения,
и второе осталось за владельцем.
