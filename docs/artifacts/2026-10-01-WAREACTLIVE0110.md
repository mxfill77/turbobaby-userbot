**Почему переименований 0, а не 1, как в прогнозе WAREACTNAME0110 §4.** Тема получает имя при
открытии из той же функции `_topic_name`: `wa_contacts`, а если там пусто — последнее непустое
имя из `wa_inbox` этого номера, причём по ЛЮБОЙ строке, а не только по строке, открывшей тему.
Подсчёт (mode=ro, только числа): строк этого номера с непустым `name` и `ts_queued` не позже
открытия темы:

| thread | строк с именем до открытия | после открытия | wa_contacts |
|---|---|---|---|
| 5 | 1 | 0 | 0 |
| 6 | 1 | 0 | 0 |
| 7 | 3 | 1 | 0 |
| 8 | 5 | 0 | 0 |
| 9 | 1 | 0 | 0 |
| 10 | 9 | 0 | 0 |

Значит, все 6 тем открылись уже с именем. Ответ Telegram «не изменено» на каждую из 6 это
подтверждает: название уже равно тому, что считает служба. Прогноз «1 тема без имени» в
WAREACTNAME0110 опирался на то, что тему открыло эхо без имени. Но имя берётся не из строки-повода,
а из последней строки номера с именем. Прогноз был неверен, а код ведёт себя правильно. Что
показывала тема до 11:49, по журналу не видно: строка «тема открыта» имени не печатает.

**Реакции живьём ещё НЕ проверены.** За окна наблюдения не пришло ни одного входящего, ни одной
реакции: строк о реакциях 0, `reacts` 0 строк. Признак работы — первая реакция клиента после
14:13:39. Тогда `react_to` у новой строки станет непустым, а в `reacts` появится строка. Если цель
показана отдельным сообщением ПОСЛЕ применения — реакция бота на сообщение темы. Если цель показана
до применения — одна строка в теме (WAREACTNAME0110 §3).
