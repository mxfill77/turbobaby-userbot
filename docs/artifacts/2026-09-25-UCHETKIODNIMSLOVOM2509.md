## 2. Что построено

### 2.1 Реестр и выбор строителей (`accounts_registry.py`, его импортирует демон)

```json
{"form": 1, "builders": 3,
 "accounts": {"1": {"profile": "ОСНОВНОЙ",            "slot": "",  "label": "основная"},
              "2": {"profile": "D:\\claude_profile_2", "slot": "B", "label": "вторая"},
              "3": {"profile": "D:\\claude_profile_3", "slot": "A", "label": "третья"}}}
```

- номер 1…99 (только ASCII-цифры) → профиль ПК (ОСНОВНОЙ = ключ `CLAUDE_CONFIG_DIR` снят) → буква
  слота сервера `TB_CLAUDE_TOKEN_<буква>` (пусто = слота нет) → метка без почты (`@` — отказ записи);
- строка с браком выбрасывается с названной причиной, остальные живут; слот у двух учёток снят у
  обеих и помечен «спорный» — слово «учётка N» на таком слоте сервер НЕ зовёт;
- выбор строителей: ОСНОВНОЙ → ключ снят; каталог есть → ключ = каталог; **всё прочее → ОСНОВНОЙ +
  WARNING**; **реестра нет вовсе → мост на прежний файл (§0.2)**. Пустого значения ключа нет ни на
  одной дороге; `apply_builders` не бросает никогда (исключение в спавне уронило бы каждый заход);
- обе ветки спавна демона зовут `accounts.apply_builders`; модуль внесён в `_ORCH_RUNTIME`;
- четвёртая и следующие учётки — строкой реестра, код не правится (`accounts_run.py --set`).

**«учётки заведи» — первый реестр одним словом (п.0 + п.1 задания на ПК).** Кладёт п.1: №1 —
ОСНОВНОЙ, №2 — `D:\claude_profile_2` + B, №3 — `D:\claude_profile_3`. Слот A отдаётся по правилу П2
**только при согласии трёх проб**: слот A сервера, основная на ПК, №3 на ПК (учётка одна, лимит у
неё один на обеих машинах):

| слот A | основная на ПК | №3 на ПК | решение |
|---|---|---|---|
| 200 | 429 | не 429 | №3 ← A (у основной в лимите 200 быть не может) |
| 429 | 429 | 200 | №1 ← A (у живой третьей 429 быть не может) |
| 529 / таймаут / сбой канала — у любой из трёх | | | **реестр НЕ пишется**, «повтори позже» |
| всё прочее (401; обе в лимите; основная жива) | | | слоты №1 и №3 пусты, сказано словами, назначить `--set` |

Окно правила — до **измеренного** сброса недели основной, 28.09.2026 21:00 UTC (артефакт 2209,
«Sep 29, 4am (Asia/Bangkok)»; «до 29.09» Штаба — местная дата). Потом A = 200 учёток не различает, и
правило гаснет само. Строители: №3 при пробе 200, иначе №1. Реестр уже есть (даже битый) → отказ,
ни одной пробы. Создание файла — `O_EXCL`: реестр, положенный рукой владельца между проверкой и
записью, не затирается. Сервер заведение только пробует — ни записи, ни рестарта (тест с ловушками
на все шесть серверных ходов).

**`claude_profile_choice.txt`** не удалён; с 25.09 он ЗАПАСНОЙ — его читает мост, пока нет своего
выбора (§0.2). Значение на `main` с 10:51 UTC — профиль 3 (`31494b3`, перенесённый `0d34f16`).

### 2.3 Сервер (`vps_token_install.py`)

Секрет наружу не выходит ни одним каналом: программа для сервера несёт только имена, вывод —
только признаки (длины, коды, «совпало/нет»).

- слоты любой буквы (`slot_name`, закрытая форма, `fullmatch`);
- `--probe-slots` меряет действующее и КАЖДЫЙ слот файла; время сброса — словами поставщика и
  только на 429;
- `--slot X`: годовой токен только в `TB_CLAUDE_TOKEN_X`, одна проба слота; 401/иное → возврат из
  копии; 429 → оставлен; демон не перезапускается;
- `--use X` — ход слова «учётка N»:
  разведка → **идёт ли заход ДЕМОНА** (процесс `claude` в cgroup `orchestrator-daemon.service`;
  сессия владельца в tmux не мешает; cgroup не прочитана → «не проверено» = стоп) → отметка жизни
  демона → копия с датой → запись серверной программой → **одна проба** по файлу →
  - отказ (401/429/иное): файл из копии; если демон сам перезапустился во время пробы (или сверить
    нечем) — один рестарт на прежнем значении, иначе рестартов 0;
  - 200: повторная разведка (заход начался / разведка оборвалась → файл из копии, рестарта нет) →
    **один рестарт**; рестарт не поднял демона → файл из копии, подъём обратно;
  - слот уже действующий: демон младше файла → ничего; старше (держит прежнее) → один рестарт после
    повторной проверки захода;
  - обрыв канала на записи → исход НЕИЗВЕСТНО, возврат по ожидаемому имени копии (её нет — запись
    до файла не дошла, так и сказано); копия не сошлась с оригиналом → из неё не возвращаем.
  Копия не удаляется никогда. `X` — буква или номер учётки реестра. `--slot` и `--use` разом — отказ;
- старый режим (без ключей) не пишет в A, если реестр отдал A другой учётке;
- удалённый питон — `python3 -u` (напечатанное до обрыва не застревает в буфере), записи — с
  `O_BINARY` (на Windows без него файл окружения получил бы `\r\n`).

**Отступление от порядка задания — названо.** Задание: «копия, рестарт, одна проба, отказ — откат».
Сделано: копия → проба → рестарт только при 200. Проба читает тот же файл, с которым поднимется
демон, но отказ не стоит второго рестарта «обратно». Второй рестарт бывает в двух названных случаях:
сам рестарт не поднял демона, либо демон перезапустился во время пробы и схватил отвергнутый вход.

### 2.4 Слова владельца (`pc_agent.py` → дверь `accounts_run.py` субпроцессом)

- «учётки» — по одной живой пробе на каждый профиль ПК (модель пробы = `EXECUTOR_MODEL`, поиск
  `claude` — как у RC, cwd вне дерева, `--setting-sources project`, `--no-session-persistence`) и на
  действующее и каждый слот сервера. Ответ: номер, метка, ответ ПК и сервера со временем сброса,
  что действует у строителей, у RC и у демона; под каким слотом серверный повтор при 429 пойдёт;
  модели проб обеих сторон. Строители откатились на ОСНОВНОЙ без его строки в реестре → меряется и он;
- «учётка N» — ПК: проба профиля N, при 200 номер строителей в реестре = N (дерево не пачкается);
  сервер: `use_slot` слота N. Итог с пробой обеих сторон;
- «учётки заведи» — §2.1;
- чужому — «⛔ Нет прав…» словами, дверь не поднимается; «учётка 9» — «Учётки «9» в реестре нет.
  Есть: …»; «учётка три» / «учётка 100» — отказ словами. В командную строку уезжает только число;
- **гейт строителей:** из захода демона (метки `PRETOOL_ASK_MARKER`/`PRETOOL_MARKER_TOKEN`/
  `GIT_SERIAL_PC_OWNER`, имена сверяет тест с исходником демона) `accounts_run.py --switch/--init/
  --report` и `vps_token_install.py --use/--slot/--probe-slots` отказывают словами до ssh;
- автопереключения по лимиту нет: дверь не зовёт ни один таймер.

## 5. Экран владельца: как завести учётку N (выводит `accounts_run.py --screen`)

0. **Первый раз, три известные учётки — одним словом с телефона: «учётки заведи».** Ответ назовёт
   каждую пробу и решение по слоту A. Проба дала 529/таймаут — повторить слово позже. Слот не
   назначен («пробы не сходятся» или правило истекло) — шаг 3 для №1/№3.
1. Профиль ПК: `$env:CLAUDE_CONFIG_DIR='D:\claude_profile_N'; claude auth login` — вход в браузере.
2. Слот сервера: `claude setup-token` в том же окне, затем
   `venv\Scripts\python.exe vps_token_install.py --slot C` (ввод скрыт; 200/429 — оставлен, 401 — откат).
3. Строка реестра:
   `venv\Scripts\python.exe accounts_run.py --set N --profile D:\claude_profile_N --slot C --label "N-я"`
   (основной: `--profile ОСНОВНОЙ`; слота нет: `--slot -`). Номер строителей — `--builders N` или словом.
4. Проверить: «учётки» в теме 205 — у №N ответ 200 (или 429 со временем сброса).
5. Перевести обе полосы: «учётка N» (= один рестарт демона сервера; идёт заход — ответ скажет «стоп»).

Консольные ходы (`--set`, `--builders`, `--slot`, `--use`) запускает только владелец: из захода
строителей они отказывают.
