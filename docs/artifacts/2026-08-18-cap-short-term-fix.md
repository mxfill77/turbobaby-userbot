## 1. ГДЕ ПРИКЛАДЫВАЛСЯ ПОТОЛОК И ДОСЛОВНОЕ УСЛОВИЕ

Подмену делает **клиентский `suggest.py`**, не лист и не мост — это сказано и самим источником
(`price_source.json` → `low_season_caps.who_applies`: «НИ ЛИСТ, НИ МОСТ… в коде моста прямо
сказано *ЛОГИКИ ПОДМЕНЫ ЦЕНЫ ЗДЕСЬ НЕТ*»). Условие стояло **в четырёх местах дословно одно и то
же**:

```python
if cap_active and cap_price is not None and total is not None and total > cap_price:
```

| точка | что делает | чья котировка |
|---|---|---|
| `_client_price` | фраза цены КЛИЕНТУ | **любого срока** ← здесь дефект |
| `_quote_j_line` | служебный quote-хвост, обязан зеркалить фразу | **любого срока** ← здесь дефект |
| `_sheet_q_month` | величина месячной колонки прайса | месячная по построению |
| `_sheet_month_cell` | текст месячной колонки прайса | месячная по построению |

**Срока условие не спрашивало вовсе.** Сравнивались РАЗНЫЕ ЕДИНИЦЫ — сумма за период против
МЕСЯЧНОГО капа; это названо самим источником (`unit_mix_mine`), а единица кепки там же:
«**฿ за месяц (30 суток)** за одну единицу техники». Порог 30 поэтому **взят у источника, а не
выдуман**.

### ЗАБОР ЧЕСТЕРТОНА — ОДНОЙ СТРОКОЙ

**Условие писалось под АКЦИЮ НИЗКОГО СЕЗОНА** (правило цен v2 п.1, коммит `94ed7ad` от
05.07.2026): перерос расчёт объявленный потолок — называем клиенту потолок, а не формулу.
**Невысказанной посылкой было, что судимая котировка МЕСЯЧНАЯ**, и у первого потребителя это
было верно; ломаться стало, когда предикат разошёлся по четырём точкам — месячная колонка
прайса скопировала его дословно шестью днями позже (`c6d8a30`, 11.07). Мы **не трогаем саму
акцию и не гасим признак** — ограничиваем только срок её приложения.

**Соседняя посылка, которую легко было сломать и которую мы не сломали.** У признака
`cap_active` есть **ВТОРОЙ потребитель, к цене не относящийся**: `_sheet_low_season` читает его
как **детектор сезона** («активный кап = низкий сезон, капы существуют только в низкий»). Погаси
мы признак вместо приложения — прайс перестал бы объявлять низкий сезон на коротких сроках, и
**ни один ценовой тест этого бы не увидел**. Живая проба (`neighbours.py`):

```
1. ДЕТЕКТОР НИЗКОГО СЕЗОНА (_sheet_low_season) — читает ПРИЗНАК, а не приложение
   сетка с месячной колонкой    низкий сезон объявлен: ДА
   ТОЛЬКО суточная колонка      низкий сезон объявлен: ДА
2. МЕСЯЧНАЯ КОЛОНКА ПРАЙСА — остаётся под кепкой (колонка «month» = 30 сут по _SHEET_TERMS)
   ячейка: от 8900 ฿      | величина: 8900
   вердикт: кепка на месте
ИТОГ: все соседние посылки целы
```

## 2. ЧТО СДЕЛАНО

Предикат сведён в **ОДНО место** — `_cap_applies(q)`, и все четыре точки зовут его. Это не
косметика: два докстринга и раньше **требовали** «предикат РОВНО как в `_client_price`», то есть
совпадение четырёх копий держалось на честном слове. К исходному условию добавлен срок:

```python
_CAP_MIN_DAYS = 30      # единица кепки — «฿ за месяц (30 суток)» (price_source.json)

def _cap_applies(q) -> bool:
    if not isinstance(q, dict):
        return False
    total, cap_price = q.get("total"), q.get("cap_price")
    if not q.get("cap_active") or cap_price is None or total is None or total <= cap_price:
        return False
    try:
        return int(q.get("days")) >= _CAP_MIN_DAYS
    except (TypeError, ValueError):
        return True
```

Три решения, каждое отдельное:

1. **Порог `>= 30`, а не `> 30`** — месячная колонка прайса квотируется РОВНО на 30 суток
   (`_SHEET_TERMS = ((1,"day"), (7,"week"), (30,"month"))`), и «строго больше» выбило бы её
   из-под кепки.
2. **Срок неизвестен → судим ПО-СТАРОМУ.** На клиентском пути этой ветки не бывает:
   `pricing.sanity_days_ok` режет котировку без валидного `days` РАНЬШЕ, чем дело доходит до
   фразы (`_resolve_model_price`) — проверено тестом. Ветка существует для месячных колонок,
   месячных по построению.
3. **Признак `cap_active` не гасится** — см. забор Честертона выше.

**Откат:** `_CAP_MIN_DAYS = 1` — правило снова перестаёт спрашивать срок, поведение до 18.08.

## 4. КОРЗИНА 30–179, ГДЕ 42 % ВСЕХ ДЕНЕГ — ОТВЕТ ОТДЕЛЬНОЙ СТРОКОЙ

**Вопрос:** не держится ли на этом условии что-то в длинной корзине.

**Ответ: НЕТ, не держится ничего — и это измерено, а не выведено рассуждением.**

```
  судимых в корзине: 236; из них со сроком КОРОЧЕ 30 суток: 0
  срабатываний кепки ДО: 210 | ПОСЛЕ: 210 | РАЗНИЦА: 0
  медиана -26.3 -> -26.3 | ±15 % 30.5 -> 30.5 | ±5 % 13.1 -> 13.1 | |ошибки| 1 141 206 -> 1 141 206 ฿
  минимальный срок в корзине: 30 сут; максимальный: 156 сут
```

Причина проста и проверяема: **минимальный срок корзины и есть 30 суток**, то есть замок её
границы не задевает по построению. Все показатели совпадают побайтно.

**Честная оговорка, которая от этой правки не зависит.** В длинной корзине приложенный потолок
сам по себе остаётся **вредным в высоком сезоне** (замер 18.08 §2.4: платят на 46.1 % выше капа,
±15 % рушится с 44.2 до 12.1) и полезным в низком (−8.6 %). Это **развилка №2 владельца —
привязка кепки к сезону**, и здесь она СОЗНАТЕЛЬНО не делается: наш заход правит единицы срока,
а не расписание сезона. Числа корзины 30–179 в таблице выше — с приложенным потолком в обоих
столбцах, поэтому её строка и не двигается.
