# Правка гарда без карточек: запись в файл ничего не исполняет

**Дата:** 2026-07-29. **Репозиторий:** ПК `D:\turbobaby-bot`.
**Решение владельца:** вариант 1 — явный поимённый список из файлов гарда; каталог клона
`D:\foreign\turbobaby-manager-bot` **не открывать** (там демон, splinter, devbot и деньги).

---

## 0. ПОСЫЛКА ЗАДАНИЯ ИСПРАВЛЕНА ЗАМЕРОМ

> В ТЗ: «гард краснеет на СОДЕРЖИМОМ своего же исходника, потому что там перечислены имена
> опасных операций».

**Замером не подтвердилось.** `_decide_write()` содержимое **не читает вообще** — решение
принимается ТОЛЬКО по пути (секрет → `edit_secret`, конфиг `.claude` → `edit_claude`, вне
проекта → `write_outside`, иначе `defer`). Прямая проба: правка `pretool_guard.py` и
`test_pretool_guard.py` инструментом Edit/Write с максимально красным содержимым
(`pkill` + `rm -rf` + `DROP TABLE` + `.env` + `clasp deploy` в одной строке) → **`defer`**, ноль
карточек, ещё ДО всякой правки.

**Настоящая причина 20 карточек — ПУТЬ клона, а не содержимое.** Все 20 `write_outside` — это
файлы в `D:\foreign\turbobaby-manager-bot`, который лежит вне проекта и вне разрешённых временных
зон. Ни одна карточка за день не пришла по содержимому файлов гарда.

Строка зафиксирована отдельно, чтобы посылка не осталась в журнале как факт.

## 2. Что сделано: явный поимённый список

`pretool_guard.py`, константа `_GUARD_SOURCES` — **четыре пути, не маска и не каталог**:

```
D:\turbobaby-bot\pretool_guard.py
D:\turbobaby-bot\test_pretool_guard.py
D:\foreign\turbobaby-manager-bot\pretool_guard.py
D:\foreign\turbobaby-manager-bot\tests\test_guard_card_min.py
```

Проверка — `_is_guard_source()`, **точное совпадение нормализованного пути**. Ни маски, ни
префикса каталога: `D:\foreign\other\pretool_guard.py` (то же имя, другое дерево) и
`…\tests\test_guard_card_min.py.bak` под карве-аут **не попадают**.

Место врезки в `_decide_write` выбрано намеренно — **строго после** секретов и конфига `.claude`
и **до** проверки «вне проекта»:

```
секрет      → ask edit_secret     (карве-аут их НЕ обходит)
.claude     → ask edit_claude     (карве-аут их НЕ обходит)
_GUARD_SOURCES → defer            ← новое
вне проекта → ask write_outside
```

### Список виден В ПРАВИЛАХ, а не только в коде

Те же четыре пути продублированы в `.claude/settings.json`, `permissions.allow`, поимённо:

```
Edit(//d/turbobaby-bot/pretool_guard.py)                                 + Write(…)
Edit(//d/turbobaby-bot/test_pretool_guard.py)                            + Write(…)
Edit(//d/foreign/turbobaby-manager-bot/pretool_guard.py)                 + Write(…)
Edit(//d/foreign/turbobaby-manager-bot/tests/test_guard_card_min.py)     + Write(…)
```

Дублирование не косметика: хук возвращает решение **поверх** слоя настроек, зелёными обязаны быть
**оба**. Расхождение двух списков сторожит тест `test_guard_sources_mirrored_in_settings` —
он разбирает живой `settings.json` и требует, чтобы каждый путь из `_GUARD_SOURCES` был там
и для `Edit`, и для `Write`.

## 3. Клон manager-bot: где оказался и что решено

**Где:** `D:\foreign\turbobaby-manager-bot` — вне проекта (`_inside_project` → `False`) и вне
разрешённых зон (`_sanctioned_outside` → `False`; там только `%TEMP%\claude\**`, скретчпад и
хранилище памяти). Поэтому **каждая** запись туда спрашивала — 20 карточек за день.

**Что решено (владелец, вариант 1):** каталог целиком **НЕ открывать**. Это рабочее дерево
боевого сервера — демон, splinter, devbot, деньги; молчаливая запись туда опаснее нескольких
карточек. Открыты ровно **два** файла клона — сам гард и его тест минимума карточки.

**Что осталось красным в клоне** (проверено тестом `test_clone_directory_is_not_opened`):
`bot.py`, `splinter.py`, `moderation_bot.py`, прочие `tests/*.py`, `docs/artifacts/*.md` — всё
это по-прежнему `ask write_outside`.

## 4. ГЛАВНЫЕ ЧИСЛА — реплей той же сессии

Реплей **всех 936 решений** дня через модуль из `HEAD` и через рабочее дерево
(`decide_for_role()` → `card_or_journal()`, как в `main()`; ничего не исполнялось):

| | HEAD | НОВОЕ |
|---|---:|---:|
| карточек за день, всего | **48** | **32** |
| из них инструментами записи | **23** | **7** |
| `write_outside` | **20** | **4** |

**Было 20 карточек `write_outside` — стало 4.** Снято **16**. Оставшиеся 4 — ровно те файлы клона,
что в список не входят (чужие тесты и `docs/artifacts`), и это ожидаемо: каталог не открыт.

Ни один другой вид не изменился: `clasp` 3+1+1, `py_write` 8, `sqlite` 5, `kill` 3, `env` 4,
`edit_claude` 3 — везде дельта `+0`. Послаблений за пределами записи в четыре файла нет.

**Почему живой журнал даёт 70, а реплей HEAD — 48.** Живые 70 набирались гардом, который в
течение дня менялся (три коммита), и часть из них принята прежними версиями правил. Реплей гонит
ВСЕ решения дня через ОДНУ версию — так числа сопоставимы между собой. Сравнивать нужно пару
48 → 32, а не 70 → 32.

## 5. Исполнение НЕ ослаблено

Карве-аут живёт **только** в `_decide_write` — то есть в ветке инструментов записи. Проба:

```
pkill ngrok                                  -> ask kill
rm -rf suggest.py                            -> ask delete
sqlite3 moderation.db "DELETE FROM queue"    -> ask sqlite
cat .env                                     -> ask env
clasp deploy -i AKfycb… -V 76                -> ask clasp_deploy
python -c "import os; os.remove(chr(120))"   -> ask py_write
```

Сторожит `test_execution_is_not_weakened`. `deny` не тронут, `bypassPermissions` не включён
(`test_deny_and_bypass_untouched`), `defaultMode` остался `acceptEdits`.

## 6. Проверка

`test_pretool_guard.py`, класс `TestGuardSourcesWriteIsNotExecution` — 8 тестов:
карточки нет даже с красным содержимым (4 пути × Edit/Write/MultiEdit); каталог клона не открыт;
совпадение по ТОЧНОМУ пути, а не по имени файла; список явный и короткий (ровно 4, без `*`);
секреты и `.claude` спрашивают всегда; исполнение не ослаблено; зеркало в `settings.json`;
`deny`/`bypassPermissions` целы.

Полный гейт ПК: **2117 тестов OK (skipped 10)** (было 2109 — +8 моих).

**С первого прогона гейт был КРАСНЫЙ — 2 падения**, и это стоит записать. Оба от одной причины:
`test_live_matches_staged_once_applied` сверяет боевой `.claude/settings.json` с ПРЕДЛОЖЕННЫМ
снимком `docs/artifacts/2026-07-29-settings-clasp-temp.json`, а я добавил восемь правил только в
боевой. Второе падение (`test_live_marker_stays_empty_after_full_suite`) — каскад: оно гоняет
весь набор дочерним процессом и требует от него кода 0. Снимок досинхронизирован теми же восемью
строками, после чего гейт зелёный. Файл снимка входит в коммит.

## 7. Остаток с точкой касания

Настоящая content-шумность живёт **не** в инструментах записи, а в `Bash`: красное слово как
ДАННЫЕ по-прежнему даёт карточку — коммит-сообщение с `pkill` (17:05:08, 17:05:49), строка
журнала с ним же (17:06:37), тело **непрослеженного git-ом** `.py` (`tmp/probe_pc.py` содержит
`cat .env` → карточка `env` в 16:20:43 и 16:55:27), heredoc-запись файла
(`cat > /tmp/x.py <<'PY' …` → `delete` в 16:21:21).

Это **другой класс**: там граница проходит не по «инструмент записи», а по «данные ≠ команда»
внутри шелла — и heredoc-запись в файл формально тоже ничего не исполняет
(`pretool_guard.py:_decide_bash` / `_scan_text`). В это задание он не входил и молча не
расширялся: ТЗ прямо оставило исполнение без послаблений. По сегодняшнему дню класс стоит
примерно 8–10 карточек.
