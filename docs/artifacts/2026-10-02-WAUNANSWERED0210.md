## 2. Порог

**2130 с** — p90 из 541 промежутка за 30 суток (сотня есть с запасом). **За последние 30 суток так долго мы не
отвечали лишь в 1 беседе из 10.** Это константа `wa_watch.WATCH_SEC` с той же строкой-обоснованием в коде.
Число не круглое: это замер. p95 (4582 с) дал бы 29 тревог за 14 суток вместо 47, а без ответа остались бы те
же 5 (п.7). Если тревог окажется много, это готовый второй шаг.

## 3. Ожидание в службе wa-agent

`wa_watch.Watch` живёт в службе: его оборот зовёт `wa_agent_svc.serve` на каждом обороте цикла, но сам оборот
идёт не чаще раза в 60 с.

1. Очередь — только `mode=ro`, строки после курсора `watch_from` за последние сутки. Для каждого номера берётся
   последнее **живое входящее** (`wa_kind.kind_of` → `inbound`; реакция клиента, квитанция, правка и
   неразобранный флаг входящим не являются).
2. Прошло ≤ 2130 с — ничего. Больше — ищется наш ответ **после** этого входящего:
   - живое эхо (`echo=1`, `history=0`): реплика (не автоответ) или наша реакция с телефона;
   - `outbox` базы агента с `ts` ≥ времени входящего — ушло из темы или по «Отправить»;
   - `tg_react_out` с исходом `sent`, непустым эмодзи и `ts` ≥ времени входящего, если цель — сообщение этого
     номера.
3. Ответа нет — тревога. Строка `watch_alarm (номер, строка входящего)` пишется **ДО** Telegram в состоянии
   `sending`, потом исход: `sent`, `fail` (Telegram ответил кодом — не дошло точно; до 3 попыток на следующих
   оборотах) или `unsure` (сеть молчит — второй раз не шлём).
4. Сообщение — в «Агенты» (`AGENTS_CHAT`), без кнопок:
   `⏰ Клиент ждёт ответа 36 мин` · имя темы · `тема: https://t.me/c/…/<тема>` · «последнее сообщение клиента —
   ЧЧ:ММ (Пхукет); после него нашего ответа нет: ни с телефона, ни из темы, ни по «Отправить», ни реакцией» ·
   «агент на паузе — черновика не будет до «Продолжить»» (если на паузе) · порог и что он значит · «следующее
   напоминание по этому клиенту — только после его нового сообщения».
5. Клиент написал снова — новая строка входящего, новый ключ, и тревога возможна снова. Повтор такта ключ не
   меняет — тишина.
6. Ожидание не пишет клиенту, не снимает паузу и не зовёт модель. От `WA_AGENT_DRAFTS`, `WA_AGENT_CARDS` и
   `WA_SEND` оно не зависит, читателя `getUpdates` не заводит.

## 4. Контракт наблюдения

- **Результат:** у каждого клиента, который написал последним, наш ответ есть не позже 2130 с. Иначе — ровно
  одна тревога на это его сообщение.
- **Источник истины:** очередь входа `wa_queue.db` (живое входящее и живое эхо с телефона, включая нашу
  реакцию) и база агента `wa_agent.db` (`outbox` — ушедшее через API из темы и по «Отправить»; `tg_react_out` —
  наша реакция из темы с исходом `sent`). Имя и ссылка темы — база показа `wa_tg_mirror.db`, только `mode=ro`.
- **Способ:** раз в 60 с — последнее живое входящее каждого номера за сутки, затем поиск нашего ответа после
  него. Автоответ (отпечаток или ≤ 10 с после «первого») ответом не считается. «Не знаю, наше ли» (флаг не
  разобран) тоже не ответ: молчание источника ответом не считается.
- **Отрицательный тест:** ответили с телефона, по «Отправить», из темы, реакцией с телефона или из темы — тревоги
  нет. Повтор такта и рестарт — тревога одна. Выключатель выключен — ни таблицы, ни чтения, ни Telegram. Это
  тесты `test_answered_from_phone_silence`, `test_answered_by_press_silence`, `test_answered_from_topic_silence`,
  `test_our_reaction_from_phone_silence`, `test_our_reaction_from_topic_silence`,
  `test_repeat_tick_and_restart_one_alarm`, `test_switch_off_nothing`.

**Чего ожидание не видит (честно).** Ответ голосом по телефону, ответ с другого номера, ответ в другом
мессенджере — тревога будет. Такая тревога лишняя, но не вредная. Сообщения клиента старше суток (служба
лежала дольше) тревоги не дают. Это сознательный предел против потока сообщений после долгого простоя.

## 5. Выключатель и состояние

- `WA_AGENT_WATCH` — по умолчанию **выключен**: включает только явное `1/true/yes/on`, тем же правилом
  `flag_on`, что у остальных выключателей службы. Без ключа бота выключен словами: «выкл (флаг 1, ключа бота
  нет)». В строке старта и в сводке он стоит рядом с прочими; при включении в сводке есть «тревог ожидания
  sent=N».
- Выключен — объекта `Watch` нет: таблица не создаётся, очередь не читается, Telegram не зовётся (тест
  `test_switch_off_nothing`, мутант 19).
- Состояние — в `wa_agent.db`: таблица `watch_alarm` (`number`, `in_id`, `state`, `tries`, `msg_id`, `ts`) и
  ключ `watch_from` в `meta`. **Первый старт:** курсор встаёт на MAX(id), переписка до включения тревог не даёт
  (тест `test_first_start_backlog_silence`). **Рестарт:** ключ «номер + строка» уже лежит, второй тревоги нет;
  оборванный посреди Telegram `sending` → `unsure`, без повтора (тесты `test_repeat_tick_and_restart_one_alarm`,
  `test_restart_mid_send_no_repeat`).
