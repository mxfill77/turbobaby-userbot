## Премисы: три да/нет с адресом

### П1. «Три строки приходят из одного места, у каждой своя метка времени» — **ПОЛОВИНА ДА, ПОЛОВИНА НЕТ**

**Место одно, и это ДА.** Документ `shtab_vitrina` папки мозга (`vitrina_pc.py:220`
`SHTAB_NODE = "shtab_vitrina"`). Пишет его **Штаб**; полоса ПК в него не пишет ни одной боевой
веткой — витрина его только ЧИТАЕТ (`vitrina_pc.py:216–218`, комментарий у самой константы).
Читает дорогой ЯЩИКА: перечисление папки + чтение по file id
(`vitrina_pc_run.read_shtab`, строки 577–617 → `shtab_box_run.read_folder` / `read_doc_text`),
потому что имя `shtab_vitrina` в реестре моста не зарегистрировано вовсе.

**«У каждой своя метка» — НЕТ, и это существенно.** Метка в узле **ровно одна на все три**:

- `vitrina_pc.py:225` — `STAMP_RE = ^\s*дата\s*=\s*(\d{4}-\d{2}-\d{2})\s*$`;
- `vitrina_pc.py:373–377` (`parse_shtab`) — штамп берётся **только до первого маркера**
  (`if cur is None`) и **только первый** (`and not out["day"]`); внутри разделов строка
  `дата =` не ищется ни одной веткой;
- живой замер 20.09 до правки: в теле узла строк, начинающихся со слова «дата», — **1**.

Следствие названо, потому что оно — готовый ложный диагноз: поправить одну строку и оставить
две старыми **нечем**. Либо свежими объявляются все три, либо ни одна. Заход 68g правит все
три сразу — не по щедрости, а потому что третьего варианта у механизма нет.

### П2. «Метка возраста считается от времени записи Штаба, а не от вывода витрины» — **ДА, с названной оговоркой**

Адрес: `vitrina_pc.shtab_words` (строки 407–432) — `old = days_between(day, today)`, где
`day` — штамп `дата=` **из узла Штаба**, `today` — день сборки витрины. Время вывода в
вычитании не участвует; сборка даёт только «сегодня».

Оговорка, которой задание не называет: это **самообъявленная дата в теле документа**, а не
время записи в Drive. Штаб, поправивший слова и забывший штамп, останется «старым»; Штаб,
поправивший один штамп, станет «свежим» при вчерашних словах. Порога отказа у узла нет —
только возраст вслух (`vitrina_pc.py:421–425`, правка 17.09, правило R1 `node_age_pc`).

### П3. «Записать может доверенный посредник, и секреты агентскому скрипту не видны» — **ДА**

Адрес: `brain_writer.apply` (строка 603) → `_config(env)` (строка 616) → `_env_file`/`_config`
(строки 99–124). Конфиг с секретами читает **сам процесс писателя**; вызывающему скрипту
достаются только `mutate`, адрес и печать результата. Замер по нашим скриптам:
`grep -c "load_env|BRIDGE_TOKEN|BRIDGE_URL|\.env"` → **0, 0, 0, 0** (`zapis.py`, `sborka.py`,

## 5. Возраст числом: было 11, стало 0

Штамп `дата = 2026-09-09` → `дата = 2026-09-20`.
`vitrina_pc.days_between("2026-09-09", "2026-09-20")` = **11**;
`days_between("2026-09-20", "2026-09-20")` = **0**.

```
now   → [Штаб обновлял 2026-09-20, 0 сут назад] Тренажёр. Источник набора сделан 09–12.09, …
goal  → [Штаб обновлял 2026-09-20, 0 сут назад] Этап 3, оркестратор как управляемый агент. …
stuck → [Штаб обновлял 2026-09-20, 0 сут назад] Карточки заявок едут к владельцу вопреки …
```

Знак `⚠️` (порог `SHTAB_STALE_DAYS = 3`) стоял у всех трёх, теперь — **0 раз из 3**.

**ПОПРАВКА К ЗАДАНИЮ, И ОНА НЕ КОСМЕТИЧЕСКАЯ.** Задание говорит «10 сут назад»; живой замер
20.09 даёт **11**. Расхождение не ошибка измерения: 09.09 → 19.09 это десять суток, и число
«10» верно на **19.09**, то есть текст задания собирался сутками раньше исполнения. Печатать
в артефакте «было десять» значило бы переписать факт под задание — тот самый класс, ради
которого весь этот заход и заведён.
