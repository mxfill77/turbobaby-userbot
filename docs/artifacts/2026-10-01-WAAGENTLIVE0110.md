## 2. Черновик и кнопки — нет ничего, путь ясен

**Сейчас:** у бота WhatsApp нет ни одного входящего пути: `getUpdates` / `callback_query` в
`wa_tg_mirror.py`, `wa_webhook.py`, `wa_send.py` — 0, `setWebhook` тоже 0. Отсюда следствие:
поток обновлений бота свободен, но читать его может **ровно один** процесс (второй получит 409).
Образец кнопок есть у Splinter: `CallbackQueryHandler` по префиксам (`bot.py:1513–1518`), ответ
на протухший запрос `_btn_answer`. Это чужой контур, его не трогаем.

**Как сделать:**
- **Карточка.** `sendMessage` в -1003999596406 с `reply_markup`, кнопки «✅ Отправить», «✏️ Исправить»,
  «✖️ Не нужно», `callback_data = wa:<действие>:<draft_id>:<версия>`. В карточке: имя · номер, ссылка
  на тему клиента в группе показа, текст черновика, пометка «нужен человек: …», если есть. Нужно,
  чтобы бот был **участником** группы «Агенты» (сейчас его там, по-видимому, нет — П3). Права
  админа не нужны: нажатия на свои сообщения бот получает при любом режиме приватности.
- **Приём.** Новая служба — единственный читатель `getUpdates` бота (`allowed_updates =
  callback_query, message`). Служба показа его не вызывает, конфликта нет.
- **Атомарный захват.** `UPDATE drafts SET state='claimed', decided_by=?, decided_at=? WHERE id=? AND
  state='pending' AND ver=?`. Решает `rowcount == 1`. Остальные получают `answerCallbackQuery`
  со словами «уже решено: <имя>, ЧЧ:ММ — <исход>». Замок стоит в базе, а не в памяти: он
  переживает рестарт и двойную доставку обновления.
- **Одно нажатие — одно сообщение.** Победитель сначала перепроверяет очередь: если после черновика
  пришло эхо или новое входящее, черновик снимается и не отправляется. Если нет, служба пишет
  `sending` и только потом вызывает `wa_send.send_text`. Затем `sent` (с `wamid`), `not_sent`
  (с причиной в карточке) или `unsure`. На старте `sending` становится `unsure`, повтора нет (как
  `_init_state` службы показа). Карточка правится (`editMessageText`) на исход и имя нажавшего,
  кнопки снимаются.
- **«Исправить».** Сотрудник отвечает реплаем на карточку своим текстом, и появляется версия +1 с
  теми же кнопками. «Отправить» шлёт текст человека дословно, модель его не трогает. Старая
  версия кнопок отвечает «устарело».
- **Кто вправе нажимать.** User id менеджеров в коде и журналах **0** (AGENTGROUP3009 §2). До
  списка от владельца нажимать могут только id владельца, а id прочих нажавших пишутся в журнал.

## 5. Ответ с телефона — признак есть в очереди

- **Признак.** В `wa_inbox` появилась строка с `from_number` = клиент, `echo=1`, `history=0`,
  `msg_type<>'status'`, `id >` последнего входящего, по которому писался черновик. Эхо приходят
  полем Coexistence `smb_message_echoes`, номер клиента кладётся из `to` (`wa_webhook.py:559–572`).
  Живьём за сутки таких строк **23** у 6 номеров.
- **Действие.** Черновик → `superseded`, кнопки сняты, в карточке «снят: ответили с телефона ЧЧ:ММ».
  Новое входящее того же клиента до нажатия → `stale`, и пишется новый черновик. У клиента в каждый
  момент не больше одного черновика.
- **Своё не снимает себя.** По документации Meta сообщения, отправленные через API, эхом
  `smb_message_echoes` не возвращаются (эхо — только от приложения). Для страховки служба помнит
  `wamid` своей отправки, и строка с этим `wamid` черновик не снимает (`wamid` в очереди
  уникален, `wa_webhook.py:148`). Живьём это **не проверено**.
- **Оставшаяся щель.** Эхо пришло между перепроверкой и POST. Окно — секунды (такт 5 с). Его
  закрывает только человек: сотрудник видит в карточке «отправлено <имя> ЧЧ:ММ».

## 7. План постройки (одна страница)

**Устройство.** Новая служба `wa-agent` (`wa_agent.py`, своя `wa_agent.db`, свой `wa_agent.log`,
свой юнит) в репозитории сервера. Это не Splinter и не служба показа: показ остаётся показом,
Splinter — своим контуром. Очередь, архив и база показа открываются только `mode=ro`. В журнал идут
только id строк, состояния и числа.

**Такт 5 с:**
1. Новые живые входящие (`id > курсор`).
2. Пауза 60–90 с после последнего сообщения клиента: клиенты пишут очередями.
3. Если уже есть эхо, ничего не делать.
4. Иначе собрать контекст: `wa_history`, факты кодом, маскировка, знания.
5. Модель возвращает JSON `{text, lang, handoff[], why}`.
