## Контракт дверей (сверен с кодом `ContractDoor.js` и маршрутами GET в `Bridge.js`)

**`contract_find`** (GET `action=contract_find`). Источник — реестр «Договоры — реестр подписей (TB e-Sign)», лист
«Реестр». Колонки находятся по имени заголовка. Если нужной колонки нет, ответ — `no_column` с перечнем недостающих.
- **Фильтры.** Нужен хотя бы один из телефона, имени или байка, иначе `no_filter`: реестр целиком дверь не отдаёт.
  - `phone` — сравнение по последним 9 цифрам в колонках «Телефон» и «Ник (Social contact)». Меньше 9 цифр → `bad_phone`.
  - `name` — слова имени в любом порядке; со слова из 3 букв допускается начало слова.
  - `bike` — по номеру через `plateOf_`, как у `tx_find`.
  - `date_from`/`date_to` — включительно по «Дата договора»; если она пуста, берётся «Документ создан», источник
    отдаётся в `date_src`. Отказы срока: `bad_date`, `bad_span`.
- **Ответ по каждой строке:** `row`, `doc_id`, `client`, `contract_date`, `date_src`, `status` (как в реестре), `signed`,
  `signed_at`, `bike`, `phone`, `pdf_id`, `matched_on`. `pdf_id` извлекается из ссылки `/d/…` или `?id=`, из богатого
  текста или из формулы HYPERLINK. Email клиента в ответ не попадает.
- **`checked`:** `rows_scanned`, `span_from`/`span_to` (по всему реестру либо по названному сроку), `matched`, `signed`,
  `returned`, `truncated`, `undated`.
- **Исход:** `one` (ровно один подписанный, он в `pick`) · `ambiguous` (подписанных несколько — неизвестно, первый не
  выбирается) · `none_signed` · `none`. Подписанным считается только статус «ПОДПИСАН»; регистр и пробелы не важны.
  «ОТПРАВЛЕН», «ОТОЗВАН», «ПОДПИСАН ЧАСТИЧНО» отдаются как есть с `signed:false`.
- **Потолок:** по умолчанию 20 строк, максимум 100. Исход считается по всем найденным строкам.

**`contract_pdf`** (GET `action=contract_pdf&id=…`).
- **Порядок проверок:**
  1. Формат id: от 25 знаков `[-\w]`, иначе `bad_id`.
  2. id есть в колонке «PDF (подписанный)» реестра, иначе `not_in_registry`. Этот отказ выносится до обращения к Drive.
  3. Строка реестра «ПОДПИСАН», иначе `not_signed` с перечнем строк и статусов.
  4. Файл не в корзине, иначе `trashed`.
  5. Один из родителей — папка подписанных, иначе `not_in_signed_folder`.
  6. mime `application/pdf`, иначе `not_pdf`.
  7. Размер не больше 15 МБ, иначе `too_large`.
- **Ответ:** `id`, `name`, `mime`, `size`, `sha256`, `content_b64`, `row`, `client`, `contract_date`, `signed_at`.
- **Адреса** — Script Properties `ESIGN_REGISTRY_ID` и `ESIGN_SIGNED_FOLDER_ID`. Если свойство не задано, ответ —
  `no_registry_config` / `no_signed_folder_config`.
- Записей нет ни в лист, ни в Drive, ни в свойства.

**`bridge_client.py`.** Оба метода ходят только через `_call` (GET) и не входят в `_REDZONE_ACTIONS`. `contract_find`
передаёт в мост только непустые фильтры. `contract_pdf` декодирует base64 и сверяет длину и sha256 с ответом моста:
совпало → `verified: true`, не совпало → `ok:false, error:"pdf_mismatch"`.
