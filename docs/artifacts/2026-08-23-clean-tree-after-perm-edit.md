# Чистое дерево после правки разрешений 23.08.2026: коммит `1a21072` снял блок авто-фетча

Ось захода — обслуживание нас самих. Правку правил сделала **не эта сессия**: её внесла сессия
Dispatch 22.08 (разбор — [`2026-08-23-perm-rule-form-edit.md`](2026-08-23-perm-rule-form-edit.md)),
здесь она только **сверена и закоммичена**. Ни одно правило не тронуто, область действия не
менялась, резервная копия не удалена.

## 1. Дифф: изменилась ФОРМА, не область

`git diff .claude/settings.json` → 12 вставок, 12 удалений, один файл. Три независимых счёта:

| ось | HEAD (`de48ed6`) | рабочая копия |
|---|---|---|
| строк формы `Write(` | **12** | **0** |
| строк формы `Edit(` | **12** | **24** |
| multiset путей в скобках | 12 уникальных, каждый **×2** | 12 уникальных, каждый **×2** — совпал дословно |

Путь не сменился **ни один**: `Write(X)` стал `Edit(X)` там, где `Edit(X)` уже стоял рядом, —
значит в файле теперь 12 пар дублей (allow 8, ask 4), а множество эффективных правил движка то
же самое. Строк вне блока разрешений дифф не тронул: `git diff -U0`, отфильтрованный от
`Edit(`/`Write(`, пуст. JSON валиден (`json.load` → allow 37, ask 49, deny 10; дублей allow 8,
ask 4 — ровно двенадцать).

**Решение по коммиту: коммитить.** Условие остановки («изменился хоть один путь») не наступило.

## 2. Секретов в файле нет

Скан `token|secret|password|api_key|bearer|BEGIN … PRIVATE KEY|[A-Za-z0-9_-]{32,}` даёт **одно**
совпадение — `"MAX_THINKING_TOKENS": "31999"`, бюджет мышления. Ключей, токенов и паролей нет.
Адрес VPS и путь к ssh-ключу в файле есть (правило `Bash(ssh -i ~/.ssh/… root@…)`), но это
**материал HEAD**, диффом не тронутый: коммит не вносит их, они лежат в git с 23.07.

## 3. Коммит

```
1a21072  правила разрешений: 12 записей Write(путь) переведены в Edit(путь) — коммит чужой правки
```

Сообщение называет автора правки прямо: сессия Dispatch 22.08, mtime файла **17:40:39 UTC**
(премиса задания говорила «около 17:48 UTC» — расхождение 7 мин, поправлено по mtime). Запушен:
`de48ed6..1a21072  main -> main`, `git rev-list --left-right --count origin/main...HEAD` → `0 0`.

**Резервная копия цела и проверена как откат:** `tmp/permform_0823/settings.json.bak-2026-08-23-permform`,
sha256 `38d04c52…` — посимвольно равна `git show 1a21072^:.claude/settings.json`. Не удалялась.

## 4. Авто-фетч: решение ДО и ПОСЛЕ

Мерено ЖИВЫМ кодом — `pc_orchestrator.git_ff_pull_tick()` через пробу
`_scratch_permclean_0823/probe_autofetch.py` без побочных эффектов (лог в temp, признак состояния
в памяти, `_cowork`/`net_witness` — заглушки, `pull` запрещён).

| момент | git-вызовы, которые сделал авто-фетч | решение | состояние |
|---|---|---|---|
| **ДО коммита** | `rev-parse --abbrev-ref HEAD` → `status --porcelain` → `diff --name-only HEAD` | `'грязно — пропуск'` | `dirty:.claude/settings.json` |
| **ПОСЛЕ коммита** | те же 2 + `fetch origin` + `rev-parse HEAD` + `rev-parse origin/main` + два `merge-base --is-ancestor` | `'впереди origin — пропуск'` | `ok` |
| **ПОСЛЕ push** | те же 2 + `fetch origin` + два `rev-parse` | `''` (уже актуально) | `ok` |

Доказательство не в слове «пропуск», а в **длине цепочки вызовов**: до коммита авто-фетч
упирался в ворота чистоты вторым шагом и до сети НЕ ДОХОДИЛ; после — `fetch origin` отработал и
сравнение с `origin/main` состоялось. Боевой `pc_orchestrator.autofetch.json` держал
`{"cond": "dirty:.claude/settings.json"}` с 22.08 17:45:29 UTC — на ближайшем тике демон сменит
его на `ok` и напишет в журнал «рабочее дерево снова чистое — пропуск снят».

## 5. Сколько раз за двое суток авто-фетч пропускал обновление из-за грязной копии

Окно **2026-08-20 18:09 → 2026-08-22 18:09 UTC**, источник — боевой `pc_orchestrator.log`
(время в логе локальное, UTC+7). Счёт: `_scratch_permclean_0823/count_dirty_skips.py`.

**Два эпизода:**

| # | когда (UTC) | файлы-причины | чем снят |
|---|---|---|---|

Три оговорки, без которых число врёт:

1. **Эпизод ≠ пропуск.** Строку рождает `_autofetch_note` только на СМЕНЕ состава грязного;
   внутри эпизода пропуск повторяется молча каждые `GIT_PULL_SEC` = 300 с. Два эпизода — это
   два ЗАХОДА грязи, а не два тика.
2. **Грязь короче 5 минут не видна вовсе** — тик мог просто не совпасть с окном грязи.
3. **Демон наблюдал не непрерывно**: 796 строк лога за окно, крупнейшая пауза **3 ч 24 мин**
   (22.08 05:36 → 08:59 local, сон ПК). Пустое окно у спящего ПК означает «не наблюдали».

**Это класс, а не случай.** За всю историю живого лога строк «грязно» 461, но 434 из них — до
дедупа (29.07), когда строка писалась КАЖДЫЙ тик. Настоящих эпизодов с поимённым списком —
**27 за 25 суток** (29.07 16:55 → 23.08 00:45 local), ≈1.1 в сутки. Частота файла-причины:

## 6. Что НЕ сделано и почему

* Правила разрешений не правились — прямой запрет задания; они уже приведены к нужной форме
  сессией Dispatch и проверены её же отрицательными тестами.
* Резервная копия не удалена — прямой запрет задания, она и есть откат.
* Процессы не трогались, ничего не перезапускалось: демон подхватит чистое дерево сам, штатным
  тиком авто-фетча.
* Остатки Dispatch-разбора (слепая проба слоя `ask`, форма пути `//d/…`) не проверялись —
  чужой заход, здесь не предмет.
