## 3. Нужен ли он — ДА, и ничего не дублирует

Проверено с двух сторон.

На сервере:
```
git cherry -v origin/main HEAD
+ 3b0368cc353a20d3a9421a0eae9248bd062b163a reviewer: ревизор качества черновиков …

##### файл: reviewer.py       → в origin/main такого файла НЕТ
##### файл: test_reviewer.py  → в origin/main такого файла НЕТ
```

В отгруженном ПК-репозитории (рабочая копия, индекс, **вся история всех веток**):
```
ls: cannot access 'reviewer.py': No such file or directory
в индексе git: []
во всей истории: 0 коммитов
depcheck  →   (нет ни одного файла)
yearcheck →   (нет ни одного файла)
jcheck    →   (нет ни одного файла)
run_reviewer → (нет ни одного файла)
модулей с именами review/check/qual/audit нет
```

**Прямой ответ: коммит нужен.** Это законченный модуль на 267 строк с 39 юнитами, которого нет
нигде, кроме этого забытого клона. Функциональность под другим именем не реализована — ни одного
совпадения по её характерным именам.

⚠️ **Но взять его «как есть» нельзя.** Он стоит на базе двухнедельной давности (192 коммита
позади) и опирается на `moderation_ipc` и зеркало `suggest._bike_key` — оба с тех пор менялись.
Нужен перенос патчем + прогон тестов против текущей main, а не слепой `cherry-pick`.

⚠️ **И это не всё.** В том же клоне **13 незакоммиченных файлов**, среди них правки
`moderation_bot.py`, `pc_orchestrator.py`, `test_pc_orchestrator.py`. Их содержимое я не
разбирал — ТЗ спрашивало про коммит. Но удалять клон, не посмотрев их, нельзя.

## 4. Ключ доступа: что есть и чего не хватает

```
~/.ssh:  authorized_keys (для ВХОДЯЩИХ), known_hosts — и всё
публичных ключей НЕТ — ключ придётся создать
проба github: git@github.com: Permission denied (publickey).
22/tcp ОТКРЫТ                      (фолбэк на ssh.github.com:443 не нужен)
репозиториев на сервере: mxfill77/turbobaby-manager-bot, mxfill77/turbobaby-userbot
```

**Работает ли ключ доступа как способ убрать токен совсем — да, но пары ключей на сервере нет
вообще.** Ситуация не «ключ есть, но не авторизован», а «ключа нет».

**Что нужно, по шагам:**

1. Создать пару на сервере: `ssh-keygen -t ed25519 -f ~/.ssh/gh_manager -N ""` и вторую
   `~/.ssh/gh_userbot`.
2. **Два ключа, а не один — это принципиально.** Deploy key на GitHub привязан к ОДНОМУ
   репозиторию, и один и тот же публичный ключ нельзя завести на двух: GitHub отклонит его как
   уже использованный. Репозитория здесь два.
3. Владелец добавляет каждый публичный ключ в Settings → Deploy keys нужного репозитория, с
   галкой **Allow write access** (иначе push не пройдёт).
4. `~/.ssh/config` с двумя псевдонимами хоста:
   ```
   Host gh-manager
     HostName github.com
     User git
     IdentityFile ~/.ssh/gh_manager
     IdentitiesOnly yes
   Host gh-userbot
     HostName github.com
     User git
     IdentityFile ~/.ssh/gh_userbot
     IdentitiesOnly yes
   ```
5. Перевести адреса: `git remote set-url origin git@gh-manager:mxfill77/turbobaby-manager-bot.git`
   (и аналогично для трёх клонов userbot).
6. Проверить `git ls-remote` и `git fetch` во всех, затем `git push` на тестовой ветке.
7. **Только после зелёного** — убрать `/root/.git-credentials` и **отозвать токен на GitHub**
   (иначе он останется валидным, просто неиспользуемым).

Альтернатива — один SSH-ключ на **аккаунт** вместо deploy-key: работает для всех репозиториев
сразу, но даёт доступ ко всему аккаунту. Deploy-keys уже́ по правам, поэтому предпочтительнее.

Шаг 3 — **действие владельца в браузере**, автоматизировать его я не могу.

## 5. Предлагаемый порядок уборки — НЕ ВЫПОЛНЯЛСЯ

Сначала спасаем работу, потом убираем. Ничего не удаляется, пока не выполнен пункт 1.

1. **Спасти `_pcport185`.** Снять патчем `git format-patch 2d58e9f..HEAD` → перенести
   `reviewer.py` + `test_reviewer.py` в актуальный ПК-репозиторий, прогнать тесты против текущей
   main, починить расхождения с изменившимся `moderation_ipc`/`_bike_key`, отгрузить. Отдельно
   разобрать 13 незакоммиченных файлов: что там — дубли уже отгруженного или потерянная работа.
2. **Разобрать `_pcport_userbot_185`.** Неотгруженного нет, но есть два незакоммиченных каталога
   с эмуляцией путей ПК (`D:\turbobaby-bot/`, `_emu_d_turbobaby-bot/`). Убедиться, что там только
   артефакты прогонов, — и клон можно снимать.
3. **Снять `baseline-origin-wt` ПРАВИЛЬНО.** Это worktree: только `git worktree remove`, иначе
   в основном репозитории останется висячая регистрация. Неотгруженного нет, `7af280c` — предок
   `origin/main`, терять нечего.
4. **Убрать `_pcport185` из `.gitignore`** (строка 48) — после того как каталога не станет,
   правило станет мусором и будет прятать возможные будущие клоны с тем же именем.
5. **Ключ доступа** — по шагам раздела 4, и лишь в самом конце отзыв токена.

## Остатки

1. Порядок из раздела 5 — на исполнение отдельной задачей.
2. Шаг «добавить deploy key» требует владельца: это браузер.
3. Токен по-прежнему валиден и лежит в `/root/.git-credentials` (600) — до шага 7 раздела 4.
