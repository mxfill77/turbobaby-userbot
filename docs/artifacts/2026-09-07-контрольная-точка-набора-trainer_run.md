## 2. Что сделано

### 2.1 Единица записи — ЗАКРЫТЫЙ КЕЙС, а не круг (п.1 задания)

Тело «все круги одного кейса + его исход по критерию» вынесено в `run_one_case` и отдаёт
САМОДОСТАТОЧНУЮ запись: `results` (круги с черновиками и чеками), `plan` (класс, круги, нужное
большинство, зелёные/красные/неизвестные, прощённые), `checks_ok`/`checks_all`, `failed`,
`unknown`. Раньше этого места исхода не существует — критерий F решает ПОСЛЕ всех кругов
(большинство ≥2 из 3), и половина кругов, записанная как исход, дала бы зелёное там, где решения
ещё нет, либо красное у кейса, который критерий зачтёт. Позже пересчитывать уже нечего: всё, чем
кейс входит в вердикт, лежит в этой записи.

Голден `test_tochka_stavitsya_posle_keisa_a_ne_posle_kruga` читает файл точки ИЗНУТРИ каждого
круга и требует ровно `[0, 0, 1, 1]` на двух кейсах по два круга.

### 2.2 Точка привязана к основанию ЦЕЛИКОМ (п.2 задания)

`point_basis` собирает **восемь** полей, а не названные четыре — четыре из задания плюс три,
без которых обещание «эти кейсы уже померены» не держится:

| поле | зачем |
|---|---|
| `commit` | назван заданием |
| `corpus` + `corpus_sha` | назван заданием |
| `runs` | назван заданием |
| `criterion_id` + `criterion` (ТЕКСТ правила) | назван заданием; текст, а не только ид: смена `CLASS_RUNS` или правила большинства меняет текст и убивает точку |
| `tree` = sha256 `git diff HEAD` | **сверх задания.** Коммита мало: python грузит модули С ДИСКА, и на грязном дереве код коммитом не опознаётся. Берём весь патч, а не список имён: дважды правленный файл даёт тот же список путей и РАЗНЫЙ код |
| `ph` = sha256 подстановок | **сверх задания.** Даты уезжают САМИ (месяц в `placeholders`, окно через границу сезонов — из живой таблицы периодов). Кейс, померенный на других датах, — другой замер |

Расхождение ЛЮБОГО поля → набор ЗАНОВО, причина НАЗЫВАЕТСЯ вслух в stdout (`ТОЧКА СБРОШЕНА —
НАБОР НАЧАТ ЗАНОВО: …`) и ложится в САМУ запись вердикта полем `point_reset`. Незнание (`?` у
отпечатка дерева или подстановок) совпадением НЕ считается ни разу, даже когда `?` стоит с обеих
сторон: два «не знаю» — это не «то же самое», а два неизмеренных факта.

**Прежний набор НЕ стирается.** Наборы лежат в файле ПО КЛЮЧУ ОСНОВАНИЯ (`sets`), смена основания
заводит набор рядом, а не поверх; возврат на прежнее основание находит прежний набор и
доигрывает его.

**Красный и «неизвестно» ложатся в точку наравне с зелёным.** Точка — запись СОСТОЯВШЕГОСЯ
замера, а не механизм повтора: перегонять красный кейс на возобновлении значило бы перекатывать
лотерею головы (измеренную 4.3% на круг, `a5f799a`) до нужного исхода.

Запись атомарна (`tmp` + `os.replace`): убитый посреди записи процесс оставляет прошлую точку
целой, а не половину файла.
