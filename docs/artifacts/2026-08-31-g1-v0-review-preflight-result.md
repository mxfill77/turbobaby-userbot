# G1 — preflight review-only транспорта V0

**Статус:** `STOP` до нового решения владельца.  Это не отменяет локальный
V0-result и не меняет его статус: `PROVEN_LOCAL`; независимая приёмка остаётся
`UNKNOWN`.

## Проверенные факты

- Выбранный маршрут — A: один локальный review-only commit/branch, без remote,
  push, запуска кода или изменения runtime.
- В исходном mirror присутствуют ровно восемь разрешённых файлов из G1-spec.
- SHA-256 и размеры всех восьми файлов сняты read-only до начала транспорта.
- Redacted scan не нашёл credential-паттернов: private key blocks, bearer
  credentials и credential assignments отсутствуют.
- В `bundle.json` обнаружено одно поле `workspace_root` с абсолютным Windows
  путём. Значение не выводилось и не копировалось в этот артефакт.
- Локальная review-ветка и отдельный worktree не созданы; Git history и
  рабочее дерево не менялись.

## Почему это STOP

G1-spec запрещает доставлять пакет с абсолютным путём. Удалить или заменить это
поле в копии можно только ценой изменения одного из восьми исходных артефактов:
тогда reviewer получил бы уже производный пакет, а не ровно тот V0 case, для
которого существует `V0_RESULT_PACKET.json`. Выдать такую копию за независимую
приёмку исходного case было бы неверно.

Создание commit с исходным файлом, напротив, сохраняло бы доказательство, но
передавало бы локальный абсолютный путь в Git-пакет, что не входит в уже данное
разрешение на redacted preflight.

## Безопасные продолжения

1. Отдельно разрешить передачу именно этого существующего локального пути в
   локальном review-only commit без remote/push.
2. Отдельно разрешить новый V0 run на нормализованном производном пакете;
   это будет новый case, а не подтверждение прежнего.
3. Оставить независимую приёмку исходного V0 case как `UNKNOWN`.

До одного из этих решений не создаются commit, branch, attachment, Drive-объект
или новый запуск H1/V0.
