pretool_guard: незнакомая команда, python без внятной цели (stdin/heredoc `python3 - <<EOF`,
неизвестный -m, нечитаемый .py, кривое квотирование) → defer (решение None, конверта и пуша НЕТ);
конверт «не распознал операцию» и дедуп ×N из main() упразднены (хелперы дедупа оставлены —
их контракт держит test_guard_inbox). Красное гарда — ТОЛЬКО доктринальный список: RED_TOKENS
(живые таблицы/CRM/деньги), файл секретов, SQL-write вне memory.db, kill/stop боевых процессов,
PID 1; clasp/массовые удаления/git-force держит ask/deny-слой settings (гард не дублирует).
Доктринальное красное при этом УСИЛЕНО — закрыты две дыры, которые открылись бы с ambiguous-defer:
(а) sqlite-write теперь ловится и в heredoc/stdin — проверка поднята ДО ambiguous-выходов (шаг 1б
_analyze); (б) ambiguous-звено компаунда не заслоняет red-скан читаемой части: ambiguous копится
флагом, red/sqlite проверяются после чтения всего читаемого (`python3 red.py && python3
нет_такого.py` → red, а не defer). Сбой классификации целиком → defer (красное держат settings);
fail-safe разбора прежний (сбой разбора цепи → скан по сырой команде, краснее).
