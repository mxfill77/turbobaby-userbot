## 2. Где живут интервалы и нужна ли правка таблицы

- **Интервалы в км** — блок `SERVICE_INTERVALS` в узле мозга `knowledge_base` (в нём `bearings` нет, проверено по
  копии #91) и фоллбэк кода `_SVC_INTERVALS_FALLBACK`. `_service_interval` берёт вид из книги, а при его
  отсутствии — из фоллбэка. Поэтому **подшипники работают без правки книги**: 20 000 из кода.
  - Правка книги по желанию: строка `"bearings": 20000,` в блок. Объект — узел `knowledge_base`, зеркало git —
    `docs/knowledge_base.md` на VPS. Откат — убрать строку. **Не применено**: боевая запись запрещена заданием.
- **Полгода** — константа `service_due.MONTHS = 6`, в таблицах её нет.
- **Живая таблица НЕ правится и правка НЕ нужна.** Регистр подшипников — своя таблица бота (Bot Data
  «обслуживание»), мост уже принимает любой `service_type` (#89 §5.1).
  - Вариант «как фильтр в Лист1» — только по «да» владельца: новая колонка Лист1 «ТО подшипники» справа от L.
    Мост: чтение в `ReadFleet.js` + запись в `setFleetService_` + выкладка (clasp — красная, серверная полоса).
    Откат — снять колонку и выкладку.
  - Даты замены в таблицах нет вовсе. Честная дата потребует колонки «дата замены» рядом с I–L (тот же путь и
    те же красные ходы) либо записи даты в `note` строки «обслуживание» при каждой замене. Ветка пишет
    `замена ГГГГ-ММ-ДД` в `note` пока только у подшипников, а читает дату из «событий». **Не применено.**
