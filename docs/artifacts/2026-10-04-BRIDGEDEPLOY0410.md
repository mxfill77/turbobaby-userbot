**Почему `clasp deploy -i`, а не `redeploy`.** На ПК стоит clasp **2.4.2**; `redeploy` есть только в clasp 3.
Исходник `deploy.js` 2.4.2 сверен до вызова: с `deploymentId` команда зовёт `deployments.update` того же
развёртывания, с `-V` новую версию не создаёт, без `-d` описание стало бы пустым — поэтому `-d` передан.
Голый `clasp deploy` без `-i` создал бы новое развёртывание со сменой адреса — не вызывался.

**Развилка владельца по папке (код двери не трогался):** `contract_pdf` пускает файл, только если среди его
НЕПОСРЕДСТВЕННЫХ родителей есть `ESIGN_SIGNED_FOLDER_ID` (`ContractDoor.js`, проверка `file.getParents()`).
А e-Sign раскладывает PDF по «Подписанные/ГГГГ/ММ». Отсюда:
- свойство = «Подписанные» `12DuYr…` → **каждый** `contract_pdf` откажет `not_in_signed_folder`;
- свойство = «10» `1TXons…` → пройдут только октябрьские 10 PDF; сентябрьские 30 откажут, с 1 ноября
  откажут все новые;
- чинится только кодом двери (принимать папку подписанных среди предков) — это отдельная сборка и выкладка.

**Почему не записано:** у Apps Script API нет метода для свойств проекта, двери записи `ESIGN_*` в мосту нет
(`setProperty` в коде — только служебные ключи мозга и `BOT_DATA_SHEET_ID`), правка кода запрещена. Запись —
руками владельца: редактор проекта «TurboBaby Bridge» → ⚙ «Настройки проекта» → «Свойства скрипта».
