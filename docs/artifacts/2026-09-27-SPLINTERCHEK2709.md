    эта цель их НЕ трогает, они названы остатком» (`odo_ceiling.py:47–48`). 27.09 — ровно этот остаток.
- **Одно ОТКРЫТОЕ.** Даже 19864 против 19130, подтверждённых в 04:45:05, — это +734 км за 1 ч 12 мин: байк в

## 4. Как ввести правило владельца — ответ «можно», с ценой

Правило владельца: «на картинке читать сумму и задачи по тексту и, если что, уточнять». Оно ложится в код без
нового денежного пути и без правки моста:
- чтение чека — **новая** функция зрения на тех фото, где промпт байка уже сказал `receipt`;
- решение «ясно / спросить» — чистая функция;
- запись работ — через уже существующие двери (строки «события», кнопки фиксации группы B, дверь масла).

Каждая из этих дверей пишет по «да» доверенного. Одно решение код сам не примет: **куда класть сумму** (§5.1, п.6).

## 5. Предложение (только предложение, кода нет)

### 5.1. (а) Чек на фото — прочитать итог и строки работ, назвать одним сообщением, спросить «верно?»

1. **Когда.** В `_handle_servicing` после цикла зрения (9414–9440), **до склейки** (9441). Если хоть у одного
   снимка `kind == "receipt"`, этот снимок читается второй раз — новым промптом чека обслуживания. Склейка не
   меняется: чек разбирается отдельно, и потеря вида в 7494–7498 его больше не касается.
   - Цена — один вызов зрения на снимок чека. По замеру §3.3 это 2 вызова за 28 суток.
2. **Промпт** `VISION_SERVICE_RECEIPT_SYSTEM`, отдельный от денежного. Денежный `VISION_RECEIPT_SYSTEM` не
   трогается, промпт байка байт-в-байт прежний. Поля:
   - `total` и `total_confidence`;
   - `currency`;
   - `lines`: `[{text, amount}]` — строки как на чеке, тайский допустим;
   - `shop`, `date`;
   - `plate` — номер байка, если есть на чеке;
   - `readable`.
3. **Решение — чистый модуль** (например `receipt_read.py`, импорт только `re`):
   `verdict(rec, bike, known_works) → CLEAR | ASK | UNREADABLE` плюс перечень причин сомнения.
   **ASK**, если выполнено хоть одно:
   - `total_confidence != high`;
   - сумма строк ≠ итогу (разница ≥ 1 ฿);
   - валюта не THB;
   - номер на чеке ≠ байку темы;
   - строк нет;
   - дата чека старше N суток (N — решение Штаба);
   - строка не опознана `_classify_work`.
   Сомнение **называется словами** в том же сообщении («итог 1280, а строки дают 1180 — какая сумма верна?»).
   База знаний 662: «если что-то не сходится — сначала уточняет у самого Пыма».
4. **Сообщение — одно на альбом, RU+TH.**
   - Пример: «🧾 Вижу чек по ADV 350 RED 9890: <строки работ>, итог N ฿. Верно?»
   - Если в альбоме есть и приборка, её вопрос идёт **в том же сообщении** (§5.2). Сейчас там два независимых
     механизма, и чек проигрывает приборке.
   - Кнопки: [✅ Верно] [✏️ Не так]. Кнопка знает автора (`q.from_user`), метка переживает перезапуск
     (`svc_tokens.json`). Это та же форма, что в §5 #88 и §5.2 #89.
   - Работы на тайский — через `_learn_works_th`: в TH-блоке ни одной кириллической буквы (база знаний 694).
   - Замок повторов — `_hint_send`, новый вид с состоянием `(total, подпись строк)`.
5. **По «Верно» доверенного** (`TRUSTED_AUTHORS`) работы пишутся существующими дверями, новых записей нет:
   - инфо-работы (колодки, цепь, прочее) → «события» строкой на работу (`_write_info_works`). Пробег берётся
     подтверждённый; если его нет — буфер `_pw_add` до пробега, как сейчас;
   - редуктор, ABS, воздушный фильтр → кнопки фиксации группы B (`_ask_service_col`), запись по «да» доверенного;
   - масло → дверь масла: вопрос H / фаза 2, запись в кол.I по «да» доверенного и под верхней границей из §5.2 (б2);
   - в заметку строки «события» — «чек: <мастерская, дата>» (не сумма, см. п.6).
   «Верно» от недоверенного — ничего не пишется, ответ «подтверждает Пым или владелец» (как в 6275–6279).
   «Не так» — одна строка «понял, чек не записываю», ничего не пишется.
6. **Сумма — только туда, где положено по базе знаний.** База знаний кладёт сумму чека в денежный журнал по
   ТЕКСТУ Пыма в денежной группе (668–673), а чтение чека держит лишь как сверку. Поэтому по умолчанию сумма
   **только называется** в сообщении и нигде не пишется. Решения владельца, которые код сам не примет:
   - (i) сумма в заметке строки «события» («чек 1280 ฿ — не проводка»). База знаний об этом молчит;
   - (ii) сверка с проводкой Пыма: чтение денежного журнала из ветки обслуживания — новая связь двух групп;
   - (iii) расход по байку или проводка — **новый денежный путь**, в предложение не входит.
7. **`oil_hint` из заметки зрения.** Пока чек не прочитан своим промптом, заметка байка остаётся единственным
   каналом, и 27.09 она зажгла долг ТО. С чтением чека `oil_hint` берётся из `lines` ПОДТВЕРЖДЁННОГО чека, а не
   из свободной `notes` снимка чека. Приборку и подпись это не затрагивает.
8. **Ручка отката** — по образцу `_talk_stage_on`, например `RECEIPT_READ`. Выключена → путь 09587d9 байт-в-байт.
