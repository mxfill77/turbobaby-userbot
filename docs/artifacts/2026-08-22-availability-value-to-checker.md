## §2. Правка — одна строка кода

```
- viol = availability_violations(client, avail=None)
+ viol = availability_violations(client, avail=(True if _AV_POS_RE.search(exp.get("j_line") or "") else None))
```

`git diff --stat` → `suggest.py | 10 ++++++++--`: **изменённых строк КОДА — одна**; остальное —
комментарий над ней (одна прежняя строка заменена семью), поведения он не несёт.

**Почему значение берётся из `exp["j_line"]`, а не «из самого quote».** Между печатью и
проверяющим границу переходит РОВНО ОДИН носитель — служебный quote-блок записки, который печатает
сам код (`_client_price` → `build_pricing_note` → `_quote_block_from_note`). Объекта котировки у
проверяющего нет и положить его некуда: у `_smoke_checks(draft, exp)` параметра наличия не
существует, а строитель эталона тренажёра (`trainer_run.expectations`) держит только строку
записки. Единственная альтернатива — **вторая котировка**, то есть ДРУГОЕ чтение склада в ДРУГОЙ
миг; это уже не «тот же источник», а новый факт, и он мог бы разойтись с тем, по которому фраза
печаталась. Поэтому берётся утверждение, которое код сам записал в свой блок: оно появляется
ТОЛЬКО под `q["available"]` (§1), значит это и есть то самое значение.

**Что НЕ ослаблено.** Ветка отдаёт `True` либо `None` — `False` не отдаётся никогда. Значит:
утверждения о ЗАНЯТОСТИ, дефицит и спеццены судятся ровно как до правки (при `True` состояние
«свободен» их не оправдывает), а «нет утверждения в блоке» → `None`, то есть ПРЕЖНЕЕ поведение
fail-closed. Меняется единственное: положительное утверждение о наличии больше не считается
недоказанным, когда наличие доказал сам код.
