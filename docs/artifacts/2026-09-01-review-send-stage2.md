|---|---|---|

Разделение и инварианты — те же, что у ступени 1 и у слоя ожиданий: логика чистая
(ни сети, ни подпроцессов, ни часов, ни `getenv` — проверяется тестом по AST), руки
делают ввод-вывод. Запуск:

```
venv/Scripts/python.exe review_send_run.py --pack docs/review_outbox/<файл>.md
venv/Scripts/python.exe review_send_run.py --pack … --channel codex --journal
venv/Scripts/python.exe review_send_run.py --pack … --dry      # наружу не ходит вовсе
```

Коды возврата: 0 — все каналы ответили, 3 — хотя бы один отказал, 4 — есть
«неизвестно», 2 — вход недействителен.

### Три исхода и почему третий обязателен

| исход | когда | пример |
|---|---|---|
| **ОТВЕТ ПОЛУЧЕН** (`answered`) | код 0, файл ответа есть, тело выше пола осмысленности | живая проба Codex |
| **КАНАЛ ОТКАЗАЛ** (`refused`) | ключа нет, адрес недоступен, код возврата ≠ 0, таймаут, **пустой ответ**, **короче пола**, **канал сам объявил обрыв**, страж задержал исходящее | живая проба Manus (`no_credentials`), отрицательный тест (`channel_unreachable`) |
| **НЕИЗВЕСТНО** (`unknown`) | обрыв ПОСЛЕ отправки, 2xx с идентификатором задачи и без текста, ответ не прочитался | асинхронная приёмка Manus (в живой пробе не достигнута) |

Правило задания «пустой или обрезанный ответ — это отказ, не успех» стои́т на четырёх
ветках сразу: `empty_answer`, `answer_too_short`, `truncated_answer`, `channel_error`
(ненулевой код возврата — отказ ДАЖЕ при непустом теле; тело при этом сохраняется
доказательством, но исходом остаётся отказ).

**Граница «расписка ≠ судьба».** Обрыв ДО отправки — отказ (работа не принята, цена
0). Обрыв ПОСЛЕ отправки — «неизвестно» (запрос мог быть принят и оплачен, цена 1).
Назвать второе отказом значило бы пригласить повторную отправку и вторую оплату; это
тот же класс, что ложный 401 моста.

### Стража исходящего

Считается ДО выбора канала и до любой сети; находка = наружу не уходит ничего ни
одним каналом. Судит по **форме значения, а не по слову**: ловит ключ провайдера,
токены GitHub/Slack/Telegram, JWT, присвоение длинного значения имени-секрету,
абсолютные пути (Windows/POSIX/UNC), почту, международный телефон, ник Telegram.

Почему не по словам: сам пакет второго мнения ОБСУЖДАЕТ запрет имён и печатает слова
`secret`, `denylisted`, `matched_token` — правило по словарю задержало бы каждый
пакет, а настоящий ключ без подписи пропустило бы.

**Ложное срабатывание поймано на живом пакете и снято** (замер: было 1 находка, стало
0): правило UNC ловило строку `"command": "venv\\Scripts\\python.exe …"` — это
ОТНОСИТЕЛЬНЫЙ путь с удвоенными слэшами от экранирования JSON. Без оговорки «UNC
только с начала слова» страж задерживал бы каждый пакет с командой прогона тестов, то
есть все. Регресс на эту строку стоит в юнитах.

## 4. ПОПРАВКА К ПОСЫЛКЕ ЗАДАНИЯ: имени переменной Manus в коде НЕ БЫЛО

Задание говорит «ключ берётся из окружения, имя переменной найти в коде самому». Имя
не найдено, потому что его там нет — проверено своим замером, а не со слов разведки
задачи 66:

| проба (свой замер 01.09) | результат |
|---|---|
| `rg -ni "manus"` по `*.py` вне venv/scratch | **0 совпадений** |
| имена вида `*_API_KEY` в трекаемом коде | ровно **2**, оба чужих провайдера |
| имена переменных окружения со словом MANUS | **0** (перечислены только ИМЕНА) |

Значит имя не «найдено», а **назначено**: отправщик читает ключ из окружения по имени,
которое стоит в его настройке по умолчанию, и это имя перекрывается ключом
`--key-env`. Когда владелец заведёт ключ под своим именем, правка кода не понадобится.

Практический смысл: **живой формат ответа Manus этой полосой не снят ни разу**.
Разбор тела написан по нескольким общеупотребимым именам полей и честно возвращает
«ни одно не несёт текста», когда не нашёл. Первый заход с настоящим ключом почти
наверняка потребует ОДНОЙ правки контракта (у Manus приёмка задачи асинхронна: код
2xx с идентификатором задачи ответом не является — у отправщика это уже отдельный
исход `accepted_no_answer` → НЕИЗВЕСТНО).

## 5. Бюджет: цена одного пакета в единицах канала

**Единица канала Codex — токены; единица канала Manus — заход (`request`).**

| замер | цена | чем снято |
|---|---|---|
| тривиальный промпт «ответь одним словом: ок» (задача 66, 01.09) | **11 706 токенов** | это НАКЛАДНЫЕ канала: контекст проекта, который CLI прикладывает сам |
| **пакет 11 093 знака, ХОЛОДНЫЙ заход** | **16 086 токенов** | живой заход №2, строка `tokens used` из stderr |
| тот же пакет, повторный заход тем же текстом через ~6 минут | **1 909 токенов** | живой заход №3 |

Три вывода для массовой отправки:

1. **Считать по холодной цене — 16 тыс. токенов на пакет.** Дешёвый повтор (1 909)
   получен на ДОСЛОВНО том же тексте; при массовой отправке каждый пакет свой, то
   есть каждый холодный. Механизм удешевления (кэш промпта у провайдера) каналом не
   объявлен и здесь не подтверждён — на нём бюджет строить нельзя.
2. **Сам пакет стоит ≈4.4 тыс. токенов**, остальные ≈11.7 тыс. — накладные канала
   (инструкции проекта, которые Codex подхватывает сам). Отсюда практическое: пакетов
   на 15 000 знаков дешевле отправлять ПОДРЯД в одном контуре, а не по одному.
3. **Manus считается заходами**: отказ до сокета — 0, любой ушедший запрос — 1. В
   токенах его цену отправщик не выдумывает: канал их наружу не сообщает.

Цена **не бесплатна и не безлимитна**: канал живёт на подписке ChatGPT владельца, и
её потолок здесь не мерялся вовсе (см. границы).

## 6. Что этот заход НЕ покрывает (честно)

- **Качество ревью не судится ни одной веткой.** Отправщик проверяет форму ответа
  (пусто / огрызок / обрыв), а не его содержание. Полезен ответ или нет — решает
  человек, читающий лоток.
- **Лимиты и квоты каналов не мерялись.** Три захода — не корпус; о потолке подписки
  из них не следует ничего.
- **Manus как приложение (ручной канал) отправщику недоступен** и в этой ступени не
  участвует: пакет туда по-прежнему кладёт человек.
- **Что именно Codex прикладывает к промпту сам, не измерено.** Косвенно видно по
  накладным (11.7 тыс. токенов на «ок»), но состав не разбирался; рабочим каталогом
  канала остаётся корень репозитория, как в разведке задачи 66.
- **Наблюдателя у ступени 2 нет.** Отправщик — это руки, которые зовут человеком или
  задачей; сам себя он не запускает и очередь не читает.
- **В `docs/review_inbox` пока ровно один настоящий ответ.** Массовой отправки не
  было и в этом заходе не планировалось.
