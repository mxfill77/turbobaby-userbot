**Дата:** 29.07.2026, сессия Dispatch (ПК, D:\turbobaby-bot).
**Задача владельца:** зафиксировать дорожную карту миграции в Brain, документ
KB_ROADMAP_MASTER, дословно, разделом В НАЧАЛО, существующее не трогать.
**Границы:** параллельно шла опись мозга (только чтение) — не мешать; код/коммиты/клиентский

## 1. НАХОДКА ДЛЯ ОПИСИ МОЗГА: `roadmap_master` — мёртвый указатель

Целевого документа **нет**. Реестр про него помнит, Drive — нет. Живые пробы (read-only, канал
`brain_writer` → Bridge `read_doc`):

| проба | результат |
|---|---|
| `read_doc name=KB_ROADMAP_MASTER` | `unknown_name` — такого **имени** в манифесте нет |
| `list_brain` | 27 имён, среди них ключ **`roadmap_master`** → id `1Z70EpgGZmaYMaZ064sXQlCCP8z8sFyZWfzVPvRB4jWE` |
| `read_doc name=roadmap_master` | `read_failed`: Drive «объекта с таким id не найдено / нет доступа» |
| `read_doc id=1Z70Epg…4jWE` | та же ошибка |
| контроль `read_doc name=index` | **OK, 83 844 символа** — канал и чтение Docs исправны |

Владелец сверился с Drive по факту: **документа с именем KB_ROADMAP_MASTER там нет вообще.**
Значит ключ `roadmap_master` в BRAIN_MANIFEST висит на несуществующем файле.

Два следствия, которые опись обязана учесть:

1. **Реестр врёт молча.** `list_brain` отдаёт ключ как живой; мёртвым он становится только на
   попытке чтения. Проверка «имя есть в манифесте» ничего не доказывает — доказывает лишь
   успешный `read_doc`. Ключей в манифесте 27; сколько из них ещё указывают в пустоту —
   **не проверено** (в этой сессии сверялись только `index`, `roadmap_master`, `review_archive`).
2. **KB_MASTER §5 устарел.** Там написано: «KB_ROADMAP_MASTER — В АРХИВЕ (_archive; перемещён
   ревизией 16.07)». По факту файла нет ни в архиве, ни где-либо ещё. Строка §5 и ссылка на
   `roadmap_master` в чек-листе ревизии (пункт [4]) описывают несуществующий объект.

**Не сделано намеренно (решение владельца):** KB_ROADMAP_MASTER заново НЕ создавали, ключ
`roadmap_master` в реестре НЕ трогали и НЕ перерегистрировали. Это остаётся открытым хвостом
описи, а не тихой правкой посреди чужого прогона.

**Смежный документ, к которому не прикасались:** `KB_ROADMAP_v2`,
id `1ekCOwspbXhJP7F2eVr3tKuwdLJ9ke9IH`, ~15 КБ, последняя правка 06.07 — лежит в архивной
подпапке. По прямому указанию владельца не читался и не менялся.

**Ограничение инструмента, вскрытое попутно:** у Bridge **нет** действия для перечисления файлов
папки Brain — есть только манифест (`list_brain`), чтение по `id`/`name`, `register_brain_doc`,
`create_brain_plain`, `move_brain_file`, `trash_brain_file`. Поэтому «а нет ли живой копии в
_archive под другим id» изнутри канала не проверяется в принципе — только глазами в Drive.
Это и была причина остановки-развилки, а не догадка.

## 2. Что записано и куда (по решению владельца)

Текст карты миграции лёг **в KB_MASTER** (манифестное имя `index`),
id `1-bH3b6c_oamqST551iLxn-voSDragdV0rUZkFwgmAqc`, **разделом в самое начало**.

Канал — `brain_writer.append(..., place="top")`: единственный легальный писатель в Brain с ПК.
Секреты Bridge берёт сам писатель; вызывающий скрипт их не читает и не видит (класс 328).

**Кодировка — отдельная предосторожность.** Текст 60 строк на кириллице передавался писателю
**файлом в UTF-8**, а не через argv и не через stdin: оба на Windows-консоли уже роняли
мохибейк в мозг (живой дефект 29.07 — «С‚РёРї РўРЎ» вместо «тип ТС», пять строк подряд).
Таймаут HTTP на время записи поднят с 30 до 180 с — док 84 КБ пишется как `clear()+setText()`
под замком, а обрыв по таймауту **не** означает «не записалось», и гадать по факту обрыва
не хотелось.

### Факты записи

| факт | значение |
|---|---|
| длина ДО | **83 844** символа |
| длина ПОСЛЕ | **86 535** символов |
| дельта | **+2 691** — ровно длина блока, ни символом больше |
| блок стоит в самом начале дока | да (`back.startswith(блок)` = True) |
| вхождений блока | ровно 1 |
| прежнее тело | **посимвольно равно бэкапу до записи** (83 844 из 83 844) |
| разделитель блок↔прежнее тело | один `\n` |
| знаки подмены в доке | U+FFFD = 0, `\u`-эскейпы = 0, мохибейк `Ð/Ñ/С‚/Ð¾` = 0 |
| знаки подмены в новом разделе | `?` = 0, U+FFFD = 0; кириллических букв 1954 |
| обе рамки блока | по 40 знаков U+2500 (как в задании) |
| бэкап прежнего тела | `tmp/brain_backup_KB_MASTER_20260729-161023.txt` |

Сверка — **по обратному чтению живого дока**, не по локальной склейке: `brain_writer` после
записи читает док заново, сверяет текст дословно, считает вхождения и сравнивает длины.

### Откат (если понадобится)

Записать в тот же id содержимое `tmp/brain_backup_KB_MASTER_20260729-161023.txt` — это
дословное тело дока за секунду до вставки.
