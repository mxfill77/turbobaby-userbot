## 1. Счёт по живым данным (mode=ro, только числа и имена полей)

- `wa_inbox` всего 5 389; `msg_type='reaction'` — **1** (echo 1, history 0, text пуст). Реакций клиента — **0**.
- Цель этой реакции — сообщение клиента, есть в очереди, показано в теме.
- Сырой архив входа: тел 58, с реакцией **1** — поле `smb_message_echoes` → `message_echoes` (то есть реакция-эхо, поставленная с телефона: **есть, 1**). Поля сообщения: `from, id, reaction, timestamp, to, to_user_id, type`; поля `reaction`: `emoji, message_id`.
- Эмодзи живой реакции: в наборе Telegram после снятия U+FE0F/оттенка (1 из 1; модификатор был).
- **Снятие реакции живьём не встречалось — 0 тел.** Как оно приходит, известно из документации Meta (тот же вид `reaction` с пустым/отсутствующим `emoji`), а не из нашего замера; вход принимает обе формы, тест проверяет обе.
- Попутно в архиве: виды `unsupported` 2, `revoke` 1 (удаление сообщения с телефона) — показом сейчас не различаются, в это задание не входили.

## 2. Вход (wa_webhook, wa_kind, wa_send)

- `wa_webhook._cloud_event`: `type=reaction` → эмодзи в `text` (снятие — `''`), wamid цели в новую колонку **`react_to`** — `_ADDED_COLUMNS`, только `ALTER TABLE ADD COLUMN`; повтор того же wamid дописывает `react_to` только в пустое (`_ENRICH_FIELDS`).
- `wa_kind`: свой вид **`reaction`**, распоряжение `drop` (ни карточки, ни контекста); решается после разбора флагов и **раньше эха** — реакция с телефона тоже реакция, кто поставил — по `echo`.
- `wa_send.last_inbound_ts`: `AND msg_type <> 'reaction'` — реакция окно 24 ч не открывает и не двигает.
- Выдача ПК: `kind=reaction, disposition=drop`. ПК-сторона (`wa_bridge.KNOWN_KINDS`) вида не знает → запись идёт как `unknown` с WARNING «вид не опознан», карточки нет — ровно как сегодня для реакции клиента. Сегодняшняя реакция-эхо при этом ехала на ПК эхом с пустым текстом в контекст — после правки не поедет. Строку `reaction` в `KNOWN_KINDS` ПК не добавлял (вне названных трёх мест).

## 3. Показ (wa_tg_mirror)

- Своё состояние, только ADD: `shown.msg_id`, `shown.solo` (ключ один в сообщении), `topics.name`, таблица `reacts(target, side, emoji, row_id)`. Ответ Telegram теперь не выбрасывается: `message_id` пишется у ключа показа.
- Реакция в живой стадии темы: цель найдена по `msg:<wamid>` или `file:<wamid>` и показана ОДНА → `setMessageReaction` (одна реакция бота: держится последняя непустая из сторон «клиент»/«мы»; снятие одной стороны возвращает реакцию другой; повторно то, что бот уже держит, не ставится). Эмодзи сравнивается без U+FE0F и без оттенка кожи (оттенок теряется — Telegram его не держит).
- Строкой (одна; когда цель показана отдельным сообщением — ответом на него): эмодзи вне набора Telegram; цель не показана отдельным сообщением (пачка предыстории, сообщение не из этой темы, показано до применения); 400 от Telegram (чат не принял реакцию). Снятие реакции, показанной строкой, — тоже строкой.
- Ключ реакции — тот же `msg:<wamid>`, что у всех строк: повтор тела, такт и рестарт её второй раз не ставят; уже показанная строкой живая реакция id 5408 повторно не пойдёт.
- Реакция темы не открывает, в предысторию не идёт, тревогу «не показано 10 минут» не будит (`_is_live` её не берёт — как и судья О9).
- Строка, легшая до правки входа (`react_to` пуст), читает эмодзи и цель из своего `raw` — порядок рестартов вход/показ не важен; колонки, которой ещё нет в очереди, служба читает как NULL.
