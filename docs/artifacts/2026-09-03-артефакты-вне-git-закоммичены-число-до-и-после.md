**Заход переживает обрыв по устройству, а не по обещанию.** Списки путей режет
`_scratch_commit_artifacts/make_batches.py` в NUL-разделённые `batch_NN.lst` (NUL обязателен:
имена кириллические, и `core.quotepath` иначе коверкает их в argv). Цикл
`commit_batches.sh N M` перед каждым коммитом смотрит, сколько путей реально встало в индекс:
пачка, уже лежащая в истории, даёт 0 и **пропускается**. Повторный запуск с любой пачки
продолжает с недостающего и дублей не делает.

Замок чистоты стои́т **перед** коммитом, а не после: если в индексе окажется хоть один путь вне
`docs/artifacts/`, цикл печатает виновников и выходит **без коммита**. Сброса индекса он при
этом не делает — `reset`/`checkout`/`clean`/`stash` запрещены заданием и не звались ни разу.

## 7. Чего заход НЕ закрыл

- **Восстановимость держится на одном удалённом репозитории.** `origin` принял 673 файла, но это
  по-прежнему одна внешняя копия. «Не в единственном экземпляре» ≠ «зарезервировано».
- **Публичность репозитория не проверена**: `gh` на ПК нет, а запрос к API GitHub — сеть вне
  разрешённой заданием. На вердикт по секретам это не влияет (боевых находок ноль), но если
  репозиторий публичен, серая зона из §2 становится вопросом к владельцу, а не справкой.
- **Остальное дерево осталось вне git как было**: scratch-каталоги, `manager-bot/`, файлы
  состояния. Заданием они прямо исключены, и ни один из них не тронут.
- **Прочие невосстановимые классы описи 03.09 не разбирались** — предметом был только
  `docs/artifacts`.
