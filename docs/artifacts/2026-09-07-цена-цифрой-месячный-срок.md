### На чём спотыкается КАЖДЫЙ чек — по отдельности

Задание право: это две разные претензии, и общую причину надо доказывать, а не объявлять.

**Чек «строка J дословно» — краснеет БЕЗ УЧАСТИЯ ГОЛОВЫ.** Его предмет — не текст ответа, а то,
собрал ли КОД канонический quote-блок. Ожидание берётся из `trainer_run.expectations` →
`suggest._quote_block_from_note(note)`; на живой записке кейса 7 это **None**. Тело чека
(`suggest._smoke_checks`, п.1): `j_lines = []` ⇒ `ok = bool(j_lines) and not missing` = **False**
при ЛЮБОМ черновике. Доказано прямым замером, а не рассуждением: тот же чек прогнан на **пустом**
черновике `""` —

```
{'name': 'строка J дословно', 'ok': False,
 'expected': '(строка столбца J из quote-блока)',
 'fact': 'quote-блок не собран — цена не доехала'}
```

Он был бы красным и при безупречном ответе, и при молчащей голове. **Претензия чека 1: «код не
доставил каноническую строку J».**

**Чек «цена цифрой» — краснеет ПОТОМУ, ЧТО ГОЛОВА ПОСЛУШАЛАСЬ.** Тело
(`trainer_run.case_checks`, п.9): `nums = re.findall(r"\d{3,}", j_line + " " + sheet_line)`. Оба
блока None ⇒ `nums = []` ⇒ ветка `has = bool(re.search(r"\d[\d\s]{2,}\s*(?:฿|бат|thb|baht)",
client))`. Записка запретила любую цифру цены, голова цифру не назвала ⇒ **False**, факт «цифры
цены в тексте нет». **Претензия чека 2: «голова не произнесла числа».**

Обратите внимание на асимметрию, которую легко потерять: чек 2 в принципе ЗАВИСИТ от головы —
скажи она число вопреки записке, он бы позеленел (и это было бы нарушением правила владельца,
а не победой). Чек 1 от головы не зависит ни в одной ветке.

**Общая причина доказана контрфактом, а не сходством.** Оба ожидания читаются из ОДНОЙ записки, и
обе пустоты рождает ОДИН ранний `return` — см. §3. Снятие этой одной ветки наполняет вход обоих
чеков сразу.

## 4. ДЕТЕРМИНИРОВАННОЕ И ЛОТЕРЕЯ (п.3 задания)

**Кейс 7 детерминирован — да, и сильнее, чем «два круга из двух».**

1. Живой замер: **2 круга из 2 красные**, оба по одной и той же паре чеков (§2).
2. Механизм чека «строка J дословно» **головы не касается вовсе** — доказано на пустом

3. `season_gate.span` — чистая функция `(дата начала, дата конца, файл периодов)`. Ни случайности,
   ни головы, ни сети внутри нет.

**Но лотерея у кейса ЕСТЬ — и она КАЛЕНДАРНАЯ, а не головы.** Подстановка
`trainer_run.placeholders` строит `when_month` как «с 6 <M> по 6 <M+1>», то есть окно **всегда**
переходит из месяца в месяц, а вердикт зависит от того, В КАКОЙ ДЕНЬ запущен набор. Замер по всем
365 дням запуска 2026 (`probe_case7_calendar.py`, головы не звали ни разу):

```
crosses  242 дня из 365      one  123 дня из 365
```

Отрезки, где ворота МОЛЧАЛИ БЫ (`probe_case7_cap.py`, ветка Б):

```
запуск с 2026-01-01 по 2026-01-31 — гейт молчит (31 день)
запуск с 2026-05-01 по 2026-07-31 — гейт молчит (92 дня)
всего 123 из 365
```

Причина видна из таблицы периодов файла цен: длиннее 31 суток только `P1 ИЮНЬ-СЕНТЯБРЬ`
(122 суток), `P5 ПИК` (53) и `P6 СЕР.ФЕВРАЛЯ-МАРТ` (54) — остальные шесть короче месяца, и
31-суточное окно внутри них не помещается физически. Для сравнения, по всем 365 стартам 2027
31-суточное окно **не** пересекает границу лишь у **136 стартов из 365**.

Отсюда практический вывод, который стоит сказать вслух: «перезапустить и посмотреть» здесь не
поможет — сегодня, 07.09, набор попадает в графу `crosses`, и кейс 7 будет красным на КАЖДОМ
заходе вплоть до запуска в январе. Это ровно противоположно кейсу 10, чей провал 10/2 —
измеренная лотерея головы, уже закрытая критерием F. **Кейс 7 критерий F не спасает**: он не в
классе «обязательное упоминание» (`require_any` у него пуст), а значит идёт 2 круга и «зелёными
обязаны быть все» — прощения большинством у него нет ни одной веткой. Строка живого прогона
подтверждает: `КРИТЕРИЙ F: кейсов класса «обязательное упоминание» — 0 (нет) … КРУГОВ ПО

## 5. ИСХОД: бот прав, неверен КЕЙС
