## 2. ГДЕ НОСИТЕЛЬ ПЕЧАТАЕТСЯ ТЕПЕРЬ И ПО КАКОМУ УСЛОВИЮ

Одна функция — **`suggest._avail_code_suffix` (`suggest.py:3740`)**, и правило в ней одно:

```python
if not isinstance(q, dict) or not q.get("available"):
    return phrase                      # не доступно ИЛИ неизвестно → носителя нет
if _AVAIL_CODE_PHRASE in phrase:
    return phrase                      # дверь уже сказала это сама → не дублируем
return phrase.rstrip() + "; " + _AVAIL_CODE_PHRASE
```

Зовут её **четыре** точки печати (`suggest.py:3779, 3788, 3796, 3824`) — три ветки
`_client_price` и J-ветка `_quote_j_line`. Условие у всех одно: **доступность пришла ответом
двери** (`q["available"]` истинно). Доступность неизвестна или занято — носителя нет, и
**молчание тут законно**: fail-closed сохранён буква в букву, «нет фразы» читается как «данных
нет», а не как «занят» (False запиской не переносится вовсе — кода, который писал бы «занят»,
не существует).

Почему правило собрано в одну функцию, а не дописано в две ветки: три точки печати уже разошлись
молча один раз — ровно это и есть разобранный здесь дефект. Четвёртая разойтись не сможет.

**ЗАМЕР ПОСЛЕ ПРАВКИ (та же проба, тот же вход):**

| | до | после |
|---|---|---|
| длина записки | 717 | **739** |
| `_AVAIL_CODE_PHRASE` в записке | нет | **есть** |
| `availability_from_note` | None | **True** |
| строка в quote-блоке | `NMAX — 2400 ฿ за 5 дней (Скидка за срок 15%, 480 ฿ в день); депозит 3000 ฿.` | `… депозит 3000 ฿; свободен на эти даты.` |

**Это ВОЗВРАТ, а не новая деталь.** `git show 3d3704b` — канон того же смоука до 13.09:
`"307 ฿/день; итого 1535 ฿; депозит 3000 ฿; свободен на эти даты"`. Хвост стоял там же и теми же
словами; 13.09 он ушёл вместе с переходом на строку двери.

**Предмет замка тот же, буква в букву:** «клейм наличия, ПОДТВЕРЖДЁННЫЙ данными Bridge,

## 4. ОТРИЦАТЕЛЬНЫЙ ТЕСТ — ОБА КОНЦА, ЧИСЛАМИ

Новый класс **`test_suggest.TestDoorPathAvailCarrier`** (`test_suggest.py:7251`), **7 тестов**.
Отличие от соседнего `TestMinQuoteAvailCarrier`: там мок моста отдаёт котировку БЕЗ поля `text`
(ветка сборки — путь до 12.09), здесь — С дословной строкой столбца J, как отвечает живая дверь
сегодня. Ровно эта разница и уронила носитель, поэтому соседний набор оставался зелёным.

Конца замка три, а не два: «сказала да», «сказала нет», «промолчала». Третий — не синоним
второго: «неизвестно» и «занято» здесь разные исходы, и записка обязана молчать в обоих.

| ответ двери | носитель в записке | `availability_from_note` | чек «нет утверждений о наличии» | факт чека |
|---|---|---|---|---|
| `available: True` | **есть** | **True** | **зелёный** | клеймов наличия нет |
| `available: False` | нет | None | **красный** | `клеймы наличия: свободен на эти даты` |
| ключа `available` нет вовсе | нет | None | **красный** | `клеймы наличия: свободен на эти даты` |

Черновик между концами **не менялся ни символом** — менялся только ответ двери. Это и есть
замок от подкрутки ради зелёного.

Точка печати проверена отдельно, на обеих J-ветках сразу
(`test_printing_point_prints_iff_door_said_yes`): при «да» носитель есть и в `_client_price`, и
в `_quote_j_line`; при «нет» и при «молчит» — нет ни там, ни там; строка двери `J_LINE` цела во
всех трёх исходах. Посылка набора тоже под замком
(`test_premise_door_answer_carries_verbatim_j_text`): если дверь перестанет отдавать `text`,
набор покраснеет и позовёт перемерить, а не позеленеет ни о чём.

**Боевых файлов набор не портит:** мок Bridge инъекцией, зоны — из фикстуры
`fixtures/delivery_zones_get.live.json`, ни базы, ни таблиц, ни живых чатов.
