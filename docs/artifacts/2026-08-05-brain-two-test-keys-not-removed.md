### 3.1 Что будет, если ключ всё-таки снять — механизм, а не опасение

```js
function brainPlainId_(key, name) {
  var manifest = getBrainManifest_();
  if (manifest[key]) return manifest[key];        // ключ есть — работаем со старым файлом
  …
  var file = folder.createFile(name, '', 'text/plain');   // ключа нет — СОЗДАЁТ НОВЫЙ ФАЙЛ
  manifest[key] = id;                                     // и МОЛЧА возвращает ключ в реестр
  PropertiesService.getScriptProperties().setProperty(BRAIN_PROP_KEY, JSON.stringify(manifest));
}
```

Снятие ключа **не ломает** самопроверку — оно хуже: следующий же `prune_cowork_selftest`

- **создаст в папке Brain два НОВЫХ файла** с теми же титулами `KB_cowork_log_TEST` /
  `KB_cowork_log_TEST_archive` (Drive одноимённые файлы разрешает);
- **сам вернёт оба ключа в реестр** — уже на новые id: уборка отменится молча, без единой записи;
- оставит нынешние два файла **сиротами вне реестра** — ровно тот класс, ради которого
  `KB_NORTH_STAR` (жил вне реестра с 03.07) пришлось регистрировать отдельной операцией 01.08;
- поднимет число уникальных id на два при пороге `BRAIN_DOC_CLUTTER_AT = 28`.

То есть «снять ключ, документ не трогать» здесь даёт **не логический архив, а мусор**: минус ноль
объёма, плюс два файла и два ключа-двойника.
