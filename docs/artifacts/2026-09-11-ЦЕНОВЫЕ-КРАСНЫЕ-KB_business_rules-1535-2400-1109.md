## 2. Причина каждого поимённо (пункт 2). Классов ТРИ, а не один

Решение Штаба №3 запрещает общую правку, пока не доказано, что класс один. **Он не один.**

### Класс A — устаревшее ОЖИДАНИЕ цены (случаи 1, 2, 4)

Ожидание списано со строки столбца J живого листа. **Лист снят с роли источника цены 20.08.2026**
(коммит `45a38cf`), и `price_source.reprice` с тех пор СНИМАЕТ дословный текст J
(`out.pop("text", None)`), чтобы чужие числа листа не звучали рядом с новой ценой. Ожидание вместе
с источником не пересчитали. **Причина: устаревшее ожидание. Ошибки расчёта нет.**

### Класс B — устаревшая ФИКСТУРА ВХОДА (случаи 3, 5)

Здесь ожидание верное и осталось нетронутым: «транспорт донёс строку цены дословно». Протух
**вход** — рукописный черновик, который тест подаёт вместо живого контура: он несёт строку листа,
которой код больше не печатает. **Причина: устаревшая фикстура. Ни ожидание, ни расчёт не виноваты.**

Разница с классом A не косметическая: в A правится правая часть `assert`, в B — текст, который
тест ПОДАЁТ. Общая правка «заменить 2400 на 1535 везде» дала бы в классе B зелёное по случайности.

### Класс C — устаревшее ожидание НАЛИЧИЯ, замаскированное (случай 6)

Причина другая и дата другая: **23.08.2026** проверяющий смоука стал ПОЛУЧАТЬ значение наличия
(`_smoke_expectations` → `avail`), а `_av_unsupported` считает клейм `avail_pos` законным при
`state is True`. Котировка мока несёт `available: True` → «свободен и в наличии» перестало быть
нарушением. Ожидание «наличие красное» писалось 15.07.2026, когда проверяющий получал `None`
(fail-closed → нарушением было всё). **Причина: устаревшее ожидание, но НЕ ценовое и НЕ от смены
источника цены.**

Замер двери, на котором это установлено (`tmp/pc_report/task25a_avail_probe.py`, чистая функция,
без сети):

```
avail=True  | []                                           | «…свободен и в наличии 👍»
avail=None  | [(avail_pos,'свободен'), (avail_pos,'в наличии')] | то же
avail=False | [(avail_pos,'свободен'), (avail_pos,'в наличии')] | то же
avail=True  | [(scarcity,'Успевайте')]                     | «Успевайте: почти разобрали.»
```

Последняя строка — ключ к починке: у дефицита и срочности **источника данных нет вовсе**, они
красные ВСЕГДА, при любом `avail` (`suggest.py:7408` `_av_unsupported`: «scarcity/special —
данных-источника нет → всегда нарушение»).

### Ошибок расчёта — НОЛЬ (пункт 4)

Ни один из шести случаев не является ошибкой расчёта, поэтому ветка пункта 4 («описать дефект и
остановиться») не наступила и продукт не тронут. Третий исход **НЕИЗВЕСТНО** тоже не понадобился:
у каждого из шести причина названа фактом, а не догадкой.

### 3.2. Счёт по правилу — по слагаемым, ни одно не взято из ответа кода

Проба смоука фиксирована самим тестом (`TODAY = 2026-07-15` → `_smoke_default_probe` даёт окно
СЛЕДУЮЩЕГО месяца): **NMAX 155, 2026-08-06 → 2026-08-11, 5 суток, зона Раваи.**

| сомножитель | значение | где записан | дословное основание |
|---|---|---|---|
| база модели | **298 ฿/сут** | `price_source.json` → `base.models[NMAX 155]`, класс «скутер» | «медиана цены суток завершённых броней низкого сезона (июнь-октябрь), окно старта с 2024-01-01, приведено к опорной корзине 7-13 суток», `measured_on 2026-09-02`, 48 броней, `judged: true` |
| × сезон | **1.000** | `price_source.json` → `season.periods[P1]`, `multiplier.скутер` | P1 «ИЮНЬ-СЕНТЯБРЬ», `06-01`…`09-30`; дата НАЧАЛА 06.08 внутри него (`formula.period_by`: «сезон приписывается по ДАТЕ НАЧАЛА аренды»); множитель 1.000 по построению — база снята отсюда |
| × ступень срока | **1.03** | `price_source.json` → `term.buckets[4-6]` | «четыре-шесть суток — на 3% дороже недельной, самая дорогая корзина», `origin: СНЯТО ЗАМЕРОМ`, `measured_on 2026-08-15` |
| депозит | 3000 ฿ | живая котировка | правило депозит не трогает вовсе |

```
298 × 1.000 × 1.03 = 306.94  →  307 ฿/сут      (округление ПОСУТОЧНОЕ)
307 × 5 суток                = 1535 ฿ за срок
```

**Кепка не участвует:** потолок NMAX 155 — 5000 ฿/мес, `1535 < 5000`, `cap_active: false`.
**Границу сезонов срок не пересекает** (все 5 суток в P1), **длинной арендой не является** — то
есть три соседних правила (кепка «от … ฿/мес», помесячный потолок, сторож границы сезонов) к
этому случаю отношения не имеют. Названы, потому что «правило есть — значит применимо» было бы
ложным ходом.

### 3.3. Что именно заменено в тесте

Строка листа **осталась на месте как ВХОД мока** — правило-класс CLAUDE.md «мок копирует живой
формат прода»: лист так отвечает и сегодня, он просто перестал быть источником цены. Заведена
отдельная константа ожидания:

```python
J_LINE      = "2400 ฿ за 5 дней (Скидка за срок 15%, 480 ฿ в день); депозит 3000 ฿"   # ВХОД мока
J_RULE_LINE = "307 ฿/день; итого 1535 ฿; депозит 3000 ฿; свободен на эти даты"        # ОЖИДАНИЕ
```

**ЧИСЛА взяты из счёта §3.2, ФОРМА фразы — контракт `_client_price`** (`suggest.py:3637`, сборка
частей через «; »), а не срисованный ответ прогона. Разделение названо здесь потому, что оно и
есть граница между пересчётом и подгонкой: подогнать было бы можно только числа, и они посчитаны
отдельно от кода.

Класс B (фикстуры входа) чинится ДРУГИМ действием: черновики теперь собираются из той же
константы (`f"NMAX — {self.J_RULE_LINE}."`), то есть подают то, что код печатает сегодня.

Класс C чинится **усилением, а не заменой ожидания**: `assertFalse(by["нет утверждений о
наличии"])` **оставлен как был** (снимать проверку задание запрещает), а в черновик добавлен
