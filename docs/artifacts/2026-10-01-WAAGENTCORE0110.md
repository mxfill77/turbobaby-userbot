## 1. Файл и база

`wa_agent.py`, своя база `wa_agent.db` (путь задаёт вызывающий), три таблицы:
- `meta(cursor)`;
- `clients(last_in_id, last_in_ts, done_upto, paused, pause_no, paused_at, pause_row, resumed_by, resumed_at, next_try)`;
- `drafts(id, number, state, ver, text, upto_id, created_at, decided_by, decided_at, reason, wamid, card_id, closed_at)`.

Индекс `one_live_draft`: UNIQUE по `number` WHERE `state IN ('pending','claimed','sending')`.

Очередь открывается только `file:…?mode=ro` (тест `test_queue_read_only`: INSERT → OperationalError).
Архив ядро не читает: контекст для модели — дело адаптера модели (п.8).

Состояния черновика — ровно девять, как в задании: `pending, claimed, sending, sent, not_sent, unsure,
superseded, stale, declined`.

## 2. Курсор, пауза тишины, один черновик

- **Курсор.** Первый старт ставит курсор на `MAX(id)` очереди, поэтому переписка до службы черновиков
  не даёт (`test_first_start_ignores_old`). Дальше каждый такт читает строки `id > курсор` (до 500 за раз).
- **Вид строки** решает `wa_kind.kind_of` плюс `history=0`. Живое входящее двигает `last_in_id/last_in_ts`.
  Время сообщения — `ts_queued`, часы сервера, а не `ts_msg` телефона. История, эхо истории и квитанции
  ничего не двигают (`test_history_receipt_ignored`).
- **Черновик** пишется, когда выполнено всё сразу:
  - клиент не на паузе;
  - `last_in_id > done_upto`;
  - с `last_in_ts` прошло `quiet` секунд (75; вне 60–90 — ValueError);
  - живого черновика нет;
  - модель дала текст.

  Перед записью ядро перепроверяет очередь: если за время работы модели пришло новое, черновик не
  пишется (`test_model_race_no_draft`). Модель не дала текста — следующая попытка через 300 с, а не
  каждый такт.
- **Новое входящее до нажатия:** `pending` → `stale`, карточка получает «снят: клиент написал ещё»,
  после новой тишины пишется новый черновик.
- **`done_upto`** закрывает входящие, на которые уже есть решение: `sent` / `not_sent` / `unsure` /
  `declined`, или человек ответил эхом. Поэтому «не нужно» и рестарт не рождают второй черновик на те же
  сообщения.

## 3. Эхо с телефона и пауза клиента

Живое эхо (не своё по `wamid`) делает три вещи:
- черновик `pending` → `superseded`;
- `done_upto` растёт до последнего входящего;
- клиент ставится на паузу условным `UPDATE … WHERE paused=0`. Только при переходе 0→1 уходит вопрос
  `ask_pause(number, pause_no)`, поэтому второе эхо на той же паузе второго вопроса не даёт.

На паузе черновиков нет (`test_paused_no_draft`), входящие только копятся. Снимает паузу только
`resume(number, pause_no, who)`, условным `UPDATE … WHERE paused=1 AND pause_no=?`. Второй нажавший
получает «уже продолжено: кто, когда». После «Продолжить» входящие, пришедшие после последнего эха
человека, дают черновик (`test_echo_supersede_pause_resume`).

## 4. Захват нажатия

```
UPDATE drafts SET state=?, decided_by=?, decided_at=? WHERE id=? AND state='pending' AND ver=?
```

Решает `rowcount == 1`. Проигравший получает «уже решено: <кто>, ЧЧ:ММ UTC — <исход>». Если черновик
снят без нажатия: «уже решено: снят, ЧЧ:ММ UTC — stale/superseded (версия N)». Замок стоит в базе, а
не в памяти: тест `test_two_presses_one_send` жмёт из двух экземпляров ядра на одной базе (два
процесса). `revise` («Исправить») даёт версию +1, кнопка прежней версии умирает
(`test_revise_old_version_dead`).

## 5. Победитель: перепроверка → sending → дверь → исход

1. Победитель читает очередь после `upto_id`. Если там эхо (или клиент на паузе) — `claimed` →
   `superseded` и пауза. Если новое входящее — `stale`. Отправки нет
   (`test_press_sees_unscanned_echo/inbound`, такт эту строку ещё не видел).
2. `claimed` → `sending` условным UPDATE, и только потом зовётся `door.send_text`.
3. Исход: `sent` (с `wamid`, эхо с этим `wamid` паузу не ставит) · `not_sent` · `unsure` (`unknown`
   двери, исключение двери). Повтора нет ни на одной дороге (`test_door_unknown_is_unsure`).
4. На старте `sending` → `unsure` и его входящие закрываются; `claimed` → `pending` — дверь ещё не
   звали, так что отправки не было. Тест `test_restart_in_sending_no_repeat` имитирует смерть процесса
   внутри двери (BaseException): после рестарта `unsure`, повторное нажатие и такт не дают ни второй
   отправки, ни нового черновика.

Оставшаяся щель названа ещё в WAAGENTLIVE0110 §5: эхо может прийти между перепроверкой и POST, окно —
секунды. Кодом она не закрывается.

## 6. Интерфейсы рук

- `Model.draft(number, upto_id) → текст | None`;
- `Telegram.card(draft_id, ver, number, text) → card_id`, `card_done(draft_id, card_id, words)`,
  `ask_pause(number, pause_no)`;
- `Door.send_text(to, text) → {outcome, reason, wamid}`.

Падение Telegram или модели пишется строкой журнала и такт не роняет. Падение двери даёт `unsure`. В
журнал ядра идут только id, состояния и числа — текстов клиентов там нет. Запуск файла отказывает
словами: «ядро без рук… службы, Telegram и модели ещё нет».
