## 3. Где на самом деле был включён пароль

Правка «в лоб» в `/etc/ssh/sshd_config` ничего бы не дала:

```
/etc/ssh/sshd_config.d/50-cloud-init.conf:1:PasswordAuthentication yes
/etc/ssh/sshd_config:24:Include /etc/ssh/sshd_config.d/*.conf
```

Значение приходило из drop-in, положенного cloud-init. У `sshd` побеждает **первое встреченное**
значение, а `Include` стоит в начале конфига — поэтому:
- создан `/etc/ssh/sshd_config.d/00-turbobaby-hardening.conf` (имя `00-` намеренно: читается раньше `50-`);
- в `50-cloud-init.conf` строка `yes` дополнительно закомментирована — чтобы не зависеть только от порядка.

```
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitEmptyPasswords no
```

## 4. Проверки — до применения и после

**До перезагрузки конфига** (иначе можно применить сломанное):
```
sshd -t exit=0
ЭФФЕКТИВНОЕ значение passwordauthentication: [no]
```
`sshd -T` — оракул эффективной конфигурации: если бы там осталось `yes`, скрипт сам откатился бы
и пароль остался как был. Только после обеих проверок — `systemctl reload ssh` (не restart:
живые сессии не рвутся).

**После:**
```
pubkeyauthentication yes
passwordauthentication no
kbdinteractiveauthentication no
permitemptypasswords no
```

## 6. Как владельцу сохранить запасной ключ

Файл лежит на ПК: `C:\Users\mxfill1\.ssh\turbobaby_vps_backup` (приватный) и `.pub` (публичный).

**Главное: увезти его с ПК.** Сейчас оба ключа на одной машине — если она умрёт, доступа не
будет ни одним. Достаточно одного из вариантов:

1. **Менеджер паролей** — вложением или защищённой заметкой (файл текстовый, 419 байт).
2. **Телефон** — положить в Termux в `~/.ssh/` и выставить права: `chmod 600 ~/.ssh/turbobaby_vps_backup`.
3. **Бумага в сейфе** — распечатать; это 7 строк, при нужде набирается руками.

**Стоит добавить парольную фразу** — этот ключ автоматика не использует, так что ничего не
сломается:
```bash
ssh-keygen -p -f ~/.ssh/turbobaby_vps_backup
```

**Как войти запасным ключом:**
```bash
ssh -i ~/.ssh/turbobaby_vps_backup root@5.223.94.179
```

**Проверить, что он ещё жив** (стоит делать раз в пару месяцев — иначе запасной путь превращается
в предположение):
```bash
ssh -i ~/.ssh/turbobaby_vps_backup -o IdentitiesOnly=yes root@5.223.94.179 'hostname'
```

## ⚠️ Граница, о которой надо знать

Оба ключа несут `from="171.6.0.0/16"` — они работают **только из диапазона провайдера**. Это
защищает от кражи файла, но означает: из другой сети (роуминг, другой оператор, поездка) **не
сработает ни один ключ**, а пароля больше нет. Последний рубеж в таком случае — **консоль
хостинг-провайдера** в личном кабинете; изнутри машины её наличие проверить нельзя, это надо
знать заранее.

Если такой сценарий вероятен, есть два пути на выбор: снять `from=` с **запасного** ключа (он
всё равно с парольной фразой и не используется автоматикой) либо заранее убедиться, что консоль
провайдера доступна и пароль от неё под рукой.

## Остатки

1. Увезти запасной ключ с ПК (раздел 6) — пока он там, запасного пути фактически нет.
2. Проверить доступность консоли провайдера — это единственный путь при смене сети.
3. `permitrootlogin yes` осталось, но при выключенном пароле это равно `prohibit-password`:
   root входит только по ключу. Менять не обязательно, разве что для строгости формулировки.
