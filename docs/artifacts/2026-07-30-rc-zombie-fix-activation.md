## §3 Почему пришлось трогать код ПЕРЕД рестартом (а не после)

Задача требует доказать порог **в памяти**, а не в файле. До этой правки такого доказательства не
существовало — все три доступных способа плохи:

| способ | чем плох |
|---|---|
| `python -c "import rc_supervisor; print(NAMED_SPEC['max_age'])"` | читает **файл**, а не память живого pid |
| mtime файла < времени старта процесса | верная, но **косвенная** цепочка, не отчёт процесса |
| строка сноса `> порога 43200с` | процесс называет число **только в момент ПРОВАЛА**; успех = молчание |

Порог связывается один раз на импорте (`NAMED_SPEC` строится из `NAMED_LIVENESS_MAX_AGE` на уровне
модуля), hot-reload в CPython нет. Поэтому строку добавляем в `main()` — и она попадёт в память
только при следующем старте. **Сделать это после рестарта = потребовать второй рестарт**, то есть
ещё раз оборвать живые сессии владельца. Порядок вынужденный.

Правка (`rc_supervisor.py`, `main()`):

```python
log.info("супервизор стартовал (pid=%s, ветки=%s, cwd=%s)",
         os.getpid(),
         ["%s:порог %sс" % (b["label"], b.get("max_age") or LIVENESS_MAX_AGE) for b in _br],
         REPO)
```

Ожидаемая строка после рестарта — её и предъявлять как доказательство:

```
супервизор стартовал (pid=<новый>, ветки=['rc-server:порог 3600с', 'named-channel:порог 43200с'], cwd=D:\turbobaby-bot)
```

Предикат, пороги и ветки **не тронуты** — добавлено только именование чисел. Два голдена:
`test_startup_line_names_thresholds_of_both_branches` (обе ветки, свои числа, pid),
`test_startup_line_survives_spec_without_max_age` (спека без ключа → общий дефолт, старт не падает).
Это тот же класс, что и в a773df7 («строка НАЗЫВАЕТ ЧИСЛА, а не только вердикт»), распространённый
со строки сноса на строку старта.

## §5 Карточка на «да»

```powershell
# PID перепроверить: ветка канала пересоздаётся каждые 21,5 мин, 16896 будет уже другим.
# 11168 и 4872 стабильны (живут с 01:17 и 12:42).

```

## §6 Проверка после рестарта — три уровня, от мгновенного к решающему

1. **Мгновенно (отчёт процесса о своей памяти):** новая строка старта в `rc_remote_control.log`
   называет `named-channel:порог 43200с`. Это печатает сам новый pid — файл на диске тут ни при чём.
2. **Структурно (подпись):** новый pid супервизора + время старта > mtime `rc_supervisor.py`.
3. **Решающе (поведение), ~22 мин:** канал обязан пережить **1290-ю секунду** — точку, где старый
   код гасил детерминированно (333 жизни из 359). Живой канал возрастом ≥1400с при 0 соединений и
   протухшем логе иначе как порогом 43200 в памяти не объясняется. Полная тишина ветки
   `named-channel` в логе за окно = фикс в силе. Если снос всё же случится — новая строка НАЗОВЁТ
   порог числом, и это тоже отчёт процесса о своей памяти.

Ориентир: строка старта — сразу; вердикт по поведению — **через ~22 минуты** (1290с + тик 30с).
