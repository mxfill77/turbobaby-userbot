## Как устроено

**Строка показа (п.2).** Дверь вернула `sent` и wamid → в теме клиента одна строка:
`ЧЧ:ММ · агент · подтвердил <кто> · черновик №N, версия V · текст:` и ниже текст ушедшей версии (PDF — `· PDF:` и
`📄 <имя файла>`). Итог хранится в ядре: `agent_show`, ключ **«wamid|часть»** (`text`/`pdf`), состояния
`wait → sending (ДО вызова рук) → shown (id сообщения темы) · gave_up`. Показанный ключ второй строки не даёт ни
повтором такта, ни рестартом службы. Telegram не принял / темы нет — повтор тем же ключом с паузой `CARD_RETRY`, не
больше `SHOW_MAX`=12; ответа Telegram нет (сеть) — тоже повтор, попытка ложится в `lost`. Прошлое не показывается:
граница — meta `show_since` (первый старт этого кода). Схема — только добавление (`CREATE TABLE IF NOT EXISTS`, meta).

**Неизвестно и отказ (п.3).** `unsure` (дверь не знает, рестарт посреди двери) — та же строка с «исход неизвестен,
проверьте телефон», ключ «?черновик|часть|попытка». `not_sent` — строки нет.

**Граница (п.4).** Строку пишет бот: `on_topic` пропускает не-человека, `relay` не пишется, пауза не ставится — это
проверено случаем при relay выкл и вкл, а не только рассуждением.

**Цель реакции (п.5).** Цель не показана зеркалом → база агента (`mode=ro`): есть строка показа — реакция бота ставится
на неё; нет — короткая строка с текстом ушедшей версии по wamid (`outbox`, затем `drafts`); не найдено, но по wamid
есть квитанция — «на наше сообщение». Квитанция текстом цели не бывает. Реакция на сообщение с телефона — прежний путь.
