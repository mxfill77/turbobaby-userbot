## 1. Доставка карточек

**Состояние на диске** — таблица `card_out (draft_id, ver)` в `wa_agent.db`, строка на каждую версию карточки:

| состояние | что значит | поля |
|---|---|---|
| `wait` | ждёт доставки | `tries`, `next_at` — следующая попытка не раньше |
| `sending` | `sendMessage` уже зван (пишется ДО вызова) | — |
| `delivered` | доставлена | `message_id`, `chat_id`, `delivered_at`; `drafts.card_id` = message_id |
| `decided` | решена: исход на карточке | `decided_at`, `words`; `edit` = `ok` / `wait` / `gave_up`; без `message_id` — «решена недоставленной» |

- **Отказ Telegram.** `Tg.card` вернул `None` (HTTP не 200, сеть, исключение) — строка снова `wait` с паузой
  `CARD_RETRY = (5, 15, 30, 60, 120, 300)` с: попытка N берёт N-й элемент, дальше последний. Повтор делает такт
  (`Core.deliver_cards`, конец `tick`, и при выключенных черновиках тоже). Строка журнала — номер черновика,
  версия, попытка, пауза. Повтор бесконечный, пока черновик ждёт: это честное «не доставлено», и оно видно в сводке.
- **Рестарт.** Очередь лежит на диске, `next_at` сохраняется. `sending` на старте становится `wait`: карточка
  могла дойти, поэтому её шлют снова. Дубль карточки безопасен — кнопки несут черновик и версию, захват в ядре
  условный, второе нажатие получает «уже решено». Черновики, которых очередь не знает (записи старше неё),
  берутся на старте: есть `card_id` — `delivered`, нет — `wait`. Так же лечится и П2 у уже застрявших.
- **Повторяются только карточки.** Дверь клиенту очередь не зовёт ни одной строкой. Тесты проверяют
  `door.sends == []` после серий повторов и рестартов.
- **Черновик решён до доставки** (клиент дописал, ответили с телефона) — карточка не шлётся: `decided` без
  `message_id`, править нечего. Пересобранный черновик получает свою карточку.
- **Исход на карточке.** `Tg.card_done` теперь возвращает True / False / None. Если False (Telegram отказал),
  правка повторяется с той же паузой, не больше `EDIT_MAX = 12` раз. Дальше `gave_up` и строка журнала:
  кнопки на карточке живы, нажатие ответит «уже решено». None (карточек нет, выключено) повтора не даёт. Старые
  подделки, возвращающие None, ведут себя как раньше.
- **Сводка службы** (`wa_agent_svc.cards_words`):
  `· карточки в «Агенты» decided=… delivered=… wait=… · черновиков без доставленной карточки N`.
  N — ждущие черновики, у которых нет доставленной карточки своей версии (`Core.undelivered`). Поле есть при
  включённых черновиках или если N > 0. Иначе строка сводки прежняя.

## 2. Актуальность

- **Новое входящее снимает оба черновика.** `_on_inbound` закрывает ждущий (как раньше) и отложенный
  (`scheduled` → `stale`, только отвечавший на более ранние строки). Слова на карточке: «снят до срока: клиент
  написал ещё (строка N) — отложенное не уходит, черновик пересобирается». `done_upto` стоит на старых
  сообщениях, поэтому через паузу тишины родится новый черновик на всю беседу. **Правило WAHUMANPACE0210
  «одобренное уходит в срок» перевёрнуто по заданию**, проверка `test_wa_pace` переписана под новое правило
  (`test_client_wrote_more_scheduled_withdrawn_new_next`).
- **Ответ с телефона и текст из темы** тоже снимают отложенное сразу (`superseded`), а не только в срок.
- **Такт отложенного** (`send_due`) смотрит очередь с входящими (`_fresh(number, upto)`). Поэтому входящее,
  которое скан ещё не разобрал (такт отложенного идёт перед сканом, или это первый такт после рестарта), тоже
  снимает отложенное. Очередь не прочиталась — отложенное ждёт следующего такта и не уходит.
- **«Отправить» привязано к последнему сообщению клиента и версии контекста** (`Core._outdated`):
  - сообщение: `drafts.upto_id` против `clients.last_in_id` и очереди (`_fresh`);
  - контекст: `clients.ctx` — +1 на живое входящее, ответ с телефона, текст из темы и «Продолжить»
    (квитанции, автоприветствие и эхо нашей отправки не в счёт); `drafts.ctx` — значение на момент черновика.
    Если не совпало, ответ «устарело: беседа сменилась после черновика (контекст a → b) — ничего не отправлено».
    Черновик старше версии контекста (`ctx` NULL) сверяется только по сообщению.
  - Устарело — `stale`, на карточке «устарело при нажатии: … черновик пересобирается», нажавшему — словами,
    дверь не зовётся. То же правило проверяется в срок отложенного.
  - `callback_data` прежний (`wa:send:<черновик>:<версия>`): контекст лежит в строке черновика. Кнопки уже
    выданных карточек работают.
- **Очередь не прочитана при нажатии** — захват откатывается в `pending`, ответ «очередь не прочитана — ничего
  не отправлено, черновик ждёт: нажмите ещё раз». Раньше черновик оставался `claimed` до рестарта, а нажатие
  оставалось без ответа.
