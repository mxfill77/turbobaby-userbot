## 2. Замок B — различающая сила по истории закрытых шагов

**Корпус.** Локального дампа колонки `result` у очереди НЕТ (демон логирует `COMPLETE id=N
status=done` без текста, а итог уходит отдельным процессом в журнал). История взята из **6
зеркал `cowork_log`**, строки «Orchestrator: задача #N → статус · итог», дедуп по (id, штамп) —
**214 закрытых записей**.

Адрес выведен из итога по названному правилу: хвост авто-выноса `→ docs/artifacts/journal/…`
отрезается (его произвёл писатель журнала, а не шаг); `commit` — только хеш, НАЗВАННЫЙ словом
(коммит/commit/хеш/git) не далее 40 знаков слева, иначе дата `20260816` дала бы ложный «НЕ
ДОКАЗАН» и оболгала шаг.

```
ДОКАЗАН     153      commit  104 / 0 / 0
НЕ ДОКАЗАН    2      file     49 / 2 / 0
НЕИЗВЕСТНО   59      brain     0 / 0 / 6      (читателя мозга не дали)
                     адрес не выводится  53
```

**Порча одного знака указателя: 153 доказанных → 153 перевёрнуто в НЕ ДОКАЗАН, осталось
доказанным 0.** Прибор различает.

**Оба «НЕ ДОКАЗАН» разобраны и оказались ЧЕСТНЫМИ.** Задачи #5 и #6 закрыты `done` и называют
продуктом `docs/task365_rest.md`; файла в дереве нет. По git: он был заведён `b0b88a1` и **снят
намеренно** — `d099087` «шаг6/6: тестовый гейт зелёный, снят временный docs/task365_rest.md».
Отсюда **названная мина МЕТОДА РЕПЛЕЯ (не судьи): судья читает НАСТОЯЩЕЕ.** На исторических
шагах «НЕ ДОКАЗАН» законно означает и «продукт был и снят», а не только «продукта не было».
Для живого шага, которого судят сразу после закрытия, класс не возникает.

## 3. Замок C — нечувствительность к окну

Окно поставлено **по данным**, а не «на сегодня»: ширина 2 часа, середина — медиана времён
прочитанных фактов (153 факта со временем из 214) → `2026-07-15 19:42:02 .. 21:42:02`. Иначе
сдвиг ничего не задевает, и «нечувствительность» доказывала бы лишь, что ручку положили мимо
корпуса (первый прогон захода был именно таким: наивный приём дал 0 изменений).

| прогон (+2ч и −2ч, 428 вердиктов) | изменений |
|---|---|
| **судья** | **0** |
| наивный приём «свежее окна = сделано» | **11** |

Ручка ЖИВАЯ — тот же сдвиг ломает наивный приём и переворачивает поле `in_window` самого чтения.
Судья его не видит: окно доезжает ТОЛЬКО до чтения, а `verdict_of()` поля `in_window` не читает
ни одной строкой — **ast-инвариант**, а не соглашение.

## 4. Замок D — виндовый путь

Указатель с двоеточием диска проходит у двух видов:
- `file D:\turbobaby-bot\result_judge_pc.py` → ДОКАЗАН, двоеточие в указателе цело;
- `row <абсолютный путь>.db:drafts:1278` → делится **СПРАВА** (`rsplit`): двоеточие диска
  принадлежит пути, а не разметке `<база>:<таблица>:<условие>`. Это ровно класс 05e54aa, и у
  вида `row` он опаснее вдвое — там разметка соседствует с диском.

Плюс путь с пробелами и сквозной случай «маркер в тексте шага → `read_item` → вердикт».

## 5. Граница захода — числом

- **вызовов судьи из боевого кода: 0.** Инвариант `RESULT_JUDGE_UNWIRED` ast-обходит **55**
  боевых `*.py` корня (tracked, без `test_*`) и ловит импорт, переименование, частичный импорт и
  динамику строкой — все четыре подлога проверены. Имя судьи не встречается и в `pc_orchestrator.py`.
- **только чтение — устройством:** все SQL-литералы модуля начинаются со `SELECT`; база
  открывается `?mode=ro`, значение условия едет связанным параметром; git знает **три** читающие
  подкоманды (`rev-parse`, `merge-base`, `show`) и отказывает вслух на любую иную; сети нет
  вовсе (`bridge_http`/`urllib`/`socket` не импортируются) — читателя мозга обязан дать вызывающий;
  вид `file` содержимого НЕ ЧИТАЕТ (только `isfile`+`getsize`), и `open` в модуле не встречается.
- **`.env` мимо замка не прочитать даже размером:** `file` и `row` пускаются только ВНУТРЬ дерева
  полосы, наружу — `НЕИЗВЕСТНО`.
- **боевая `moderation_ipc.db` не открыта ни разу**: фикстуры набора живут во временном корне
  (`Ctx.repo` подставляется), корпус не порождает адресов вида `row`.

**Замок метода: разности времени только через `julianday()`.** В модуле НИ ОДНОГО вычитания на
Python (инвариант считает узлы `ast.Sub` и требует ноль), нет `datetime`/`time`/`timedelta`.
Три вида времени сведены на одну шкалу прямо в SQL — ISO со смещением, unix-секунды и виндовый
FILETIME (`julianday('1601-01-01') + ?/864000000000.0`); FILETIME сознательно НЕ переводится на
Python, как это делает сосед `expectations_pc_run._pid_alive_probe` (`cre.value / 1e7 -
_FILETIME_EPOCH`). Проверено на живой паре git: `2026-08-15T17:26:20+07:00` = `1786789580`.

## 6. Расхождения с полосой VPS — названы

1. **Исходник VPS отсюда не читается**, поэтому порядок силы повторён по формулировке задания,
   а не сверен построчно. Совпадение формы не проверялось — это остаток.
2. **Корпус другой по природе.** Там 75 шагов, здесь 214 записей журнальных зеркал: у полосы ПК
   локального дампа колонки `result` нет вовсе. Числа раскладок сравнивать нельзя.
3. **2 «НЕ ДОКАЗАН» против заявленных 0** — и оба честные (§2). Ноль здесь был бы хуже: он
   означал бы прибор, который не умеет сказать «нет».
4. **Отрицательный набор шире заявленного**: 22 случая против 14.

## 7. Мины, названные заранее

1. **`origin/main` — локальная ссылка, судья её НЕ ОБНОВЛЯЕТ** (в сеть не ходит). Сейчас она
   отстаёт от `HEAD` на **18 коммитов** (`9603f60`, 15.08 17:26 +07). Значит **коммит этого
   захода судья назовёт «НЕ ДОКАЗАН»**, пока он не отгружен, — и это по определению вида, а не
   сбой. Подключающий обязан либо освежать ссылку, либо принять класс сознательно.
2. **`brain` без базовой линии — всегда НЕИЗВЕСТНО.** Половина «содержит названное» ловит подлог
   «текст был там и до шага» только при известном размере ДО; линии в адресе нет, выдумывать её
   судья не станет. По порядку силы «нашлось, но роста не с чем сравнить» садится в НЕИЗВЕСТНО.
3. **`row` делится справа** — при условии, содержащем двоеточие, разбор развалится. Названо в
   докстринге; расширять разметку не стал, пока нет живого адреса этого вида (их 0).
