| источник урока | **есть, сбоку и односторонне** | `trainer_rules.json` — плоский dict `{нормализованный текст: "тренажёр"}` (`trainer.py:279-290`) |

manager-bot/docs/playbook.md` → **0**).

**Механизм появления сирот назван в коде:** `PLAYBOOK_MAX_RULES = 100` и FIFO-вытеснение самых
ранних буллетов (`suggest.py:674`, `:748-752`) — правило исчезает из книги, а его пометка в

**Пометку никто не читает в бою.** `is_trainer_rule` / `rule_source` вызываются только внутри

**Асимметрия хранения:** пометка источника лежит В git (`trainer_rules.json` отслеживается),
само правило — ВНЕ git. То есть история есть у ярлыка и нет у содержимого.

## 5. Причина цены в черновике — НЕТ

Клиенту доезжает **число**, а не разбор.

**Что доезжает:** дословная строка столбца J листа плюс депозит.

```python
    if isinstance(q.get("text"), str) and q["text"].strip():
        phrase = q["text"].strip()             # J-цена дословно (п.5)
        dep = q.get("deposit")
        if dep is not None and str(dep) not in phrase:
            phrase += f"; депозит {dep} ฿"                            # suggest.py:3298-3305
```

Ступень видна клиенту только как чужой текст «(Скидка за срок N%, … в день)» — код его не
строит и не разбирает (`suggest.py:3319-3341`, «столбец J ДОСЛОВНО … БЕЗ пересборки»).

**Структура разбора СУЩЕСТВУЕТ и в текст не идёт:**

```python

                season=season, bucket=buck.get("bucket"), term=term,
                cls=row.get("class"), low_season=(season == 1.0),
                file_model=row.get("model"))
    return int(round(base * season * term)), info                     # price_source.py:209-213
```

и рядом, докстрингом, прямой запрет:

```python

    клиентский текст он не влияет ни одной буквой."""                 # price_source.py:183-184
```

Канал обрывается в `price_source.py:299-308`: в котировку переносятся только числа, `info`
выбрасывается. Контракт котировки плоский — `pricing.py:60-76`: `day_price, total, deposit,
available, season, bike, model, days, text, cap_active, cap_price`. Полей `breakdown / steps /
tiers / reason` **нет**.

**Сезон код ЗНАЕТ, но клиенту не говорит.** `price_source.json` держит девять периодов
границами дат владельца (`P1 ИЮНЬ-СЕНТЯБРЬ` … `P5 ПИК` `from 12-15 / to 02-05` … `P9`) и формулу

отсечки:

  МОДЕРАТОРА … В КЛИЕНТСКОЕ тело её больше не кладём», режется `client_facing_text`.

## 7. Кейс с будущей датой — по ДАТЕ работает, по ЦЕНЕ бессмыслен

**Механика гейта** — правило «ближайшее вхождение», порог назван числом:

```python
_PAST_ROLL_MAX_DAYS = 182                                             # suggest.py:2055

    if prev and prev < today and (today - prev).days <= _PAST_ROLL_MAX_DAYS:

```

Спросили **18 августа про 1 января**: вперёд 136 суток, назад 229 — назад дальше порога, значит
берётся будущее → `date_status = 'future'` → штатная котировка, переспроса нет. **Работает
сегодня.**

Границу фиксирует тест числом:

```python

```

Флип-точка — **2 июля**: раньше неё «январь» читается как ПРОШЛОЕ и уходит в переспрос без цены.
В августе запас есть. Явный год в тексте снимает неоднозначность вовсе (`suggest.py:2074-2075`,
тест `:6493`).

**Что нужно, чтобы завести такой кейс:**

- в живой группе — ничего: написать «с 5 по 15 января» обычной репликой;
- в корпусе безголового прогона — тоже можно (строка идёт через `str(raw).format(**ph)`, литерал
  без фигурных скобок проходит насквозь), но ГОТОВОЙ подстановки на дальний месяц нет:
  `placeholders()` строит ровно шесть и **все в следующем месяце** (`trainer_run.py:177-194`).

**Главное ограничение — цена.** Цена за январь сегодня равна цене за август: живая дверь
`quote_price` сезон не знает, и это названо замером в шапке модуля —

## 8. Состояние группы тренажёра

**Как резолвится группа** (`trainer.py:37-39`, `:336-363`; `userbot_listen.py:388-403`):
env `TRAINER_GROUP_ID` (жёстко) → сохранённая привязка `moderation_ipc.meta['trainer_chat_id']` →
иначе ленивая привязка по первому сообщению в группе с title == `TRAINER_GROUP_NAME`
(по умолчанию «Тренеровка»).

**Кто в ней сейчас — НЕИЗВЕСТНО, и это честный ответ.** Списка участников в коде нет; проверка
требует либо открытия боевой `moderation_ipc.db`, либо запроса в Telegram — обе операции красные
для этого захода. По коду предполагаются три роли (`trainer.py:11-17`): владелец-человек, userbot
(единственный, кто шлёт клиентские ответы), модербот (единственная роль — панель кнопок; в диалог
не пишет, `moderation_bot.py:286`). Состояние сессии — 9 ключей `trainer_*` в
`moderation_ipc.meta` (`trainer.py:42-61`).

**Как туда попадает черновик:** одним способом — `client.send_message` из userbot
(`userbot_listen.py:247`) с шапкой `[тренажёр | ТЕСТ-N | правил: K]`. Панель кнопок вешает
модербот, опознавая **именно эту шапку** (`moderation_bot.py:514` `trainer.has_header`).

**Как забирается вердикт:** двумя равноправными каналами — кнопки модербота (`tr:*`) и
текст-команды userbot; текст работает, даже если модербот лёг (`trainer.py:13-14`).

**Хрупкость:** «🎓 Обучить» живёт ТОЛЬКО в модерботе (гипотезы рождаются там,
`moderation_bot.py:393-396`). Модербот лёг → предложенных гипотез нет вовсе, остаётся только
«урок: …» своими словами.
