## 3. Какая модель фактически отвечает

```
claude-opus-5        -> отвечает claude-opus-5
claude-sonnet-4-5    -> отвечает claude-sonnet-4-5-20250929
claude-haiku-4-5     -> отвечает claude-haiku-4-5-20251001
fable                -> ОТКАЗ not_found_error: model: fable
```

Сейчас: `ask`/`quick`/`vision` → **`claude-sonnet-4-5-20250929`**, `judge` → **`claude-haiku-4-5-20251001`**.
`ORCH_MODEL_FALLBACK=fable` — **несуществующее имя**, фолбэк демона мёртв (см. инцидент 25.07).

## 4. Нагрузка — и честная оговорка

⚠️ **Считать вызовы модели по журналу НЕЛЬЗЯ.** Счётчики `quick()`, `judge()`, `upstream down`
появляются в логе **только в строках ошибок** (`Claude quick() upstream down…`). Успешные вызовы
не логируются вовсе. Поэтому «`quick()` 6» за сегодня — это **6 ошибок**, а не 6 вызовов, и ноль
за 24.07 означает «ошибок не было», а не «модель не звали».

Косвенная мера — входящие сообщения по категориям:

| категория | 24.07 (сутки) | 25.07 (до 15:11 Бангкок) |
|---|---|---|
| delivery | 35 | 18 |
| money | 13 | 5 |
| attendance | 5 | 3 |
| servicing | 2 | 9 |
| **всего** | **55** | **35** |

Порядок величины — **десятки обращений в сутки**, не тысячи. Прямая денежная мера — леджер:

```
spend_ledger.json: {"topup": 0.0, "spend": 7.644447, "warned": false}
```
$7.64 накопленных трат по API-пути при `topup: 0.0`. Пишется `spend_ledger.record_usage`
(`spend_ledger.py:184`), порог предупреждения — `spend_ledger.THRESHOLD_USD` (`bot.py:758`).
⚠️ Теперь, когда весь Splinter ушёл на платный API, эта цифра начнёт расти — стоит убедиться,
что `topup` отражает реальный баланс, иначе предупреждение о низком остатке либо не сработает,
либо сработает вхолостую.

## 5. Существующая эскалация

**В Splinter её нет.** Есть только:
- смена **канала**, не модели: `SPLINTER_LLM_VIA_CLI=1` → подписка, иначе платный API
  (`claude_client.py:705`), и деградация в `''` при отказе (`:727`);
- жёсткий тиринг одного пути: `judge()` на Haiku (`:739`);
- комментарий `:34` — «(fallback, НЕ удалён — обесточен). vision()/ask() Фаза 1 НЕ трогает».

**У оркестратора эскалация настоящая и её стоит скопировать** (`orchestrator_daemon.py:129-137`):
`ORCH_MODEL` + `ORCH_MODEL_FALLBACK`, причём подъём выполняет **сам CLI** флагом
`--fallback-model` в рамках ОДНОГО вызова: «невалидная primary + `--fallback-model=opus` → CLI сам
берёт opus, exit 0». Смена модели — правка конфига, без правки кода.

## 6. Предложение лестницы — НЕ ПРИМЕНЯТЬ, на решение владельца

Главный вывод из замеров: объём — десятки вызовов в сутки, $7.64 за всё время. **Экономия здесь
не главный приз.** Реальная ценность лестницы — скорость на механических путях и устойчивость
на денежном. Поэтому лестница «снизу вверх», а не «всё вниз ради цены».

| ступень | модель | пути | почему |
|---|---|---|---|
| 1 — лёгкая | `claude-haiku-4-5` | `splinter.py:1561` (тайские работы), `splinter.py:458` (перевод RU→TH), `auditor.py:293` `judge()` (уже там) | словарные задачи со строгим коротким ответом; быстрее и дешевле, качество не критично |
| 2 — рабочая | `claude-sonnet-4-5` (как сейчас) | `splinter.py:5250`, `:5495` (обслуживание+одометр), `:5884` (приём), `vision()` | структурный разбор в JSON, средняя сложность |
| 3 — тяжёлая | остаётся `claude-sonnet-4-5`, при желании `claude-opus-5` | **`splinter.py:2007` касса**, `bot.py:1034/1073` `ask()` | цена ошибки — потерянная запись денег или испорченный диалог; здесь не экономят |

**Точки подъёма:**
1. `_parse_json` вернул пусто/мусор → повтор ОДИН раз на ступень выше.
2. Пустой ответ `''` → подъём на ступень выше.
3. Отказ апстрима (`SplinterLLMError`/`AnthropicError`) → это **не** повод менять модель, а повод
   менять **канал** (подписка ↔ платный API). Сегодняшний сбой — ровно этот случай.
4. Касса: при первом же неудачном парсе — сразу на тяжёлую, без промежуточной ступени.

**Механика — минимальная, образец уже в коде:**
- добавить `quick()` необязательный `model: str = None` — ровно как у `judge()` (`:739`);
- один хелпер `_quick_ladder(system, user, tiers)`: идёт по списку ступеней, при неуспехе поднимается;
- имена ступеней — в конфиг, как у оркестратора: `SPLINTER_MODEL_LIGHT` / `_MAIN` / `_HEAVY`,
  чтобы смена модели не требовала правки кода;
- заодно починить `ORCH_MODEL_FALLBACK=fable` → полный идентификатор (вероятно `claude-fable-5`).

**Чего делать НЕ стоит:** переводить кассу на лёгкую ступень ради экономии — при объёме 5–13
денежных сообщений в сутки выигрыш центовый, а риск — потерянная запись, как сегодня трижды.

## Две неудачные попытки и что они дали

**Попытка 1** — ступени сделаны атрибутами класса, на точках вызова `model=claude.HEAVY`.
Гейт: `❌ КРАСНЫЕ ТЕСТЫ (12/131)`. Автооткат, дерево не изменилось.

**Попытка 2** — прогон подтвердил, что причина не та, что я предполагал:
```
AttributeError: 'ClaudeUpstreamDown' object has no attribute 'HEAVY'   splinter.py:2010
AttributeError: 'FakeClaude' object has no attribute 'MAIN'            splinter.py:5499
```
Ошибка проектирования: `claude` на точке вызова — это объект, переданный параметром, а в тестах
двойник. Обращение к атрибуту привязывает каждый двойник к внутренностям клиента.

**Попытка 3 (эта)** — ступень передаётся **строкой** `model="HEAVY"`, `_resolve_tier` и так
принимает имя ступени. Обращений `claude.LIGHT/MAIN/HEAVY` в `splinter.py` — **0**.

Вторая проблема оказалась реальной, просто не первой по порядку: после строковых ступеней
двойники с жёсткой сигнатурой дали бы `unexpected keyword argument`. Поэтому им добавлен `**kw` —
**16 заглушек в 12 файлах** (`quick`/`judge`/`ask`/`vision`), логика тестов не тронута.
Класс тот же, что записан в CLAUDE.md про моки, только наизнанку: **двойник обязан переживать
расширение живого контракта**.

Ранний сигнал перед гейтом (три ранее красных): `test_llm_loud_fail` 19/19,
`test_servicing` ВСЕ PASS, `test_works` ВСЕ PASS.
