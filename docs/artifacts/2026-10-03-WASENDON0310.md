# WASENDON0310 — отправка из карточек wa-agent включена (задание 0128ra-79r.0310)

Полоса ПК, исполнение на сервере. Слово владельца: 03.10 16:32 «мы сейчас делали месяц все для того что бы агенты
общались через ватсап с клиентами…» и 16:34 «включай и отправляй этому клиенту…» (чат Штаба). Ось — бизнес.

## Итог

**ВКЛЮЧЕНО.** «✅ Отправить» в карточке «TurboBaby · Агенты» теперь шлёт текст клиенту в WhatsApp. Пересылка из тем,
реакции, напоминания, ритм, ожидание и прочие выключатели остались как были.

**Почему можно было включать.** По коду `9c4aac6` при нынешних выключателях клиенту уходит только по нажатию человека
в группе «Агенты». Путей без нажатия — 0 (§2). Флаг `WA_SEND` открывает только дверь отправки, больше ничего. Файл ключей
не правился: ключ 360dialog дверь берёт из того же `.env`, что и показ (§1, П2).

- **Как включено:** новый drop-in `/etc/systemd/system/wa-agent.service.d/send.conf` — `[Service]` и одна строка
  `Environment=WA_SEND=1`. Затем `daemon-reload` и **один** `systemctl restart wa-agent`.
- **PID:** `wa-agent` MainPID **3136118 → 3158933**, active/running, NRestarts 0, старт 10:10:47 UTC.
- **Строка старта:** до — `WA_SEND=выкл`, после — **`WA_SEND=вкл`**. Остальные пять выключателей те же, что в П1.
- **Наблюдение 10:10:47 → 10:16:31 UTC (5 мин 44 с):**
  - отправок клиентам 0: строк `дверь →` 0, нажатий 0, `реакций наружу 0 · из тем 0`;
  - Traceback 0, ERROR/CRITICAL/WARNING 0, `упало 0`, `сбой=0`, `409=0`.

**Что это значит для бизнеса.** Сотрудник отвечает клиенту прямо из карточки, без телефона. На обоих ждущих черновиках
(№1 и №2) кнопки «Отправить» пока **нет**: у обоих версия 1 с причинами «нужен человек». Чтобы отправить клиенту
черновик №2 (тот, где суммы без опоры в цене):
1. ответить реплаем своим текстом на его карточку («Исправить»);
2. придёт карточка версии 2 с «✅ Отправить»;
3. нажать — текст уйдёт клиенту дословно.

Старые карточки по-прежнему несут строку «⛔ отправка выключена — ответьте клиенту сами»: их нарисовали до включения,
и сами они не перерисовываются. На новых карточках этой строки не будет.

## 1. Откуда дверь берёт ключ

- Правило одно для двери и показа: `wa_send.api_key` (`wa_send.py:171–188`) — `WA_360_API_KEY`, иначе `WA_D360_API_KEY`,
  берётся первое годное имя.
- Ключ берётся из `os.environ` процесса. Туда его кладёт `load_dotenv` корня дерева (`wa_tg_mirror._env`, его зовёт
  `wa_agent_svc.env_of`, `:95–98`).
- В `first.conf` ключей нет: по именам там только `WA_AGENT_*` и `WA_SEND`.
- Рабочий ключ канала лежит в `.env` под `WA_D360_API_KEY`. Его форму проверяли без печати (WAMIRRORSVC0110 П3), им
  работают О10 и показ (WAD360APPLY0110, WATEMPLATES0210). **Править файл ключей не нужно.**
- **НЕИЗВЕСТНО:** годен ли ключ, который правило выберет для двери. Если в `.env` задан `WA_360_API_KEY` и он не равен
  рабочему, первое нажатие получит отказ 360dialog. Это `not_sent` со словами сервера на карточке, клиенту не уходит
  ничего. Живьём правило ещё не проверено: показ с 02.10 не скачал ни одного медиа. Последний «медиа: OK» был
  02.10 02:43, до правила; все 606 отказов — `CEILING`, это предел диска, до сети.
