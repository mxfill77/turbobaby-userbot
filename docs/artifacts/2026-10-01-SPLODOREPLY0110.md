## 5. Как применить (серверная полоса, словом владельца) и откат

Ветка стоит прямо на живом `main` 08c3f97, поэтому пройдёт fast-forward.
```
cd /root/turbobaby-manager-bot
git rev-parse --short HEAD                      # обязано быть 08c3f97, иначе остановиться
git fetch origin splinter-odo-reply-0110
git merge --ff-only FETCH_HEAD                  # HEAD → a7f81c3
venv/bin/python3 gate.py                        # живой гейт со своим .env
systemctl restart splinter.service              # ОДИН рестарт: self-update у сервера нет
```
**Цена рестарта:** стираются буферы в памяти (фото, ожидания, кнопки отмены, лента темы). Вопросы о
пробеге, заданные ДО рестарта, на диске не лежат: файл появится с первым новым вопросом.

**Проверка после рестарта.** Первый вопрос о пробеге даёт строки
`📟 вопросы о пробеге: память в /root/turbobaby-manager-bot/mileage_question_state.json` и
`📟 вопрос о пробеге N (…) запомнен: сообщение <id>, тема <t>`. Реплай на него даёт
`📟 реплай на вопрос о пробеге N (сообщение <id>, возраст X ч, тема <t>) — вопрос открыт снова`,
а затем прежние строки подтверждения.

**Откат (ничего не удаляя):**
- **без кода:** `MILEAGE_Q_PERSIST=0` в серверном `.env` + рестарт. Диск выключен: реплай узнаётся
  только в пределах жизни процесса, но в любом возрасте вопроса;
- **полный:** `git revert a7f81c3` + рестарт. Это возврат к поведению 30.09: реплай после 3 ч или
  после рестарта снова уходит в мозг.
