## 3. Замена — пара действий подряд, и почему окна не открылось ни на миг

Задание просило пару «переименовать прежнюю → создать новую» и предупредило, что между
ними узел не существует по имени. **В этом канале окна можно не открывать вовсе**, и это
строго лучше: ключ реестра переставляется ОДНИМ вызовом `register_brain_doc(overwrite:true)`,
атомарно на стороне моста. Порядок (один скрипт, без чтений и вопросов посередине):

```
A  register_doc("shtab_frame_arhiv_20260922_1824utc" → 1DiXr3jxoZYxkWaS7k4X4SR0u2xQKUTCi)
   → {"ok":true,"registered":true,"total":40}      прежняя редакция получила архивное имя

B  create_plain(name="KB_shtab_frame", БЕЗ ключа, 68788 символов)
   → {"ok":true,"id":"1CTLS2YnAWwZccbj7k501_lKOWbNJe3mG","chars":68788,
      "verified":true,"chars_back":68788,"fffd":0}  новый файл + обратное чтение по id

C  register_doc("shtab_frame" → 1CTLS2YnAWwZccbj7k501_lKOWbNJe3mG, overwrite=True)
   → {"ok":true,"registered":true,"total":40}      канон-имя переехало на проверенный файл
```

Между A и C имя `shtab_frame` не исчезало: до C оно показывало прежнюю редакцию, после C —
новую. Читающий в любую микросекунду получал целую редакцию, а не пустоту. Создание стоит
ДО переключения намеренно: переключать канон-имя на непроверенный текст нечестно, а
обратное чтение внутри `create_plain` делает файл проверенным ещё до переключения.

**Что в этой системе есть «имя узла».** `read_doc` по имени смотрит РОВНО манифест
(`handleReadDoc_`: `id = man[name]`, поиска по имени файла в папке нет), поэтому имя узла —
это КЛЮЧ РЕЕСТРА, и переименован именно он. Отказ по слабой ветке был заложен заранее:
скрипт умеет вытащить id из текста отказа `create_plain` и досудить чтением (повтор
создания дал бы ДУБЛЬ) — ветка не понадобилась, все три шага ответили ok с первой попытки.

Скрипты пары и проверок: `tmp/ramka_2209/step3_replace_pair.py`,
`step4_verify_and_negative.py`, `step5_registry_and_shape.py`.

## 6. Отрицательный тест — сверка ОТКАЗЫВАЕТ, а не зеленеет

Предмет ловли — состояние «канал ответил ok, а в узле лежит ПРЕЖНИЙ текст». Оно взято НЕ
выдуманной строкой, а живым архивным узлом: в нём лежит ровно прежняя редакция, и мост на
его чтение отвечает `ok:true`. То есть «ok» настоящее, не смоделированное; отказать обязана
сверка, и только она. Функция `compare()` — ОДНА И ТА ЖЕ для п.5 и п.6.

```
ЧИТАЛИ KB_shtab_frame_arhiv_20260922_1824utc: мост ok, 60779 знаков
[п.6 прежний текст] НЕ СОВПАЛО. Длины: в узле 60779 знаков / в файле 68788 (108899 / 122999 байт)
[п.6 прежний текст] ПЕРВОЕ РАСХОЖДЕНИЕ: знак №55 (байт №96); совпало знаков подряд от начала: 55
   в узле:  '… (версия 18.09.2026 #1) ═══\nПРИНЦИП: …'
   в файле: '… (версия 22.09.2026 #1) ═══ ПРИНЦИП: …'
[п.6 прежний текст] ВЕРДИКТ: ОТКАЗ — работа сделанной не считается
```

**Контроль (обе стороны одной функцией):** `compare()` дала **СОВПАЛО** на новом узле и
**ОТКАЗ** на прежнем тексте. Первое расхождение — знак **№55**, ровно номер редакции в
шапке: зелёный на подменённом тексте был бы виден числом, а не «наверное».

   (`review_pack.py`), а не «первой строкой», — версия читается; `node_age_pc` рамку в таблице
