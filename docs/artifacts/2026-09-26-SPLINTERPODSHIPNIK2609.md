## 7. Нужна ли записи своя правка

**Да, но она не условие включения.** Правило п.6 запись уже различает. Почему правка нужна:

- Запись **ложная**: согласие на цену, а не факт работ (дверь I; ветка чинит именно рождение таких записей).
- Запись **вечная по устройству**. `prune` выбрасывает только `written`, `expire` лишь меняет исход, а закрыть её
  может только `settle`, то есть реальная запись работы «подшипники» по теме 76 с пробегом. Сейчас для неё нет
  ни буфера, ни факта работ.
- Следствие: `[ERROR]` о «принятой и НЕ записанной работе живого байка» на каждом старте и каждом приёме работ в
  любой теме, на любом дереве. После 12:51 это ещё и ложная «потеря». Шум размывает настоящие потери.

Варианты. **Ничего не сделано** — только названо:

- **(а) код — рекомендую.** Закрытый исход `void` («снято: работы не было», с причиной) в `works_persist.py`:
  не входит в `OPEN_STATES`, `prune` ротирует его как закрытый. К нему — дверь `void(state, chat_id, topic_id,
  slots, why, now)`, ручка снятия по слову владельца и тесты: снятая позиция уходит из `report`, `settle`/`lose`
  её не трогают, `prune` ротирует. Потом этой ручкой снять позицию тема 76 / «подшипники» / 09:51:04.
  **Откат:** revert коммита. Старый код файл с `void` читает безопасно: исход вне `OPEN_STATES` → ни `report`,
  ни ERROR; `prune` старого кода считает закрытыми только `written`, поэтому позиция просто лежит одной строкой.
- **(б) данные разово.** Копия `works_persist_state.json` в `/tmp`, затем атомарная перезапись без позиции 4.
  Файл читается на каждом зове, кэша нет — рестарт не нужен. **Откат:** вернуть копию. Минусы: это удаление
  открытой позиции, против принципа модуля и запрета «ничего не удалять», нужно слово владельца. Закрытого
  исхода кроме `written` нет, а `written` здесь ложь.
- **(в) ждать мира.** Если подшипники действительно сделают и в теме 76 придут работа и пробег, `settle` закроет
  позицию сам. До тех пор ERROR остаётся.
