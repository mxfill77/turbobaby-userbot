## 1. Почему манифест НЕ является заменой перечислению — круг, а не обходной путь

Соблазн очевиден: раз `list_brain` перечисляет — назначим префикс не именам файлов, а КЛЮЧАМ
реестра, и ящик берёт задания из папки по префиксу ключа. **Это не работает, и вот замыкание:**

1. чтобы ключ появился в манифесте, нужен `register_brain_doc(name, id)`;
2. `register_brain_doc` требует **file id** документа;
3. file id документа, созданного Штабом, взять неоткуда — его дало бы **только перечисление
   папки**, которого нет (замеры 1–3);
4. по имени id тоже не добывается — именной путь загорожен манифестом (замер 4).

Круг замкнулся: чтобы увидеть документ в реестре, надо знать его id; чтобы узнать id, надо увидеть
документ. Полоса ПК разорвать этот круг не может ничем из того, что у неё есть.

Единственный разрыв, который у полосы ЕСТЬ, — `create_brain_plain(name, key=…)`: один вызов и
создаёт файл, и регистрирует ключ, id при этом приезжает распиской. Но зовёт его тот, кто КЛАДЁТ
документ, — то есть Штаб, а не демон. Есть ли у Штаба такой вызов, отсюда не видно: по канону
рамки (версия 02.09.2026 #1, `docs/tasks/frame-edition-20260902.txt`) Штаб «кода не выполняет», а
стартовый шаг любого его чата — `tool_search("google drive")`, то есть Drive-коннектор.
**Это и есть вопрос, который решает Штаб, а не полоса.**

## 2. Меню решений для Штаба — с ценой и полосой у каждого

Пункты 2–7 задания (префикс, порядок разбора, способ отзыва, замки на новом источнике,
отрицательные тесты, три числа) исполнимы КАК НАПИСАНЫ только при варианте А или Б. Остальные
меняют само задание.

### А. Добавить мосту экшен перечисления папки — *рекомендуемый*

Сырьё уже лежит на месте: `folder_id` приезжает в манифесте каждым `list_brain`, а ходить в папку
мост умеет (`findChildFileByName_` внутри). Нужен один GET-экшен «имена и id детей папки».

* **цена:** правка Apps Script и выкладка через `clasp`;
* **полоса:** **Dispatch**. Канон рамки шлёт `clasp` туда прямо («328 devbot НЕ МОЖЕТ: реестр
  моста, живые таблицы, деньги, удаление, clasp — такие задачи в Dispatch»);
* **мина, названная заранее:** папка моста `bridge-gs` вне git и УЖЕ ПРОДА на 18 функций и
  5 маршрутов — push из неё сотрёт чужую работу. Базу брать свежим `clasp pull`, а не тем, что
  лежит;
* **что откроется после:** ящик по префиксу собирается полосой ПК за один заход, без второй двери
  в мозг и без единого нового канала.

### Б. Штаб кладёт задания ЧЕРЕЗ МОСТ, с ключом

`create_brain_plain(name="shtab_task_…", key="shtab_task_…")` — файл создаётся и ключ регистрируется
одним вызовом. Тогда перечисление — это `list_brain` с отбором по префиксу КЛЮЧА, тем же путём,
без единой правки моста.

* **цена:** у Штаба должен быть POST-канал к мосту с токеном;
* **вопрос, на который отвечает только Штаб:** есть ли он. Если нет и вызов пойдёт через владельца
  или Dispatch — владелец снова становится транспортом, то есть ЦЕЛЬ ЗАДАНИЯ НЕ ДОСТИГНУТА, и
  вариант отпадает не по технике, а по смыслу;
* **побочное свойство, которое надо знать:** `create_brain_plain` НЕидемпотентен — Drive держит
  одноимённые файлы спокойно. Повтор при потерянной расписке кладёт дубль.

### В. Префикс на ключах, а регистрирует полоса ПК — НЕ РАБОТАЕТ

Разобрано в §1: нужен id, id даёт только перечисление. Записан здесь не для полноты, а чтобы его
не предложили заново: снаружи он выглядит самым дешёвым и он единственный полностью тупиковый.

### Г. Читать папку страницей `embeddedfolderview`

Перечисление даёт: `https://drive.google.com/embeddedfolderview?id=<folder_id>#list` отдаётся
**анонимно**, обычным `urllib` без единой куки (замер 15.08.2026 — снято 38 имён; техника
описана в `docs/artifacts/2026-08-05-audit-package-v2-to-drive.md:78`). В коде полосы не
использована ни разу — только в разовых разведках.

**Но пункт 1 спрашивал не «есть ли способ», а «доступно ли ТЕМ ЖЕ ПУТЁМ», и ответ здесь «нет»:**
другой хост, без токена, без расписки, разбор HTML регуляркой, права — «читаемо любым, у кого есть
ссылка». Это **вторая дверь в мозг** со своим набором отказов, и молчать она будет иначе, чем мост.
Решение о второй двери — Штаба, не полосы.

### Д. Оставить один узел, а дозапись Штабу дать иначе

Предмет не полосы ПК: узел `shtab_box` жив, ключ зарегистрирован, ящик его читает. Меняется не
ящик, а инструмент Штаба.

## 3. Что НЕ тронуто (проверено, а не обещано)

Кода не менялось ни строкой, поэтому все замки и сигналы остались ровно теми же — и это доказано
не словами, а прогоном:

```
venv/Scripts/python.exe -m unittest test_shtab_box test_shtab_box_signals
```

**Три прогона одной командой — три одинаковых числа: 130 · 130 · 130, OK.**

В этих 130 живут, среди прочего, оба инварианта, о которых спрашивало задание:

* `SHTAB_BOX_PURE` — чистая логика решения (`TestPurity`);
* **`SHTAB_BOX_READS_ONLY`** (`TestReadsOnly`) — **ящик читает один узел и НЕ ПИШЕТ в мозг ни одной
  веткой**, обходом AST. Инвариант «только чтение» проверяется ТЕМ ЖЕ способом, что и до захода,
  потому что и способ, и предмет остались прежними.

Сверх того не тронуты и не касались вовсе: ворота приёма (`check`), четыре сигнала остановки
(`shtab_box_signals`), суточный потолок, дедуп по ключу, лимит витка, стоп-файл, гард, карточки,
клиентский контур, боевая очередь. Ни один тестовый ряд в боевую очередь не ставился: все живые
обращения захода — ЧТЕНИЕ моста (`list_brain`, `read_doc`, проба неизвестных экшенов).
