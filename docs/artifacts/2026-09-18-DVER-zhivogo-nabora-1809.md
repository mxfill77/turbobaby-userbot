## 1. Развод хранилищ

| что | тренажёр (не менялось) | живой набор (новое) |
|---|---|---|
| журнал вердиктов | `exam_verdicts.tsv` | `exam_live/verdicts.tsv` |
| стол (отметки, ожидание «своё») | `exam_session.json` | `exam_live/desk.json` |
| база уроков | `lesson_store.tsv` (боевая, её читает голова) | `exam_live/lessons.tsv` |
| корпус / снимки | `trainer_cases.json` / `exam_shots/` | `exam_live/cases.json` / `exam_live/shots/` |
| голова кнопки | `exam:` | `examlive:` |

Весь `exam_live/` уже был под `.gitignore`, новые файлы в git не идут.

**Как устроено.** `use_live_set` теперь переключает все пять путей разом, плюс имя набора, голову кнопки и имя
разбора в агенте. Перечень переключаемого один (`SET_FIELDS`), `set_state`/`restore_set` возвращают его целиком.
Повторный вызов не затирает базу головы.

**Происхождение записи.**
- **Вердикт:** в конце строки журнала новая графа `набор` (`тренажёр`/`живой`). Версия набора лежит в графе
  `корпус`: это отпечаток `cases.json`, равный версии набора (63-q). Случай — графа `кейс`. Квитанция называет
  набор и файл журнала, трасса печатает `набор … · версия … · кейс …`.
- **Урок:** набор виден по файлу базы. Номер урока лежит в графе `уроки` строки вердикта, а через неё видны
  версия и случай. **Своей графы набора и версии у строки урока нет:** источник в `lesson_store` — закрытый
  перечень из четырёх слов, и расширять его этим заходом я не стал.
- **Карточка живого набора:** шапка `🎓 ЭКЗАМЕН · ЖИВОЙ НАБОР (версия <отпечаток>) · кейс …`. Карточка тренажёра
  байт в байт прежняя.

**Следствие, названное вслух: уроки живого набора на ответы бота НЕ действуют.** Голова читает боевую базу, а
не `exam_live/lessons.tsv`. Карточка, квитанция «Применить» и ответ «своё» говорят это словами. Подсказка
перевода несёт `--path exam_live/lessons.tsv`: без него `lesson_promote.py --promote N` перевёл бы урок
тренажёра с тем же номером. Перенос урока из живого набора в боевую базу — отдельное решение владельца.

**Версия правил снимка** (`freeze`) берётся с базы, которую читает голова (`head_rules_version`), а не с базы
уроков живого набора. Иначе снимок живого набора назвал бы правила, по которым бот не отвечал.

## 2. Дверь

- **Кнопка → агент.** `EXAM_LIVE_CB_RE = ^examlive:(ok|no|own|go|h[1-4]):([0-9]{1,3})$`, хвост по-прежнему одно
  число. `_chain_cb_route` отдаёт вид `exam_live`, исполнитель зовёт ту же дверь `_exam_cli(…, live=True)`, к
  аргументам спереди встаёт `--live`. Тост начинается словами «живой набор:». Разбор тренажёра `EXAM_CB_RE` не
  тронут ни символом.
- **Текст «своё» в группе.** `_exam_pending_set` читает оба стола. Если ждут оба, текст уходит столу с более
  поздним ожиданием (последняя нажатая «своё»), и ответ двери называет набор. Проверено на стенде (Ш11, Ш12).
- **Замок показа.** `agent_parse` ищет разбор по имени набора. Карточка живого набора сверяется с
  `EXAM_LIVE_CB_RE`, карточка тренажёра — с `EXAM_CB_RE`.
- **Открыто под `--live`:** `--freeze`, `--card`, `--slots`, `--show`, `--tap`, `--toggle`, `--apply`, `--own`,
  `--own-text`, `--rollback`, `--trace`, `--agent`.
- **Закрыт один ход — `--reach`:** группа-тренажёр одна на оба набора, её видимость от набора не зависит. Отказ
  дословно (Ш26): `rc=2 ⛔ ход «--reach» живому набору не нужен: группа-тренажёр одна на оба набора, и её
  видимость проверяется без --live. Ничего не сделано.`
- **Живой агент сейчас.** `exam_show.py --live --agent --case 13` на боевом дереве, только чтение, дословно:
  `НЕТ — живой агент (pid 13740) СТАРШЕ кода кнопки на 461561 с: файл «pc_agent.py» правлен после его старта. …
  Цена снятия: владелец шлёт агенту в тему 205 одно слово «обновись»…`; колбэков карточки 6, все `examlive:`.
  Показ живого набора до «обновись» откажет сам, и тап не потеряется. Процесс я не трогал.
