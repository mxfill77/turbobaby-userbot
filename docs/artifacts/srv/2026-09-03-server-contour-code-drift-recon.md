## 5. Чем это увидеть штатно: что есть и чего нет

**ЕСТЬ (проверено кодом и живым следом):**
1. `prod_drift` в памяти демона — замыкание импортов, порог 4 ч, заметка в ленту 829 + строка в

2. О3 в слое ожиданий — таймер каждые 10 минут, тот же список юнитов, порог 4 ч, окно судейства

   смерть демона и не подвержен собственному классу.
3. Путь C — `deliver_card`: вердикт О3 «не доставлен» превращается в **вопрос владельцу карточкой**
   (`_maybe_deliver_ask`, зовётся в `cycle()` строкой 6616), с дедупом между дверьми
   (`ask_ledger`). Ветка гаснет только явным `DELIVER_CARD=0`.

**ЧЕГО НЕТ (законный исход, названный прямо):**
1. **wa-webhook не наблюдает никто.** Список наблюдаемых — два юнита, и О3 берёт ТОТ ЖЕ список.
2. **Нет прибора у видов доставки, кроме «код в памяти» и «байты с диска».** Выкладка Apps Script
   наружу О3 числит ненаблюдаемой; конфиги и юниты у владельца — тоже. Сегодняшний redeploy @84
   ни один механизм сервера событием не сделал.
3. **Ни один прибор не смотрит на venv и сторонние зависимости** — замыкание считает только файлы
   нашего репозитория.
4. **До 4 часов отставание не называется вовсе** — по построению порога.
5. **Прибор говорит, но не чинит,** и говорит в каналы, на которые не отвечают (лента 829 и
   журнал). Дверь ответа (карточка) существует, но за всё наблюдение в журнале рождения карточек
   `chain_cards.jsonl` записей о доставке — **0**, и в журнале демона строк `[доставка коммита` —
   **0**. То есть путь C на сервере живьём ещё не отрабатывал.
6. **Гейт к отставанию отношения не имеет:** он судит дерево, а не то, что процесс держит в памяти.
7. **Нет прибора на «работа идёт, а в git не ложится».** Оба механизма меряют путь «коммит →
   процесс» и по построению слепы к разрыву раньше: три дня без единого коммита при полусотне
   отработанных заходов не породили ни одной заметки — и не могли. То же и с неудачным push:
   отказ удалённой стороны не является событием ни для одного наблюдателя на этой машине.
