# Мост врёт о результате записи: код ответа описывает РАСПИСКУ, а не судьбу записи

**Сделано:** 01.08.2026, ПК-контур, `brain_writer.py` + `test_brain_writer.py`.
Живой повод: задача 166 — запись блока в KB_MASTER, мост ответил **HTTP 404**, а блок **ЛЁГ**
(проверено чтением назад: 91 959 → 92 827 симв., вхождение 1, хвост побайтово равен бэкапу).
Дубля не возникло только потому, что `append` идемпотентен и повтор стал пустой операцией.

---

## 1. Механизм — факт, не гипотеза. Где именно

Три звена, каждое проверяемо:

1. **Тело POST-а Apps Script отдаёт ВТОРЫМ ПЛЕЧОМ.** Ответ собирается через
   `ContentService.createTextOutput(...).setMimeType(JSON)` (`tmp/bridge_v75/Bridge.js:495-497`),
   но `/exec` на POST отвечает **302** на `script.googleusercontent.com/macros/echo?...`, и тело
   забирается уже оттуда. `urllib.request.urlopen` идёт по редиректу **внутри себя** — значит
   падение второго плеча приходит к клиенту **тем же исключением**, что и падение первого.
   Различить их снаружи нечем.
2. **Мутация фиксируется ДО того, как расписка вообще отправлена.** `writeDoc_` зовёт
   `brainTextWrite_(id, text)` и лишь **потом** собирает `{ok:true, chars}`
   (`tmp/bridge_v75/ReadDocs.js:352-354`). К моменту, когда 404 родился на втором плече, документ
   уже перезаписан.
3. **Флакость измерена раньше нас.** `docs/artifacts/2026-07-28-journal-write-fixes.md` §1:
   «404 … разовым отказом endpoint'а Apps Script (класс известной флакости `/exec`: POST → 302 →
   `googleusercontent`, цель редиректа иногда отдаёт 404)» — при совпавших адресах и токенах ПК/VPS.

**Вывод:** HTTP-код описывает **доставку расписки**, а не судьбу записи. Использовать его как факт
записи нельзя в принципе — не «пока мост флапает», а никогда.

### Место, которое превращало это в ЛОЖЬ

`brain_writer.apply()`, до правки:

```python
try:
    w = (post or _post)(url, dict(addr, action="write_doc", ...))
except Exception as e:
    raise BrainWriterError("write_doc(%s) упал: ..." , 4)   # ← обратное чтение НИЖЕ не выполнялось
```

`except` — короткое замыкание: обратное чтение, ради которого канал и построен, **не запускалось
вовсе**. А CLI поверх этого печатал `НЕ ЗАПИСАНО.` — **утверждение о факте, которого код не
проверял**. Ровно эта строка и толкает исполнителя на повтор.

## 2. Это КЛАСС, а не единственный случай

Ни один POST-сайт писателя не судил по чтению — все судили по ответу:

| место | что говорило | чем опасно |
|---|---|---|
| `apply()` (write_doc) | «упал», CLI — «НЕ ЗАПИСАНО» | ложь при легшей записи; спасал только идемпотентный `append` |
| `create_plain()` | «create_brain_plain упал» | создание **НЕидемпотентно**, id приходит только с распиской → повтор кладёт **второй файл** тем же именем, и проверить нечем |
| `_brain_admin_post()` — `register_doc` / `move_into_brain` / `unregister_doc` | «упал» | `unregister_brain_doc` **односторонний**: «упал» читается как «ключ на месте», хотя ключа уже нет |
| `cowork_log_append.py` | спулит строку и рапортует отказ | известный класс «ложный 401 при уже легшей строке» → дубль в журнале при досылке |

Обратная сторона того же: мост может ответить `ok`, а док не измениться — по коду ответа
неотличимо от успеха.

## 3. Правка: судит ЧТЕНИЕ, а не код ответа

Bridge не наш (прод, деплой не делаем) — поэтому достоверность строится на нашей стороне.

- **Отказ моста больше не обрывает проверку.** Он запоминается в `receipt_err`, после чего
  **всегда** идёт обратное чтение, и оно выносит вердикт.
- **«Не записано» говорится ТОЛЬКО когда док прочитан и не изменился** — и тогда прямо сказано,
  что **повтор безопасен**.
- **Легло при отказе моста → это УСПЕХ** с честной пометкой: `receipt="lost"`,
  CLI печатает «потеряна РАСПИСКА, А НЕ ЗАПИСЬ … Повторять НЕ НУЖНО».
- **Не удалось ни то, ни другое → так и сказано**: `written=None`, «ИСХОД ЗАПИСИ НЕ ПОДТВЕРЖДЁН …
  СЛЕПОЙ ПОВТОР ЗАПРЕЩЁН» + путь бэкапа. Врать в любую сторону здесь нельзя.
- `BrainWriterError.written` (`False` — проверено чтением, `None` — не подтверждено) отделяет
  **судьбу записи** от **причины отказа**; CLI печатает вердикт по нему.
- Сам POST по-прежнему **не повторяется никогда**, идемпотентность `append` не ослаблена.
- Соседние экшены (`create_plain`, админ-посты реестра) больше не говорят «упал»: они называют
  исход **неизвестным** и предупреждают о дубле/одностороннести.

## 4. Регресс (красный до правки, зелёный после)

Класс `TestReceiptIsNotTheFact` — 6 тестов на все концы развилки. Мок **копирует живой формат
разрыва** (правило-класс CLAUDE.md): `lose_receipt` сначала **меняет док** и только потом бросает
`HTTPError`, потому что именно так ведёт себя второе плечо; `drop_write` бросает **до** мутации.

| тест | что держит |
|---|---|
| `test_landed_write_with_lost_receipt_is_reported_as_success` | 404 при легшей записи → `status=ok`, `receipt=lost` |
| `test_lost_receipt_does_not_weaken_idempotency` | повтор после потери расписки → `noop`, вхождение ровно 1 |
| `test_write_that_never_landed_still_errors` | не легло → ошибка 4, `written is False`, «НЕ ЛЕГЛА» |
| `test_bridge_ok_but_doc_untouched_is_caught` | мост сказал `ok`, док не изменился → ошибка 5 |
| `test_unknown_outcome_is_named_unknown_not_failure` | оба канала молчат → `written is None`, запрет слепого повтора |
| `test_cli_claims_not_written_only_when_it_read_the_doc` | «НЕ ЗАПИСАНО» печатается только по прочитанному факту |

**Замер:** на старом `brain_writer.py` (через `git stash`) новые тесты — **5 errors + 1 failure из
6**; после правки — `test_brain_writer` **55/55 OK**.
Полный гейт: `python -m unittest discover` → **2752 теста, OK (skipped=10)**.
