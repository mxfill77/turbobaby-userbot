## 1. Прибор экзамена — четыре части контракта наблюдения

Прибор: `_scratch_exam_s1_0815/exam_instrument.py`. Прогон: `_scratch_exam_s1_0815/exam_s1_run.py`.

1. **РЕЗУЛЬТАТ, названный словом** (не «шаг отработал»): в `drafts` появилась **ровно одна** строка,
   у неё `status='new'`, `client_id` = тестовый id, `incoming` **дословно** равен последней строке
   клиента, `draft` непуст, `transcript` и `pricing_note` непусты (E1.1 + E1.2 артефакта).
2. **ИСТОЧНИК ИСТИНЫ** — файл `moderation_ipc.db`, таблица `drafts`. Не лог, не PID, не код возврата.
   Прибор открывает файл **сам**, отдельным соединением, и результат `on_client_message` не смотрит
   вовсе — в §2 видно, что код возврата (`None`) и вердикт получены независимо.
3. **СПОСОБ** — чтением источника **назад** после шага: снимок ДО, снимок ПОСЛЕ, разница по `id`.
4. **ТРИ ИСХОДА** — `ПРОШЛО` / `НЕ ПРОШЛО` / `НЕ СУДИМО`. Главное правило прибора: **при нуле новых
   строк сказать `ПРОШЛО` запрещено** — источник не различает «прихода не было» и «приход был,
   продукт не родился», поэтому честный исход тут ровно один: `НЕ СУДИМО`.

Рядом заведён **контрфакт** — наивный прибор из артефакта, считающий приходы как `COUNT(drafts)`.
Он нужен, чтобы показать не «наш прибор осторожен», а **разницу вердиктов на одних и тех же байтах**.

## 2. Отрицательный тест S1 — шёл ПЕРВЫМ, до всего остального

**Посылка воспроизведена, а не объявлена.** Bridge отдаёт живой `HTTPError 404` на `opener.open`

```

```

Без этой проверки сценарий выродился бы в тест ни о чём.

Все четыре ноги «правильного» поведения S1 подтвердились: черновик не собран, строки в `drafts`

### Источник истины ПОСЛЕ шага — состояние B «приход был, продукт не родился»

```
1.3 СОСТОЯНИЕ B «приход был, продукт не родился» — ДОСЛОВНЫЙ вывод источника ПОСЛЕ шага
<0 строк в drafts>
heartbeat модербота свеж: True
```

### Вердикты

```
КОНТРФАКТ (наивный прибор, COUNT(drafts)): ПРОШЛО — COUNT(drafts)=0 → «приходов не было», претензий нет
ПРИБОР ЭКЗАМЕНА на состоянии B: НЕ СУДИМО — новых строк в drafts НЕТ. Источник истины НЕ различает
  «прихода не было» и «приход был, продукт не родился»: в обоих случаях 0 строк и ни одного
  поля-следа. Зелёным это состояние объявить нельзя

N1 «замок от ложного зелёного»: прибор на B НЕ сказал ПРОШЛО → УСТОЯЛ (прибор умеет краснеть)
N2 «корневой отрицательный тест S1»: различает ли ИСТОЧНИК ИСТИНЫ A и B? → False
   (снимки drafts совпали ПОБАЙТОВО (0 строк ↔ 0 строк))
   исход N2: КРАСНЫЙ — источник НЕ различает A и B (как и предсказал артефакт)
```

**Вердикт отрицательного теста: УСТОЯЛ.** Читать так:

- **N1** — на состоянии, которое выглядит идеально спокойным (drafts пусты, heartbeat свеж), прибор
  дал **ОТКАЗ**, а наивный прибор на тех же байтах дал **зелёное**. Разница вердиктов на одном и том
  же содержимом источника — и есть доказательство, что прибор отказывается зеленеть.
- **N2** — источник истины A и B совпал **побайтово**. Артефакт требовал: «тест обязан падать, пока
  прибор не различает эти два состояния». Тест **пал в красное** — ровно как предсказано. Красный
  N2 — это не поломка прибора, это его правильная работа: он назвал дыру контура, а не замазал её.

Если бы N1 дал зелёное — прогон обязан был остановиться на этом месте («прибор не годен»). Ветка
остановки в коде есть (`sys.exit(2)`) и не сработала.
