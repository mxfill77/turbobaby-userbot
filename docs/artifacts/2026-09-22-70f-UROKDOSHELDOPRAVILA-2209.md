## 3. Диагноз на обрыве — ровно, как требует задание

Обрыв **не один**, и диагнозы у них РАЗНЫЕ; слить их значило бы предложить не ту правку:

1. **Перенос урока из базы живого набора в боевую — ХОДА НЕТ И СОСУДА ТОЖЕ.** Функции, которая

   вызывающего нет, следа нет.
2. **Перевод кандидата в действующие внутри ОДНОЙ базы — СОСУД ЕСТЬ, И ХОД ЕСТЬ, НО ХОЛОСТОЙ.**
   Есть функция (`lesson_store.promote`), есть дверь (`lesson_promote.py`), есть живой вызывающий

3. **Чтение действующих правил — ход есть и работает.** Девять правил боевой базы доезжают до

## 4. Отрицательный тест: сломал пройденный шаг — проверка заметила числом

Ломался шаг 4 (единственный, прошедший живьём целиком), и ломался ЖИВОЙ ДВЕРЬЮ, а не руками:

```
lesson_batch.py --path tmp/trener_cep_2209/lessons.tsv --who cepproba --off перенос_книги --count 9
  → «🧹 Набор «перенос_книги» СНЯТ ЦЕЛИКОМ: 9 строк(и) больше не отвечают клиентам»
читатель ответа        → буллетов 0, прочитана True          (было 9)

  → «↩️ Набор «перенос_книги» ВОЗВРАЩЁН: 9 строк(и) снова в том состоянии…»
читатель ответа        → буллетов 9, прочитана True          (вернулось)
```

**9 → 0 → 9.** Проверка заметила поломку и заметила починку; значит числа п.2 опубликованы
законно. Вторая проба — на третий исход: читатель, направленный на путь, которого нет, ответил
`0 буллетов, прочитана False`, то есть «действующих нет» и «источник не прочитан» он НЕ путает
(в первом случае секция промпта пустеет, во втором вызывающий возвращается к книге-снимку).
