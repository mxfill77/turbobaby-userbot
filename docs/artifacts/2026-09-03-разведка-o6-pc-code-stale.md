## Причина срабатывания (цепочка названа поимённо)

Ребро, по которому `zayavki_pc.py` попадает в «замыкание userbot», — четыре ленивых импорта
подряд, каждый со своей строкой:

```
userbot_listen.py:43   import trainer
trainer.py:593             import lesson_router          # ленивый, внутри функции
lesson_router.py:425           import pc_orchestrator    # ленивый, ради очереди
pc_orchestrator.py:9975            import zayavki_pc_run # ленивый, оборот ступени G
zayavki_pc_run.py:46                   import zayavki_pc
```

Это ровно то ребро, о котором предупреждает шапка `client_contour.py:28–36`: «через это одно
ребро в клиентский контур въезжает весь демон… Это межпроцессная граница-вызов, а не рантайм
бота». Для вопроса о клиентском контуре обход его РЕЖЕТ (`FOREIGN_ENTRIES =
("pc_orchestrator.py", "pc_agent.py")`). О6 срез снимает СОЗНАТЕЛЬНО — `code_facts` зовёт
`contour.closure(REPO, entries=(entry,), cut=())` (`expectations_pc_run.py:441`), потому что ветку
заводили ради `pc_agent`, где замыкание — 5 своих файлов и снятый срез верен. У ребёнка-бота тот
же снятый срез втягивает чужой процесс целиком.

**И это расходится с намеренным решением о рестартах, записанным в самом демоне**
(`pc_orchestrator.py:5846–5848`, дословно):

> «Маршрут РЕСТАРТА детей (`_classify_changed` → userbot/moderbot) не тронут ни одной строкой и
> по-прежнему идёт по карте: замыкание бота — 63 файла, и **рестартить живого бота на каждый
> коммит в инфраструктуру никто не просил**.»

То есть О6 судит детей по мерке, которую владелец для рестарта детей отверг явно.

## Ложное или настоящее — числом

**Ложное по предмету.** Предмет заметки — «в памяти процесса код старее диска». Своих файлов,
новее старта, у userbot **0 из 8** по карте и **0 из 4** по принадлежности только ему. Всё
отставание в 3288.86 с даёт **1 файл** (`zayavki_pc.py`), который userbot не импортирует ни на
одном живом пути: до него нужно, чтобы userbot исполнил оборот ступени G демона.

**Верное по букве.** По определению «замыкание с `cut=()`» вердикт посчитан правильно, и ветка
честно fail-closed. Дефект не в вычислении, а в выборе замыкания для детей.

**Оговорка, которая усиливает вывод.** Все четыре ребра цепочки — ленивые импорты внутри функций.
Если userbot когда-нибудь пойдёт по этому пути, он загрузит модуль **с диска в тот момент**, то
есть получит СВЕЖИЙ код. Для лениво-неимпортированного модуля правило «newest > started ⇒ в
памяти старое» не выполняется вовсе: О6 здесь пессимистична дважды.
