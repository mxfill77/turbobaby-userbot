# Наблюдатель называет файл лока целиком: срез в 60 символов съедал имя до трёх букв

**Дата:** 05.09.2026 · **Полоса:** ПК · **Задание:** `00-lock-path.0905` (ящик Штаба,
док `shtab_task_00-lock-path.0905`) · **Коммит:** `d79f556`

имя лока перестало обрезаться

## Признак сделанности (первым действием)

Адрес результата — файл в `docs/artifacts` за 05.09 со словами адреса. Перед работой в каталоге
лежало 20 артефактов за 05.09; ни одного со словами адреса нет, вопросы задания не отвечены нигде.
Ближайшие по теме — `2026-07-24-rc-lock-standstill.md` и `2026-07-31-*-lock-*` — про совсем другие
замки (RC и гард), к сообщению наблюдателя отношения не имеют. Вывод: задача делается с нуля.

## Премиса — проверена своими командами, не на слово

Проба `_scratch_lock_path_0905/probe1.py` (только чтение, боевых файлов не трогает).

**П.1 — битый путь воспроизведён дословно.** Прежний код клал в сообщение `str(e)[:60]`:

```
лок pc_agent не прочитан: [Errno 2] No such file or directory: 'D:\\turbobaby-bot\\pc_
```

Ровно та строка, что стои́т в задании. Замер длин на живой машине (пятая секция probe1):

| процесс | полная строка отказа | что доезжало до владельца после `[:60]` |
|---|---|---|
| `moderation_bot` | 77 симв. | `…'D:\\turbobaby-bot\\mod` |
| `pc_agent` | 71 симв. | `…'D:\\turbobaby-bot\\pc_` |
| `pc_orchestrator` | 78 симв. | `…'D:\\turbobaby-bot\\pc_` |
| `userbot` | 70 симв. | `…'D:\\turbobaby-bot\\use` |

**П.2 — лок существует, имя названо точно.** В корне репозитория лежат все четыре лока:
`pc_agent.lock` (174 байта), `pc_orchestrator.lock` (182), `moderation_bot.lock` (180),
`userbot.lock` (181). Настоящее имя из премисы — **`pc_agent.lock`**, полный путь
`D:\turbobaby-bot\pc_agent.lock`. Живой `_read_lock` на момент разбора читает все четыре без
жалоб: `pc_agent` → `pid=25688, opened=True, started=1788584758` (запуск 05.09 12:05), `err=''`.

**П.3 — про «стои́т вечно»: подтверждено механизмом, но с поправкой, и поправку говорю вслух.**
Цепочка проверена по коду: лок не прочитан → `started=None` → `expectations_pc.code_state` ветка 7
→ `CODE_UNKNOWN` с текстом «момент запуска pc_agent не добыт (<текст отказа>)» → заметка
`o6_pc_code_unknown` с ключом `o6u|pc_agent`; закрыть её (`expectations_pc.closures`) может ТОЛЬКО
`CODE_FRESH`, а `CODE_FRESH` требует того самого `started`. То есть пока лок не читается, пометка
не снимается ни одной дорогой — премиса верна.

Поправка честности: **в момент моего замера (05.09 ~15:00) пометка не стоит** — `tmp/expect_pc/
state.json` держит открытыми только эпизоды `userbot` и `moderation_bot` (`o6c|…`, `o6l|…`), а
строка `pc_agent` в разделе `code` показывает «код с диска». Отказ чтения был жив, пока лока не
было на диске (агент поднялся в 12:05 и написал лок), — и всё это время владелец видел про него
сообщение, по которому нельзя было понять, о каком файле речь. Ни один из четырёх процессов по
такому сообщению не опознаётся, а `pc_agent` и `pc_orchestrator` не отличаются даже друг от друга.

## Где путь терял хвост: механизм назван

**Это НЕ склейка и НЕ разделение по подстроке. Это обрезание по длине — `str(e)[:60]`** в
`expectations_pc_run._read_lock` (строка 319 до правки). Путь всё это время собирался ВЕРНО
(`os.path.join(REPO, "pc_agent.lock")`), и `open()` получал его целиком; резалось только
СООБЩЕНИЕ об отказе.

Почему срез попадал ровно в имя — арифметика, а не случайность:

```
[Errno 2] No such file or directory: 'D:\\turbobaby-bot\\    ← 57 символов
                                                        pc_  ← оставшиеся 3 из 60
```

`str(OSError)` кладёт имя файла ПОСЛЕДНИМ и через `repr`, а `repr` на Windows **удваивает каждый
разделитель** (`\` → `\\`). Постоянная часть — текст ошибки (37) плюс кавычка, диск и корень репо
в удвоенном виде (20) — съедает 57 символов из 60. На имя остаётся три буквы, и они одинаковы у
двух разных процессов. Отсюда и вид «путь обрезан»: обрезан не путь, а рассказ о нём.

## Другие процессы: страдают все, механизм один

Затронуто **4 имени из 4** (`pc_agent`, `pc_orchestrator`, `userbot`, `moderation_bot`) — таблица
выше. Место сборки сообщения при этом ОДНО: `_read_lock` — общий кусок для О3, детей и О6, его
зовут все четыре ветки. Поэтому чинится один раз, а не четыре.

Рядом нашёлся тот же класс на соседнем файле: в `own_facts` продукт ребёнка резался как
`str(e)[:80]`, а `repr` пути `turbobaby_session.session` — 83 символа, то есть у userbot имя
продукта обрезалось ровно так же. Вылечено тем же вызовом (см. ниже); третье место —
`code_facts` («файл замыкания не прочитан») — переведено на тот же помощник, там имя и раньше
стояло до среза.

## Правка: имя берётся целиком и стои́т ДО среза

Единица одна — одно место сборки сообщения плюс единый источник имени.

1. **Один источник имени.** Заведён `LOCK_FILES` (4 строки) и `lock_path(name)`. До правки имя
   лока лежало литералом в трёх местах модуля, а `pc_agent.lock` был написан руками ДВАЖДЫ
   (`KID_FILES` и `CODE_LOCKS`). Теперь `MOD_LOCK_FILE`, `KID_FILES` и `CODE_LOCKS` берут путь
   у него; собрать имя из кусков в модуле больше негде.
2. **`_why_short(exc, path)`** — причина отказа СЛОВАМИ, из которой путь вырезан. Режется только
   она (`ERR_TAIL = 80`).
3. **Сообщение**: `лок <процесс> (файл <basename>) не прочитан: <причина>`. Имя файла берётся у
   пути одним куском (`os.path.basename`) и стои́т ДО любого среза.

Против предсмертного взгляда задания («впишут правильное имя строкой рядом с битым, а следующий
процесс с длинным именем сломается так же»): имя нигде не вписано литералом в текст сообщения —
оно вычисляется из пути, и срез до него не доходит вовсе. Тест держит это именем в 91 символ.

## Честность наблюдателя не ослаблена

Третий исход на месте и говорится словами: при непрочитанном локе состояние по-прежнему
`неизвестно`, заметка ставится, а `closures` её не закрывает — правка не тронула ни одной ветки
решения (`expectations_pc.py` не менялся вовсе, в коммите его нет). Изменился только ТЕКСТ, каким
прибор сознаётся в своей слепоте: теперь он называет файл.

## Тесты

Новый класс `TestLockNameIsNeverCut` в `test_expectations_pc.py` — 8 проверок: все четыре имени
целиком · имя длиной 91 символ переживает срез · режется причина, а не имя · единственность
источника имени (разбор `ast` по модулю: литералов `*.lock` ровно 4 и все в `LOCK_FILES`) · три
отрицательных теста задания · живой замер по боевым локам («отказ обязан назвать свой файл»).

Свой набор целиком: `python -m unittest test_expectations_pc` → **Ran 186 tests, OK** (было 178).
