## 1. Что чинили — ровно одно место

`expectations_pc_run._bridge()` ставил тест-флаг НАВСЕГДА и никогда не снимал:

```python
def _bridge():
    os.environ.setdefault("TURBOBABY_TEST_LOGS", "1")   # ← возврата нет нигде
    import pc_orchestrator as o
    return o.bc
```

Флаг нужен на **импорт** демона (иначе наблюдатель вешает хендлер на боевой лог того, за кем
следит). Но тот же флаг читает `log_setup.is_test_context`, а по нему `dispatch_notify._cowork`
отказывает строке в журнале владельца (замок 19.08.2026). `_bridge()` зовётся ПЕРВЫМ в боевой
форме `run()` (`getter=None` → `queue_facts` → `_bridge`), поэтому к моменту `send_pulse`
наблюдатель уже выглядел тест-прогоном — **для самого себя**.

Правка — зеркало уже написанного в этом же репо `queue_snapshot_pc._guard_test_logs`
(посылка сверена, а не форма: флаг там глушит `brain_writer`, здесь — `_cowork`; механизм и
цена совпадают дословно):

```python
def _guard_test_logs(fn):
    key = "TURBOBABY_TEST_LOGS"
    had, prev = key in os.environ, os.environ.get(key)
    os.environ[key] = "1"
    try:
        return fn()
    finally:
        if had:
            os.environ[key] = prev
        else:
            del os.environ[key]

def _bridge():
    return _guard_test_logs(_daemon).bc
```

Флаг живёт **ровно один импорт**. Возврат в `finally` — сознательно: падение импорта не смеет
оставить флаг стоять, иначе один сбой демона глушит пульс до конца жизни процесса.

**Возврат КАК БЫЛО, а не удаление.** Если флаг заявлен снаружи (средой задачи, вызывающим), это
его решение, и стирать чужое заявление мы не вправе. Отсюда честная неизвестность §5.

## 2. Чего правка НЕ открыла — замок 19.08 стои́т

Класс «тест-прогон пишет в журнал владельца» (21 строка из 26 за сутки) ловится ещё **тремя

Снятие **утёкшего** флага у боевого наблюдателя не делает прогон тестов боевым ни одной веткой.

## 3. Регресс: покрыт склон, которого не было

Существующий `TestPulseChannelMutedInTestRun` (19.08) сторожил ОДНУ сторону — «из-под тестов
наружу не течёт», и он зелен. Мёртвым был обратный склон: боевая форма `run(getter=None)` не
проверялась ни одним тестом, и **зелёный гейт был полностью совместим с мёртвым пульсом
двенадцать суток**.

Заведён `TestBridgeDoesNotLeakTestFlag` (3 кейса, `test_expectations_pc.py`):

1. `test_live_form_leaves_no_test_flag_behind` — боевая форма проходится ЦЕЛИКОМ
   (`run → queue_facts → _bridge → _guard_test_logs`), демон подменён на `_daemon`; проверяется,
   что на импорте флаг **стоял** (`"1"`), а после возврата его **нет**, и оставленное окружение
   само по себе канал не глушит. Ветка публикации при этом обязана быть ЗАДЕТА (`kids_pulse ==
   "ушла"`) — иначе замок сторожил бы пустоту.
2. `test_flag_returns_even_if_the_import_explodes` — падение импорта флаг не оставляет.
3. `test_flag_value_that_was_there_is_returned_as_it_was` — заявленное снаружи значение
   возвращается, а не стирается.

**Почему предмет — окружение, а не спавн писателя.** Спавна изнутри прогона не увидеть НИКОГДА
и по честной причине: мы сами исполняемся тест-раннером, и `_started_as_test_runner()` глушит
канал по `argv[0]` независимо от флага. Утверждать «в бою запись пойдёт», сидя внутри теста, —
это подгонять голден под удобство. Проверяется ровно та переменная, которую портил дефект.

**Своё отделено от чужого.** `TESTING`/`PYTEST_CURRENT_TEST` заявляет о себе САМ прогон, поэтому
из снимка окружения они изъяты: оставь мы их — замок был бы вечно красен по причине, к дефекту не
относящейся.

### 3.1. Контрфакт: тест ловит СТАРЫЙ дефект

Зелёный тест на исправленном коде о сторожевой силе не говорит ничего — ровно так гейт оставался
зелёным при мёртвом пульсе. `_scratch_pulserevive_0901/counterfact.py` подменяет `_bridge` его
дословно старой редакцией (живой файл не трогая) и гоняет тот же класс:

### 3.2. Побочная находка: замок вываливал боевые токены

Первая редакция кейса стояла на `assertNotIn("TURBOBABY_TEST_LOGS", os.environ)`. Контрфакт
показал цену: `assertNotIn` печатает при провале **весь словарь окружения**, а в нём живут боевые
токены моста и трёх ботов — то есть отказ замка в логе гейта означал бы утечку секретов.
Заменено на `assertIsNone(os.environ.get(...))` — предметом стало ЗНАЧЕНИЕ ключа, а не членство
в отображении. Замок, чей отказ дороже ловимого дефекта, — плохой замок.
