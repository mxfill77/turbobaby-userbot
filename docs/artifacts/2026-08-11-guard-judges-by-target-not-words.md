# Гард судит ЦЕЛЬ команды, а не слова в её теле (11.08.2026)

## Живой случай

`pretool_guard.log:7798`, **11.08 12:04:45 локального (= 05:04:45 UTC)**:

```
ssh … root@5.223.94.179 'cat > /root/turbobaby-manager-bot/docs/artifacts/
2026-08-11-curator-goal-repeats-duplicates.md <<"MDEOF" # Кураторские цели …
```

Вердикт — `ask | env`, объект пустой. Секретов операция не касалась: удалённая команда —
`cat > <артефакт>.md`. Слово `.env` пришло из **блока запретов записываемого ТЗ**, то есть
стояло ПОД ОТРИЦАНИЕМ в данных.

## Место в коде (названо ДО правки)

Решение принимает не «признак секрета», а разбор heredoc:

| строка | что делала | почему красила |
|---|---|---|
| `_strip_heredoc` → `_line_runs_code(line)` | «телом подают КОД → вырезать нечего, всё под сканом» | `_HEREDOC_EXEC` содержал `ssh` **безусловно** |
| `_seg_runs_stdin_as_code` | `ssh` → «исполняет stdin» | ssh stdin НЕ исполняет — он **передаёт** его удалённой команде |
| терминатор heredoc | `lines[j].strip() != delim` | внутри аргумента ssh закрывающая кавычка едет на строке терминатора: `MDEOF'` ≠ `MDEOF` → «терминатора нет» → тело под сканом целиком |

Причин было **две**, и обе про носителя, а не про цель. Контроль: та же команда **без ssh**
(`cat > docs/artifacts/x.md <<'MDEOF'` с тем же телом) молчала и до правки — значит красил
именно носитель.

## Что изменено

1. **`ssh` — носитель, а не исполнитель.** Граница взята ТА ЖЕ, что уже измерена для питона
   (задача 87, 31.07): `python -` исполняет, `python cowork_log_append.py` — нет.
   `ssh host 'bash -s'` тело ИСПОЛНЯЕТ, `ssh host 'cat > файл'` — ПИШЕТ. Решает удалённая
   команда (`_ssh_remote_cmd` + рекурсия `_line_runs_code`).
2. **Терминатор с хвостовой кавычкой** узнаётся (`_is_heredoc_end`). Ошибка в эту сторону
   безопасна: терминатор раньше настоящего оставляет под сканом БОЛЬШЕ текста.
3. **Fail-closed везде:** хост не опознан, удалённой команды нет (`ssh host <<EOF` — тело
   достаётся ЛОГИН-ШЕЛЛУ и исполняется), кавычки не чинятся → тело остаётся под сканом.

## Замена признака (граница НЕ снята, а уточнена)

Тело, ушедшее из-под скана, не должно стать слепым пятном. Признак сменён с **упоминания
имени** на **присваивание ЗНАЧЕНИЯ** (`_secret_value_leak`): нужны сразу три мерки — есть
`=`/`:`, значение от 16 символов и смешанное (буквы+цифры) либо от 32, и это не ритуальная
заглушка (`<masked>`, `***`, `$VAR`, `os.getenv(…)`, `ВАШ_ТОКЕН`).

**Это усиление, а не ослабление:** до правки значения в теле heredoc не проверял НИКТО —
`_RE_ENV` знает только литералы `.env`/`.session`, поэтому `BRIDGE_TOKEN=<боевое значение>`
в теле артефакта уезжало молча. Ветка стои́т на `not _stays_red(...)`, а не на `action ==
"defer"`: у вида `unknown` действие тоже `ask`, но карточкой он не становится — на проверке
по `action` утечка уезжала бы ровно тем путём, которым ходит вся серверная работа.

## Read-only: файл на VPS СУЩЕСТВУЕТ

```
-rw-r--r-- 1 root root 25890 2026-08-11_07:28:42 /root/turbobaby-manager-bot/docs/artifacts/2026-08-11-curator-goal-repeats-duplicates.md
  294 25890 (строк, байт)
```

Посылка «одно из двух неверно» **не подтвердилась — неверна она сама**. ПК живёт в **UTC+7**
(замер: `19:48:52` локального = `12:48:52` UTC), VPS — в UTC (подтверждено корреляцией: mtime
`07:28:42` попадает ровно внутрь пачки ssh-записей `14:26–14:30` локального).

| UTC | локальное | событие |
|---|---|---|
| 05:04:45 | 12:04:45 | карточка `ask|env` на **heredoc**-форму — запись ЗАБЛОКИРОВАНА (лог 7798) |
| 07:25:45 | 14:25:45 | карточка `ask|env` на обходную форму `mkdir && scp` (лог 7802) |
| **07:28:42** | 14:28:42 | **файл записан** — mtime |

Отчёт захода «в 07:29 записал» — **правда, подтверждена mtime до секунды**. Карточка пришла
**за 3 минуты ДО** удачной записи, а не после неё: заход обошёл её (локальный `Write` во
временный файл → `scp`) и довёл дело до конца. Карточки в **08:04 UTC не существует** ни одной —
ближайшие две названы выше; это единственное неверное число в посылке.
