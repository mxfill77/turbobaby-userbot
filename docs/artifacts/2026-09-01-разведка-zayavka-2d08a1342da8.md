## 3. Три претензии — по одной, с числом

### 3.1 «`result_head` длинный и обрезанный» — **ДЕРЖИТСЯ**

```
venv/Scripts/python.exe tmp/measure_zayavka_2d08.py
  → расписок всего: 24
  → result_head: max=902 min=2, упёрлось в потолок 900: 12 из 24
  → суммарно знаков result_head по всем распискам: 11537
```

Доля объёма пакета, занятая `result_head`:

| пакет | знаков | из них result_head | доля |
|---|---|---|---|
| `2026-09-01-digest-2026-09-01.md` | 13008 | 2706 (3 шт.) | **21%** |
| `2026-09-01-chain-pc-2026-09-01-72.md` | 6246 | 902 (1 шт.) | **14%** |
| `2026-09-01-chains-2026-08-31.md` | 10358 | 0 | 0% |

Пятая часть дайджеста — обрезанные головы результатов. Ревьюер прав в наблюдении:
**половина голов (12 из 24) обрывается на полуслове**, и в оборванном виде она независимой
приёмки действительно не даёт.

### 3.2 «дубли объявленных/подтверждённых коммитов» — **ДЕРЖИТСЯ НА СЕГОДНЯ, но ветка не наблюдалась**

```
grep -l '"change_reason": "commit_unverified"' docs/review_receipts/*.json | wc -l   → 0
grep -l '"change_reason": "commit_verified"'   docs/review_receipts/*.json | wc -l   → 10
grep -l '"change_reason": "no_commit_claimed"' docs/review_receipts/*.json | wc -l   → 14
```

`claimed_commits == verified_commits` в **24 расписках из 24**. То есть сегодня два поля
действительно несут одно и то же. **Но это ровно тот же вид честности, что «ветка ПРОТУХЛА
живыми данными не наблюдалась»**: расхождение — это новость «отчёт разошёлся с деревом», и её
отсутствие за 24 расписки не доказывает её невозможность. Убрать поле — значит убрать прибор,
который ни разу не сработал; насколько это безопасно — **НЕИЗВЕСТНО**, и разведка это не решает.

### 3.3 «отдельные одинаковые хеши источника и выдержки» — **ЛОЖНА КАК «ЛИШНИЙ СЛОЙ»**

Равенство `source_sha256 == excerpt_sha256` не дублирование, а **единственный признак
«выдержка = весь файл, ничего не урезано»**. Проверено сверкой всех строк таблиц «ИСТОЧНИКИ
В ПАКЕТЕ» с живыми файлами дерева:

```
venv/Scripts/python.exe tmp/measure_zayavka_2d08b.py
  → равны И выдержка = весь файл : 15
  → равны, но файл длиннее       : 0     ← сломало бы смысл равенства
  → РАЗНЫ и выдержка урезана     : 12
  → разны, но выдержка = весь файл: 0    ← сломало бы смысл равенства
  → файла сегодня нет в дереве   : 0
```

**27 строк, контрпримеров ноль.** Соответствие точное в обе стороны. Снять «одинаковый» хеш —
значит потерять именно тот случай, когда ревьюеру приложили файл ЦЕЛИКОМ, и не отличить его от
случая, когда приложили первые 80 строк из 372 (`chain-pc-75`: `0b63adef93a1` ≠ `d6e3ba745fa1`).

Наблюдение канала при этом объяснимо: он смотрел `chain-pc-72`, где **все 3 пары одинаковы**
(3 равных / 0 разных) — единственный источник там короткая расписка на 23 строки, взятая целиком.
Обобщение с одного пакета на все ложно: по 13 пакетам **38 одинаковых против 19 разных**, а в
`chains-2026-08-31` одинаковых **ноль из 12**.

Вторая половина той же претензии — «не даёт независимой верификации» — **верна**: хеш считает
тот же процесс, что собирает пакет. Это самозаверение, и им независимость не покупается. Но
предмет у двух половин разный: «не независимо» ≠ «не нужно».

## 4. Чего находка НЕ учитывает (то, ради чего разведка и ставилась)

1. **Артефакт в пакете УЖЕ прикладывается — кроме одного случая, и причина там другая.**
   ```
   grep -c "НЕ ПРИЛОЖЕНО стражей исходящего" docs/review_outbox/*.md
     → 2026-09-01-chain-pc-2026-09-01-72.md:1, у остальных 12 файлов — 0
   ```
   Артефакт снял **страж исходящего** (`review_send.outbound_violations`) за абсолютные пути
   POSIX и Windows, и пакет сам это сказал в СВОДКЕ. Из 10 цепочечных пакетов артефакт назван в
   расписке у 8; приложен выдержкой `1-80` у 7; у `#80` и `#84` артефактов нет вовсе
   (`"artifacts": []`). Совет «достаточно приложить сам артефакт» в 7 случаях описывает уже
   работающее поведение, а в 8-м требует ровно того, что запрещено стражем.
2. **В `chain-pc-72` `result_head` — ЕДИНСТВЕННЫЙ носитель результата.** Артефакта нет (снят
   стражем), выдержка одна — сама расписка. Убери из неё голову результата — и ревьюеру
   останутся постановка задачи, статус и хеш коммита, то есть ноль сведений о том, ЧТО сделано.
   Претензии 3.1 («голова лишняя») и «приложите артефакт» в этом пакете **взаимно исключаются**:
   выполнить обе одновременно нельзя.
3. **Три источника говорят о РАЗНОМ.** Склейка дала одну заявку с тремя источниками, но
   `chains-2026-08-31` #1 — про объединение цепочек b1.2/b1.2a, где `result_head` не участвует
   (в пакете его 0 знаков). Заявка читается как «три канала об одном», а по факту это три
   претензии, объединённые словом вида. Порог склейки `MERGE_JACCARD = 0.145` мерился на ОДНОЙ
   истинной паре (§4 артефакта ступени B) — это ровно предсказанный там риск, увиденный живьём.
4. **Тот же адрес держит и ДРУГУЮ заявку.** В том же сухом прогоне: `ключ=c9b39939842c
   вид=НЕ ДЕЛАТЬ ВОВСЕ премиса=ЖИВА` — премиса та же, `` `result_head` `` по
   `review_auto.py:249`. «Премиса жива по адресу» не выделяет заявку и правотой её не делает
   (§8 ступени B: контур проверяет премису, а не правоту).
5. **Потолок 900 назначен, а не измерен.** Замер показывает только следствие (12 из 24 обрыва);
   на чём стоит само число 900 — в коде не сказано, комментарий говорит лишь «голова результата
   задачи в расписке». Это остаток, а не дефект.

## 7. Правки, названные СЛОВАМИ (не применены — решение владельца)

Ни одна не сделана. Разведка кончается здесь.

1. **Не снимать пару `sha источника` / `sha выдержки`.** Замер §3.3 говорит против; вместо снятия
   — назвать смысл в шапке таблицы («равны = приложено целиком»), чтобы внешний читатель не
   принимал равенство за дубль. Правка текстовая, в `review_pack.py` рядом со стр. 746.
2. **Голову результата резать по границе фразы, а не по 900-му знаку** — как это уже делает
   писатель журнала (`cowork_log_append.stamp_line`, порог 600 измерен). Класс тот же, решение
   на полосе уже есть; сейчас `review_auto.sanitize(limit=…)` обрывает на полуслове в 12 случаях
   из 24.
3. **`claimed`/`verified` не трогать** до первого живого `commit_unverified`, а до тех пор —
   выводить в текст пакета ОДНУ строку с исходом (`change_reason`), а два списка оставить в JSON
   расписки. Тогда «несколько слоёв одного заявления» исчезает из глаз ревьюера, а прибор
   остаётся.
4. **Порог склейки `MERGE_JACCARD` перемерить** на сегодняшнем корпусе (42 находки против 9).
