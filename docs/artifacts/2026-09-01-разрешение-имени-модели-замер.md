# Разрешение имени модели из речи клиента — замер дыры (01.09.2026)

**Что здесь есть:** числа и классы. **Чего здесь нет:** предложений правил, правок кода,
порогов и рекомендаций — по условию задачи. Бот, правило цены, голдены, чеки и кейсы не
тронуты ни строкой; клиентам ничего не отправлялось; в рабочие таблицы не писалось.

## Как считано

| что | факт |
|---|---|
| корпус | **607 записей**: 529 черновиков боевой очереди `moderation_ipc.db` (таблица `drafts`, окно `2026-07-03T11:31:35` .. `2026-08-31T06:50:54` UTC) + **78** экзаменационных файлов `case_*.json` из шести каталогов (`_scratch_examset_0820`, `_scratch_examrerun_0821`, `_scratch_longrent_0821`, `_scratch_sheetrule_0821`, `_scratch_trainerrun_0822`, `_scratch_truenum_0822`) |

| инструмент | `_scratch_modelname_0901/` (вне git): `measure3.py` — счёт, `claims.py` — проверка утверждений живым кодом, `final_table.py` — таблица и деньги |
| отсев | **171** черновик из 529 — заглушки стенда (`DRAFT ответа клиенту` / `GREETED`), они выброшены; **287** записей модель не упоминают вовсе |

Детектор упоминаний — **надмножество** боевого: он ловит и те формы, которых бот не знает
(кириллица вне словаря, гомоглифы, разрывы, опечатки). Иначе дыру не увидеть: мерить бот его
же словарём значит получить ноль по построению.

## 1. Сколько раз имя названо НЕПОЛНО и чем это кончилось

**30 из 45 уникальных реплик (67%)** называют модель неполно.

| форма имени в речи клиента | реплик | бот видит `hints.model` |
|---|---|---|
| голое семейство без кубатуры (`NMAX`, `xmax`, `pcx`) | 13 | да 13 |
| кубатура есть, поколения нет (`XMAX 300`) | 5 | да 5 |
| кубатура, которой в парке нет (`adv160`, `Cbr500r`) | 2 | да 2 |
| кириллица ИЗ словаря бота (`адв`, `хмакс`) | 2 | **НЕТ 2** |
| кириллица ВНЕ словаря — склонение (`форзу`, `форзы`) | 2 | **НЕТ 2** |
| гомоглиф — латинское имя русскими буквами (`рсх`, `МТ`) | 2 | **НЕТ 2** |
| написание с разрывом (`x-max`, `X-ADV-750`) | 2 | НЕТ 1 / да 1 |
| только марка, модели нет (`Honda`, `Мопедом Honda`) | 2 | **НЕТ 2** |
| **итого неполных** | **30** | **слеп на 9** |
| для сравнения — полное имя | 15 | да 15 |

**Чем кончилось** (исход черновика; «промолчал» — 0 в обеих группах):

| исход | неполное имя (30) | полное имя (15) |
|---|---|---|
| назвал цену | 10 | 6 |
| переспросил про другое (даты/гео/опыт) | 12 | 4 |
| переспросил про МОДЕЛЬ | 3 | 2 |
| ответ без цены | 3 | 3 |
| вывалил всю сетку прайса | 2 | 0 |

Читать это как «неполное имя мешает назвать цену» нельзя: доля названных цен в обеих группах
близка (10/30 против 6/15). Дыра лежит не в объёме ответа, а **в том, какая модель попала в
расчёт** — см. §3.

## 2. Разрешимо однозначно по листу — или нужен вопрос по существу

Считано пересечением корня с реальным парком (`suggest._bike_key` — тот же нормализатор, что
у `park_allowlist`), поколения — по токену `NEW` в имени юнита, как их различает боевой код.

| разряд | реплик | что именно |
|---|---|---|
| **разрешимо однозначно по листу** | **14** | `nmax` 9, `forza` 2, `adv` 1, `mt` 1, `xadv` 1 — за каждым корнем в парке РОВНО одна модель одного поколения |
| **требует вопроса по существу** | **9** | все девять — **XMAX**: в парке **3 юнита старого поколения и 7 нового**, тарифы разные |
| «нет в парке» — вопрос не о разрешении, а о наличии | 5 | `PCX` ×3 (в парке нет ни 150, ни 160), `ADV 160`, `CBR 500R` |
| марка без модели — разрешать нечего | 2 | `Honda` |

### «Две модели с одним корнем»: класс есть, а входа в него нет

В парке такой корень **ровно один — `CB`** (и `CB 300R`, и `CB 650R`). Ветка резолвера для него
работает: `resolve_park_model("CB")` → `('ambiguous', ['CB 300R', 'CB 650R'], None)`.

Но **до неё не доехать**: среди 28 токенов `_MODEL_TOKENS` голого `cb` **нет** (есть `cb300`,
`cb 300`, `cb650`, `cb 650`, `cbr650`, `cbr 650`, `cbr`), поэтому `_detect_model("нужен cb")` →
`None`. Остальные три серии `_MODEL_SERIES` по живому парку однозначны:
`xsr → [xsr155]`, `adv → [adv350]`, `pcx → []`.

**Следствие:** исход `ambiguous` из речи клиента **недостижим ни одной дорогой**, и в корпусе
607 записей он не случился ни разу. Голое «CB» в корпусе тоже не встретилось ни разу — класс
пока теоретический, но его сторож заведомо слеп.

### «Два поколения»: девять случаев, и решение принимается молча

`_model_products_for_quote("XMAX")` по умолчанию отдаёт **только `XMAX 300 New Gen`**; оба
поколения показываются лишь при явной просьбе клиента про прежнее (`want_old_gen=True`).
Вопроса клиенту правило не задаёт. Как это выглядело на одинаковом голом «xmax»:

| черновик | реплика | что вышло |
|---|---|---|
| id 202 | «Привет а есть xmax с 5 по 10ое августа» | назвал цену **704 ฿/день, депозит 7 000** (New Gen) — поколение не обсуждалось |
| id 291 | «пару скутеров xmax нужно» | **переспросил**: «какой именно XMAX 300 — старый (2020–2022) или новый (с 2023)?» |

Одна и та же форма имени — два разных поведения. Разницу дала не ручка, а генерация: правило
поколений вопроса не предусматривает.

## 3. Цена дыры

**13 диалогов из 26 (50%)**, где клиент вообще называл модель, упёрлись в дыру — это 18 реплик
из 45. В «упёрлись» считаны реплики, где выполнено хотя бы одно: бот не увидел модель вовсе,
подставил чужую, или за формой стоял вопрос по существу, которого он не задал.

Ставки взяты **из сетки, которую бот выложил сам** (черновик id 494 от 19.08.2026) — то есть из
живого прайса, а не из фикстуры:

## 4. Классы (только имена и факты)

| класс | факт |
|---|---|
| **K1 · порядок и подстрока** | `_detect_model` берёт ПЕРВЫЙ токен по порядку списка, матчинг — подстрока без границ слова. `adv` раньше `xadv` → любой X-ADV читается как ADV 350 |
| **K2 · разрыв в написании** | `x-max`, `n-max` не читаются вовсе: токен `xmax` подстрокой в `x-max` не входит |
| **K3 · кириллица не доезжает до цены** | 15 кириллических форм знает ТОЛЬКО `extract_requested_models` (фильтр сетки). `_detect_model`, заполняющий `hints.model` (от него зависит расчёт цены), — латинский. «хмакс 300» → `hints.model=None` при `req=['XMAX']` |
| **K4 · склонение** | синоним матчится целым словом (лукэраунд по буквам): `форза` — да, `форзу`/`форзы` — нет. То же у `вулкан`/`вулкана`, `ниндзя`/`ниндзю` |
| **K5 · гомоглифы** | `рсх` (PCX русскими буквами), `МТ` (MT-03) — `_bike_key` стирает кириллицу целиком, остаётся пустая строка. В корпусе 2 случая, оба кончились выкладкой всей сетки |
| **K6 · кубатура отброшена при откате на корень** | `Cbr500r` → `CBR` → `CBR 650R`. Названное клиентом число в резолве не участвует |
| **K7 · единственная развилка парка недостижима** | ветка `ambiguous` жива и верна, но голого `cb` среди токенов нет |
| **K8 · поколение решается молча** | по умолчанию только New Gen; вопрос задаётся не правилом, а генерацией — отсюда два разных ответа на одну форму (id 202 / id 291) |
| **K9 · нечёткого сравнения нет** | `difflib`/`Levenshtein` в `suggest.py` — **0 совпадений**. Опечатка `Honda ADB350` (черновик id 413) не опознана ни одной веткой: `hints.model=None` |

## Что замер НЕ покрывает (честно)

1. **Парк взят снимком 02.06**, Bridge не звался — если живой парк разошёлся со снимком,
   сдвинуться может разряд «нет в парке» (PCX, ADV 160), но не K1–K9: они про разбор текста.
2. **Корпус — черновики, а не отправленные клиенту сообщения.** По основанию от 17.08
   (`docs/artifacts/2026-08-17-bot-output-path.md`) клиентам за всё время ушло 0 сообщений,
   поэтому «чем кончилось» — это исход ЧЕРНОВИКА, а не реакция клиента.
3. **45 уникальных реплик — узкая база.** Каждая клетка §2 стои́т на однозначных числах,
   но 9 XMAX-случаев дали 4 разных исхода: разброс поведения шире, чем корпус.
4. **Классификация ведётся по ГЛАВНОМУ упоминанию реплики.** Сообщения с несколькими моделями
   («Xmax, adv350 или Forza») попадают в разряд по самому специфичному имени.
5. **Реплика id 278** — рекламная рассылка конкурента со списком 16 моделей, не запрос клиента;
   в счёт «чужой модели» она включена как факт работы резолвера, а не как потерянная сделка.
