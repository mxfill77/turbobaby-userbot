# WASENTSHOW0410 — «Отправить» дошло клиенту в WhatsApp, а в теме его нет (Q23, TB-CHECK-0410-0120)

Полоса ПК, только чтение на сервере. Ось — бизнес: ответ клиенту ушёл и прочитан, но в его теме в Telegram этого
ответа нет. Повторно клиенту ничего не отправлялось.

выключен. Показ сам такой ответ тоже не нарисует: эха на отправку через API не приходит, а квитанции показ пропускает.

## 5. Тема клиента

- Тема у клиента **есть**: `wa_tg_mirror.db` → `topics`: thread 10, stage `live`, открыта 01.10 18:50 PKT. Значит, причина
  не в отсутствии темы.
- **Показ ничего не рисовал.** Строк `shown` с wamid черновика 4 — 0. Последние показы этого клиента до утра 04.10 —
  16:48:26 и 16:48:52 UTC: это два его входящих (строки 5645 и 5646). «показано» в сводках показа — 422 без изменений
  с 16:51:24 до 18:07:23 UTC.
- **Почему показ сам не покажет такой ответ.**
  1. Показ читает только очередь: `outbox` и `wa_agent.db` в `wa_tg_mirror.py` не упомянуты ни разу.
  2. Квитанции он выбрасывает (`:793`, `_is_receipt` `:272–273`).
  3. Эха на отправку через API нет: по wamid черновика в очереди одна строка, и та квитанция.
  Ответ с телефона показ видит через эхо. Ответ из карточки — нет.
- **Почему нет строки «отправил агент».** Единственный путь — `agent_sent`, а он вышел на `:955–956` (relay выключен) без
  вызова Telegram и без строки журнала. Подтверждение по журналу: «отправил агент» — 0 совпадений в `wa_agent.log`,
  «тема: строки» — 0. Вид строки, который был бы при включённом relay: «мы · агент, отправил <кто>: <текст>»
  (`AGENT_LINE`, `wa_agent_tg.py:113`).

## Что дальше — решать владельцу (не сделано)

- **Включить `WA_AGENT_RELAY` только ради строки — значит открыть и путь из темы в WhatsApp.** Тогда любой текст человека
  в теме клиента уйдёт клиенту (`on_topic`). Это другое решение, а не «показать ответ».
- **Развести без такого побочного действия может только правка кода**, на выбор:
  - (а) отдельный флаг у `agent_sent`;
  - (б) показ рисует строки `outbox` агента.
  Ни то, ни другое здесь не делалось.
- **Квитанции delivered и read в очереди теряются по построению** (уникальный wamid). Если доставку и прочтение нужно
  видеть не только в сыром архиве — это тоже правка вебхука. Сырой архив стоит под потолком места: 03.10 до 10:32 UTC
  тела в него не писались.
