## 4. Что можно перевести на запуск до входа

### Сначала — то, что НЕ мешает (проверено, снимает четыре гипотезы)

| гипотетический блокер | замер | вердикт |
|---|---|---|
| сетевой профиль до входа | **все** Wi-Fi профили — `All User Profile`, включая текущий `Bless_house_2.4GHz` | **не блокер**, сеть поднимается до входа |
| BitLocker с pre-boot PIN | прямого статуса нет (`Get-BitLockerVolume` → «Отказано в доступе», не админ), но 06.08 машина дошла до экрана входа **без запроса ключа** | **не блокер** |
| Telethon session | `turbobaby_session.session`, 999 424 байт, лежит в `D:\turbobaby-bot`, не в профиле, не DPAPI | **не блокер** |
| Claude в Credential Manager | `cmdkey /list` → только MicrosoftAccount SSO, `git:https://github.com`, WindowsLive. **Claude там нет** | токен лежит файлом `C:\Users\mxfill1\.claude\.credentials.json` (3768 байт, mtime 06.08 19:38:43 — обновляется сам при старте RC) |

### Главный стопор — учётка (владелец прав, но не по той причине, что кажется)

```
net user mxfill1
  Password last set     18.02.2022 3:18:30
  Password required     No
  Last logon            06.08.2026 19:38:27
HKLM\SYSTEM\CurrentControlSet\Control\Lsa\LimitBlankPasswordUse = 1
```

Вход выполняется **ПИН-кодом (Windows Hello)**. ПИН **не годится** ни для Планировщика, ни для
служб — там нужен именно пароль учётной записи. `Password required: No` — это флаг
`UF_PASSWD_NOTREQD`; он **не доказывает**, что пароль пуст (дата установки 18.02.2022 говорит,
что пароль когда-то задавался). Но если он всё же пуст, `LimitBlankPasswordUse = 1` запрещает
этой учётке любой неконсольный логон — batch, service, network — и варианты **В** и **Г** ниже
отпадают физически.

**Это должен проверить владелец.** Из непривилегированной сессии установить факт «пароль пуст /
не пуст» нельзя, а подбирать или вводить учётные данные я не буду.

### Варианты

**А. BIOS: `Restore after AC Power Loss` = Power On**
- **Даёт:** машина сама включается при возврате питания. Вход не решает.
- **Цена:** один заход в UEFI. Ни AnyDesk, ни Tailscale до старта ОС не работают → нужен человек
  у машины (один раз) либо IPMI/BMC, которого на потребительской MSI Z390I нет.
- **Риск:** если причиной был хардлок, а не обрыв питания — не поможет.
- **Обязателен как основа:** без него любые автозапуски бессмысленны — машина просто стоит
  выключенной.

**Б. Автологон (`AutoAdminLogon`) + немедленная блокировка экрана** ← рекомендую
- **Даёт: полное решение.** Сессия пользователя создаётся сама → все шесть процессов
  поднимаются ровно так же, как сейчас, **без единой правки задач**. DPAPI, TTY, профиль,
  credential store — всё как при живом человеке. `rundll32 user32.dll,LockWorkStation` в Startup
  запирает экран сразу: машина стоит **заблокированной**, контур работает.
- **Цена:** пароль учётки хранится на машине. Через реестр (`HKLM\…\Winlogon\DefaultPassword`) —
  **открытым текстом**; через Sysinternals `Autologon.exe` — в LSA Secrets (лучше, но админом
  всё равно извлекается). Требует непустого пароля. Сейчас `AutoAdminLogon` **не настроен**
  (ключи пусты).
- **Риск:** физический доступ к машине = доступ к сохранённому паролю и к сессии в те доли
  секунды, пока не сработала блокировка. Машина стоит в чужой квартире, у друга есть физический
  доступ — риск реальный, не бумажный. Смена пароля учётки сломает автологон **молча**.

**В. `LogonType = Password` + `BootTrigger`** («Выполнять вне зависимости от регистрации»)
- **Даёт:** задачи стартуют в session 0 при загрузке, без входа. Профиль загружается,
  DPAPI-мастер-ключ разворачивается паролем → `.credentials.json` доступен.
- **Цена:** пароль вводится один раз в Планировщик (хранится в LSA Secrets). Нужно право
  «Log on as a batch job» для учётки (`secpol.msc`, админ). Нужен непустой пароль.
- **Риск: нет рабочего стола (`Winsta0\Default`).** Всё, что требует GUI или живого TTY, ломается
  — а это прямо задевает RC (п.5.1).
- **`S4U` («не сохранять пароль») — не годится:** без пароля DPAPI-ключ пользователя не
  разворачивается, всё DPAPI-защищённое становится нечитаемым, а в логах это выглядит как
  «токен протух» — готовый ложный диагноз.

**Г. Служба Windows (NSSM / `sc.exe`) под учёткой mxfill1 с паролем**
- **Даёт:** то же, что В, плюс автоперезапуск средствами SCM.
- **Цена:** те же пароль и права (+ «Log on as a service»), плюс новая сущность вне Планировщика
  — придётся переучивать вотчдог, он ходит `schtasks /Run /TN pc_orchestrator`.
- **Риск:** тот же session 0 без TTY. Поверх В смысла немного.

**Д. Второй канал входа для владельца вместо друга** (не автозапуск, но снимает бо́льшую часть боли)
- **Замер:** `AnyDesk` — служба `LocalSystem`, `Auto`, **Running** → работает **до входа**,
  показывает экран блокировки, ПИН/пароль можно ввести удалённо. `Tailscale` — служба
  `LocalSystem`, `Auto`, **Running**, узел `mxfillpc 100.95.10.116` в тайлнете `1turbobaby@` →
  туннель поднимается до входа. RDP **выключен** (`fDenyTSConnections = 1`, `TermService`
  Stopped/Manual), sshd не установлен.
- **Даёт:** простой сжимается с «когда придёт друг» до «когда владелец увидит алярм» — **при
  условии, что машина включена**. Требует, чтобы у AnyDesk был настроен пароль неконтролируемого
  доступа (настройка приложения, не проверял).
- **Цена:** ноль правок нашего кода.
- **Риск:** кто владеет AnyDesk-ID и паролем — владеет экраном машины.

### Рекомендация — одна

**А + Б.** Это единственная пара, поднимающая контур **целиком, включая RC**, на пустой машине,
и стоит она одной настройки BIOS плюс одной записи автологона. В и Г ломают RC ради экономии на
риске, которой они всё равно не дают: пароль лежит на машине в обоих случаях.

Отдельно и дешевле всего: **`AutoReboot = 1`** (снимает сценарий «BSOD → стоим до человека») и
**UPS** — он закрывает бо́льшую часть класса из таблицы п.1, а не только его последствия.

## 5. Что нельзя поднять без человека в принципе — честно

1. **RC-сервер (`claude --remote-control` / `claude rc`) — нельзя перевести в session 0.**
   Это не догадка, причина записана в нашем же `rc_remote_control.vbs`: «интерактивной сессии
   `claude --remote-control` нужен живой TTY… именно поэтому здесь НЕ `pythonw.exe` и НЕ
   `CREATE_NO_WINDOW`: они убирают саму консоль, а вместе с ней TTY, без которого интерактивная
   сессия не поднимется». Варианты **В/Г** для RC = заведомо мёртвый канал. Автологон (**Б**) —
   единственный способ поднять RC без человека.
2. **Вход в UEFI/BIOS.** Ни AnyDesk, ни Tailscale до старта ОС не работают; IPMI/BMC на этой
   плате нет. `Restore after AC Power Loss` выставит **только человек у машины** — один раз.
3. **Физическое включение, если питание не вернулось само** (сгоревший БП, выбитый автомат,
   выдернутый шнур). Никакая настройка ОС этого не покрывает. Единственное средство — UPS.
4. **Если пароль учётки пуст** — всё, кроме автологона с заново заданным паролем, отпадает:
   `LimitBlankPasswordUse = 1` запрещает неконсольный логон. Задать пароль — действие владельца.
5. **Первичная авторизация Claude (OAuth).** Если токен потребует повторного входа в браузере —
   это интерактивный шаг, автозапуск его не заменит. Обновление по refresh-токену идёт само
   (файл переписан 06.08 19:38:43).
6. **DPAPI при `S4U`.** Является ли `.credentials.json` DPAPI-шифрованным — **нет данных**: файл
   не открывался и открываться не будет. Владелец проверяет одной командой: первый символ `{` =
   обычный JSON (переживёт session 0 с паролем), base64-блоб = DPAPI (переживёт только с
   паролем, но не с `S4U`).

## 6. Попутные находки (не спрашивали, но это мины)

1. **`AutoReboot = 0`.** При синем экране машина не перезагрузится сама. Одна галка — минус один
   сценарий «ждём человека».
2. **Журнал Планировщика выключен** (`Microsoft-Windows-TaskScheduler/Operational`,
   `IsEnabled = False`). По отказам задач фактов нет и не появится.
3. **«34 часа» — это НЕ время простоя контура.** Числа: машина мертва **19 ч 32 м**
   (`00:05:33` → `19:37:15`). Строка вотчдога «`moderation_bot МЁРТВ (лежал 121942с)`» =
   33 ч 52 м, но `_log_age_sec` меряет **mtime лога**, а не смерть процесса.
   `moderation_bot.log` замолчал 05.08 в `09:51:35` на сетевом сбое (`Netwtw08` 7021/6062
   09:22–09:51, `getaddrinfo failed`, затем `CERTIFICATE_VERIFY_FAILED`) — а сам процесс жил:
   контур-вотчдог тикает каждые 5 минут (`CLIENT_WATCH_SEC = 300`) и за 14 часов до смерти
   машины **ни разу** не вынес вердикт «moderation_bot МЁРТВ». Реальный простой контура =
   19 ч 32 м, и он равен простою машины.
