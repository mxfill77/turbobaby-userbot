### Правило (ставится без домысла)

**R1 — время в первой строке показа, во всех местах.** Показ узла начинается строкой
`<узел> · снято <ГГГГ-ММ-ДД ЧЧ:ММ UTC> · <возраст> назад`. Время берётся из штампа в тексте узла: у моста
времени изменения нет. Таблица «узел → регулярка штампа → порог L» живёт в одном модуле на полосу, и оба
модуля одинаковы:
`pulse` — `^(\d{4}-\d{2}-\d{2} \d{2}:\d{2})` (UTC); `pulse_pc` — `числа менялись последний раз: (…) UTC`;
`queue_state`/`queue_state_pc` — `снято: (…) UTC`; `cc_log`/`cowork_log` — штамп первой (свежей) строки;
`shtab_vitrina` — `дата=ГГГГ-ММ-ДД`.
На сервере образец уже есть: `revizor_age.mark`, там же в `_g_pulse`.

**R2 — старше порога значит «устарел» вместо содержимого.** Если возраст больше L(узел), показ заменяет
текст узла строкой
`⚠️ <узел> УСТАРЕЛ: снят <время UTC>, <возраст> назад (порог <L>, замер docs/artifacts/2026-09-17-VOZRAST-uzlov-chitateli-1709.md) — содержимое не показано`.
Штамп не найден или не разобран — строка `возраст <узла> неизвестен — содержимое не показано` (третий исход,
не «свежо»). Образец отказа на ПК уже есть: `contour_digest_run.fresh_or_none`.

**R3 — порог L = p99 промежутков записи узла по замеру, округлённый вверх до минуты:**
`pulse` **3074 мин (51 ч 14 мин)** · `pulse_pc` **58 мин** · для слепков очереди см. R4.
Проверка на живом случае: в 12:43 UTC `pulse` было 193 ч 15 мин, это больше 51 ч 14 мин. Кнопка сказала бы
«УСТАРЕЛ» вместо записи от 09.09.
Для `shtab_vitrina`, `cc_log` и `cowork_log` L **не замерен** (НЕИЗВЕСТНО). Первый шаг постановки — снять
его тем же методом по штампам в самом тексте. До замера для них действует только R1 (плюс нынешние 3 суток
у A5 как есть).
Под правило не попадают A4 (`knowledge_base`, справочник), A7 (архивный вынос) и A8 (номер редакции): это
не состояние.

**R4 — писатели «по смене» (только `queue_state`, `queue_state_pc`).** Штамп в шапке обязан означать СВЕРКУ.
Писатель переписывает слепок и при неизменной подписи, если последняя запись старше p95: сервер 3110 с,
ПК 2170 с. Цена по замеру — **+13.4 записи/сут** на сервере (сейчас 42.4) и **+17.9/сут** на ПК (сейчас
142.9). Тогда L = p95 + законная пауза тика: сервер 3110 + 600 = 3710 с → **62 мин**; ПК 2170 + 605
(max законной паузы витка, замер О2) = 2775 с → **47 мин**. Без R4 порог p99 (7 ч / 76 мин) давал бы
ложный «устарел» 22.7 % / 24.6 % времени. В подвале обоих слепков «15 минут» заменяется на этот L.
Прогон наблюдателя длится до 225 с (замечено 13:30:06→13:33:51) — в заходе постановки проверить, влезает
ли он в запас.

## 6. Цена

| заход | что | мест |
|---|---|---|
| 1 (ПК) | модуль таблицы R1/R2 полосы ПК + A5 `read_shtab` + A6 `--probe` + тесты; замер L для `shtab_vitrina`, `cowork_log` | 2 |
| 2 (ПК) | R4 в `queue_snapshot_pc.tick` (сверка раз в 2170 с) + подвал + тесты | 1 писатель |
| 3–4 (сервер) | тот же модуль + A1 `_g_pulse` (время и отказ; строку ревизора не терять при сбое опроса) + A3 `_g_cclog` + R4 в `queue_state.py`/`expectations_run` + гейт | 2 + 1 писатель |

**Итого 3–4 захода.** **Дороже всех — A1, кнопка на сервере.** Причины:
- сессий на сервере нет с 09.09 11:28 UTC;
- push с сервера отбит аутентификацией с 30.08 (докстринг `pc_orchestrator._srv_delivery`), доставка идёт
  через ПК;
- раскатка требует рестарта `splinter.service`, а это красная операция владельца (`devbot` грузится в процессе
  splinter: его строки лежат в `splinter.log`).
Наблюдателю сервера рестарт не нужен: `expectations.timer` каждый раз поднимает свежий процесс.
