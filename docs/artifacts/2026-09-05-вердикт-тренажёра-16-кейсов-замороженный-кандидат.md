## 2. ПУНКТ НОЛЬ: применение АВТОМАТИЧЕСКОЕ. Три доказательства, последнее — живое

### 2.1. Код: зелёный вердикт и «да» владельца — ОДНО И ТО ЖЕ основание

`client_contour.release_reason` (`client_contour.py:625`) знает ровно два ответа и оба равносильны:

```python
def release_reason(commit, kind=None, path=None, trainer_path=None, env=None):
    if owner_approved(commit, path):
        return "owner"
    if trainer_green(commit, trainer_path, env):
        return "trainer"
    return None
```

Ворота (`pc_orchestrator._client_block`, `pc_orchestrator.py:7089`) на любом непустом основании
**возвращают пустой список, то есть «применять МОЖНО»**, и пишут в журнал строку «применяем»:

```python
reason = (reason_fn or client_contour.release_reason)(commit)
if reason:
    st.pop(kk, None)
    log.info("ворота контура (%s): основание пропуска «%s» — коммит %s применяем к %s", …)
    return []
```

Дальше по всем трём боевым входам идёт рестарт живых детей — `_restart_via_pc_agent(kind)`:

| вход | строка | когда срабатывает |
|---|---|---|
| `maybe_update_bots` | `pc_orchestrator.py:7293` | после каждой дев-задачи, коммит = `_head_commit()` |
| `_selfupdate_restart_children` | `pc_orchestrator.py:7418` | после самообновления демона, коммит = `new_commit` |
| **`_reconcile_children`** | `pc_orchestrator.py:7828` | **каждый виток `main_loop` (≈60 с)**, коммит = `head[:9]` |

Третий вход — главный, и его собственный комментарий говорит прямо (`pc_orchestrator.py:7822`):
«метку `_last_child_commit` НЕ двигаем: **придёт «да» — следующий тик применит ЭТОТ ЖЕ коммит**».
Зелёный вердикт стои́т в этой фразе на месте «да» без единой оговорки.

Совпадение коммита при этом **широкое, а не точное**: реконсиляция подаёт `head[:9]`, а
`_verdict_holds` сверяет полные 40 hex только когда обе стороны 40-символьные
(`client_contour.py:520`), иначе сверяется нормализованная семёрка. Вердикт, записанный полным
хешем, откроет ворота на девятисимвольном коммите того же префикса.

## 6. Что делать владельцу — точно и одним движением

Запись зелёного вердикта = выкатка на живых `userbot` и `moderbot` в ближайший виток (≈60 с).
Если это решение принято, исполняет его **владелец**, и вот чем:

```
venv/Scripts/python.exe trainer_run.py --runs 2
```

(прогон на текущем HEAD, вердикт пишется в `pc_orchestrator.client_trainer_green.json`;
разведка без записи — тот же вызов с `--no-write`).

**Перед этим стоит знать три вещи:**

* прогон занимает порядка **15 минут** на 16 кейсов × 2 прогона (замер 05.09: 832 с);
* дерево на прогоне обязано быть **чистым**, иначе `clean=false` и вердикт не засчитается;
* **красный прогон СНОСИТ прежнюю зелень** коммита (fail-closed `write_verdict`) — реестр меняется
  в любом исходе, а не только в зелёном.

**Если выкатки не хочется, а замер нужен** — есть безопасная дорога, и она уже проверена 05.09:
прогон с `--no-write` или своим прогонщиком даёт те же числа и реестра не касается. Ровно так и
получены 16/16.
