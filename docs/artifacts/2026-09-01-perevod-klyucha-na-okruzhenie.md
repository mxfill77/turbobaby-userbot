## 1. Каким путём ЖИВЫЕ userbot и moderbot получают ключ

Из трёх исходов задания — **ОКРУЖЕНИЕ** (наполняется файлом `.env` через `load_dotenv`),
а на фактически исполняемом маршруте генерации — **не используют вовсе**.

### 1.1 Литерал исключён, и не «сейчас», а исторически

| проба | результат |
|---|---|
| `git log -S 'sk-ant' -- suggest.py` | **0 коммитов** |
| откуда взялась строка чтения | `d9e719b` — первый коммит, вносивший LLM-путь suggest |
| `Anthropic(` в трекаемом коде | `suggest.py:5506`, `collect_booking.py:128` — обе с переменной, не с литералом |

Ни одна версия трекаемого `suggest.py` литерала не держала. Поэтому **возраст живого процесса
здесь не важен**: сколь угодно старая его версия всё равно читала `os.getenv`.

### 1.2 Единственный источник в коде

```
suggest.py:232   ANTHROPIC_API_KEY = os.getenv("ANTHROPIC_API_KEY", "").strip()
```

Наполняется он до импорта, обоими детьми одинаково:

```
userbot_listen.py:34,38,42   from dotenv import load_dotenv / load_dotenv() / import suggest
moderation_bot.py:27,29,31   from dotenv import load_dotenv / load_dotenv() / import suggest
                             # комментарий в коде: «после load_dotenv — читает конфиг из окружения»
```

Ни `userbot_listen.py`, ни `moderation_bot.py`, ни `moderation_core.py` имени
`ANTHROPIC_API_KEY` не содержат вовсе — ключ они видят **только** через `suggest`.

**Важная поправка к слову «окружение»:** процессы стартуют с чистым env, а значение в
`os.environ` кладёт `load_dotenv()` из файла `.env` репо. То есть механизм — окружение,
а **хранилище — файл**. Для отзыва ключа это и есть адрес.

### 1.3 На боевом маршруте ключ не используется вовсе

Ветку выбирает флаг, тоже из окружения:

```
suggest.py:5496   return _cli_llm if SUGGEST_LLM_VIA_CLI else _default_llm     # generate_draft
moderation_core.py:33   fn = suggest._cli_llm if suggest.SUGGEST_LLM_VIA_CLI else suggest._default_llm
moderation_bot.py:394   llm = suggest.default_llm_caller()
```

`_cli_llm` (`suggest.py:5712`) идёт через `claude` CLI по подписке Max и **вычищает ключ**:

```
suggest.py:5724   env.pop("ANTHROPIC_API_KEY", None)   # ← ключ НЕ утекает: CLI идёт по подписке Max
suggest.py:5725   env.pop("OPENAI_API_KEY", None)
```

Живое подтверждение маршрута (строку `SUGGEST: голова=` печатает **только** `_cli_llm`,
`suggest.py:5744`):

| проба по `logs/userbot_stderr.log` (86 838 строк, append через все рестарты) | число |
|---|---|
| `SUGGEST: голова=…` | **63** |
| `credit balance` / `authentication_error` / `invalid x-api-key` | **0** |

То есть каждая наблюдаемая генерация клиентского контура шла CLI-маршрутом, и ни разу —
платным ключом.

### 1.4 Что здесь ЧЕСТНО неизвестно

- **Текущий процесс ещё ни разу не генерировал.** Живой userbot поднят
  `2026-08-31 19:38:29` (шапка лога, строка 86368; совпадает с `CreationDate` PID 13284),
  а последняя `голова=` — строка 52780, то есть прогон от `2026-07-31 16:07:18`. Значит
  ветка у *этого* экземпляра доказана кодом и наследованием `.env`, но не собственным следом.
- **Значение `SUGGEST_LLM_VIA_CLI` не проверялось**: это строка `.env`, чтение запрещено
  условиями задания. Проверяется владельцем одной командой без показа значений:
  `grep -c '^SUGGEST_LLM_VIA_CLI=1' .env` (ждём `1`).
- `logs/moderbot_stderr.log` строк `голова=` не содержит вовсе (**0**) — модербот с этих
  запусков не классифицировал. Маршрут у него по коду тот же, но своего следа нет.

## 3. Что нужно, чтобы применить S1 к детям (не сделано — красное)

Применение к живым ботам закрыто **воротами клиентского контура**: `suggest.py` входит в
import-замыкание обоих детей (`pc_orchestrator.py:5889`, `client_contour.closure`), а коммит,
задевший клиентский файл, к живым ботам автоматически не применяется. Ворота открывают ровно
два основания (`pc_orchestrator.py:5891-5895`): «да» владельца через рычаг `client_contour.approve`
либо зелёный прогон тренажёра `trainer_run.py`.

Рычаг владельца — отдельная команда, и её якорь требует, чтобы **весь текст задачи был командой**
(`pc_orchestrator.py:2335-2338`):

```
выкати
```

**Три оговорки, каждая — готовый ложный шаг:**

1. **Рычаг выкатывает ТЕКУЩИЙ HEAD, а не 768729b.** HEAD сейчас `3b1143d`, над S1 стоят ещё
   четыре коммита (`6cbdd15`, `93b0ed2`, `acba7e5`, `f731e49`, `3b1143d`). «Применить S1»
   в одиночку рычага не имеет.
2. **«рестартни userbot» ≠ «выкати».** Рычаг рестарта (`pc_orchestrator.py:2327-2328`) поднимает
   бота прямо сейчас **мимо всех проверок**; «выкати» — это основание, после которого применение
   идёт штатным путём со всеми гейтами (`pc_orchestrator.py:2331-2333`).
3. **Выигрыш от выкатки по ключу — ноль.** Путь ключа у детей уже окружение (п.1), а
   `_default_llm` на боевом маршруте не вызывается вовсе. S1 добавляет страховку на случай,
   если флаг CLI когда-нибудь снимут.

## 5. Подготовка безопасного отзыва старого ключа

Отзыв — это правка `.env`, красная операция; здесь только подготовка адресов.

**Кого сломает отзыв (по коду):**

- **клиентский контур — не сломает**, пока `SUGGEST_LLM_VIA_CLI=1`: `_cli_llm` ключ и так
  выбрасывает. После S1 даже случайный уход в `_default_llm` даёт понятную ошибку без значения,
  а не `credit balance too low` из недр SDK;
- **`collect_booking.py`** — упадёт осознанно (`collect_booking.py:168-169`), это ручной скрипт;
- **`manager-bot`** — упадёт на старте `ClaudeClient` (`ValueError`), у него свой `.env`;
- **`health.py` на сервере** — синт-проба честно отрапортует «нет ANTHROPIC_API_KEY (проба
  пропущена)», сама не упадёт.

**Файлы, где значение ключа может лежать** (имена, без чтения; получено `grep -rl` по образцу
префикса, значения не выводились):

```
.env                                   ← боевой
.env.bak-bom-20260731-160512           ← 4 старых бэкапа .env
.env.bak-fable-20260730
.env.bak-gateflags-20260716
.env.bak-mojibake-20260731-161107
manager-bot/.env                       ← отдельный контур, вне git

bridge-transcript-cse_016WXCF8f1VKM73LiBExHtYy.jsonl
```

Два вывода, которые тут важнее списка:

1. **Бэкапы `.env` и логи гарда переживают ротацию ключа.** Отзыв в провайдере обесценивает
   значение везде сразу, а вот «поправили `.env`» — нет: четыре бэкапа и два лога останутся
   с прежним значением. Поэтому порядок обязан быть **сначала отзыв у провайдера, потом
   вычистка адресов**, а не наоборот.
2. **`test_suggest.py:2137` держит строку-фикстуру намеренно** — она проверяет, что ключ
   вычищается из env CLI. Её трогать нельзя, она не утечка.
