**Контракт и порядок решения** (`expectations.wa_mirror_state`):
1. Юнит не прочитан → НЕИЗВЕСТНО, адрес `systemctl show wa-tg-mirror`.
2. Юнит не активен → **ОТКАЗ при любом флаге**: медиа качаются всегда. Свежая «сводка» в журнале не оправдывает.
3. Флаг берётся порядком службы:
   - сначала `/proc/<MainPID>/environ`, только строка флага;
   - иначе файл ключей через `dotenv_values`, только флаг;
   - толкует значение `wa_tg_mirror._flag_on`;
   - узнать нельзя → НЕИЗВЕСТНО с адресом.
4. Флаг выключен → **удержание**, это не тревога.
5. База показанного `wa_tg_mirror.db` (mode=ro) не открывается → НЕИЗВЕСТНО с путём.
6. Точки включения (`kv.show_start_id`) нет:
   - юнит активен дольше 600 с → **ОТКАЗ «показ не стартовал»**;
   - моложе → «в порядке: показ включается».
7. Очередь `wa_queue.db` (mode=ro) не открывается → НЕИЗВЕСТНО с путём.
8. Живые строки `id > show_start_id` проверяются функциями службы `_is_live`/`_row_key`. «Показано» — строка `shown` с ключом `msg:<ключ>` в любом состоянии, как `_is_shown` у службы. Не показанная старше 600 с — **ОТКАЗ** «просрочено N живых строк», с id строк.

Строка «СТОИТ» и «сводка: показ=…» из `wa_tg_mirror.log` едут в заметку только пояснением (`hint`). Решение по ним не выносится.

Закрытие эпизода — только когда показ доказанно судим (исход не НЕИЗВЕСТНО). Молчание источника не закрывает.

## Применение

Живой main `08c3f97 → 8dc61b4` в 08:24:16 UTC. `expectations.service` — oneshot, каждый тик таймера запускает свежий процесс с диска. Новый код подхватывается первым же тиком после перемотки, ничего перезапускать не нужно. Замер: тик 08:34:13 UTC (Result=success) выдал `"wa_mirror": "удержание: показ выключен (флаг: не задан — по умолчанию выключен)"`, PID всех четырёх служб прежние.

## Чего прибор не видит (честно)

- Флаг читается из файла ключей СЕЙЧАС, а процесс прочёл его при своём старте. Если флаг включили в файле, а службу не перезапустили, ловится как «показ не стартовал» через 10 мин. Если выключили в файле при живом показе, прибор скажет «удержание», хотя процесс ещё показывает. Вреда клиентам нет.
- Пути баз — умолчания службы от её корня (`wa_queue.db`, `wa_tg_mirror.db` рядом). Переопределение `WA_QUEUE_DB`/`WA_TG_MIRROR_DB` из окружения прибор не берёт: правило задания «из окружения юнита только флаг». При переносе баз прибор скажет НЕИЗВЕСТНО с путём, а не «в порядке».
- Поток событий вебхука (П4) — не предмет О9.
