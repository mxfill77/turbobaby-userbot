  задача завершена» ответа не требует и содержания не несёт (ни задачи, ни итога, ни хеша), а тот
  же факт через секунду уходит в инбокс 1160 карточкой `session_end` — уже со сводкой. Замер за

- `pc_orchestrator.py` → `_notify_task`: личка-пуш снят **целиком**, включая `needs_approval`.
  Порядок доставки одного красного: (1) `pretool_guard._emit_ask` → пуш → личка, полная карточка;
  (2) `bc.set_needs_approval(topic=829)` → та же карточка **с кнопками ✅/❌**; (3) `_notify_task`
  → личка ещё раз, обрезанная первая строка той же карточки. Третье беднее первого и слабее

**(б) конкретный путь под временными каталогами — «не высший вид».** `pretool_guard`:
`_POSIX_TMP_ROOTS` + `_is_posix_tmp_target`, подключены в `_delete_targets_all_temp`. Временным
считается **конкретный путь** под `/tmp/`, `/var/tmp/`, `/dev/shm/`; маска (`*`/`?`), сам корень
(`/tmp`, `/tmp/`) и `..` в хвосте остаются красными. Разбор лексический — путь может жить на
другой машине (сегмент ssh). Заведено **отдельным именем**, а не строкой в `_is_temp_zone`:
та питает ещё `_sanctioned_outside` и `is_probe`, расширять их правка права не имела.

Посылка сверена **на своей полосе**, а не взята с VPS (правило зеркала, CLAUDE.md): здесь класс
не закрыт ничем другим — `_is_temp_zone` требует `_inside_project`, поэтому любой `/tmp/...` у
неё `False`. Живой повод: карточка высшего вида «⛔ ВЫСШАЯ ЦЕНА · НЕОБРАТИМО» на `/tmp/_win.txt`
(05.08 10:25) и на `/tmp/autofetch_measure.py` (29.07 16:21) — обе на **уборку за собой**.

**(в) разряд `env` судит по ДЕЙСТВИЮ; объект и откат — про одну операцию.** Четыре правки:
- `_EXISTS_TEXT_CMDS` / `_TEXT_SINK_CMDS` / `_probe_pipe_stays_text`: труба из смотрелки с
  **текстовым** выводом в **фильтр**-приёмник зелена. Оба условия обязательны — объектные
  командлеты PowerShell отсеяны первым (`Get-Item <секрет> | Get-Content` вернул бы содержимое),
  исполнители вторым (`ls <секрет> | xargs cat` открыл бы файл по собственному листингу; дыру
  поймал собственный голден `test_probe_does_not_open_bypasses`, а не рассуждение).
- перенаправление меряется `_RE_CFG_REDIR` по `_redirect_text` — тем же прибором, что полоса
  конфига (`2c8ded0`). Грубое `>>?` считало записью в секрет и `2>&1`. Живой брак: задача 297,
  `ls -l … turbobaby_session.session 2>&1 | head -20` → карточка «хочу обратиться к секретам».
- `_ENV_CARRIER_CMDS` (`ssh` + вложенные шеллы) + глубина `_ENV_REACH_MAX_DEPTH=3`: аргумент-
  носитель разбирается **как команда**, а не как путь. Живой брак: задача 302, `ssh … "python3 -
  <<'PY' … PY"`, считавший окна по датам, дал карточку с пустым числом. `ssh … "cat <секрет>"`
  остаётся красным — смягчает только полный разбор (fail-closed).
- `_env_object` + `_env_rollback`: объект карточки — **путь**, а не расширение `.session`, и
  откат строится по этому же объекту. Природы три: `.env` (бэкапы `.env.bak*`), файл сессии
  Telethon (бэкапа нет — только повторная авторизация), прочий секрет (только бэкап).

### Один красный в первом прогоне — и почему он не дефект

Первая редакция проверки (v) держала пару `kind="env"` + путь `*.key` и дала `FAIL`: объект
пуст, откат общий про `.env`. Пара **невозможна**, и это измерено, а не предположено:

```
_RE_ENV на .key : False        живой decide 'cat /root/deploy/client.key' : ('defer', '', '')
_RE_ENV на .pem : False        живой decide Write client.key : ('ask', 'edit_secret', 'client.key')
```

Вид `env` такому объекту гард не присваивает вовсе — `.key`/`.pem` идут видами
`edit_secret`/`read_secret` от Write/Read, и там откат называет свой файл (обе строки таблицы
зелены). Пустой объект попадает в ветку `_env_rollback` «объекта нет — выдумывать имя не из
чего», объявленную в коде сознательно. Проверка переписана в честную форму — сплошной сверткой
по корпусу живых красных, а не по выдуманной паре.
