боевого кода не правлено, процессов не трогали. Повод — повторившееся дважды «отказ канала

## 3. Свойство ПРИБОРА и свойство ПОЛОСЫ — это разные вещи

### 3.1 Прибор: модель мы не выбирали, и это доказуемо

`review_send_run.py:268` печатает адрес канала так:

```python
facts["target"] = "%s exec --sandbox %s%s" % (os.path.basename(exe), sandbox, (" -m " + model) if model else "")
```

Суффикс ` -m <модель>` появляется ТОЛЬКО когда модель задана. В обоих вердиктах стои́т

```
адрес канала: `codex.CMD exec --sandbox read-only`
```

— суффикса нет, значит `model=None`, значит `gpt-6-astra` выбрал сам прибор, а не полоса.
Ключ `--codex-model` в отправщике есть (`review_send_run.py:1169`) и не был использован.

Второе доказательство непричастности содержимого: у двух пакетов **разные** sha256
(`73dbf76a23f9…` у chain-pc-17 и `b34cd44115ad…` у дайджеста), а ошибка побайтово одна.
Отказ от содержимого не зависит.

**Вывод: это свойство ПРИБОРА.** В репозитории ключа модели нет
(`.codex/config.toml` держит только `shell_environment_policy`).

### 3.2 Полоса: один и тот же 400 маршрутизируется двумя противоположными способами

`review_send.py:371` — любой ненулевой код возврата CLI схлопывается в ОДНУ причину:

```python
return make("refused", "channel_error", "код возврата %s; хвост: %s" % (returncode, tail or _NA), answer), answer
```

Дальше `review_outbox_queue.py:132` кладёт её в `_EXTERNAL`, а `retry_kind` (строка 229) отвечает
«канал лёг — повторяем ОТПРАВКОЙ». Между тем тот же самый 400, пришедший по HTTP-каналу, ловится
как `http_400` и получает прямо противоположное решение (`review_outbox_queue.py:212-216`):

```python
if code >= 400:
    return "ours", ("канал ответил кодом %d — запрос не по формату (размер, ключ, адрес); "
                    "повтор воспроизвёл бы ту же ошибку" % code)
```

Асимметрия не теоретическая — она замерена на живом лотке: у manus **10 вердиктов `http_400`**
(`for f in docs/review_inbox/*-manus.md; do grep -h "^причина:" "$f"; done | sort | uniq -c`),
у codex тех же по существу 400 — **2 вердикта `channel_error`**. Один и тот же статус, разные
имена, разные судьбы.

**Цена этого места числом.** `RESEND_PAUSES_SEC = (300, 900)`, `MAX_ATTEMPTS = 3`
(`review_outbox_queue.py:78-83`): каждый пакет с `channel_error` покупает **3 запуска за 20 минут**,
из которых **2 заведомо обречены** — прибор не чинится паузой. На двух пакетах это 6 запусков
вместо 2. Кровотечение ограничено замком здоровья `CHANNEL_DOWN_STRIKES = 2`
(`review_auto.py:100,512`): после двух страйков канал объявляется лежачим и заходы прекращаются.
То есть ущерб **ограничен, но не нулевой**.

## 5. Что повод ЗАКРЫВАЕТ, что остаётся, что неизвестно

**ЗАКРЫВАЕТ (доказано числом):**

- отказ не случайный и не про содержимое: 11 суток 100 % ответов → 2 из 2 отказов, побайтово
  одна ошибка на двух пакетах с разными sha256;
- виноват не пакет и не полоса, а прибор: `-m` в адресе канала нет, модель выбрана прибором;
- отчётность не соврала: исход `refused`, причина `channel_error`, ответ 0 знаков — контур
  назвал провал провалом и ничего не выдал за ревью. Тихого зелёного здесь не было.

**ОСТАЁТСЯ ОТКРЫТЫМ (названо словами, решение владельца — разведка кода не правит):**

1. **Поднять прибор** — обновить `codex-cli` с 0.151.0 до версии, знающей `gpt-6-astra`.
   Закрывает СЕГОДНЯШНИЙ случай и не закрывает класс: как только дефолтная модель снова уедет
   вперёд установленного CLI, всё повторится теми же строками. Операция вне репозитория и вне
   полосы автономного захода (установка пакета, сеть) — **красное, класс `outside`/`network`,
   исполняет владелец**.
2. **Либо приколотить модель** — задать `--codex-model` с моделью, которую 0.151.0 точно знает.
   Ручка уже есть (`review_send_run.py:1169`), новый код не нужен; цена — ревью поедет на
   модели постарше.
3. **Закрыть КЛАСС (главная правка, назначения не делаю).** Научить `classify_codex` заглядывать
   в stdout/stderr и, найдя там `"status":4xx`, отдавать `http_4xx` вместо плоского
   `channel_error`. Тогда `origin()` уведёт постоянный отказ в `ours` → «повтора нет», как он
   уже делает для HTTP-канала, и обречённые 2 запуска из 3 не покупаются. Цена: правка
   `review_send.py` + голдены на живом хвосте (он снят и лежит в `tmp/review_send/codex_stderr.txt`).
4. **Завести признак «контур внешнего ревью мёртв целиком».** Сегодня мёртвых каналов видно
   только поштучно, и неделя работы без резерва прошла незамеченной. Предмет — счёт по ДНЮ,
   а не по вердикту.

**НЕИЗВЕСТНО (третий исход, законный):**

- **откуда взялся `gpt-6-astra`.** В `.codex/config.toml` репозитория ключа модели нет, значит
  он приходит из пользовательского `~/.codex/config.toml` либо из встроенного дефолта CLI.
  Пользовательский файл лежит **вне проекта** — по запретам разведки не читал и обхода не искал.
  Сказать, ручка это владельца или дефолт прибора, по имеющимся фактам нельзя.
- **когда именно сменился дефолт.** Окно сужено до 12 ч 22 мин (11.09 19:53:45 → 12.09 08:16:14),
  внутри окна доказательств нет: прибор версию не логирует между заходами.
- **чинит ли обновление CLI канал НАСОВСЕМ** — проверяется только живым заходом после обновления,
  а обновление здесь красное.
