# Вердикт ворот клиентского контура: полный набор, два круга — 16/16 кейсов, 300/300 чеков

**Исход в одной строке.** На кандидате `1454db0` **полный набор корпуса (16 кейсов из 16) прошёл
ВСЕ зачётные чеки в ОБОИХ кругах**: 32 единицы из 32, чеков **300/300**, красных **0**, «неизвестно»
**0**, вершина за оба захода не двигалась. По правилу задания («полный набор, все чеки, тот же
коммит, два из двух») это **ЗЕЛЁНЫЙ**. По правилу КОДА ворот зелёного всё равно нет: у него пятое
условие — **чистое дерево**, а дерево грязно четырьмя неотслеживаемо-изменёнными файлами, и ни один
из них не код (`docs/review_inbox/…-codex.md`, `…-manus.md`, `docs/review_outbox/…-72.md`, `todo.md`).

**В реестр ворот (`pc_orchestrator.client_trainer_green.json`) не записано НИЧЕГО** — ни зелёного,
ни красного. Так задумано: зелёная запись в этом файле и ЕСТЬ открытие ворот (см. §6).

Ось: бизнес — ворота клиентского контура. **Кода не правилось ни байта**: задача только гоняла и
писала.

## 4. Прерываемость: единица на диск сразу, ключ «круг, кейс» (п.3)

Раннер `_scratch_gate_verdict/run_gate.py` пишет единицу в `units.jsonl` НЕМЕДЛЕННО (`flush` +
`fsync`), а перед стартом читает файл и собирает множество сделанных пар **(круг, кейс)**. Обход
круго-мажорный: сначала весь набор кругом 1, потом кругом 2 — оборванный заход оставляет полный
первый круг, а не половину обоих. Единица, снятая на ДРУГОМ коммите, за сделанную не считается.

**Механизм отработал в живую, а не заявлен:** заход 1 оборвался на потолке (13 единиц), заход 2
напечатал **13 строк** `[ЕСТЬ] круг 1 кейс N — уже на диске, не повторяю` и сделал 19 новых.
Головы ни одна повторная единица не звала. Итог: 32 единицы, дублей 0, битых строк 0.

## 5. Арифметика, названная ДО старта, и что вышло (п.4)

| до старта | вышло |
|---|---|
| 16 кейсов × 2 круга = **32 единицы** | 32 единицы, все на диске |
| цена единицы 31 с (вчерашний замер EN) → **992 с ≈ 16.5 мин** | сумма `sec` по единицам **1000.2 с**, то есть **31.3 с/ед** |
| потолок задачи `TASK_TIMEOUT = 2700 с` (45 мин) | wall двух заходов **1002 с** = **37 %** потолка |
| потолок одного вызова оболочки 600 с → резать заходами по 460 с | заход 1 — 490 с (13 ед.), заход 2 — 512 с (19 ед.) |

Вчерашняя цена 31 с/ед оказалась точной до 1 %. Влезло целиком, урезать набор не пришлось.

## 7. ВЕРДИКТ

**По правилу задания — «полный набор, все чеки, тот же коммит, два из двух»:**

```
полный набор  : 16 кейсов из 16 корпуса (cases == cases_total)   → ДА
все чеки      : 300 зелёных из 300 зачётных, красных 0, unknown 0 → ДА
тот же коммит : 1454db0 на входе и на выходе обоих заходов        → ДА
два из двух   : круг 1 и круг 2 полными, 32 единицы из 32          → ДА
ВЕРДИКТ ЗАДАНИЯ: ЗЕЛЁНЫЙ
```

**По правилу КОДА ворот (`client_contour.trainer_verdict` + `trainer_run.build_verdict`) — НЕ
ЗЕЛЁНЫЙ, и причина ровно одна:**

| условие кода | факт |
|---|---|
| `result == 'green'`, `checks_passed == checks_total > 0` | 300 == 300 ✔ |
| `cases >= 12` и `cases == cases_total` | 16 ≥ 12, 16 == 16 ✔ |
| `runs >= 2` | 2 ✔ |
| `corpus_sha` совпал с диском | `6d5d78f0d83acdca` ✔ |
| коммит тот же, `head_moved` пусто | `1454db0` ✔ |
| **`clean` — дерево чистое** | **✘ `tree_dirty: true`, 4 пути** |

`build_verdict` собрал запись `result = "red"` — но красным её делает НЕ продукт: список `failed`
**пуст**, `unknown` **0**. Это надо сказать прямо, иначе слово «red» соврёт: **ни один кейс, ни один
круг, ни один чек не покраснел**. Красным вердикт называет состояние рабочего дерева.

Правило «почти зелено вердиктом не является» соблюдено: зелёного вердикта у ворот НЕТ, и мы его не
рисуем. Что нужно, чтобы он появился, — одно движение владельца: закоммитить или откатить четыре
текстовых файла выше, после чего прогон повторить (он стоит 17 минут и 32 единицы).

## 8. Ворота не тронуты — и вот что случится, если их открыть (п.6)

**В реестр ворот не писалось ничего.** `run_gate.py` не зовёт `trainer_run.write_verdict` ни одной
веткой. Причина названа в его шапке: зелёная запись в `pc_orchestrator.client_trainer_green.json`
— это и ЕСТЬ открытие. `client_contour.release_reason` вернёт `'trainer'`, `_client_block` не
удержит тик, и `reconcile_children_tick` перезапустит детей САМ, следующим тиком реконсиляции —
без карточки и без «да». Дословно из `trainer_run.main()`: «ворота клиентского контура откроются на
этот коммит по основанию „trainer“». Отсюда и запрет задания: «да» за владельца никто не говорит.

Состояние реестра на 03.09 не менялось: зелёная запись одна и она на `74be777` (26.08, ещё
12-кейсовый корпус), красных четыре, последняя — `298a387` от 02.09 (6/12 кейсов). Одобрения
владельца на `1454db0` в `pc_orchestrator.client_release.json` **нет** (там пять коммитов от 30.07).

**СТРОКА ДЛЯ ВЛАДЕЛЬЦА — ОБЪЁМ ПРЫЖКА: при открытии ворот дети получат РАЗОМ 138 коммитов
(`6cbdd15` → `1454db0`, 55 часов), и клиентских файлов в них ровно ТРИ — `suggest.py` (3 коммита),
`price_source.json` (2 коммита), `model_name.py` (1 коммит, файл НОВЫЙ, 345 строк); суммарно
+419 / −53 строки.**

Разложение прыжка (считано `client_contour.split` — тем же чистым кодом, которым судят ворота;
замыкание `userbot_listen.py` построилось, `ok=True`, 59 файлов):

| что | число |
|---|---|
| коммитов разом | **138** |
| путей тронуто | 214 (189 уникальных по basename) |
| из них **клиентских** | **3** |
| неклиентских | 186 (доки, тесты, `pc_orchestrator.py`, хуки) |

Пять коммитов, которые трогают эти три файла: `768729b` (локализация источника секрета suggest),
`ef7d6ac` (разведение поколений XMAX), `298a387` (правило разрешения имени модели — сюда приходит
новый `model_name.py`), `50ded10` (перемер медианы, слепок цены), `27d0f8d` (язык EN-клиенту,
вариант A). Прыжок на 138 коммитов — это прыжок по КОДУ КЛИЕНТА на **пять** содержательных правок.

Отдельно: контур **ЗАМОРОЖЕН** (`client_contour.frozen()` → True, флаг `pc_orchestrator.contour_frozen`
лежит с 21.08 19:36). Заморозка глушит ПОВТОРНЫЕ карточки отказа, уводя их в ленту, — то есть если
владелец ждёт напоминания карточкой, он его может и не увидеть: держащие ворота молчат по замыслу.

## 10. Что осталось НЕИЗВЕСТНО (п.7)

- **Вердикт стареет от коммита этого артефакта.** Ворота судят ТЕКУЩИЙ HEAD, а `trainer_verdict`
  сверяет хеш целиком. Коммит артефакта двигает вершину с `1454db0` на новый хеш, и вердикт этого
  замера ему уже не принадлежит. Клиентское СОДЕРЖИМОЕ при этом не меняется ни на байт (артефакт —
  файл в `docs/artifacts/`), но зелёного по основанию «trainer» на новой вершине нет и не будет без
  повторного прогона. Обойти это в рамках задания нельзя: «коммит только артефакта в конце».
- **Устойчивость 300/300 — это два круга, а не двадцать.** Генератор недетерминирован; правило
  ворот требует два прогона и на них исход одинаков, но частоту редкого провала два круга не мерят.
  Вчерашние 20 EN-единиц и сегодняшние 10 складываются в 30 подряд без языкового провала — это
  сильнее, чем каждый замер по отдельности, но доверительного интервала здесь не считалось.
- **Грязь дерева не наша, и её судьба не наша.** Четыре текстовых файла изменены до этого захода;
  трогать их задача не имела права («ничего не удалять», «коммит только артефакта»). Пока они
  висят, зелёная запись вердикта физически не соберётся ни у кого — ни у нас, ни у демона.
- **Прыжок мерился по КЛИЕНТСКОМУ замыканию, а не по поведению.** «Три файла» — это ответ на
  вопрос «что доедет до живого клиента», а не «насколько изменится ответ клиенту». Регрессия
  поведения между `6cbdd15` и `1454db0` этим прогоном не мерилась: тренажёр судил ТОЛЬКО кандидата.
- **Модербот на прыжке не проверялся отдельно.** Корпус тренажёра меряет клиентский черновик
  (`suggest`), а `moderation_core.py`/`moderation_bot.py` в дифф прыжка не попали вовсе — значит
  модерботу в этих 138 коммитах менять нечего, но и вердикта о нём у нас нет.

## 11. Воспроизведение

```
venv/Scripts/python.exe _scratch_gate_verdict/run_gate.py 1454db0 2 460     # прогон, прерываемый
venv/Scripts/python.exe _scratch_gate_verdict/jump.py <база детей> <вершина> # объём прыжка
```

Файлы замера (временное, в коммит не идёт): `_scratch_gate_verdict/units.jsonl` — 32 единицы со
всеми чеками и дословными черновиками; `summary.json` — свод и запись вердикта ровно в том виде,
который читают ворота (с полем `written_to_gate: false`); `jump.json` — разложение прыжка.
