## 3. Где рез и в какой единице

Путь задания ящика до судьи (строки на `8b6cb0f`):

1. `shtab_box.task_text` собирает шапку и тело. Среза нет.
2. `shtab_box_run.Queue.place_task` вызывает `pc_orchestrator.enqueue_pc_task`
   (`pc_orchestrator.py:4729`). Там только `.strip()`.
3. `Bridge.enqueue_task` (`pc_orchestrator.py:1114`) отправляет POST, тело собирает
   `json.dumps(payload)` (`bridge_http.py:171`). Среза нет.
4. **Мост, `doPost` → `enqueueTask_`: `String(p.task_text || '').slice(0, 5000)`.** Это и есть рез
   (`BotData.js:309` в копии `tmp/drive_public_recon_20260826/bridge_head`).
5. `get_pending` → `getPending_` (`BotData.js:324–344`) отдаёт ячейку как есть, без среза.
6. `_process_one` берёт `text = task["task_text"]` (`pc_orchestrator.py:4249`). **Один и тот же
   текст** уходит исполнителю (`prompt += text`, `:2777`) и судье (`done_judge_pc.baseline(text)`
   `:4336`, `_judge_done(tid, text, …)` `:4385`). Нет адреса — судья отвечает
   `done_judge_pc.py:491–493` «адрес результата не назван задачей».

**Единица — кодовые единицы UTF-16** (JS `slice`). Это не символы Python и не байты:

| проба | `len` Python | UTF-16 | байт UTF-8 | итог |
|---|---|---|---|---|
| кириллица, ряд 5000 | 5000 | 5000 | 9120 | **цел** |
| кириллица, ряд 5001 | 5001 | 5001 | 9122 | срезан до 5000 |
| ASCII-заполнитель, ряд 5000 | 5000 | 5000 | 5574 | **цел** |
| ASCII-заполнитель, ряд 5001 | 5001 | 5001 | 5575 | срезан до 5000 |
| 40 эмодзи, ряд UTF-16 5000 | 4960 | 5000 | 9134 | **цел** |
| 40 эмодзи, ряд UTF-16 5001 | **4961** | 5001 | 9136 | срезан до `len` 4960 |

Кириллический ряд в 9120 байт доходит целым, а ряд в 5001 единицу режется, значит байты ни при
чём. Эмодзи-ряд режется при `len` 4961 < 5000, значит `len()` Python — не та единица.

### Как построен стенд

- `stand_bridge.js` загружает в node vm **настоящие** `Bridge.js` и `BotData.js` из копии моста.
  Подменены только службы Apps Script: лист очереди — массив в памяти, `LockService` — пустой
  замок, `ContentService` — строка, `verifyToken` — «да». Роутинг `doPost`/`doGet`,
  `enqueueTask_` и `getPending_` работают дословно.
- `stand.py`: пробное тело идёт через **настоящие** `shtab_box.task_text` →
  `shtab_box_run.Queue.place_task` → `pc_orchestrator.enqueue_pc_task` → `pc_orchestrator.Bridge` →
  `bridge_http`. Сокет заменён opener'ом, который отдаёт байты запроса в node. Дальше
  `Bridge.get_pending` → текст ряда → `done_judge_pc.read_address`. Процесс запущен с
  `TESTING=1`/`TURBOBABY_TEST_LOGS=1`, `witness` подменён пустым.
- Сети нет, живой очереди, мозга и живых заданий стенд не касается. Пробные тела — свои строки с
  меткой `STEND-…`. Потолок ворот поднят только в процессе стенда (`sb.BODY_MAX = 10**9`), потому
  что мерился канал, а не ворота.

| 6000 | 6349 | 5000 | нет | **нет** |

Граница сужена бинарным поиском до одной единицы:

- **наибольший ряд, доходящий целым: 5000** (тело 4651);
- **наименьший ряд с потерянным хвостом: 5001** (тело 4652).

**Тихий класс, найденный стендом.** Ряды 5001–5016 теряют только хвост строки адреса, и судья
читает адрес с ОБРЕЗАННЫМИ словами: при 5001 это `STEND-H4652 160` вместо `… 1609`, при 5016 —
одна буква `S`. Адрес целиком пропадает (вердикт «не назван») только с ряда **5017**. В этой
полосе судья ищет продукт по неверным, укороченным словам и может засчитать чужой файл. Новый
потолок закрывает и этот класс: ряд длиннее 5000 в очередь больше не уходит.

## 5. Новый потолок и его обоснование

`shtab_box.py:325–327` (`bdbfd82`):

```
QUEUE_ROW_CAP = 5000
HEADER_RESERVE = 500
BODY_MAX = QUEUE_ROW_CAP - HEADER_RESERVE      # 4500
```

Тело меряет `units()` (`shtab_box.py:845`) в UTF-16, а не `len`.

**Запас 500 под шапку.** Стенд мерил шапку, которую `task_text` ставит над телом:

| форма шапки | единиц |
|---|---|
| живая: ключ 25, file id 33, полоса названа | 349 |
| ключ 40 (`KEY_MAX`), id 33, полоса названа | 379 |
| ключ 40, id 44 (длина id документа Google Docs), полоса названа | 390 |
| **худшая допустимая: ключ 40, id 44, полоса НЕ названа** | **414** |

500 = 414 + 86. Запас 86 покрывает file id длиннее 44 или слово, дописанное в шапку (так 03.09 слова
полосы выросли на 24). Если шапка перерастёт запас, покраснеет набор тестов, а не живой ряд:
`test_the_worst_header_with_the_longest_body_fits_the_queue_row`.

**Цена запаса, названная числом.** С живой шапкой (349) целым дошло бы тело до 4651. Тела 4501–4651
теперь получают отказ, хотя доехали бы. Это плата за то, что худшая шапка (414) тоже умещается.

Ещё одна копия числа сведена с потолком: умолчание `shtab_box_accept.retry_body(body_max=…)` было
литералом 6000, стало 4500 (`shtab_box_accept.py:455`). Расхождение ловит
`test_the_retry_default_moved_with_the_body_ceiling`. Боевой дожим и раньше передавал
`shtab_box.BODY_MAX` явно (`shtab_box_run.py:553`).

## 6. Запись замера и замок против повтора

Рядом с потолком лежит `shtab_box.py:335` `CAPACITY_RECORD`: дата `2026-09-16`, `cap` 5000, единица
`utf16`, `max_whole` 5000, `min_cut` 5001, `how` (стенд, путь, копия моста снята 26.08,
`BotData.js` sha256 `c92d414eed9643ab…`, рез `slice(0, 5000)`). Срок `CAPACITY_TTL_DAYS = 30`
(`:354`).

`capacity_state(today)` (`:854`) краснеет словами в четырёх случаях:

- **записи нет или не хватает поля** — «записи замера ёмкости строки очереди нет … ворота закрыты до замера стендом»;
- **запись меряла другое число или единицу** — «… не сходится с ёмкостью в коде … число правили без замера»;
- **дата не разобрана** — «свежесть замера НЕИЗВЕСТНА», это отказ, а не пропуск;
- **старше 30 суток** — «запись … ПРОТУХЛА: замер 2026-09-16, прошло N сут при сроке 30 … Перемерить стендом и обновить shtab_box.CAPACITY_RECORD».

`check(block, today)` (`:907`) спрашивает запись до проверки длины и отказывает причиной
`capacity_unmeasured`. День передают обе дороги постановки: `select` (`:1364`) и `task_text`
(`:984`); ещё `--status` рук (`shtab_box_run.py:962`). Без дня (`today=None`, так зовёт тренажёр)
проверяются наличие записи и сведение числа, возраст не проверяется.

**Почему 30 суток.** Срок взят по окну, на котором число наблюдалось неизменным, а не по частоте
выкаток моста (её полоса не видит). Все 11 копий моста на этой машине с 29.07 по 26.08 несут один и
тот же `slice(0, 5000)`, и живые тела Штаба 15–16.09 с ним согласны.

**Последствие для владельца.** С **17.10.2026** (день 31) ящик перестанет брать задания и скажет
словами, что запись протухла. Лечение: перемерить стендом на свежей копии моста и обновить запись.
