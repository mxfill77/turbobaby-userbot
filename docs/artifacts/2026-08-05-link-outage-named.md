## 2. Чем меряем — 0 новых запросов, 0 мс

Свидетели — вызовы, которые контур делает и так. Прямая проба DNS (27,1 мс замерено) **не
заведена**: она не нужна, пока есть бесплатные свидетели.

| канал | где снимается | живая форма отказа 04.08 |
|---|---|---|
| **мост** | `Bridge._call` (каждый `get_pending`/`claim`/`complete`) | `TimeoutError` / `URLError` — 37 отказов за окно |
| **github** | `git_ff_pull_tick` → `git fetch origin` | `Failed to connect to github.com port 443 after 21115 ms` |
| **api модели** | хвост вывода headless при `rc≠0` | `API Error: Unable to connect to API (ConnectionRefused)` |

**Правило вердикта (`LinkWatch`).** Подтверждение связи ОДНИМ каналом гасит отказы ВСЕХ (мы
доказанно в сети → лежит сервис, а не связь). «Связи нет» — только когда молчат **два**
независимых канала; один молчащий = «связь не подтверждена». Свидетельство **троично**:
`True` — ответ получен, `False` — не дошли, `None` — **не измерили** (не смеет выдавать себя ни
за то, ни за другое; тот же разворот, что `pids is None` у вотчдога, класс #171).

**Ключевая проверка на живом числе:** `BridgeTransportError`/`BridgeReceiptLost` — это «мост
**ответил**, обмен не завершён», то есть связь ЖИВА. В логе таких **354** за 02–05.08 при
полностью исправной сети (последняя — сегодня в 11:16). Считать их обрывом = 354 ложных «связи
нет». Голден `test_354_zhivyh_bridge_transport_ne_dayut_ni_odnogo_obryva` держит это число.

## 3. Детектор сна: молчит, когда сна не было

`diagnose_gap(gap, slept, link_lost, worked)` — чистая функция, четыре исхода:

| исход | условие | что делает |
|---|---|---|
| `сон машины` | сон **измерен** часами бодрствования и > 10 с | прежняя строка «детект пробуждения ПК» + grace + карточка 🛌 |
| `связи нет` | сна нет, полоса измерена молчащей | своя строка (слова «пробуждение» в ней нет **намеренно** — по нему грепают) + grace |
| `длинный виток` | в отрезке была работа задачи | INFO и только при скачке ≥300 с |
| `залипание вызова моста` | ни сна, ни обрыва, ни работы | **тишина** — это 297 строк из 305 за сутки |

**Порог сна 10 с измерен, а не назначен:** 303 строки из 305 несут ровно `сна 0с`, оставшиеся
две — `сна 1с` и `сна 2с` (суточная поправка службы времени). Короче 10 с ПК не спит.

**Grace вотчдога** теперь взводится на двух исходах из четырёх (сон и обрыв), а не на любом
скачке: прежнее поведение стоило **71 подавленный тик в сутки ≈ 5,9 ч отложенного надзора**.
В окне обрыва grace взводится по-прежнему — это защита клиентских ботов, и ослаблять её правка
не имеет права.

## 5. Границы правки — чего она НЕ делает

1. **Не сбрасывает латч `halted`** клиентского вотчдога: 04.08 сеть вернулась, а латч «умер 3
   раза подряд» держал личку мёртвой ещё 73 минуты. Grace в окне обрыва снижает шанс набрать
   латч, но снятия латча здесь нет — отдельный класс.
2. **Окна обрыва живут в памяти процесса.** Рестарт демона их теряет → возраст задач считается
   как прежде (fail-open). State-файл ради этого не заводился: дороже, чем стоит поправка.
3. **Telegram и userbot свидетелями не стали:** их отказы видны только в чужих логах, а не
   в процессе демона. Два канала из трёх дают вердикт и без них.
4. **Спул журнала по-прежнему без потребителя** (§2.3 разбора): «в спуле N строк» никто не
   говорит. Сделано меньшее — на возврате связи в журнал уходит одна строка «связи не было
   N минут», чтобы разрыв в мозге перестал быть неотличим от «ничего не происходило».
5. **Латентность моста мерится, но не хранится:** `ms` кладётся в ответ `Bridge._call` и пока
   читается только диагнозом отказа; строки METRICS для моста нет.
