# turbobaby-bot

ПК-контур TurboBaby. Brain/Bridge живут на VPS (репозиторий `turbobaby-manager-bot`) —
здесь только исполнение на ПК.

Правила работы в этом репозитории — [`CLAUDE.md`](CLAUDE.md) и
[`docs/ENV_PLAYBOOK.md`](docs/ENV_PLAYBOOK.md). Читать до первой правки.

## Что здесь живёт

**Клиентский контур** (общение с клиентом):

| модуль | роль |
|---|---|
| `userbot_listen.py` | приём входящих ЛС клиента, точка входа контура |
| `suggest.py` | генерация черновика ответа, прайс-блоки, гварды и пост-чеки (самый большой модуль репо) |
| `moderation_bot.py`, `moderation_core.py` | модерация черновика человеком: карточки, кнопки, решения |
| `moderation_ipc.py` | SQLite-очередь черновиков (`moderation_ipc.db`, таблица `drafts` — источник правды по окнам) |
| `pricing.py`, `delivery.py`, `booking_draft.py` | тарифы/quote, зоны доставки, карточка брони |

**Служебный контур** (исполнение задач и надзор):

| модуль | роль |
|---|---|
| `pc_orchestrator.py` | ПК-дирижёр: очередь задач через Bridge, headless-исполнитель, локальные цепи, ревизор |
| `pc_agent.py` | бот управления процессами ПК (allowlist, без произвольного шелла) |
| `pretool_guard.py` | гард разрешений: что зелёное, что требует «да» владельца |
| `rc_supervisor.py` + `rc_auth_detect.py` | сторож канала Remote Control и детектор протухшей авторизации |
| `cowork_log_append.py`, `brain_writer.py`, `dispatch_notify.py` | запись в мозг и уведомления (единственные легальные каналы) |
| `lesson_router.py`, `trainer.py`, `reviewer.py`, `session_watch.py` | уроки, тренажёр, детерминированные чеки черновиков, детект немоты сессий |

## Как запускается

- Интерпретатор — **`venv/Scripts/python.exe`** (не системный `python`).
- Канал Remote Control — задача Планировщика `TurboBabyRC`; в репозитории лежат
  установочный шаблон `pc_remote_control.task.xml` и лаунчер `rc_remote_control.vbs`.
  **Внимание:** трекаемый XML — это шаблон с URI `\pc_remote_control`, а живая задача
  установлена под именем `\TurboBabyRC`. Содержимое файла в репо **ничего не говорит**
  о настройках живой задачи — сверять только через Планировщик.

## Тесты и гейт

```
venv/Scripts/python.exe -m unittest discover -p "test_*.py"
```

Способ запуска — часть формата: `-m unittest` и прямой запуск `test_x.py` дают разное
поведение логгера (см. `ENV_PLAYBOOK` §8). Выборочный прогон — `gate_selective.py`.
Числа «полный гейт NNNN OK», встречающиеся в старых документах, протухли: сверять зелень
по ним нельзя, запускай гейт.
